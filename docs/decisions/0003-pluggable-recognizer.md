# 0003. 인식기는 플러그인, 교체는 수치로

상태: 채택 (2026-09)

## 상황

기존 구현은 상용 OCR 서비스에 묶여 있었다. 과금이 계속되고, 현장 문서가 외부로 나가며, 손글씨에 맞게 학습시킬 수 없다.
로컬에서 학습·추론하는 모델로 바꾸고 싶지만, 바꾸었을 때 더 좋은지는 재 보기 전에는 모른다.

## 결정

- 파이프라인은 `Recognizer` 인터페이스(셀 크롭 + 문맥 → 텍스트·신뢰도·후보)만 안다. 구현체는 설정으로 고른다.
- 인식기 없이도 파이프라인이 끝까지 돌게 한다(`null`). 인식기를 뺀 나머지는 `oracle` 로 검증한다.
- 백엔드의 채택·교체는 같은 평가셋에서의 수치로 정한다. 기준선은 기존 상용 OCR 의 **이미 받아 둔 결과**로 계산한다.
- 상용 OCR 을 새 백엔드로 연결하지는 않는다. 로컬 모델이 기준선을 넘지 못하는 동안에도 파이프라인 개발은 막히지 않는다.

## 이유

- 모델 선택이 구조를 막지 않는다. 어떤 모델을 쓸지 정하기 전에 나머지 전부를 만들고 검증할 수 있다.
- 입력이 페이지가 아니라 **정합된 셀 크롭**이므로 문제가 작다. 숫자 한두 자리, 닫힌 집합에서 고르기, 짧은 문구.
  작은 모델로 풀 수 있는 부분과 큰 모델이 필요한 부분을 나눌 수 있다.
- 문맥(`CellContext`)이 템플릿에서 확정되어 넘어간다. 인식기는 "이 칸은 어느 장비의 점검내역"임을 알고 읽는다.

## 대가

- 평가셋이 없으면 아무 결정도 못 한다. 평가셋 구축이 인식기보다 먼저다.
- 신뢰도의 뜻이 백엔드마다 다르다. 자동 적재 기준은 백엔드를 바꿀 때마다 평가셋에서 다시 잡아야 한다.
