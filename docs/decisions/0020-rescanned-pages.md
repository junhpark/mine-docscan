# 0020. 다시 스캔한 쪽은 같은 날·같은 계열 안에서 손글씨 자리의 유사도로, 문서의 순서로 붙잡고 사람이 정한다

상태: 채택 (2026-10). 작업 지시서 [tasks/0007](../tasks/0007-intake.md) 4.6. [ADR 0019](0019-intake-dates-and-decisions.md)의 결정으로 푼다.
서명의 판 2 (넓힌 마스크): [tasks/0010](../tasks/0010-release-followups.md) 4.3 — 아래 5.

## 상황

문서 ID 는 파일의 해시라 같은 파일만 막는다. 급지식 스캐너는 걸리면 묶음을 다시 넣는다. 실제 하루치 30쪽을 다시 스캔한 것처럼 한 파일 더
넣으면 업무 행이 두 배가 되고 그날의 교차검증에 가짜 행 200개(`missing_matrix`)가 붙는다.

## 결정

1. **서명**: 정합 그림 → `grid.binarize` → 지울 자리를 0 → 2 × 2 열기 → 16 × 16 px 칸마다 잉크 화소의 수 (`imaging/signature.py`).
   지울 자리는 인쇄(템플릿에 인쇄 층이 있으면 그 마스크, 없으면 기준 이미지를 인쇄 층으로 본 마스크)와 **표 밖 필드**(날짜 줄·차량번호·작성자 칸).
   유사도는 두 서명의 코사인. 서명이 전부 0 이거나 모양이 다르면 견주지 않는다. 적재된 쪽의 서명만 `doc_page_sig` 에 남긴다.
2. **규칙**: 쪽은 같은 날짜·같은 계열(`family`, 없으면 템플릿 이름)의 **자기보다 앞 순서인 적재된 쪽** 중 가장 비슷한 것과의 유사도가
   `dup_min_sim`(0.80) 이상이면 적재하지 않고 붙잡힌다 (`duplicate`, `duplicate_of`, `duplicate_sim`, 필드·업무 행 없음, 문서는
   `needs_review`). 다른 날의 쪽과는 견주지 않는다. `keep` 이 있는 쪽은 견주지 않고 적재한다.
3. **처리한 순서와 상관없게**: 문서 X 를 처리한 뒤(버리기·날짜 바꾸기·실패 포함) 뒤 순서의 문서에 다시 처리를 요청한다 — ① X 의 쪽(지우기
   전의 것 포함)과 같은 날짜·계열에 붙잡힌 쪽이 있는 문서, ② X 의 적재된 쪽과 같은 날짜·계열이고 서명이 기준 이상인 적재된 쪽(`keep` 없음)이
   있는 문서. 요청은 뒤로만 가므로 끝난다.
4. **사람이 정한다** (전부 결정이다): 같은 종이 — 뒤쪽을 버린다(뒤쪽 `discard`), 같은 종이 — 앞쪽을 버리고 뒤쪽을 쓴다(앞쪽 `discard`),
   다른 종이 — 둘 다 쓴다(두 쪽 모두 `keep`). 기계가 스스로 버리거나 합치지 않는다.
5. **서명의 판** (tasks/0010 4.3): 판 2 는 지울 자리(인쇄 + 표 밖 필드)를 9 × 9 로 넓힌다 (`signature.WIDEN`, `Template.signature_mask` 가
   템플릿마다 한 번). 서명의 글자열 앞에 판을 적는다 (`2|높이x너비:…` — 앞머리가 없는 옛 글자열은 판 1). **판이 다른 서명은 견주지 않는다**
   (`decode` → None, 유사도 None — 다시 스캔으로 보지 않는다). 스키마는 그대로(글자열). 옛 판의 쪽이 있으면 `report` 에 `old_signatures`
   (그런 쪽이 있을 때만 — 지금의 판으로 만든 DB 의 리포트는 예전과 같다), `info` 가 그 수와 `run --fresh` 를 알린다.
   붙잡는 규칙과 기준 `dup_min_sim` 0.80 은 그대로다.

## 이유

- 실제 3일치, 지금의 서명(표 밖 필드도 지운다)으로 다시 잰 것 (tasks/0008 1절 라 — 지시서 0007 1절의 0.91 은 한 번 뽑은 값이고 서명의 정의도
  그 뒤에 바뀌었다): 같은 날·같은 계열의 다른 종이 286쌍 최대 0.593 (99 % 0.524), 다른 날의 다른 종이 642쌍 최대 0.853(같은 사람이 같은 차로
  같은 칸에 쓴다 — 그래서 같은 날 안에서만). 같은 종이를 세 번씩 흔들어 다시 정합하면 중앙 0.99 지만 **0.80 아래가 2–3 %** 다
  (순하게 — ±1°, ±15 px, 배율 ±1 %, JPEG 60–90 — 243쪽 최소 0.700, 0.80 미만 5쪽; 거칠게 — ±2.5°, ±25 px, ±3 %, JPEG 45–80 — 최소 0.284,
  0.80 미만 7쪽). 하루치 30쪽과 그 다시 스캔 30쪽을 파이프라인에 넣으면 28쪽이 붙잡혔다(최소 0.857, 나머지 2쪽은 기준 이미지로 쓴 종이 — 서명 0).
  0.70 이면 실데이터의 순한 흔들기를 전부 잡고 같은 날 다른 종이는 하나도 붙잡지 않지만, 합성은 같은 날 다른 종이가 0.771 까지 올라간다
  → 기본값 0.80 은 그대로 두고, 현장의 값은 실제 다시 스캔을 본 뒤 정한다 (tasks/0007 8절 4).
- **표 밖 필드를 지우는 것은 구현에서 정했다** (지시서 4.6 에는 인쇄만 지웠다). 합성 글씨는 사람마다 획이 같아, 같은 날 모든 일보의 머리 칸
  (그날의 날짜, 비슷한 차량번호)이 화소까지 같았다 — 그 칸들이 서명 질량의 58–66 %, 같은 날의 다른 종이가 0.81 까지 올라가 기준을 넘었다
  (`--low-cells` 0.810, `--meta-fields --mix-pages` 0.814). 표 밖 필드를 지우면 다른 종이 최대 0.594(기본)·0.645(낮은 칸)·0.771(메타 필드와
  섞인 쪽), 다시 찍은 쪽(흔들기·JPEG 45 재압축·90° 돌림) 최소 0.998. 실제 종이도 같은 날의 머리 칸에는 같은 날짜를 쓴다. 실제 다시 스캔으로는
  아직 재지 않았다 — 지시서 8절에서 사람이 잰다.
- **판 2 — 넓힌 마스크** (tasks/0010 4.3): 판 1 은 정합의 작은 어긋남에 약했다. 실제 81쪽의 정합 그림을 옮기거나 돌려 원래 그림과 견주면
  (`scripts/sig_probe.py` 의 방법) (2, 1) px 에서 최소 0.608, (3, 2) px 0.316, 0.2° 0.810 — 인쇄(괘선·글자)가 넓히지 않은 마스크 밖으로 밀려
  나온다 (손글씨는 1–2 px 옮겨도 같은 칸에 남는다). 정합의 괘선 오차는 대개 1 px 안이지만 양식에 따라 4 px 까지 나오고, 윈도우의 OpenCV 는
  합성 다시 스캔 한 쪽을 1 px 다르게 정합해 그 쪽이 0.9987 → 0.8626 이었다. 실제 다시 스캔의 2–3 % 가 0.80 아래였던 것(위)도 같은 까닭일 수 있다.
  후보를 합성 다시 스캔 묶음(`synth --rescans`, 3일 — 원래 쪽 17, 다시 스캔 4쌍, 같은 날·같은 계열의 다른 종이 15쌍, 리눅스)으로 한 번에 쟀다
  (5 % / 최소 — 기준: (2, 1) px·0.2°·둘을 같이, 셋마다 5 % ≥ 0.93·최소 ≥ 0.85, 다시 스캔 ≥ 0.95, 다른 종이의 최대가 0.02 넘게 오르지 않는다,
  쪽 하나의 시간·글자열이 2배 안):

  | 서명 | (2, 1) px | 0.2° | (2, 1) px + 0.2° | 0.4° (참고) | (3, 2) px + 0.3° (참고) | 다시 스캔 최소 | 다른 종이 최대 | 기준 |
  |---|---|---|---|---|---|---|---|---|
  | 판 1 | 0.975 / 0.971 | 0.869 / 0.861 | 0.602 / 0.597 | 0.332 / 0.330 | 0.290 / 0.283 | 0.9985 | 0.594 | 못 넘는다 |
  | 넓힌 마스크 5 × 5 | 0.975 / 0.971 | 0.981 / 0.981 | 0.954 / 0.946 | 0.602 / 0.599 | 0.514 / 0.510 | 0.9985 | 0.594 | 넘는다 |
  | 7 × 7 (1절의 후보) | 0.975 / 0.971 | 0.981 / 0.981 | 0.955 / 0.952 | 0.786 / 0.786 | 0.703 / 0.696 | 0.9985 | 0.594 | 넘는다 |
  | **9 × 9 (판 2)** | 0.975 / 0.971 | 0.981 / 0.981 | 0.955 / 0.952 | **0.933 / 0.920** | **0.872 / 0.867** | 0.9985 | 0.594 | 넘는다 |
  | 긴 선(41 px)을 지움 | 0.974 / 0.968 | 0.973 / 0.969 | 0.894 / 0.881 | 0.661 / 0.660 | 0.641 / 0.633 | 0.9985 | 0.594 | 못 넘는다 |
  | 7 × 7 + 긴 선 | 0.974 / 0.968 | 0.981 / 0.980 | 0.954 / 0.947 | 0.923 / 0.915 | 0.875 / 0.875 | 0.9985 | 0.594 | 넘는다 (1.4–1.6배 느리다) |

  기준을 넘는 것들은 기준의 세 경우에서 같다 — 더 크게 어긋날 때 갈린다. 9 × 9(±4 px)는 실제 괘선 오차가 양식에 따라 4 px 까지인 것을 덮고, 0.4° 에서
  7 × 7 보다 0.13 넘게 높다. 긴 선을 같이 지우면 나아지지 않고 느리다. 쪽 하나의 서명 시간(마스크는 템플릿마다 한 번)은 판 1 과 같은 자리(약 20 ms),
  글자열 길이는 앞머리 두 글자만 늘었다. 윈도우의 수치는 CI 의 windows 작업이 같은 도구로 잰다 (tasks/0010 12절).
  넓힌 만큼 괘선에 걸친 손글씨도 지워진다 — 같은 날 다른 종이의 최대는 합성에서 그대로였다. 실데이터로는 사람이 잰다 (`sig_probe --site …`,
  tasks/0010 8절 2 — 실제 81쪽의 7 × 7 은 다른 종이 최대를 0.601 → 0.610 으로 올렸다).
- 붙잡는 쪽으로 틀리는 것이 두 번 들어가는 것보다 낫다: 붙잡힌 쪽은 홈에 뜨고 한 번 누르면 풀린다. 두 번 들어간 값은 아무도 모른다.
- 규칙이 "앞 순서의 적재된 쪽"이라 결과가 순서로 정해진다 — 처리한 순서가 아니라 문서의 순서(보관 경로, 접수한 것은 받은 시각). 앞 문서가
  바뀌면 뒤 문서를 다시 처리하는 것으로 처음부터 만든 DB 와 같아진다 (합성 흔들기에 다시 스캔한 묶음을 넣어 확인).

## 하지 않는 것

- 옛 판(1)의 서명과 새 판의 서명을 견주기 — 서명의 정의가 다르다. `run --fresh` 로 다시 만든다.
- 다른 날의 쪽과 견주기, 계열이 다른 쪽과 견주기.
- 기준 이미지로 쓴 그 종이 자신의 다시 스캔: 자기 손글씨가 인쇄 자리로 지워져 서명이 0 에 가깝다 — 잡지 못한다. 그대로 둔다.
