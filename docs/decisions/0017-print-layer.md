# 0017. 인쇄 층: 여러 쪽에서 추정하고, 값 유무에만 쓰고, 템플릿이 켠다

상태: 채택 (2026-10). 작업 지시서 [tasks/0006](../tasks/0006-print-layer-and-variants.md) 4.1–4.5.

## 상황

로우더 작업일보의 작업량 칸에는 "하단: _ 대 / 저광장: _ 대", 근무 시각 칸에는 "~", 계기 칸에는 "시작:" 이 **칸 안에 인쇄되어** 있다.
잉크 판정(잉크 비율, 덩어리 배정)은 인쇄와 손글씨를 가리지 못한다. 0005 의 마지막 수정(ADR 0016 — 두 판정 중 하나라도 "있음"이면
인식기·검수로)으로 값이 사라지지는 않게 되었지만, 그 대가로 인쇄가 있는 칸은 비어 있어도 늘 검수 대기였다 (실제 3일치: 작업량의 인쇄 칸
48/48, 근무 시각의 빈 칸 9/9). 근무 시각 칸이 검수 대기면 그 쪽의 가동 시간도 NULL 이다. 인쇄를 나눔 선으로 떼어 내는 것으로는 안 된다 —
쓴 숫자가 양옆의 인쇄와 이어져 두 자리 숫자를 48칸 중 0칸에서 잡았다 (tasks/0005 12절).

## 결정

1. **인쇄 층은 사이트 팩의 데이터다.** 판 하나에 `print.png` 하나 — 기준 이미지와 같은 크기·같은 좌표(템플릿 좌표계)의 회색조 PNG, 인쇄된
   것만. 템플릿의 `print_image: print.png` 가 켠다. 키가 없으면 모든 것이 예전과 같다 (원칙 1 — 코드는 양식 이름을 모른다). 키가 가리키는
   파일이 없거나, 크기가 기준 이미지와 다르거나, 확장자가 `.png` 가 아니면 템플릿 오류다 (사이트 팩을 읽을 때는 PNG 의 머리만 읽는다 —
   깨진 PNG 는 `template check` 가 알린다). 저장소에 넣지 않는다 — 늘 같은 자리에 같은 글씨로 쓰는 칸(작성자 이름, 서명)은 쪽이 많아도
   잔상이 남는다. 현장 글씨다.
2. **여러 쪽에서 추정한다** (`template print-layer`). 그 템플릿으로 분류된 쪽(`loaded`·`classified_only`)을 날짜별로 돌아가며 최대 40장 →
   템플릿 좌표로 편 그림 → 쪽마다 잉크를 1 px 넓힌 뒤(회색조 erode 3×3) → 화소마다 밝기의 75 백분위, 보간 없이(`method="higher"` — 그 자리
   위의 실제 쪽 값. 3·4장이면 가장 밝은 쪽).
   편 그림은 저장된 정합 그림, 없으면 원본을 `render_dpi` 로 렌더링해 `doc_page.homography` 로 다시 편 것이다 (정합과 같은 함수라 바이트까지
   같다). 칸 정의가 없는 분류 전용 양식의 쪽은 정합하지 않았으므로 명령이 직접 정합하고, 인라이어가 60 이상인 쪽만 쓴다.
   3장 미만이면 거절, 5장 미만이면 경고하고 만든다. `--percentile` 이 75 미만이면 그 층은 괘선을 잡는 데(`add-region`)만 쓰라고 경고한다 —
   값 유무에 쓰는 층은 75 다. 명령은 DB 를 읽기 전용으로 열고 `print.png` 만 쓴다. `print_image` 키는 사람이 적는다 —
   파일보다 키가 먼저 있으면 템플릿 오류로 사이트 팩 전체가 읽히지 않는다. 해시 `print_sha` 는 sha256(높이·너비 + 화소)의 앞 16자다.
3. **값이 있는가에만 쓴다.** 쓰는 칸은 `Template.role_value_cell` 하나로 정한다: role 이 `meter`·`shifts`·`tally` 인 표의 형식 있는 손글씨 칸.
   그 칸의 잉크 비율(`cells.observe_cells`)과 덩어리 배정(`blobs.assign_blobs`)을, 지금처럼 이진화(`grid.binarize`)한 직후 인쇄 마스크(인쇄 층을
   같은 `grid.binarize` 로 이진화해 2 px 넓힌 것)의 화소를 0 으로 한 그림으로 잰다 — 잉크 비율은 쪽 전체를, 덩어리 배정은 표 영역을
   이진화한 그림이다 (지금과 같다). 규칙과 임계값은 그대로다 — ADR 0016 의 "둘 중 하나라도 있음"도.
   쓰지 않는 곳: 표 밖 필드(서명·체크·메타 필드), 작업 표(`activities`), 인쇄된 칸, role 이 없는 표, ✓ 판정, 정합·분류,
   **크롭 전부**(인식기·내보내기·검수 화면). 인식기와 사람은 인쇄가 있는 원래 그림을 본다.
4. **어느 층으로 쟀는지 쪽에 남긴다** (`doc_page.print_sha`, 스키마 7 — 원칙 3). 그런 칸이 있는 양식(`Template.uses_print_layer`)에서만 남고,
   아니면 NULL 이다. `report` 의 `print_layer` 는 양식별로 인쇄 층으로 잰 적재된 쪽의 수다. 그런 쪽이 없으면 키가 없다 — 인쇄 층이 없는
   사이트의 리포트와 회귀 기준은 그대로다.
5. **인쇄 층은 기준 이미지가 아니다.** 정합·분류의 기준은 지금처럼 스캔 한 장(`reference.png`)이다. 다만 괘선을 잡는 데는 인쇄 층이 낫다 —
   `template add-region` 은 `print_image` 가 있으면 그것에서 잡는다.
6. **켜는 것은 템플릿이다.** 운반·점검표 양식은 이번에 켜지 않는다. 그 표에는 role 이 없어 키를 적어도 쓰이지 않고(`print_sha` 도 NULL),
   `template check`(참고 — 오류가 아니다)와 `info` 가 그렇다고 알린다.

## 이유

- 인쇄는 모든 쪽에서 같은 자리에 있고 손글씨는 쪽마다 다르다 — 백분위 하나로 갈린다. 새 판정 수치가 없다: 이진화는 값 유무와 같은 함수,
  1 px 은 정합의 흔들림, 2 px 은 실데이터에서 1–3 px 이 같았던 폭이다.
- 실제 3일치로 미리 재 본 것 (26장·6장·4장으로 만든 층, tasks/0006 1절): 빈 칸이 "있음"이 된 수가 작업량의 인쇄 칸 48/48 → 1/48,
  근무 시각 칸 9/9 → 0/9, 계기 칸 5/60 → 2/60. 값이 적힌 칸(근무 시각 9, 계기 30, 작업량 칸에 숫자를 그려 넣은 48)은 그대로 전부 "있음".
  백분위 50·75, 넓히는 폭 1–3 px 에서 결과가 같았다.
- 합성 3일치(15쪽): 인쇄만 있는 칸 29개(작업량 24, 근무 시각의 "~" 5)가 끄면 전부 검수 대기, 켜면 전부 빈 칸으로 자동 적재.
  값이 적힌 role 칸 63개(인쇄 사이의 두 자리 숫자 포함)는 켜든 끄든 하나도 빈 칸이 되지 않았다. 검수 대기 칸(계기·근무 시각·작업량)은
  26·18·27 → 26·13·3.
- **흰색으로 칠하지 않고 이진화한 뒤 지운다**: 회색 그림을 255 로 칠한 뒤 적응 이진화하면 칠한 자리의 가장자리가 잉크가 되어 인쇄만 있는
  칸이 남았다 (합성 10일치 89칸 중 13칸). 이진화한 뒤 지우면 넓히는 폭 0–3 px 모두 0칸.
- **필드·작업 표에 쓰지 않는다**: 날마다 같은 자리에 같은 글씨로 쓰는 칸(이름, 늘 "ok" 인 점검란, 서명)은 쪽이 많아도 인쇄 층에 들어간다.
  합성 로우더의 점검란도 켜면 6쪽 중 6쪽에서 빈 칸이 되었다. 서명은 검수 경로가 없어 `signed` 가 조용히 0 이 되고, 메타 필드는 잉크가 0 이면
  모델을 건너뛴다. 지금 role 칸이 아닌 행은 켜든 끄든 바이트까지 같다 (시험).
- **크롭에 쓰지 않는다**: 인쇄와 겹친 획이 지워져 숫자에 틈이 생긴다. 값 유무에는 지장이 없었지만 인식기와 사람은 원래 그림을 본다.
  크롭 PNG 는 켜든 끄든 바이트까지 같다 (ADR 0011 의 "크롭 구현 하나").
- **괘선은 인쇄 층에서**: 채워진 스캔에서 잡으면 손글씨의 세로획이 괘선이 된다. 합성 로우더의 채워진 쪽에서는 계기 값이 세로 괘선을 하나 더
  만들었고, 분류 전용으로 돌려 만든 인쇄 층에서 잡은 괘선은 생성기의 괘선과 2 px 안에서 같았다.
- **운반 양식에 켜지 않는다**: 실제 운반 양식에 켜 보면 숫자 칸 4,620개 중 16칸의 값 유무가 달라진다 (없음→있음 15, 있음→없음 1).
  좋아진 것인지는 숫자 정답이 생긴 뒤 `regress`·`eval` 로 판단한다.

## 버린 것

- 칸 안의 인쇄를 나눔 선으로 떼어 `printed` 칸으로 — 양옆에 인쇄가 있는 칸에서 숫자를 놓친다 (tasks/0005 12절).
- 빈 양식을 현장에서 스캔해 오기 — 현장에 요청하지 않는다. 판이 바뀔 때마다 다시 받아야 한다.
- 인쇄 층을 기준 이미지로 — 인라이어의 중앙값이 1,315 → 777 로 줄었다 (여러 쪽을 겹친 그림이라 획이 무르다).
- 층과 쪽이 맞는지 보는 안전장치 — 새 수치가 필요하다. 대신 틀린 층(다른 양식의 층, ±5 px 밀린 층)으로도 값이 적힌 role 칸이 빈 칸이 되지
  않고 검수 대기만 는다는 것을 합성에서 시험으로 고정했다. 구조로 보장되는 것은 아니다 — 두 판정이 같은 마스크로 지운 그림을 쓰므로
  마스크가 손글씨를 덮으면 둘 다 "없음"이 된다.

## 대가

- 쪽이 적으면 늘 같은 자리에 쓰는 값의 잔상이 층에 남는다. 합성 운행일보는 모든 쪽이 계기 값을 같은 자리에 쓴다: 보간하던 때 9쪽으로 만든 층은
  role 칸의 인쇄 아닌 화소 중 1.9 % 를 인쇄로 잡았고, 10일치(31쪽)로는 0.46 % 였다 (보간 없이 0.31 %).
- 잔상은 값을 지울 수 있다. 백분위를 보간하면 쪽이 적을 때 한 쪽의 손글씨가 반쯤 남는다 (3장의 75 백분위 = 둘째·셋째 밝기의 중간): 합성 로우더
  에서 명령의 차례로 2장 층이 값이 적힌 작업량 칸 3칸, 3장 층이 4칸을 잃었다 (인쇄 사이의 두 자리 값). 지시서 4.3 의 "2–5장으로 만든 층에서도
  잃지 않았다"와 달랐다. → **보간 없이** 잡으면 3·4·5장은 0칸이고, 2장(두 쪽 중 밝은 쪽)은 그대로 3칸이라 **3장 미만은 거절**한다
  (PR #11 검토에서 정했다). 쪽이 적을수록 같은 위험이 커서 5장 미만은 경고한다. 시험이 3·4·5장 통과와 2장 거절을 고정한다.
- 잔상은 괘선이 되기도 한다. 보간하던 때 합성 운행일보 4쪽으로 만든 층에서 `add-region` 이 계기 표의 시작 칸 안에 세로 괘선을 하나 더 잡았다.
  보간 없이는 3·4쪽 층도 생성기의 괘선이다. 영역을 넓혀서는 풀리지 않는다 — 쪽이 쌓이면 층을 다시 만든다. `add-region` 의 요약이 그렇게 안내한다.
- 판이 섞인 양식의 첫 층에는 두 판의 쪽이 섞인다. 소수 판이 25 % 를 넘으면 75 백분위에서 다수 판의 괘선이 빠지므로 `--percentile 50` 으로
  만든다 ([0018](0018-concurrent-variants.md), tasks/0006 4.2·8절). **이 층은 괘선을 잡는 데(`add-region`)만 쓴다** — 낮은 백분위의 층에는
  같은 자리에 쓴 값의 잔상이 더 남는다. 값 유무에 쓰는 층은 판을 나눈 뒤 판마다 75 로 다시 만든다 (75 미만이면 요약이 경고한다).
  보간하지 않으므로 50 의 층은 한 판이 쪽의 절반을 넘을 때만 그 판의 괘선을 남긴다 — 두 판이 꼭 반씩이면(2+2, 5+5) 둘 다 빠진다
  (쪽 수를 홀수로 하면 늘 한 판이 절반을 넘는다). 보간하던 때 실제 운행일보의 A 몫 0.50 에서 50 백분위가 괘선을 다 남긴 것은 이 때문에
  보간 없이는 성립하지 않을 수 있다.
- 같은 쪽이라도 OpenCV 판이 다르면 층의 화소와 `print_sha` 가 조금 다르다. 바이트 비교는 같은 환경 안에서만 하고, 판 사이에서는 값 유무의
  결과로 본다.
- 잔상은 사람이 본다: `print-layer` 요약의 "인쇄에 덮인 손글씨 칸", `template check` 의 "인쇄 층이 칸의 절반 넘게 덮은 표의 손으로 쓰는
  칸"(필드는 세지 않는다 — 필드에는 쓰지 않으므로), `template preview --print`.

## 정한 것 (PR #11 검토)

적은 쪽으로 만든 층의 위험(위): 백분위를 보간 없이 잡고 거절 기준(`MIN_PAGES`)을 3장으로 올렸다. 5장 미만 경고는 그대로다. 판 B 처럼 나중에
나눈 판의 층은 처음에 쪽이 적다 — 5장 이상이 쌓인 뒤 만드는 것이 여전히 낫다.
