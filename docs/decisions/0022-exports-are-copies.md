# 0022. 내보낸 것은 사본이다 — 한 방향, 확정되지 않은 값은 싣지 않는다, 가린 그림은 템플릿이 아는 자리만

상태: 채택 (2026-10). 작업 지시서 [tasks/0008](../tasks/0008-export.md) 4.1–4.7, 4.9. [ADR 0008](0008-review-records.md)(기계 값과 최종 값은 따로)의
연장이다.
고침 (2026-10, [tasks/0009](../tasks/0009-release.md) 4.1·4.2): 기록 파일의 사이트 이름과 글자(4), 빈 작업 DB 는 지우지 않는다(4), 자동 내보내기의
조각으로 나눈 전체 훑기와 다시 쓰기 간격(6), 기계 값의 열이 일별 업무 시트에도 있다는 것(2 — 0008 의 글이 코드와 달랐다).

## 상황

현장 사용자는 결과를 엑셀로 확인하고, 2단계는 통합 DB 를 읽고, 발표·보고서에는 쪽 그림이 필요하다. 셋 다 DB 밖으로 나간다.

- 엑셀은 화면과 달리 출처도 신뢰도도 보이지 않고, 현장은 그것을 그대로 옮겨 적는다. 검수 대기인 행에도 기계 값이 들어 있다
  (`prod_haul.trips`, `doc_field.value_final`).
- 같은 내용을 두 번 쓰면 xlsx 의 바이트가 다르다 (zip 안에 만든 시각).
- 템플릿은 이름·서명·차량번호의 자리를 안다 — 그러나 표 위에 걸쳐 쓴 메모, 수 칸에 적은 이름, 템플릿에 적지 않은 인쇄는 모른다.

## 결정

1. **원본은 셋이다 — 스캔 파일, 검수 기록, 결정 기록.** DB 는 그것들에서 만든 것이고, 엑셀·통합 DB·가린 그림은 DB 에서 만든 **사본**이다.
   한 방향이다 — 엑셀을 고쳐도, 통합 DB 를 고쳐도 돌아오지 않는다 (엑셀을 읽어 들이지 않는다). 언제든 지우고 다시 만든다.
   내보내기는 작업 DB 에 쓰지 않는다 (읽기 트랜잭션 하나로 모델을 만든다 — 한 시점).
2. **확정되지 않은 값은 싣지 않는다.** 칸의 상태는 한 함수(`export/model.field_cell`)가 정한다: 검수 대기 `?`, 사람이 읽지 못한 칸 `판독 불가`,
   확정된 값만 값으로. 업무 행의 값 열은 그 행이 나온 칸이 전부 확정일 때만, 아니면 비우고 상태 열에 적는다. 교차검증·계기 검산의 판정에 확정되지 않은
   값이 끼면 `(잠정)`. 기계 값은 기본으로 싣지 않는다 — `[export] machine_values = true` 일 때만 일별 업무 시트와 월별 긴 표의 따로 둔 열에 ("기계 값(확정 아님)").
   이것은 사람이 읽는 사본(엑셀)의 규칙이다. 통합 DB 는 작업 DB 의 행 그대로다 — `review_status` 와 기계 값 열(`value_raw` …)이 같이 가고
   읽는 쪽(2단계)이 `review_status` 로 거른다 (ADR 0021 — 대상의 행 = 작업 DB 의 행).
3. **합계는 확정된 줄만** (운반 표의 블록 합계 — 그 줄의 칸이 전부 확정일 때만, 값으로. 수식을 쓰지 않는다). 교차검증의 불일치는 맞춰 넣지 않는다 —
   일보의 값을 그대로 적고 표시만 한다 (ADR 0006).
4. **바뀌었나는 내용의 해시로** 본다 (모델의 정규화한 JSON). 해시가 같은 파일은 건드리지 않는다. 이름 규칙(`daily/<달>/<날짜>.xlsx`,
   `monthly/<달>.xlsx`)에 맞는 파일만 쓰고, 기록 파일(`.minedocscan-export.json`)에 있는 것만 지운다 — 사용자가 그 폴더에 둔 파일을 지우거나 덮지 않는다.
   - **기록 파일은 바이트로 읽어 UTF-8 로** 디코딩한다 (tasks/0009 4.1 나). 디코딩하지 못하거나(다른 인코딩으로 다시 저장했다 — UTF-16 이면
     트레이스백이었다), JSON 이 아니거나, 꼴이 다르면 "기록을 잃음" — 전부 다시 쓰고 기록에 없는 파일은 지우지 않는다. 쓰는 것은 UTF-8.
   - **사본의 주인** (tasks/0009 4.1 다): 기록 파일에 사이트 팩의 `site.toml` 에 **적힌** `[site] name` 을 둔다 (폴더 이름으로 대신하지 않는다 —
     ADR 0021 의 10 과 같은 표식). 기록의 이름이 다르면 그 폴더에 **아무것도 쓰거나 지우지 않는다** (`watch`·`serve` 의 요약과 홈: "다른 사이트의 폴더" —
     이름은 찍지 않는다). 기록에 `site` 가 없거나 `null` 이면 옛 기록(0008)으로 받아들이고 적는다. 글자가 아니거나 빈 `site` 는 깨진 기록이다. 이름이 없는
     사이트 팩이면 명령은 한 줄로 거절하고 자동 내보내기는 켜지 않는다.
   - **빈 작업 DB 는 지우지 않는다**: 작업 DB 에 쪽이 하나도 없으면 기록된 파일도 지우지 않고 "남겨 둔 파일"로 센다 — 빈 작업 DB 로 훑어 엑셀
     폴더를 비우지 않게 (0008 에서는 다 지웠다).
5. **가린 그림은 템플릿이 아는 자리만 가린다**: 서명 필드, 가릴 메타 키(기본 작성자·차량번호)의 필드, 템플릿의 `redact` 상자(판마다), 글자 칸(기본).
   한 색으로 채운다 — 흐리게 하지 않는다 (되돌릴 수 없게). 명령과 문서가 "사람이 보고 나서 쓴다"고 말한다. 가렸다고 저장소·이슈에 넣어도 되는 것이
   아니다 — 가린 그림도 현장 데이터다.
6. **자동 내보내기**(`watch`·`serve` 의 바퀴 끝)는 더러운 날짜와 **전체 훑기의 조각 하나**를 한다 (tasks/0009 4.2 가 — `sweep.Sweep`, 자동 싣기와
   같이 쓴다). 조각 = 달 하나(그 달의 날짜 파일과 달 파일) — 달의 목록은 바퀴를 시작할 때 작업 DB 의 달과 기록 파일·폴더에만 있는 달을 합친다.
   엑셀에는 날짜 없는 조각이 없다 (날짜가 없는 쪽은 엑셀에 나가지 않는다). 조각을 한 바퀴 다 돌면 전체 훑기와 같다 (흔들기 시험). 기록 파일이 없거나
   깨졌으면(처음 쓰는 빈 폴더 포함) 그 바퀴에 전부 쓰지 않고 새 조각 바퀴로 다시 쓴다. 명령 `export excel` 은 지금처럼 한 번에 전부다.
   바꾸지 못한 파일(윈도우에서 엑셀이 열고 있다)은 `[export] retry_seconds`(60초)가 지난 뒤에 다시 하고 그 사이에는 모델도 만들지 않는다 (4.2 라).
   바퀴의 요약은 쓰지 못한 파일의 수가 바뀔 때만 찍는다 (홈에는 늘 보인다).

## 이유

- 엑셀에 확정되지 않은 값을 확정된 것처럼 실으면 그 값이 사람 손을 거쳐 "확정"된다. 비어 있고 `?` 인 칸은 검수 화면으로 가는 길이 된다.
- 해시로 보면 바퀴마다 써도 파일이 그대로다 (수정 시각이 그대로 — 열어 둔 엑셀과 다투지 않는다). 합성 30일치의 시간은 지시서 0008 12절.
- 템플릿이 모르는 자리는 코드도 모른다. 모른다는 것을 말하는 쪽이 "가렸다"고 믿게 하는 것보다 낫다.
- 조각과 다시 쓰기 간격: 한 해 규모의 합성 복제(약 125만 행, 파일 264개)에서 바뀐 것 없는 전체 훑기가 바퀴 하나에 76.5초, 빈 폴더의 처음
  바퀴가 190.6초였다 — 그동안 접수가 선다. 조각으로는 바뀐 것 없는 조각 하나가 최대 4.1초, 처음 쓰는 조각이 11–16초
  (`docs/test-report/scale-2026-10-09.json`). 열려 있는 파일 하나는 바퀴마다(3초) 모델을 만들고 임시 파일을 쓰고 실패하고 한 줄을 찍었다 (20초에 8줄).
- 사이트 표식과 빈 작업 DB: 엑셀 폴더도 통합 DB 처럼(ADR 0021 의 10) 다른 사이트의 작업 폴더로 훑으면 덮이고, 빈 작업 DB 로 훑으면 기록된
  파일이 다 지워졌다 (tasks/0009 1절 다).

## 버린 것

- **엑셀을 원본으로 받아 들이기** (2단계의 입력 체계) — 두 원본이 생긴다. 직접 입력은 2단계의 일이다.
- **기계 값을 흐린 글씨로 같이 싣기** — 색·글씨체는 옮겨 적을 때 사라진다.
- **가린 그림을 흐리게** — 되돌릴 수 있다.
- **자동으로 이름을 찾아 가리기**(글자 인식) — 외부 API 없이(ADR 0003) 믿을 만한 것이 없고, 놓친 것을 놓쳤다고 말하지 못한다.
- **엑셀의 원천 지문**(날짜의 행을 해시해 모델 만들기를 건너뛰기, tasks/0009 3절) — 하지 않았다. 훑기를 달 단위로 나누는 것으로 바퀴 하나를
  5초 안에 두었다.

## 대가

- 검수가 끝나기 전의 엑셀에는 `?` 가 많다 (합성 null 묶음은 값이 있는 수 칸이 전부 `?`). 검수가 진행되면 다음 내보내기에 값이 된다.
- 가린 그림은 사람이 한 장씩 봐야 한다.
- 자동 내보내기의 처음 훑기(빈 폴더, 기록을 잃은 폴더)는 조각을 다 돌 때까지 폴더에 몇 달만 있다 (홈: "처음 훑는 중 n/N"). 한 번에 다 써야 하면
  명령 `export excel`.
- 사이트 팩의 `[site] name` 을 바꾸면 엑셀 폴더의 기록 파일을 지운다 (전부 다시 쓴다). 그 전에 `[eval] split_salt` 에 지금 값을 적는다
  ([DATA.md](../DATA.md) — 평가셋의 분할 소금값이 이름을 기본으로 쓴다).
