# 0002. 사이트 팩을 저장소 밖에 둔다

상태: 채택 (2026-10)

## 상황

템플릿과 기준 이미지는 실제 양식에서 만든다. 거기에는 작업자 이름, 서명, 차량번호가 있다
(행렬 양식은 머리글에 운전자와 차량번호가 인쇄되어 있다). 저장소에 넣으면 삭제해도 기록에 남는다.
한편 소프트웨어는 독립 등록 대상이라 특정 현장에 묶이면 안 된다.

## 결정

현장에 관한 것(템플릿, 기준 이미지, 현장 옵션, 페이지 라벨, 회귀 기준)은 **사이트 팩**으로 묶어 저장소 밖에 둔다.
저장소에는 코드와 문서, 그리고 개인정보가 없는 **합성 데이터 생성기**만 둔다. 테스트는 합성 데이터로 돈다.

## 이유

- 개인정보가 저장소 기록에 들어갈 길을 구조적으로 막는다.
- 다른 현장에 적용할 때 바뀌는 것이 사이트 팩 하나로 한정된다.
- 합성 데이터는 정답을 알고 있으므로 정확히 비교하는 시험을 쓸 수 있다. 실제 문서로는 그럴 수 없다(정답이 없거나 일부뿐이다).

## 버린 것

- 시험용 실제 스캔 몇 장을 저장소에 넣고 나중에 지우는 방안: 기록에서 지우려면 이력을 다시 써야 하고, 그 전에 복제된 곳에는 남는다.
- 실제 양식에서 이름만 가린 이미지: 가림이 완전한지 보장하기 어렵고 서명·필체가 남는다.

## 대가

- 실데이터 회귀는 데이터가 있는 컴퓨터에서만 돈다. CI 는 합성 시험만 한다.
- 사이트 팩의 버전 관리가 저장소와 분리된다. 템플릿을 고치면 회귀 기준도 같이 갱신하고, 공유 드라이브의 판 관리 기능에 의존한다.
