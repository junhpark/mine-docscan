# 0011. 인식기 입력 규격은 하나, 학습은 torch·추론은 ONNX + OpenCV, 모델은 사이트 팩에

상태: 채택 (2026-10). 작업 지시서 [tasks/0003](../tasks/0003-digit-recognizer.md) 4.1, 4.2, 4.5.

## 상황

첫 인식기(운반 횟수 숫자)를 학습해 붙인다. 학습 데이터는 검수값으로 만든 크롭(`review export-crops`)이고, 운용에서는 파이프라인이
같은 칸을 잘라 인식기에 넘긴다. 둘이 다른 그림이면 검증 날짜에서 잰 수치가 운용에서 재현되지 않는다.
현장 PC 는 외부 네트워크 없이 돌고(ADR 0003), 설치를 늘리기 어렵다. 운반 칸은 낮아서 글씨가 괘선을 넘는다 — 칸 그대로 자르면 숫자가 잘린다.

## 결정

1. **크롭 규격(`imaging/cropspec.CropSpec`)은 하나다: 해상도(`aligned` 200 dpi 정합 이미지 | `source` 원본), 배율, 여유.**
   파이프라인(`handlers/base.recognize`)과 내보내기(`review/export.py`)와 검수 화면이 같은 함수(`crop_cell`)로 자른다.
   같은 칸이면 내보낸 PNG 와 파이프라인이 인식기에 넘긴 배열이 화소까지 같다 (시험으로 고정).
2. **백엔드가 규격을 선언한다** (`crop_spec` / `crop_spec_for(kind)`). 선언하지 않은 백엔드(`null`, `oracle`)는 예전 크롭(정합 이미지, 칸 그대로)을 받는다.
   숫자 모델은 자기가 학습한 규격을 모델 카드에 적고, `digits` 백엔드는 그 규격을 그대로 선언한다. 설정으로 따로 주지 않는다.
   기본 규격: 원본, 1.5배, 여유 = 행 높이의 절반(최소 8 px) — `export-crops` 의 기본값과 같다.
3. **칸 종류마다 백엔드를 고른다** (`[recognize.by_kind]`). 파이프라인은 여전히 `Recognizer` 하나만 안다 (`ByKindRecognizer`).
4. **학습은 torch(선택 의존성 `[train]`), 추론은 ONNX 파일을 OpenCV `cv2.dnn` 으로.** 현장 PC 에는 새 의존성이 없다.
   그래서 모델은 합성곱·배치 정규화·ReLU·풀링만 쓴다 (순환층·어텐션 없음), 배치는 1 로 고정한다. torch 를 import 하는 곳은
   `recognize/digits/train.py` 하나다. 학습이 끝나면 **내보낸 파일을 OpenCV 로 다시 읽어** 검증 성적을 낸다 (torch 의 수치가 아니라 운용 경로의 수치).
5. **모델은 사이트 팩에 둔다**: `<site>/models/<이름>/` 에 `model.onnx`, `card.json`, `train-log.jsonl`. 현장의 손글씨로 학습한 것은 그 현장의 데이터다.
   카드에는 규격·입력·문자·구조·학습 인자·씨앗·데이터 요약(셀 수·날짜 수·값별 개수)·검증 성적·온도·자동 적재 기준과 그 표·라이브러리 버전·
   `model.onnx` 의 SHA-256 을 적고, 이미지·이름·차량번호·검수자는 적지 않는다. 백엔드는 카드와 다른 `model.onnx` 를 받지 않는다.
   예외 하나: 합성 셀만으로 학습한 시험용 모델(`tests/fixtures/digits-fixture`, 0.58 MB).
6. 모델을 골랐는데 없으면 `run` 이 시작할 때 무엇이 없는지 말하고 멈춘다. `null` 로 조용히 물러나지 않는다.

## 이유

- 학습·평가·운용이 같은 그림을 봐야 검증 수치를 믿을 수 있다. 구현이 하나면 어긋날 자리가 없다 — "같은 입력이면 같은 출력"을 시험으로 고정했다
  (크롭 단위 평가의 답 = 파이프라인의 `value_raw`, 칸마다).
- OpenCV 는 이미 필수 의존성이다. 4.9(지원 하한)와 5.0 에서 같은 ONNX 를 읽어 출력 차이 2e-5 를 확인했다.
- 세로를 학습되는 합성곱으로 접은 구조는 이웃 칸 글씨가 섞인 셀에서 학습이 되지 않았고, 최대 풀링으로 접은 구조는 됐다 (지시서 4.2 의 사전 확인).
  최대 풀링 앞에서 "칸 안의 글씨인가"를 가르도록 입력에 위치 채널(가로·세로)을 같이 넣는다.
- 모델은 검수 기록처럼 현장의 것이다. 저장소에 두면 다른 현장으로 새고, 현장 글씨의 흔적이 저장소 이력에 남는다.

## 대가

- 쓸 수 있는 층이 제한된다. 숫자 몇 자리에는 충분하지만 긴 한글 문장 인식기는 다른 런타임이 필요할 수 있다 (그때 새 결정).
- 원본 해상도 크롭은 쪽마다 원본을 한 번 더 렌더링한다 (합성 쪽당 약 0.1 초).
- 규격을 바꾸면 모델을 다시 학습해야 한다 (카드의 규격이 백엔드의 규격이다).
