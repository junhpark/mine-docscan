# 0018. 같은 날 섞여 쓰이는 판은 괘선 오차로 고른다

상태: 채택 (2026-10). [ADR 0010](0010-template-versions-by-date.md) 을 보완한다. 작업 지시서 [tasks/0006](../tasks/0006-print-layer-and-variants.md) 4.6.

## 상황

중기운행일보 30쪽 중 5쪽은 다른 인쇄 판(판 B)이었다: 표가 8–12 px 아래에 있고 줄 간격도 조금 다르다. 머리 상자와 제목은 같은 자리다.
묵은 양식을 같이 쓰는 것이라 **같은 날 묶음에 두 판이 섞여 있다** — ADR 0010 의 전제(판은 날짜로 갈린다)가 깨진다.
판 A 의 템플릿 하나로는 4쪽이 `align_failed`, 1쪽은 괘선 오차 5.5 px 로 정합 기준(6 px)을 통과해 칸이 8–12 px 어긋난 채 적재되었다.
모양(분류의 인라이어)으로는 못 가린다: 두 판의 1위/2위 비율이 중앙값 1.57, 최소 1.01.

## 결정

1. **판은 지금처럼 별도 템플릿이다** (이름이 다르고 자기 `template.yaml`·`reference.png`·`print.png` 를 가진다). 같은 `family` 를 적는다.
   같은 계열에서 유효 기간이 겹치면 오류인 규칙(0010)은 두고, **겹치는 두 판 모두에 `concurrent: true` 가 있으면 허용**한다 — 사람이
   "같은 날 섞여 쓰인다"고 적은 것이다. 한쪽에만 있으면 지금처럼 오류. `concurrent` 는 `family` 가 있을 때만 쓸 수 있다 (없으면 템플릿 오류).
   계열에 `concurrent` 판이 하나뿐이어도 오류다 — 묶음이 생기지 않아 틀린 판으로 조용히 적재될 수 있는 상태(`template variant` 가 기존 판에
   적을 두 줄을 안내한 채로 남은 상태)다. 오류는 그 판과 계열, 두 줄을 적을 판(계열과 이름이 같은 템플릿)을 말한다. 두 동시 판의 유효
   기간이 겹치지 않아도 읽힌다. 이름(`name`)이 같은 템플릿이 둘이어도 오류다 (하나가 말없이 덮이지 않게).
2. **동시 판끼리 기하 밖의 모든 것이 같아야 한다**: `handler`·`handler_options`, 표(이름·`role`·`header_rows`·열과 행 — 메타까지 통째로),
   필드(bbox 밖 전부). 형식을 적지 않은 칸은 칸 종류의 기본 형식으로 비교한다. 괘선 좌표(나눔 선 포함)·필드의 bbox·기준 그림·인쇄 층·
   이름·제목·유효 기간만 다를 수 있다. 다르면 사이트 팩을 읽을 때 오류다 (메시지에는 표 이름과 항목의 종류만 — 행 키·값은 찍지 않는다).
3. **분류는 그날의 동시 판을 한 후보로 본다** (`SitePack.concurrent_groups(date)` — 그날 유효한 동시 판이 둘 이상인 계열만). 점수는 판 중
   최댓값, 1위/2위 여유(`classify_margin`)는 후보 사이에서 잰다. 묶음이 없는 템플릿의 점수·여유는 예전과 같다.
4. **묶음이 이기면 판마다 정합해 고른다**: 통과한 판 중 괘선 오차가 가장 작은 판. 차이가 0.5 px 안이면 그 판에 정합한 인라이어가 많은 판,
   그다음 이름 순서. 통과한 판이 없으면 같은 규칙으로 고른 판의 수치로 `align_failed`. 정합 뒤의 모든 것(칸, 인쇄 층, 핸들러,
   업무 테이블의 `source_form`)은 고른 판을 쓴다. 판이 하나뿐인 양식은 지금처럼 한 번만 정합한다 — 결과와 속도가 그대로다.
   `run --template X` 로 양식을 정하면 묶지 않고 한 번만 정합한다.
5. **쪽에 남긴다** (스키마 7): `doc_page.template_name` = 고른 판, `doc_page.variant_errs` = 판마다의 괘선 오차 JSON `{판 이름: 오차 | null}`
   (괘선을 못 찾아 유한하지 않으면 null). 판이 하나면 NULL. 정답을 템플릿 이름으로 찾는 곳(oracle, `eval`)은 사이트 팩이 있으면 동시 판을
   계열로 묶어 찾는다 (`SitePack.answer_key`) — 판 A 로 적힌 정답이 판 B 로 적재된 같은 쪽에도 붙는다.
6. **판을 만드는 일을 쉽게**: `template variant <기존 판> --scan F --page N --name NAME`. 그 쪽을 **표 영역(괘선 범위 + 60 px) 밖의
   특징점만으로** 기존 판에 맞춰 편 그림이 새 기준 이미지다. 표마다 기존 괘선을 ±min(40 px, 이웃 표의 가장 가까운 괘선까지의 절반) 안의
   가장 가까운 괘선과 짝짓는다 (이웃 = 다른 축의 범위가 겹치는 표, 거리는 기존 판의 괘선으로 잰다 — 표의 순서와 무관하다).
   짝이 없는 괘선이 있는 표와 인쇄되지 않은 나눔 선(`split_ys`·`split_xs`)이 있는 표는 기존 괘선을 두고 알린다.
   열·행·필드와 표 밖 필드의 bbox 는 그대로, `family` 는 기존 판의 것(없으면 기존 판의 이름), 새 판에는 `concurrent: true`.
   `print_image` 는 복사하지 않는다. 기존 판의 파일은 고치지 않고 적을 줄을 안내한다 (적기 전에는 1의 규칙으로 사이트 팩이 읽히지 않는다).
   출력 폴더가 git 작업 트리 안이거나 이미 있으면, 옆 템플릿이 이미 쓰는 이름이면 거절한다 (기준 이미지는 현장 스캔이다).
7. **리포트는 세기만 한다**: `report` 의 `variants` — 계열마다 판별로 고른 쪽 수, `align_failed` 의 수, 고른 쪽 중 작은 두 오차가 모두
   유한하고 차이가 1 px 미만인 쪽(가르기 어려웠던 쪽)의 수 (두 판 모두 실패한 쪽은 판을 고르지 않았으므로 `align_failed` 로만 — 빠진 판을
   가리키는 쪽이다). 사이트 팩이 없으면 판 이름들("A / B")로 묶는다. 그런 쪽이 없으면 키가 없다 — 판이 하나뿐인 사이트의 리포트와 회귀
   기준은 그대로다. 가르기 어려웠던 쪽은 `pages --variants` 로 본다 (정합 실패 쪽도 상태와 함께 나온다).

## 이유

- 괘선 오차로는 갈린다: 실제 30쪽을 두 판에 각각 정합해 오차가 작은 쪽을 고르면 A 25 / B 5 / 실패 0. B 로 간 5쪽의 오차는 A 에서
  5.5–10.5 px, B 에서 0.0–1.5 px.
- 합성(판 B = 작업 표와 계기 표만 10 px 아래, 줄 간격 +1 %, 날마다 두 판이 섞인다): 시험의 3일치에서 판 A 만 있으면 판 B 의 4쪽이 전부
  정합 실패. 두 판을 두면 15쪽이 전부 `loaded` 이고 고른 판이 정답과 같다. 고른 판의 오차는 0.0 px, 다른 판은 7.0–12.5 px 또는 null.
- 0.5 px 는 새 임계값이 아니라 단위다: 괘선 오차는 재검출한 괘선 자리(정수)와의 거리의 중앙값이라 0.5 px 단위로 나온다. 같거나 한 단위
  차이는 가르지 않는다. 실제 판 B 의 쪽은 두 판의 차이가 4 px 이상이었다.
- 묶는 이유: 판끼리의 비율(≈ 1)이 낮은 여유 표시(`low_margin`)를 늘 켜고, 분류가 고른 판 하나에만 정합하게 된다. 합성 운행일보에서 묶지
  않으면 여유가 기준(1.5) 아래, 묶으면 위다.
- 키가 같으면 `field_id`(`<page_id>:<표>:<열>:<행 번호>` — 템플릿 이름이 없다)가 같아, 판 선택이 바뀐 쪽(오차가 비슷한 쪽, 템플릿을 고친 뒤
  `--fresh`)에도 검수가 그대로 붙는다. 키가 다르면 조용히 떨어진다 — 그래서 읽을 때 오류로 한다.
- 표 영역 밖으로 펴는 이유: 쪽 전체의 호모그래피 하나로 펴면 RANSAC 이 표 쪽으로 타협해 표를 기존 판 자리로 끌어오고 머리를 옮긴다 —
  다시 잡은 괘선이 판 B 의 실제 자리와 2–16 px 달랐다 (합성에서도 어떤 스캔은 6–18 px). 머리에 맞춰 펴면 새 기준 그림이 판 B 와 같은
  좌표계라 표 밖 필드의 bbox 를 그대로 둘 수 있다. 합성 판 B 의 깨끗한 쪽으로 만든 괘선은 생성기의 괘선과 2 px 안에서 같았다.
- 짝짓는 창을 이웃 표까지의 절반으로 줄인 것은 표 사이가 좁을 때(합성 운행일보는 50 px) 이웃 표의 괘선을 잡지 않으려는 것이다.

## 버린 것

- 날짜로 가리기(ADR 0010 그대로) — 같은 날 묶음에 두 판이 섞여 있다.
- 표마다 괘선을 다시 맞추는 2차 정합(괘선 스냅) — 판 B 는 줄 간격까지 달라 평행 이동으로 풀리지 않고, 넣으면 모든 양식의 수치가 바뀐다.
- 모양으로 판 고르기(분류 점수) — 1위/2위 비율 최소 1.01. 가르지 못한다.
- 동시 판을 계열 없이 허용 — 묶이지 않으면 분류가 모양으로 판 하나를 골라 그 판에만 정합한다. 틀린 판의 괘선 오차가 정합 기준(6 px)
  안이면 칸이 어긋난 채 조용히 적재된다 (판 A 하나일 때 실제로 1쪽이 5.5 px 로 그랬다).

## 대가

- 묶음의 쪽은 판의 수만큼 정합한다. 합성에서 쪽당 시간(분류·정합·핸들러, 중앙값)은 판이 하나인 로우더 0.45 s, 판이 둘인 운행일보
  0.52–0.54 s.
- 판마다 기준 이미지와 인쇄 층을 따로 둔다. 판 B 의 인쇄 층은 B 로 적재된 쪽이 쌓인 뒤에 만들 수 있고, 처음엔 쪽이 적다
  ([0017](0017-print-layer.md) 의 대가). 판을 나누기 전의 첫 층에는 두 판의 쪽이 섞인다 — `--percentile 50` 으로 만들고, 나눈 뒤 판마다
  다시 만든다.
- 키 검사는 `field_id` 와 정답에 드는 것(표 이름·열·행 키·필드)만이 아니라 기하 밖의 전부를 본다 — `header_rows` 가 다르면 같은 `row`
  번호가 다른 인쇄 줄을 가리키고, 열·행의 메타(근무조·소계·장소 …)나 `handler_options` 가 다르면 같은 `field_id` 가 판마다 다른 뜻으로
  업무 테이블에 간다. `template variant` 는 그것들을 그대로 복사하므로, 한 판을 손으로 고치면 다른 판도 같이 고친다 (아니면 사이트 팩이
  읽히지 않는다).
- `template check` 는 템플릿 하나만 본다. 동시 판끼리의 키는 사이트 팩을 읽을 때(`info`, `run`) 드러난다. 동시 판에 표를 더할 때는 계열의
  모든 동시 판에 같은 표를 더한다 (`template add-region` 이 안내한다).
- "어긋난 채 통과"는 경계에서 일어난다. 실데이터에서는 판 B 의 1쪽이 5.5 px 로 통과했다. 합성 3일치에서는 판 A 만 있으면 판 B 의 4쪽이
  전부 정합 실패였고, 10일치(`--usage-variants`)에서는 OpenCV 5.0 에서 판 B 의 15쪽 중 1쪽이 괘선 오차 6.0 px(기준과 같다)로 통과해 칸이
  어긋난 채 적재되었다 (4.9 에서는 15쪽 전부 실패). 판 A 하나로는 이것을 막을 장치가 없다 — `template variant` 로 판 B 를 만들어 두면
  그 쪽은 B 로 갔다 (B 에서 0.5 px).
- 다른 양식에도 섞인 판이 있는지는 코드가 찾지 않는다. `report` 의 양식별 괘선 오차(`--by-month` 의 중앙값·최대)와
  `pages --status align_failed --thumbs` 로 사람이 본다.
