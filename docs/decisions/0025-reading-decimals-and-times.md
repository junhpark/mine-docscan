# 0025. 소수·시각은 적힌 대로 읽고 형식으로 고른다 — 글씨 띠, 쓸 수 있는 표기로 배우고, 자동 적재는 칸의 기준과 쪽 안 검산을 다 지나야

상태: 채택 (2026-10). 작업 지시서 [tasks/0011](../tasks/0011-reading-decimals-and-times.md) 4절. 0011·0012·0015·0016 을 고친다 (그 ADR 의 상태 줄).
모델을 학습하고 고르는 순서는 [DATA.md](../DATA.md) "소수·시각 인식기", 구조는 [ARCHITECTURE.md](../ARCHITECTURE.md) 8절.

## 상황

- 장비 가동 일보의 형식 칸(`decimal`·`time`·`time_range`·`reading` — ADR 0015)은 인식기에 보내지 않았다. 잉크가 있으면 검수 대기, 없으면 빈 칸.
  실제 가동 일보 40쪽(3일치)에서 하루 약 14칸, 40쪽 중 26쪽이 `readings` 대기열에 오른다. 가동 기록(`eq_usage_daily`)은 기계가 값을 하나도 정하지
  못하는 유일한 업무 표였다 — 가동 시간은 사람이 넣기 전까지 NULL.
- 숫자 모델(ADR 0011·0012)은 정수만 배웠다: 글자 0–9, 입력 32 × 96. 근무 시각 11글자(`08:00~17:00`)를 96 px 폭에 넣으면 점이 1–2 px 다.
- 실제 칸의 모양 (tasks/0011 1절 나): 계기 칸 폭 112–297 × 높이 51, 글씨 높이 중앙 35 px(19–51), 글씨 폭 / 칸 폭 중앙 0.93. 근무 시각 칸은
  308 × 62·99·100 이고 키 큰 칸(99·100)은 글씨가 칸의 5분의 1 — 크롭 전체를 높이 48 로 줄이면 4–7 px 다. 윗줄(오전 칸)의 글씨가 크롭에 같이 들어온다.
- 검수는 정규화한 값만 남긴다 (`08:00~17:00`). 종이의 글자(`8-17`, `08.00`)와 다르다 — 정규형을 그대로 CTC 의 목표로 쓰면 종이에 없는
  `:00` 을 읽으라는 것이 된다.
- 점으로 쓴 시각(08.00)과 계기 값(8.00)은 모양으로 갈리지 않는다 (ADR 0015 — 사람이 콜론으로 가른다).

## 결정

1. **형식 칸을 인식기로 보내는 길은 설정의 `[recognize.by_format]` 이다** (형식 → 백엔드, `by_format` > `by_kind` > `backend`). 적지 않은 형식의
   칸은 지금처럼 읽지 않는다 — 설정하지 않은 상태는 바이트까지 그대로다. 정수(`integer`)는 받지 않는다(`by_kind`). 그 형식을 읽는다고
   선언한 백엔드(`formats`)만 꽂을 수 있다 — `digits`·`null` 을 꽂으면 처리가 시작할 때 멈춘다. 표 밖 필드의 형식 칸은 이 길로 읽지 않는다.
   인식기는 칸의 형식과 자리를 안다 (`CellContext.fmt`·`bbox`).
2. **적힌 대로 읽고 정규화한다.** `value_raw` 는 종이의 글자(`8-12`, `08.00`), `value_final` 은 `formats.normalize` 의 값. 답은 셋 —
   값·빈 칸·거절 (ADR 0012). 칸의 표 (`handlers/base.format_row`): 빈 칸은 신뢰도 ≥ 기준이면 값 없음으로 자동 적재, 거절과 **계기 칸에
   점으로 쓴 시각은 늘 검수 대기**, 값은 신뢰도 ≥ 기준이면 자동 적재. 검수 대기인 형식 칸의 `value_final` 은 NULL 이다 — 기계의 추측으로 가동
   시간·계기 검산이 계산되지 않게 (ADR 0016).
3. **자동 적재는 칸의 기준과 쪽 안 검산을 다 지나야 한다** (`handlers/usage.page_gate`). 계기 표: 검수 대기인 칸이 없고, 값 칸이 있으면
   시작·종료가 둘 다 값이고 종류가 같다(시각과 계기 값이 섞이지 않는다). 계기 값이면 0 ≤ 종료 − 시작 ≤ 24시간이고 시작·종료가 둘 다 24
   이하가 아니다(점으로 쓴 시각을 소수로 읽었을 수 있다 — `clock_like`). 총이 적혀 있으면 총 = 종료 − 시작(허용 0.05) — 총이 빈 칸(실제로
   거의 늘 그렇다)이거나 표가 다 빈 칸이면 통과. 근무 시각 표: 검수 대기가 없고 합이 24시간 이하. 걸리면 그 표의 자동 적재 값 칸을 전부
   검수 대기로 내린다 (이유별로 센다). 날짜 사이의 연속성(어제 종료 = 오늘 시작)은 고르지 않고
   보여 준다 (`usage-check`, ADR 0006).
4. **소수·시각 모델 `readings` 는 숫자 모델과 따로 둔다** — 같은 망(합성곱·배치 정규화·ReLU·최대 풀링, CTC)과 같은 학습 코드, 다른 글자
   (blank + `0123456789.:~-?`)·입력(48 × 320, 가로 80칸)·답. 숫자 모델의 코드는 글자·입력을 담은 `Shape` 를 인자로 받고 숫자 모델의 값을
   기본으로 둔다 — 숫자 모델은 바이트까지 그대로다 (출력·학습한 모델). 모델 폴더를 읽는 곳은 카드의 `reader` 를 먼저 본다 — 숫자·메타·
   소수·시각 모델을 잘못 꽂으면 무엇인지 말하고 멈춘다.
5. **입력은 글씨 띠다** (`readings/model.band` — 학습·추론·평가·틀린 칸 모아 보기가 같은 함수). 크롭 안의 칸 자리를 규격으로 계산하고,
   무게 중심이 칸 안에 있는 잉크 덩어리를 줄로 묶어 가장 잉크가 많은 줄의 세로 범위 ± 15 %, 가로는 칸 ± 칸 높이의 1/4. 괘선에서 끊긴 조각은
   짝을 지어 이웃 글씨의 꼬리는 빼고 이 칸의 글씨가 넘은 조각은 잇는다. 높이 48 로 줄이고 폭 320 까지 채운다(넓으면 가로만 줄인다). 위치
   채널은 칸에 맞춘다 (가로는 칸의 왼쪽·오른쪽이 −1·+1). 띠는 자리만 정한다 — 모델이 보는 것은 회색 그림이다. 카드에 띠의 수를 적고
   코드와 다르면 읽지 않는다.
6. **해독은 고르기만 한다** (원칙 4). CTC 빔(32)의 후보 중 그 칸의 형식에 맞는 글자와 빈 칸·거절만 남기고, 같은 값의 표기(`08:00`·`8:00`)는
   확률을 더한다. 신뢰도 = 그 값의 확률 — 맞지 않는 글자의 몫은 다시 나누지 않는다. 맞는 답이 빔에 없으면 거절.
7. **쓸 수 있는 표기로 배운다** (`formats.spellings`·`same_value`). 실제 칸의 정답(정규화한 값)이 될 수 있는 종이의 글자를 모두 목표로 —
   손실 = −log Σ P(표기). 평가와 기계 값의 비교(`--target raw`)는 `same_value` 로 견준다 (점으로 쓴 시각은 기계가 읽은 글자에만 봐준다 —
   사람이 넣은 최종 값은 아니다). 온도·자동 적재 기준은 숫자 모델의 규칙 그대로(검증 날짜 또는 `--cv K`, 자동 적재된 검증 칸 100 미만이면
   기준 없음, 윌슨 상한) — 기준은 하나, 형식마다 두지 않는다.
8. **합성 칸은 실제에서 잰 것으로 만든다** (`tools/synth_readings.py`): 계기 값·시각(콜론·점·붙여 쓴 것)·시각 범위(정규형·`8-12`·인쇄된
   `~` 양옆), 흘려 쓴 00, 사선 하나의 1, 칸보다 큰 글씨, 칸 폭을 다 쓰는 값, 덧쓴 숫자, 이웃 칸의 글씨, 인쇄(이름표·`~`), 빈 칸의 갈래.
   기존 합성의 바이트는 그대로다. 이 칸의 수치로 손글씨 인식률을 말하지 않는다.
9. **이 결정으로 현장의 자동 적재가 켜지지는 않는다.** 기준은 실데이터의 정답(검수)으로만 정한다 — 합성만으로 학습한 모델의 기준은 시험용이다.

## 버린 것

- **숫자 모델에 글자(`.`·`:`·`~`)를 더하기**: 입력 32 × 96 에 근무 시각 11글자를 넣으면 점이 1–2 px 다. 입력을 키우면 숫자 모델의 카드·
  시험용 모델·현장 모델이 다 바뀐다. 따로 두고 코드만 같이 쓴다.
- **크롭 전체를 줄여 읽기**: 실제 크롭 전체를 높이 48 로 줄이면 글씨가 계기 칸 17 px, 근무 시각 7 px, 키 큰 칸 4 px 이고 윗줄의 글씨가 같이
  들어온다. 덩어리를 줄로 묶지 않고 모두 합치면 키 큰 칸의 띠가 132 px 까지 커져 6 px 로 줄었다. 띠로 자르면 계기 칸 21–36 px, 근무 시각
  10–18 px 이고 윗줄이 빠진다 (여기까지 가로·세로를 같이 줄인 수 — 결정 5 처럼 넓은 띠를 가로만 줄이면 합성 칸에서 입력의 글씨 높이 중앙
  38–42 px, tasks/0011 12절).
- **정규형을 그대로 목표로**: 종이에 없는 `:00` 을 읽으라는 것이 된다 (`8-12` → `08:00~12:00`).
- **연속성으로 후보 고르기**(어제의 종료와 같은 후보를 오늘 시작으로): 계기를 잘못 적은 날(실데이터에도 있다)을 기계가 "맞게" 고쳐 넣는다 —
  교정은 고르기지만 이것은 다른 칸의 값으로 이 칸을 정하는 것이다. 보여 주고 사람이 정한다.
- **점으로 쓴 시각을 기계가 가르기**: 1234.5 와 08.00 은 모양으로 갈리지 않는다 (ADR 0015). 기계가 읽어도 그 칸은 늘 사람이 정한다.

## 결과

- 합성(tasks/0011 단계 2·3 — 손글씨 인식률이 아니다): 글씨 띠가 값 칸의 99.7 % 에서 글씨 잉크의 95 % 이상을 담고 높이가 1.5 배 이하.
  시험용 모델(합성만, CPU 4코어 13.5분)은 따로 뽑은 2,000칸에서 값 0.944–0.979(형식마다)·빈 칸 0.977–1.0. 합성 가동 일보 15일치(75쪽)에서
  값이 있는 형식 칸 189 의 기계 값 정확도 0.979, 설정의 기준 0.5 로 자동 적재 139/220 (몫 0.63) 중 틀린 것 0 (윌슨 상한 2.7 %), 점으로 쓴 시각
  15칸은 모두 검수 대기, 자동 적재된 쪽 42 의 가동 기록이 정답과 같다. 다만 값의 신뢰도가 낮아(0.5–0.85) 카드의 기준(0.8)으로는 자동 적재의
  몫이 0.16 이다. 지시서의 문턱 둘을 고쳤다 (tasks/0011 12절). 형식 칸 하나에 64 ms (띠·망·해독은 약 11 ms), 쪽당 0.68 → 0.87 초.
- 실데이터: 정답이 쌓이면 `review export-crops` → `recognizer train --readings --cv 5` → `recognizer eval` → `[recognize.by_format]`. 그 전에도 기계
  값이 검수 화면에 미리 채워진다.
