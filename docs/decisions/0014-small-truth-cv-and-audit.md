# 0014. 정답이 적을 때: 기준은 날짜 묶음 교차로 정하고, 자동 적재된 쪽은 표본으로 다시 본다

상태: 채택 (2026-10). 작업 지시서 [tasks/0004](../tasks/0004-page-fields-and-checks.md) 4.5, 4.6.

## 상황

메타 필드(차량번호·작성자)는 쪽마다 한 칸이라 정답이 적다. 20일치를 입력해도 약 200쪽이다. 0003 의 방식(train 날짜의 20 % 를 검증 날짜로 떼고
그 날짜에서 기준을 정한다, ADR 0012)이면 검증은 40쪽쯤이고, "자동 적재된 검증 읽기 100개 미만이면 기준 없음" 규칙에 걸려 기준이 나오지 않는다.

그리고 모델이 메타를 채우기 시작하면 사람은 기계가 못 정한 쪽만 보게 된다 (`page-fields` 는 기계가 채운 키를 묻지 않는다). 그러면 자동 적재된
쪽의 오류를 잴 정답이 더 생기지 않는다.

## 결정

1. **`--cv K`**: train 날짜를 K 묶음으로 나눈다 (날짜 단위, `hash(소금값:cv:날짜)` 순서로 돌려 담아 고정). 묶음마다 "나머지 날짜로 학습 → 그 묶음을
   읽기"를 하고, **그렇게 모은 읽기 전체**에서 온도와 기준을 정한다. 기준을 고르는 규칙은 ADR 0012 그대로(목표 이하인 가장 낮은 임계값, 자동 적재된
   읽기 100개 미만이면 기준 없음, 옆에 윌슨 95 % 상한). 메타 필드의 목표 오류율 기본값은 2 %.
2. 내보내는 모델은 **train 날짜 전부로 학습한 것**이다. 카드에 방식(`cv5`), 묶음마다의 날짜·읽기 수를 적는다. 묶음마다의 모델은 남기지
   않으므로 그 날짜를 다시 읽어서는 잴 수 없다 — 묶음 교차에서 읽은 결과를 모델 폴더의 `cv-reads.jsonl` 에 **값 없이**(맞았나, 신뢰도,
   답의 종류) 남기고, `recognizer eval --split val` 이 그것으로 카드와 같은 표와 틀린 칸 모아 보기를 낸다.
3. `test` 는 여전히 학습·기준에 쓰지 않는다 (ADR 0009). `--cv` 가 없으면 0003 과 같은 방식(검증 날짜)이다.
4. **표본 감사** `review serve --queue page-fields --audit N`: 기계의 상태와 상관없이 날짜별로 고르게 뽑은 쪽 N 개(씨앗으로 고정, 검수가 진행되어도
   표본의 구성이 바뀌지 않는다)에서 사람·파일명의 값이 없는 키를 **기계 값 없이** 보여 준다. 입력한 값은 보통의 검수가 되어 기계 값을 이기고,
   `eval --meta` 의 정답이 된다. 기계가 채운 값은 정답으로 세지 않는다.
5. ✓ 판정의 정답(`checks`)도 같은 원칙이다: 기계의 판정을 보여 주지 않고, 판정 불가·`column_unused` 행까지 날짜별로 고르게 뽑는다.

## 이유

- 묶음 교차는 정답 전부를 한 번씩 검증 읽기로 쓴다. 200쪽이면 기준을 정할 수 있는 수에 닿는다 (100–150쪽부터).
- 묶음을 날짜 단위로 나누는 것은 같은 날의 쪽끼리(같은 사람, 같은 펜) 학습과 검증에 갈라 들어가 수치가 부푸는 것을 막으려는 것이다.
- 기계가 채운 쪽만 빼고 정답을 만들면 정답의 분포가 "기계가 어려워한 쪽"으로 치우친다. 기계의 상태와 무관한 표본만이 자동 적재 오류율을 잰다.

## 대가

- 학습을 K+1 번 한다 (CPU 에서 몇 분 × K).
- 묶음 교차의 기준은 내보낸 모델(전부로 학습)이 아니라 묶음마다의 모델로 잰 것이다. 전부로 학습한 모델이 조금 더 나을 것이므로 기준은 보수적인 쪽으로
  틀린다.
- 표본 감사는 사람의 시간이 든다. 100쪽이면 자동 적재 오류 0 일 때 상한이 약 3.7 % 다 — 2 % 를 뒷받침하려면 약 190쪽 (ADR 0012 의 계산).
