# 0004. 교차검증의 조인 키는 자리(slot)

상태: 채택 (2026-10)

## 상황

운반 횟수는 차량별 일보와 편×차량 행렬 두 곳에 적힌다. 둘을 비교하려면 일보 한 장이 행렬의 어느 열인지 알아야 한다.
행렬의 열 머리글에는 운전자와 차량번호가 인쇄되어 있다.

처음에는 운전자 이름으로 이으면 된다고 보았다. 실제 문서를 더 보니 틀렸다.
머리글은 양식을 만든 당시 상태로 굳어 있고, 그 뒤로 사람도 차도 바뀌었다.
같은 운전자가 다른 차를 몰기도 하고, 같은 차를 다른 사람이 몰기도 한다.

## 결정

- 조인 키는 행렬의 **열 자리(slot)** 다. 운전자도 차량번호도 키가 아니다.
- 일보 한 장을 자리에 대응시키는 순서: (1) 작성자가 머리글 운전자와 같은 자리, (2) 아니면 차량번호가 머리글 차량번호와 같은 자리.
- 대응 결과를 그날의 **관측값**으로 `eq_assignment_obs` 에 남긴다: 실제 차량·운전자, 인쇄된 머리글, 어떻게 맞췄는지, 머리글과 다른지.
- 어느 자리에도 대응되지 않는 일보는 버리지 않고 `unresolved:` 로 교차검증 결과에 드러낸다.

## 이유

- 인쇄된 값을 사실로 믿으면 조용히 틀린 조인이 생긴다. 관측값으로 남기면 머리글이 낡았다는 것 자체가 데이터가 된다.
- 배차 이력은 2단계(장비 가동, 운전자별 실적)에서 필요한 정보다.

## 대가

- 일보의 차량번호·작성자를 읽어야 한다. 인식기가 생기기 전에는 사람이 붙인 라벨에 의존한다.
- 운전자와 차량이 동시에 바뀐 날은 대응되지 않는다. 그런 날은 `unresolved` 로 남고 사람이 본다.
