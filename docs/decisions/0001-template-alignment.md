# 0001. 범용 표 인식 대신 템플릿 정합

상태: 채택 (2026-09)

## 상황

기존 코드는 페이지마다 표 구조를 새로 검출하고(셀 좌표를 영상에서 찾고) 상용 OCR 결과의 글자 상자를 그 셀에 끼워 맞췄다.
그런데 현장 양식은 몇 종류뿐이고 인쇄된 서식은 날마다 같다. 달라지는 것은 손으로 쓴 내용뿐이다.

## 결정

양식마다 기준 이미지 한 장과 셀 좌표(템플릿)를 미리 정해 두고, 스캔 페이지를 기준 이미지에 정합한다.
정합 뒤에는 모든 셀의 위치를 이미 안다.

- 분류: 각 템플릿과 ORB 정합을 시도해 인라이어가 가장 많은 양식
- 정합: ORB → 비율 검정 → RANSAC 호모그래피
- 품질: 정합 뒤 표마다 괘선을 다시 검출해 템플릿과의 오차를 잰다. 미달이면 값을 뽑지 않는다

## 이유

- 셀 좌표가 확정되므로 "이 값이 어느 장비의 어느 열인가"가 인식 전에 정해진다. 인쇄된 값은 읽을 필요가 없다.
- 모델이 필요 없고 CPU 에서 쪽당 1초 안팎이다.
- 실패가 눈에 보인다(인라이어 수, 괘선 오차). 표 검출 모델의 실패는 조용히 틀린 셀을 만든다.
- 첫 대상 현장의 70쪽에서 정합 실패가 없었다.

## 버린 것

- 범용 표 구조 인식 모델: 양식이 고정된 상황에서는 문제를 더 어렵게 푸는 것이다.
- 문서 전체를 비전-언어 모델에 넣어 구조화된 출력을 받는 방식: 출처(좌표)를 잃고, 값이 맞는지 검증할 단위가 없다.

## 대가

- 새 양식마다 템플릿을 만들어야 한다 → `minedocscan template init` 으로 뼈대를 만든다.
- 서식이 개정되면 템플릿도 새로 만들어야 한다. 분류 여유(`low_margin`)와 괘선 오차가 그 신호다.
- 양식이 아닌 자유 서식 문서는 다루지 못한다. 1단계의 범위 밖이다.
