# 0016. 가동 기록은 쪽 하나에 한 행, 가동 시간은 근거와 함께, 계기의 연속성은 보여 주기만

상태: 채택 (2026-10). 작업 지시서 [tasks/0005](../tasks/0005-usage-logs.md) 4.2–4.5, 9절.

## 상황

하루치 묶음의 절반이 "분류만 하는" 양식이었다: 중기운행일보, 점보 작업일보, 로우더 작업일보 — 셋 다 **장비 한 대의 하루**를 적는다.
앞의 둘은 같은 짜임(머리 / 작업 표 / 계기 칸 / 특이사항)이고 로우더 작업일보는 다르다(작업량 표 / 근무 시각 / 계기). 계기 칸에는 가동 시간계의
값을 적거나(시작·종료·총), 계기가 없는 장비는 시각을 적거나, 비워 둔다. 같은 장비의 어제 종료 값은 오늘 시작 값과 같아야 한다.
한 장비가 하루에 두 장을 내기도 한다. 2단계(통합 DB)의 가동 시간 분류가 이 기록을 읽어 간다.

## 결정

1. **핸들러는 하나(`usage`), 양식의 차이는 템플릿의 표의 역할로.** 표(region)마다 `role`: `meter`(시작·종료·총), `shifts`(근무 구분 × 시각
   범위), `tally`(구분 × 근무조·장소의 정수), `activities`(작업 표의 글자 칸 — 글씨가 있는 줄의 수만). 새 양식이 이 네 가지의 조합이면 코드를
   고치지 않는다 (원칙 1). 칸 안의 인쇄된 줄(하단 / 저광장)은 인쇄되지 않은 나눔 선(`grid.split_ys`)으로 행을 나눈다 — 칸만 자르고 정합 판정과
   괘선 지우기에는 쓰지 않는다 (없는 괘선을 찾으면 정합이 실패한다).
2. **쪽 하나에 한 행** (`eq_usage_daily`). 하루 두 장이면 두 행이고 합치지 않는다 — 합치는 것은 읽는 쪽(2단계)의 일이다. 작업량 표는 칸 하나에
   한 행(`prod_tally`, 소계 칸도 적힌 대로 — 표시만 한다).
3. **가동 시간은 근거와 함께.** `hours` 는 적힌 값에서 계산하고 `hours_basis` 에 무엇으로 계산했는지 남긴다:
   `meter`(종료 − 시작) > `total`(총 칸) > `clock`(시각의 종료 − 시작, 자정을 넘으면 다음 날) > `shifts`(범위의 합) > NULL.
   **추정하지 않는다**: 앞선 근거에 아직 모르는 칸(잉크는 있는데 값이 없다 — 검수 대기, "읽을 수 없음")이 있으면 뒤의 근거로 내려가지 않고
   NULL, 시작·종료가 계기 값과 시각으로 섞였으면 NULL. 총은 수일 때만 근거다 (길이라 시각 옆에 수로 적혀도 섞인 것이 아니다).
4. **장비는 마스터와 맞춘다.** 장비명은 쪽 메타 `equipment`(0004 의 틀 그대로 — 검수 > 라벨 > 기계 값), 장비 ID 는 사이트 팩의 대응표
   `[equipment.aliases]`(적힌 이름 → 점검표의 장비 키)로만. 표에 없으면 ID 는 NULL 이고 이름은 남는다. 비슷한 이름으로 맞추지 않는다 (원칙 4).
   마스터에 없는 키를 가리키는 대응표는 사이트 팩을 읽을 때 오류다.
5. **검산은 보여 주기만 한다** (ADR 0006, `xcheck_usage`): 쪽 안(총 = 종료 − 시작, 소계 = 합)과 날짜 사이 — 같은 장비(ID, 없으면 적힌 이름)의
   계기 값이 있는 바로 앞 기록의 종료와 이 기록의 시작: `match` / `gap` / `overlap` / `first` / `unknown`, 차이와 사이에 낀 날 수. 허용 오차
   0.05 시간. 순서는 날짜 → 계기 시작 값 → 쪽. 비교하지 못하면 `unknown` — 바로 앞 계기 기록의 종료를 모르거나(검수 대기, 시작만 적혔다)
   같은 날 시작 값을 모르는 다른 장이 있거나 날짜를 모를 때. 더 앞의 기록과 비교하지 않는다(가짜 gap). 어긋난 쪽의 값은 바꾸지 않고,
   앞날의 종료로 오늘의 시작을 채우지도 않는다. 검수 대기열 `usage-check` 에서 사람이 두 칸을 같이 본다.
6. 검수를 저장하면 그 쪽의 업무 행과 검산, **그 장비의** 연속성(장비명이 바뀌었으면 예전·새 장비 둘 다)만 다시 계산한다. 연속성은 장비마다
   그 장비의 기록만으로 정해지는 함수라 마무리 단계의 전체 계산과 같다 — 불변식(저장 직후의 DB = 같은 검수 파일로 새로 돌린 DB)이 새 테이블에도
   성립한다.

## 버린 것

- **장비마다(또는 양식마다) 핸들러**: 양식 셋 중 둘이 같은 짜임이고, 다음 현장의 양식도 같은 조각(계기·근무 시각·작업량·작업 표)의 조합일
  가능성이 높다. 역할을 데이터로 두면 새 양식은 템플릿만 쓴다.
- **하루 단위로 합친 행**: 두 장의 근무조·운전자가 다르고, 합치는 규칙(겹치는 시간, 다른 운전자)은 2단계의 분류와 같이 정해야 한다.
- **계기 값이 없으면 근무 시각에서 가동 시간을 "추정"하기 / 앞날의 종료로 시작을 채우기**: 근거가 없는 값이 근거가 있는 값과 섞이면 2단계에서
  가를 수 없다. 대신 근거(`hours_basis`)를 남긴다.
- **비슷한 이름으로 장비 맞추기**: "로우더 3" 과 "로우더 8" 은 한 글자 차이다. 틀린 연결은 연속성 검산을 망가뜨리고 보이지도 않는다.

## 대가

- 대응표는 사람이 관리한다. 표에 없는 이름은 ID 없이 남고, 연속성은 적힌 이름으로만 이어진다 (이름을 다르게 쓴 날은 끊어진다 — `first`).
- 하루 두 장의 순서를 계기 시작 값으로 정하므로, 시작을 잘못 적은 쪽은 순서도 틀릴 수 있다 — 그 경우도 검산에 드러난다.
- 소수·시각은 아직 기계가 읽지 않는다(0006). 그때까지 계기 칸은 전부 사람이 입력한다 (`readings`).
