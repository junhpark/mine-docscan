# 0009. 평가셋은 날짜로 나누고, 한 번 정하면 바꾸지 않는다

상태: 채택 (2026-10). 작업 지시서 [tasks/0002](../tasks/0002-full-archive-and-evalset.md) 4.6.

## 상황

검수값이 곧 정답이자 학습 데이터다 (ADR 0007, 0008). 인식기를 학습·선택하려면 학습용과 평가용을 나눠야 하는데,
같은 날의 차량별 일보와 편×차량 행렬에는 같은 값이 적힌다. 셀 단위로 무작위로 나누면 학습 쪽에서 본 값이 평가 쪽에 그대로 나온다.

## 결정

1. **날짜 단위로 나눈다.** 한 날짜의 모든 셀은 같은 분할(`test` 또는 `train`)에 있다. 날짜가 없는 쪽은 `unknown` 으로 어느 쪽에도 넣지 않는다.
2. **분할은 날짜와 사이트 팩의 소금값만으로 정해진다.** `site.toml` 의 `[eval] split_salt`(없으면 사이트 이름), `test_share`(기본 0.2).
   `hash(소금값, 날짜)` 의 앞 32비트를 [0, 1) 로 보고 `test_share` 미만이면 `test` 다 (`evaluate/split.py`).
   검수가 늘어도, 다른 컴퓨터에서도, 나중에 돌려도 같다.
3. **`test` 는 학습, 문구 사전, 임계값 조정에 쓰지 않는다.** 내보내기(`review export-answers`, `export-crops`)가 `--split` 으로 둘을 가르고 섞지 않는다.
4. **소금값을 바꾸는 것은 평가셋을 버리는 것이다.** 바꿨다면 그 전의 수치와 비교하지 않는다.

## 이유

- 날짜 단위라야 두 양식의 같은 값이 한쪽에만 있다. 교차검증 일치율도 같은 단위로 계산된다.
- 소금값으로 정하면 분할 목록을 따로 저장·동기화할 필요가 없다. 사이트 팩만 같으면 어디서나 같은 평가셋이다.
- 처음 150일치에서 20 % 면 약 30일, 숫자 셀 수천 개다. 인식기 비교에 충분하고 학습 쪽도 충분히 남는다.

## 대가

- 날짜 수가 적을 때는 비율이 정확히 20 % 가 아니다 (해시라 날짜마다 독립). 3일치 같은 작은 묶음에서는 한쪽이 빌 수 있다.
- 양식이 개정되거나 현장이 바뀐 기간이 한쪽 분할에 몰릴 수 있다. `review stats` 의 분할별 날짜 수로 확인한다.
