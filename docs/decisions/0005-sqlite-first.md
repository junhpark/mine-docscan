# 0005. SQLite 로 시작하고 PostgreSQL 로 옮길 수 있게

상태: 채택 (2026-09). 보완 → [0021](0021-publish-to-the-shared-db.md) (2026-10): 작업 DB 는 SQLite 그대로 두고 PostgreSQL 로 옮기지 않는다 —
통합 DB 에는 결과의 사본을 싣는다. 아래의 "운영용 PostgreSQL 어댑터"는 만들지 않는다.

## 결정

- 개발과 시험은 SQLite 파일 하나로 한다. 설치할 것이 없고 `WORK_ROOT` 를 지우면 처음부터 다시 만들 수 있다.
- 스키마와 쓰기 문법은 SQLite 와 PostgreSQL 에서 같이 도는 부분집합만 쓴다:
  날짜·시각은 ISO 8601 문자열, 불리언은 0/1, 쓰기는 `INSERT … ON CONFLICT … DO UPDATE`.
- 쓰기는 `store.db.upsert()` 를 거친다. 기본 키는 내용에서 결정되는 값(파일 해시, `페이지:표:열:행`, `날짜:장비`)이라 재실행이 멱등이다.
- 운영용 PostgreSQL 어댑터는 연결과 자리표시자만 바꾸면 되도록 남겨 둔다.

## 이유

- 지금 단계에서 중요한 것은 규칙을 고치고 전체를 다시 돌려 수치를 비교하는 속도다.
- 2단계와 공유할 운영 DB 는 여러 사용자가 동시에 쓰므로 PostgreSQL 이 맞지만, 그 결정이 1단계 개발을 막을 이유는 없다.

## 대가

- 날짜를 문자열로 두므로 DB 차원의 날짜 연산을 쓰지 못한다. 필요해지면 PostgreSQL 쪽에서 뷰로 변환한다.
- 스키마 변경 이력(마이그레이션) 도구가 아직 없다. 운영 DB 를 붙일 때 도입한다.
