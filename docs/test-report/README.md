# 시험 성적서

등록(tasks/0009)에 내는 시험 성적서의 구성과 만드는 법. 성적서 자체는 CI 의 산출물이다 — 판마다 사람이 받아서 기관의 서식으로 옮긴다.
저장소에 넣는 것은 **틀(생성기)과 규모의 JSON** 뿐이다.

| 무엇 | 어디 |
|---|---|
| 생성기 | `scripts/test_report.py` (`env` — 작업마다의 환경, `build` — 성적서) |
| 규모의 수치 | 이 폴더의 `scale-<날짜>.json` (`scripts/bigdb.py measure` — 손으로, 같은 기계에서 고치기 전과 뒤) |
| 성적서 | CI 의 `report` 작업이 만드는 산출물 `test-report` → `시험성적서-<판>.md` |

## 구성

1. **시험 환경** — CI 작업마다 OS·파이썬·의존성의 판 (`test_report.py env` — 호스트 이름·경로 없이)
2. **자동 시험** — 작업마다(우분투 3.11·3.12, 하한 판, `slow`, `postgres`, 윈도우) 시험 수·통과·실패·건너뜀·시간 (`pytest --junitxml`), 건너뛴 이유별 수
3. **자가 시험** — 우분투(test 3.12 작업)와 윈도우(설치한 묶음)의 `minedocscan selftest` 결과
4. **설치 시험** — windows-install 작업의 단계마다 결과와 수치(묶음 크기, 설치·올리기 시간, 자가 시험 시간, serve 를 띄운 것), 묶음 보고(바퀴, VC 런타임)
5. **규모** — 가장 새 `scale-*.json` 의 기준과 값 (조각 하나의 시간, 메모리, 가동 일보 검수의 더러운 날짜 …)
6. **확장성** — 가상 양식(V2)을 템플릿만으로 더한 합성 묶음의 표 (`scripts/v2_metrics.py` — slow 작업), 보통·거친 글씨
7. **라이선스** — 윈도우 묶음과 우분투 설치 환경의 라이선스마다 배포판 수, 허용 목록 밖
8. **실데이터** — 칸과 명령만. **사람이 채운다** (회귀, 정합·분류, 값 유무, 숫자 인식기, 쪽 메타, ✓ 판정, 처리 시간 — 수만, 이름·차량번호·파일명 없이)

## 만드는 법

CI 가 한다: 시험 작업들이 `junit-<작업>` 산출물(JUnit·환경, test 3.12 는 자가 시험·라이선스 목록도), windows-install 이 `windows-install-report`,
slow 가 `v2-metrics` 를 올리고, `report` 작업(다른 작업이 끝난 뒤 — 실패한 작업도 실패로 나오게 `if: always()`)이 그것을 모아 성적서를 만든다.

손으로 (받은 산출물이 한 폴더에 있을 때):

```bash
python scripts/test_report.py build --artifacts 받은-산출물 --out 성적서 --needs '{"test": {"result": "success"}}'
```

## 지킬 것

- 합성 데이터만. 합성의 수치로 인식률을 말하지 않는다 (`CLAUDE.md`). 실데이터의 수치는 8절에 사람이 수만 넣는다.
- 성적서에 경로·사용자 이름·호스트 이름·통합 DB 의 주소를 싣지 않는다 — 생성기는 실패한 시험의 글을 싣지 않고(이름과 수만), 건너뛴 이유의 경로를 지운다.
- 갈무리를 붙이지 않는다 (설명서의 갈무리도 합성 데모의 것뿐이다).
