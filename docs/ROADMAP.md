### 첫 대상 현장에서의 수치 (인식 백엔드 없이)

입력: 일일 점검표 27일치 + 하루치 묶음 3일치 = 문서 30건, 110쪽. 기준 파일은 그 현장의 사이트 팩에 있다.

| 항목 | 값 |
|---|---|
| 양식 분류 | 110쪽을 6종으로 분류 (셀 정의가 있는 3종 70쪽, 분류 전용 3종 40쪽) |
| 정합 | 70/70 통과. 괘선 오차 최대 4 px |
| 점검표 ✓ 판정 | 675행 중 유 288 / 무 286 / 판정 불가 101 (판정 불가 중 100은 점검을 하지 않은 4일치) |
| 교차검증 (값 유무) | 일치 564 / 불일치 36 |
| 배차 관측 | 30건 중 인쇄된 머리글과 다른 것 8건 |
| 오라클 백엔드 | 점검내역 CER 0.0, 행 자동 적재율 0.83 (나머지는 ✓ 판정 불가 행) |
| `null` 백엔드 | 행 자동 적재율 0.27 (점검내역이 빈 행만 자동) |
| 속도 | 쪽당 약 1초 (CPU) |

✓ 판정의 정답은 아직 없다. 유/무 수치는 판정 결과이지 정확도가 아니다.
교차검증의 불일치 36건은 읽기 오류와 현장의 기재 차이가 섞여 있고, 아직 사람이 분류하지 않았다.

## 1단계의 남은 일

순서는 의존 관계 때문이다: 평가셋이 있어야 인식기를 고를 수 있고, 인식기가 있어야 교정과 검수가 의미가 있다.

### M1. 양식 넓히기
- 분류 전용 3종(중기 운행일보, 갱외 상차 일보, 천공 작업일보)의 셀 정의
- 묶음 PDF 에 아직 템플릿이 없는 양식(관리 계열: 선광 작업일지, 경비 근무일지, 전기 안전일지 등) 추가
- 여백 행에 손으로 추가한 장비의 처리 규칙 (지금은 `doc_field` 에만 남는다)
- 완료 기준: 묶음 PDF 의 `unknown_form` 0쪽, 새 양식마다 정합 통과율과 괘선 오차를 회귀 기준에 추가

### M2. 평가셋
- 숫자 셀(운반 횟수) 정답: 스캔과 같은 기간의 현장 입력 엑셀 확보 → `answers.json` 으로 변환하는 도구
- 점검표: 기존 연구팀이 가진 전체 스캔과 정답 확보 (지금은 27일치)
- 기존 상용 OCR 결과(JSON)로 같은 평가셋에서의 기준선 계산 — 새로 호출하지 않고 이미 받은 결과를 쓴다
- ✓ 판정 정답 (표본 추출해 사람이 확인)
- 완료 기준: 양식·필드 종류별로 표본 수와 기준선 수치가 표로 정리됨

### M3. 인식 백엔드
- 숫자 전용 인식기 (횟수는 대부분 한두 자리) — 가장 작고 효과가 바로 교차검증으로 드러난다
- 표 밖 필드: 날짜, 차량번호, 작성자 — 닫힌 집합(`choices`)에서 고르는 문제로 푼다 → 사람이 붙인 라벨을 없앤다
- 손글씨 텍스트: 로컬에서 학습·추론하는 비전-언어 모델. 같은 평가셋에서 기준선보다 좋을 때 교체한다
- 완료 기준: 평가셋에서 백엔드별 CER·필드 정확도·자동 적재율 비교표. 채택한 백엔드가 기준선 이상

### M4. 교정
- 문구 DB: 행(장비)·열별로 반복되는 문구를 모아 후보를 내고 편집거리 제한 안에서 고른다
- 후보 목록을 주고 고르게만 하는 언어모델 교정기
- 완료 기준: 교정 전후 CER 비교. 교정이 틀린 값을 만든 건수(과교정)를 따로 센다

### M5. 운영 형태
- 검수 화면: `pending` 인 값을 정합 이미지의 그 자리와 함께 보여 주고 고친다. 교차검증 불일치도 같은 화면에서 본다
- 폴더 감시: 복합기가 공유 폴더에 저장하면 자동 처리
- PostgreSQL 어댑터
- 완료 기준: 스캔부터 DB 까지 사람이 명령을 치지 않고 흐르고, 검수한 값이 `reviewed` 로 남는다

### M6. 등록 준비
- 설치 절차, 사용 설명서, 시험 성적 (합성 시험 + 실데이터 수치)
- 라이선스와 저작권 표기 확정

## 확장성 검증 (V2)

`tools/synth.py` 를 넓혀 가상의 다른 양식(유류일지, 환경일지 등)과 더 거친 손글씨를 만들고,
코드 변경 없이 템플릿 추가만으로 적재되는 것을 보인다. 여기서 나오는 수치는 **확장성의 증거**이지 인식 정확도가 아니다.

## 2단계와의 접점

- 업무 테이블(`eq_*`, `insp_*`, `prod_*`)에 직접 입력 값이 같이 들어간다 (`entry_source`).
- `xcheck_*` 를 날짜별로 계속 쌓아 물질수지 불일치의 추이를 보여 준다. 조정 규칙은 2단계에서 정한다.
- 노드를 잇는 교차검증을 늘린다: 채광 → 선광 → 출하, 장비 가동 ↔ 운반 실적.
