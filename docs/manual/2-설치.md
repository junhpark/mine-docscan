# 2. 설치

이 장은 관리자가 읽는다. 현장 PC(윈도우)에는 **설치 묶음** 하나로 설치한다. 인터넷이 없어도 되고, 관리자 권한도 필요 없다.
리눅스 PC 는 이 장의 끝 [리눅스](#리눅스)를 본다.

설치가 끝나면 [3장 처음 설정](3-처음-설정.md)으로 간다.

## 준비

- **64비트 윈도우 PC**와, 화면을 쓸 사람의 **윈도우 계정**. 그 계정으로 로그온해서 설치한다. 설치한 것은 그 계정에만 생긴다.
- **설치 묶음** `minedocscan-1.0.0-win64.zip` (80 MB 안팎).
- **폴더의 자리.** 설치할 때 사이트 팩·보관 폴더·작업 폴더·접수 폴더·엑셀 폴더의 경로를 적는다. 무엇을 어디에 둘지는
  [3장의 "폴더"](3-처음-설정.md#폴더)를 먼저 읽는다. 나중에 설정 파일에서 고칠 수 있다.
- **검수자 ID.** 이 PC 의 화면에서 검수·결정을 남길 사람의 짧은 영문 이름 (보기: `jp`).

## 묶음에 든 것

zip 안에는 `minedocscan-1.0.0-win64` 폴더 하나가 있다.

| 파일 | 무엇 |
|---|---|
| `install.ps1`, `uninstall.ps1` | 설치·지우기 스크립트 (PowerShell) |
| `INSTALL.txt` | 설치 순서를 줄인 것 |
| `manual.html` | 이 설명서 한 장 (그림 포함). 브라우저로 연다. 종이나 PDF 가 필요하면 브라우저의 인쇄("PDF로 저장")를 쓴다 |
| `python-3.12.10-embed-amd64.zip`, `pip-….whl` | 앱 전용 파이썬 (python.org 의 embeddable 패키지)과, 그 안에 놓을 pip |
| `wheels\` | minedocscan 과 그것이 쓰는 꾸러미 전부 (통합 DB 드라이버 포함). OpenCV 의 동영상 플러그인(FFmpeg)은 뺐다 — 쓰지 않는다 |
| `sources\` | 묶음에 든 LGPL 꾸러미(통합 DB 드라이버 psycopg)의 소스와 `README.txt`. 설치에는 쓰지 않는다 |
| `minedocscan.example.toml` | 설정 파일의 보기 — 모든 키와 설명 |
| `THIRD_PARTY_NOTICES.txt`, `NOTICE` | 라이선스 문구 |
| `SHA256SUMS.txt`, `VERSION` | 묶음 안 파일의 해시, 판 (`1.0.0`) |

## 차단 풀기와 실행 정책

### 차단 풀기

메일이나 인터넷으로 받은 zip 에는 윈도우가 "인터넷에서 온 파일" 표시를 붙인다. 표시가 남은 채로 풀면 안의 파일에도 붙는다.
그래서 **풀기 전에** 푼다.

zip 을 오른쪽 클릭 → **속성** → 아래쪽 "보안"의 **차단 해제**에 체크 → **확인**. 그 칸이 없으면 이미 풀린 것이다.
PowerShell 로 해도 된다.

<!-- 시험: 돌리지 않음 -->
```powershell
Unblock-File D:\setup\minedocscan-1.0.0-win64.zip
```

- 그다음 zip 을 오른쪽 클릭 → **압축 풀기**(윈도우 판에 따라 "모두 압축 풀기"). 탐색기는 zip 이름의 폴더를 하나 더 만들기도 한다.
  `install.ps1` 이 들어 있는 폴더를 찾는다. 폴더 경로는 영문으로 두는 것이 좋다 (보기: `D:\setup\minedocscan-1.0.0-win64`).
- 푼 폴더는 지우지 말고 둔다. 지우기 스크립트(`uninstall.ps1`)가 그 안에 있다. 설치 폴더로는 복사되지 않는다.
- 차단 풀기를 놓쳤어도 괜찮다. `install.ps1` 이 묶음 폴더 안의 표시를 풀고 "인터넷에서 받은 표시(차단)를 풀었습니다: 파일 N개"라고 알린다.

### 실행 정책

윈도우는 처음에 PowerShell 스크립트(`.ps1`)를 돌리지 않게 되어 있다. PC 의 정책을 바꾸지 않고, 그 한 번만 허락해서 돌린다.

<!-- 시험: 돌리지 않음 -->
```powershell
powershell -ExecutionPolicy Bypass -File install.ps1 …
```

`-ExecutionPolicy Bypass` 는 PC 의 설정을 바꾸지 않는다. 이 줄이 여는 PowerShell 하나만 스크립트를 돌린다.
회사의 그룹 정책으로 실행 정책을 정해 둔 PC 에서는 이 줄로도 돌지 않는다. 그때는 PC 관리자에게 묻는다.

## install.ps1 돌리기

시작 메뉴에서 **Windows PowerShell** 을 연다. "관리자 권한으로 실행"은 하지 않는다 — 지금 사용자로 설치한다.
`cd` 로 묶음 폴더에 간 뒤 `install.ps1` 을 돌린다.

<!-- 시험: 돌리지 않음 -->
```powershell
cd D:\setup\minedocscan-1.0.0-win64
powershell -ExecutionPolicy Bypass -File install.ps1 -Site D:\minedocscan\site -Archive D:\minedocscan\archive `
    -Work D:\minedocscan\work -Inbox C:\Scans -ExcelDir D:\minedocscan\excel -Reviewer jp
```

- 둘째 줄 끝의 `` ` `` 는 다음 줄로 잇는 표시다. 한 줄로 적어도 된다.
- 빈칸이 든 경로는 따옴표로 감싼다 (보기: `-Inbox "D:\스캔 저장"`).
- 위의 경로는 보기다. 이 현장의 경로로 바꾼다.

### 매개변수

| 매개변수 | 뜻 | 주지 않으면 |
|---|---|---|
| `-Site` | 사이트 팩 폴더 | 처음 설치에서는 멈춘다 (`-Config` 를 주면 괜찮다) |
| `-Archive` | 보관 폴더 — 스캔 원본 | 〃 |
| `-Work` | 작업 폴더 — 작업 DB·정합 그림. 이 PC 의 디스크에 | 〃 |
| `-Inbox` | 접수 폴더 — 스캐너 프로그램의 저장 폴더 | 접수 폴더를 보지 않는다. 스캔이 저절로 들어오지 않는다 |
| `-ExcelDir` | 엑셀 폴더 — 미리 만들어 둔 폴더 | 엑셀을 저절로 쓰지 않는다 (홈의 내려받기는 된다) |
| `-Config` | 이미 있는 설정 파일. 주면 위 다섯은 보지 않고 이 파일을 쓴다 | 위 다섯으로 설정 파일을 새로 쓴다 |
| `-Reviewer` | 검수자 ID — 영문·숫자·`_` `.` `-`, 32자 안. 작업 스케줄러의 serve 가 이 이름으로 검수·결정을 남긴다 | 멈춘다 (`-NoTask` 면 괜찮다) |
| `-InstallDir` | 프로그램을 둘 폴더 | `%LOCALAPPDATA%\minedocscan` |
| `-NoTask` | 작업 스케줄러에 serve 를 등록하지 않는다. serve 는 필요할 때 손으로 띄운다 | 등록하고 바로 켠다 |
| `-Quiet` | 진행 글을 찍지 않는다. 끝의 요약과 오류는 나온다 | 진행 글과 `minedocscan info` 의 결과를 보여 준다 |

- 다섯 경로(`-Site` … `-ExcelDir`)는 **절대 경로**로 적는다. `D:\…` 또는 `\\서버\공유\…` 꼴이다. 아니면 멈춘다.
- 설정 파일 `%APPDATA%\minedocscan\minedocscan.toml` 이 **이미 있으면** 그 파일을 그대로 쓴다. 다섯 경로는 보지 않고
  "설정 파일은 그대로 둡니다"라고 알린다. 경로를 바꾸려면 설정 파일을 고친다 ([3장](3-처음-설정.md#설정-파일)).
- `-InstallDir` 은 새 폴더나 빈 폴더를 준다. 그 안에 minedocscan 의 것이 아닌 `python` 폴더가 있으면 멈춘다.
- 매개변수가 틀리면(빠졌다, 상대 경로다, 검수자 ID 의 글자가 틀렸다) 파이썬을 풀기 전에 빨간 줄 "설치를 멈춥니다: …" 로 멈춘다.
  PC 에는 아무것도 생기지 않는다. 설치가 멈출 때 나오는 글과 할 일은 [6장의 "설치할 때"](6-문제-해결.md#설치할-때)에 모아 두었다.

### 설치가 하는 일

1. **묶음 확인.** `SHA256SUMS.txt` 와 파일마다의 해시를 견준다. 다르면 "묶음이 손상되었습니다 … — 다시 받으십시오"로 멈춘다.
   차단 표시가 남은 파일은 푼다.
2. **매개변수 확인.** 위의 규칙대로.
3. **앱 전용 파이썬.** `<설치 폴더>\python` 에 푼다. 레지스트리와 시작 메뉴를 건드리지 않는다. PC 에 다른 파이썬이 있어도 섞이지 않는다.
4. **minedocscan 설치.** 묶음의 `wheels\` 에서만 가져온다. **망에 닿지 않는다.**
5. **런타임 확인.** 그 파이썬이 영상·PDF·엑셀·통합 DB 꾸러미를 읽어 들이는지 본다. 실패하면 "런타임 확인에 실패했습니다 (…)"로 멈춘다.
   그 줄에 `DLL load failed` 가 보이면 이 PC 에 **Visual C++ 재배포 패키지(x64)** 가 필요하다. N·KN 판 윈도우라면
   **미디어 기능 팩**도. 마이크로소프트의 것을 설치한 뒤 `install.ps1` 을 다시 돌린다.
   묶음의 꾸러미가 쓰는 런타임은 앱 전용 파이썬에 들어 있어, 보통은 필요 없다.
6. **설정.** 설정 파일이 없으면 매개변수로 쓴다 (`%APPDATA%\minedocscan\minedocscan.toml`). 사용자 환경 변수 `MINEDOCSCAN_CONFIG` 를
   그 파일로 두고, 사용자 `Path` 에 `<설치 폴더>\python\Scripts` 를 더한다. 그래서 새 PowerShell 창에서는 어느 폴더에서나
   `minedocscan` 명령이 돈다.
7. **`minedocscan info`.** 설정과 사이트 팩을 보여 준다 ([3장](3-처음-설정.md#info-로-확인하기)). 실패하면 노란 줄
   "minedocscan info 가 실패했습니다 — 설정의 경로를 보십시오 (설치는 끝났습니다)"가 나온다.
8. **작업 스케줄러.** `minedocscan-serve` 를 등록하고 바로 켠다 ([아래](#작업-스케줄러의-serve)).
9. **바탕 화면 바로 가기** "광산 문서 스캔" → `http://127.0.0.1:8765/`.
10. **요약.**

CI 의 윈도우 PC 에서는 설치가 15초쯤 걸렸다.

### 끝에 나오는 요약

<!-- 시험: 돌리지 않음 -->
```text
minedocscan 1.0.0 을 설치했습니다 (15 초)
  프로그램: C:\Users\<사용자>\AppData\Local\minedocscan (앱 전용 파이썬 python\, 로그 logs\)
  설정: C:\Users\<사용자>\AppData\Roaming\minedocscan\minedocscan.toml
  화면: http://127.0.0.1:8765/ (바탕 화면의 '광산 문서 스캔')
다음: 새 PowerShell 창에서 'minedocscan selftest' — 그리고 설명서(묶음의 manual.html)의 3장 '처음 설정'
```

설치를 돌린 창에서는 아직 `minedocscan` 명령이 보이지 않는다. **새 PowerShell 창**을 연다 (`Path` 를 새로 읽는다).
그다음은 [3장](3-처음-설정.md)이다.

## 설치한 뒤에 있는 것

| 무엇 | 자리 |
|---|---|
| 프로그램 (앱 전용 파이썬) | `%LOCALAPPDATA%\minedocscan\python\` |
| 판 | `%LOCALAPPDATA%\minedocscan\VERSION` |
| 로그 | `%LOCALAPPDATA%\minedocscan\logs\serve-YYYYMMDD.log` |
| 설정 파일 | `%APPDATA%\minedocscan\minedocscan.toml` (`-Config` 를 줬으면 그 파일) |
| 사용자 환경 변수 | `MINEDOCSCAN_CONFIG` (설정 파일의 자리), `Path` 에 `%LOCALAPPDATA%\minedocscan\python\Scripts` |
| 작업 스케줄러 | `minedocscan-serve` |
| 바탕 화면 | "광산 문서 스캔" (`http://127.0.0.1:8765/` 바로 가기) |

`-InstallDir` 을 줬으면 `%LOCALAPPDATA%\minedocscan` 대신 그 폴더다.
`%LOCALAPPDATA%` 는 보통 `C:\Users\<사용자>\AppData\Local`, `%APPDATA%` 는 `C:\Users\<사용자>\AppData\Roaming` 이다.
탐색기의 주소 칸에 `%LOCALAPPDATA%\minedocscan` 처럼 그대로 적어도 열린다.

사이트 팩·보관 폴더·작업 폴더·접수 폴더·엑셀 폴더는 `install.ps1` 이 만들지도 지우지도 않는다. 데이터는 설정이 가리키는 그 폴더들에 있다.
데이터 폴더를 설치 폴더 안에 두지 않는다. 설치·올리기·지우기가 무엇을 건드리고 무엇을 남기는지는 [DATA.md](../DATA.md)의
"현장 PC: 설치 폴더와 데이터 폴더"에 표로 있다.

### 작업 스케줄러의 serve

`serve` 는 운영 화면(홈)을 열고 접수 폴더를 지켜보는 프로그램이다. 설치는 이것을 윈도우 작업 스케줄러에 `minedocscan-serve` 로 등록한다.

- 그 사용자가 **로그온할 때** 켜진다. 설치가 끝날 때도 바로 켠다. 켜지 못하면 "작업을 지금 켜지 못했습니다 — 다음 로그온에 켜집니다"라고 알린다.
- **창이 뜨지 않는다.** 돌고 있는지는 홈이 열리는지로 본다.
- 작업이 실패하면 1분 뒤에 다시 해 보도록(세 번까지) 등록한다. 시간 제한은 없다. 노트북이 배터리로 돌아도 켜고, 멈추지 않는다.
- 설정 오류처럼 고쳐야 하는 까닭으로 멈췄으면 다시 해 봐도 같다. 로그를 보고 고친 뒤 작업을 켠다 (아래).

돌리는 명령은 이렇다. `--reviewer` 는 설치할 때 준 검수자 ID 다.

<!-- 시험: 돌리지 않음 -->
```text
<설치 폴더>\python\pythonw.exe -m minedocscan.cli serve --config "<설정 파일>" --reviewer jp --log-dir "<설치 폴더>\logs"
```

보기·멈추기·켜기는 PowerShell 에서 한다. 관리자 권한 없이 된다. 시작 메뉴의 **작업 스케줄러** → "작업 스케줄러 라이브러리"에서도 보인다.

<!-- 시험: 돌리지 않음 -->
```powershell
Get-ScheduledTask -TaskName minedocscan-serve      # State 가 Running 이면 돌고 있다
Stop-ScheduledTask -TaskName minedocscan-serve
Start-ScheduledTask -TaskName minedocscan-serve
```

- 작업 폴더 하나에 처리하는 프로그램은 하나만 돈다. 이 작업이 도는 동안 창에서 `minedocscan serve` 나 `minedocscan run` 을 띄우면
  "다른 파이프라인(run·watch·serve)이 이미 돌고 있습니다"로 끝난다. 그런 명령은 작업을 멈춘 뒤에 돌리고, 끝나면 다시 켠다
  ([5장의 "serve 를 멈추고 하는 명령"](5-관리.md#serve-를-멈추고-하는-명령)).
- 설정 파일이나 사이트 팩(템플릿·`site.toml`)을 고쳤으면 작업을 멈췄다가 켠다. 돌고 있는 serve 는 고친 것을 모른다.
  이미 처리한 쪽에도 쓰려면 다시 처리한다 ([5장의 "다시 처리"](5-관리.md#다시-처리)).
- 검수자 ID 를 바꾸려면 `install.ps1` 을 새 `-Reviewer` 로 다시 돌린다 ([올리기](#올리기)와 같다 — 프로그램을 다시 설치하고,
  설정 파일은 그대로 두고, 작업을 새 ID 로 다시 등록한다).
- `-NoTask` 로 설치했으면 필요할 때 PowerShell 창에서 `minedocscan serve --reviewer jp` 를 띄운다. 그 창을 닫으면 serve 도 끝난다.

### 로그

- `%LOCALAPPDATA%\minedocscan\logs\serve-YYYYMMDD.log` — 날마다 새 파일이고, UTF-8 이라 메모장으로 열린다. 30일 지난 파일은 저절로 지운다.
- 찍히는 것: 접수·처리한 수와 문서 ID, 화면이 받은 요청의 경로와 상태 코드, 시작할 때의 알림(엑셀·통합 DB 를 켜지 않은 까닭 …),
  serve 가 멈춘 까닭. 파일명·이름·값은 찍지 않는다.
- serve 가 켜지지 않으면 그날 파일의 **맨 끝의 몇 줄**에 까닭이 있다 (보기: "설정 오류: …", "접수 폴더를 쓸 수 없습니다: …").
  [6장의 "serve 가 켜지지 않을 때"](6-문제-해결.md#serve-가-켜지지-않을-때)를 본다.
- 로그도 현장의 운영 기록이고, 설정한 폴더의 경로가 든 줄이 있을 수 있다. 메일·이슈에 통째로 붙이지 않는다. 필요한 줄만, 경로를 지우고 보낸다.

## 통합 DB 의 비밀번호

설치는 통합 DB(PostgreSQL)의 주소를 묻지 않는다. 통합 DB 에 싣지 않는 현장이면 이 절을 건너뛴다.

싣는다면 **주소와 비밀번호를 따로** 둔다. 설정 파일에는 둘 다 적지 않는다.

**1. 주소(URL)** — 사용자 환경 변수 `MINEDOCSCAN_PUBLISH_URL`. 비밀번호를 넣지 않는다.

<!-- 시험: 돌리지 않음 -->
```powershell
[Environment]::SetEnvironmentVariable('MINEDOCSCAN_PUBLISH_URL', 'postgresql://minedocscan@db-server:5432/mine', 'User')
```

꼴은 `postgresql://계정@서버:포트/DB` 다. 위의 값은 보기이고, 통합 DB 관리자에게 받은 값을 적는다.
계정은 이 프로그램의 스키마에만 쓰는 전용 계정이 좋다.

**2. 비밀번호** — PostgreSQL 의 연결 라이브러리(libpq)가 읽는 비밀번호 파일 `%APPDATA%\postgresql\pgpass.conf`.
프로그램이 따로 하는 일은 없다. 연결할 때 libpq 가 이 파일에서 찾는다. 메모장으로 만든다.

<!-- 시험: 돌리지 않음 -->
```powershell
New-Item -ItemType Directory -Force "$env:APPDATA\postgresql" | Out-Null
notepad "$env:APPDATA\postgresql\pgpass.conf"
```

메모장이 새 파일을 만들지 물으면 "예". 아래처럼 한 줄을 적고 저장한다. 꼴은 `서버:포트:DB:계정:비밀번호` 다.

```text
db-server:5432:mine:minedocscan:여기에-비밀번호
```

- 앞의 넷은 URL 과 같은 값이다.
- 비밀번호에 `:` 나 `\` 가 들어 있으면 그 글자 앞에 `\` 를 하나 더 적는다.
- 메모장의 기본 인코딩(UTF-8)으로 저장한다. BOM 이 붙은 UTF-8 로 저장하면 첫 줄을 읽지 못한다.
- `%APPDATA%` 는 그 사용자만 여는 폴더다. 이 파일을 다른 곳에 복사하거나 메일로 보내지 않는다.

**3. 스키마** — 실을 스키마가 `minedocscan` 이 아니면 설정 파일의 `[publish] schema` 에 적는다 ([부록 — 설정 목록](설정.md)).
설정 파일의 `[publish]` 에 `url`·`dsn`·`password` 를 적으면 모든 명령이
"설정 오류: [publish] 에 URL·비밀번호를 적지 않습니다 — 환경변수 MINEDOCSCAN_PUBLISH_URL 로만 받습니다"로 멈춘다.

**4. 다시 로그온** — 로그오프했다가 다시 로그온한다. 작업 스케줄러의 serve 는 로그온할 때의 환경 변수를 가지고 켜진다.

**5. 확인** — 새 PowerShell 창에서.

<!-- 시험: 돌리지 않음 -->
```powershell
minedocscan info
minedocscan publish --check
```

- `info` 의 "통합 DB:" 줄에 `db-server:5432/mine 스키마 minedocscan (켜짐, …)` 처럼 나온다. 프로그램은 서버와 DB 이름만 찍는다.
  계정과 비밀번호는 어디에도 찍지 않는다.
- `publish --check` 는 아무것도 쓰지 않고 견주기만 한다. 종료 코드 0 은 같음, 1 은 다름(처음에는 표가 없어 1),
  2 는 닿지 못함·설정 오류·다른 사이트의 대상이다 ([5장의 "publish --check"](5-관리.md#publish---check)).
- 싣는 것은 serve 가 한다. 홈의 윗줄 "통합 DB …"에 상태가 나온다 ([4장](4-날마다-쓰기.md#통합-db-의-상태)).
- 사이트 팩에 `[site] name` 이 있어야 싣는다 ([3장](3-처음-설정.md#사이트-이름을-적는다)).

이미 URL 에 비밀번호를 넣어 쓰고 있었다면 비밀번호를 `pgpass.conf` 로 옮기고 URL 에서 뺀다. 환경 변수는 그 사용자로 도는 프로그램에
다 넘어가기 때문이다. 규칙과 까닭은 [DATA.md](../DATA.md)의 "통합 DB"에 있다.

통합 DB 의 주소·계정·비밀번호는 문서·메일·이슈에 적지 않는다. 자가 시험으로 통합 DB 까지 시험하는 법은
[3장](3-처음-설정.md#통합-db-까지-시험하기)에 있다.

## 올리기

새 판이 나오면 새 묶음으로 같은 일을 한다. 설정·로그·데이터는 그대로 남는다. CI 의 윈도우 PC 에서 14초쯤 걸렸다.

새 묶음 `minedocscan-<판>-win64.zip` 의 [차단을 풀고](#차단-풀기) 푼다. 새 PowerShell 창에서 그 폴더로 가서 돌린다.

<!-- 시험: 돌리지 않음 -->
```powershell
powershell -ExecutionPolicy Bypass -File install.ps1 -Reviewer jp
```

- 경로 매개변수는 주지 않는다. 있는 설정 파일을 그대로 쓴다 ("설정 파일은 그대로 둡니다: …"). 처음에 `-Config` 로 준 파일도 그대로 쓴다.
- `-Reviewer` 는 다시 준다 (작업을 다시 등록한다). `-NoTask` 로 돌리면 있는 작업을 건드리지 않고 다시 켠다.
- 처음에 `-InstallDir` 을 줬으면 같은 값을 준다.
- 설치는 새 파이썬을 옆 폴더(`python.new`)에 다 만든 다음, 작업을 멈추고 바꿔 끼운다. 도중에 실패하면 옛 판이 그대로 남는다
  ("… — 옛 판은 그대로입니다"). 끝나면 작업을 다시 켜고, 요약의 첫 줄 끝에 "— 올렸습니다"가 붙는다.

### 새 묶음은 어디서 오나

묶음은 개발 쪽이 CI 의 윈도우 러너에서 만든다. 꾸러미의 판은 저장소의 잠금(`scripts/bundle.lock`)에 해시와 같이 적혀 있어, 같은 커밋이면
몇 번을 만들어도 **같은 바이트의 zip** 이 나온다 — 받은 zip 의 SHA-256 을 등록한 판(GitHub Release)에 적힌 것과 견줄 수 있다.

<!-- 시험: 돌리지 않음 -->
```powershell
Get-FileHash minedocscan-1.0.1-win64.zip -Algorithm SHA256
```

꾸러미의 판을 올리는 순서 (개발 쪽, 인터넷이 되는 곳): `python scripts/bundle.py lock` 으로 잠금을 새로 쓴다 → CI 의 `windows-install` 작업이
묶음을 두 번 만들어 같은지 보고, 망을 막고 설치하고, 자가 시험을 돈다 → 통과하면 잠금을 커밋한다 (`scripts/README.md`).

### 작업 DB 의 스키마가 바뀌는 판

작업 DB 의 꼴(스키마 버전)이 바뀌는 판이면 요약에 노란 줄이 나온다 (판 1.0.0 의 스키마 버전은 8 이다).

<!-- 시험: 돌리지 않음 -->
```text
  작업 DB 의 스키마가 바뀌었습니다 (8 → 9): 새 창에서 minedocscan run --fresh 로 다시 만드십시오 (검수·결정 기록은 그대로)
```

설치는 이것을 스스로 하지 않는다. 그동안 serve 는 옛 DB 를 열지 못해 켜지지 않는다 (로그: "DB 오류: DB 스키마 버전이 다릅니다 …").
새 PowerShell 창에서 작업을 멈추고, DB 를 다시 만들고, 작업을 켠다.

<!-- 시험: 돌리지 않음 -->
```powershell
Stop-ScheduledTask -TaskName minedocscan-serve
minedocscan run --fresh
Start-ScheduledTask -TaskName minedocscan-serve
```

`run --fresh` 는 작업 DB 를 지우고 보관 폴더의 스캔을 처음부터 다시 처리한다. 검수·결정 기록은 사이트 팩에 있어 그대로 다시 붙는다.
스캔이 많으면 오래 걸린다. 다시 처리에 대해서는 [5장 관리](5-관리.md#run---fresh)를 본다.

## 지우기

묶음 폴더(또는 같은 판의 묶음을 다시 푼 폴더)에서 돌린다.

<!-- 시험: 돌리지 않음 -->
```powershell
powershell -ExecutionPolicy Bypass -File uninstall.ps1
```

| 매개변수 | 뜻 |
|---|---|
| `-InstallDir` | 지울 설치 폴더. 주지 않으면 작업 스케줄러의 작업이 가리키는 폴더, 작업도 없으면 `%LOCALAPPDATA%\minedocscan` |
| `-RemoveConfig` | 설치가 쓴 설정 파일 `%APPDATA%\minedocscan\minedocscan.toml` 도 지운다. `-Config` 로 준 다른 자리의 파일은 지우지 않는다 |
| `-Quiet` | 진행 글을 줄인다 |

**지우는 것은 프로그램뿐이다.** 작업 `minedocscan-serve`(멈춘 뒤), 바탕 화면 바로 가기, 설치 폴더의 `python\`·`logs\`·`VERSION`
(그러고 비면 폴더도), 사용자 `Path` 의 그 항목, 환경 변수 `MINEDOCSCAN_CONFIG`.

**남기는 것**은 설정 파일, 사이트 팩, 보관 폴더, 작업 폴더, 접수 폴더, 엑셀 폴더다. 어디에 있는지 끝에 찍는다.

<!-- 시험: 돌리지 않음 -->
```text
minedocscan 을 지웠습니다 — 프로그램만.
남겨 둔 것 (지우지 않았습니다):
  설정: C:\Users\<사용자>\AppData\Roaming\minedocscan\minedocscan.toml
  site D:\minedocscan\site
  archive_root D:\minedocscan\archive
  work_root D:\minedocscan\work
  inbox C:\Scans
  excel_dir D:\minedocscan\excel
```

- **로그(`logs\`)는 지워진다.** 남기려면 먼저 다른 곳에 복사한다.
- 설치 폴더에 다른 파일이 있으면 그것은 남기고 폴더도 둔다 ("남은 것이 있어 폴더를 두었습니다: …"). minedocscan 의 설치 폴더가
  아니면(`VERSION` 도 앱 전용 파이썬도 없다) 그 폴더 안은 하나도 지우지 않는다 ("minedocscan 의 설치 폴더가 아니라 지우지 않았습니다: …").
- 데이터 폴더는 지우지 않는다. 보관 폴더(스캔 원본)와 사이트 팩의 검수·결정 기록은 다시 만들 수 없다.
  [5장 관리](5-관리.md#백업)대로 백업한다. 작업 폴더와 엑셀 폴더는 다시 만들 수 있다.
- 통합 DB 의 환경 변수 `MINEDOCSCAN_PUBLISH_URL` 과 `pgpass.conf` 는 건드리지 않는다. 이 PC 에서 더 싣지 않으면 손으로 지운다 — 아래.

<!-- 시험: 돌리지 않음 -->
```powershell
[Environment]::SetEnvironmentVariable('MINEDOCSCAN_PUBLISH_URL', $null, 'User')
notepad "$env:APPDATA\postgresql\pgpass.conf"      # 그 줄을 지우고 저장
```

## 리눅스

리눅스에는 묶음이 없다. 파이썬 **3.11 또는 3.12** 와 pip 으로 설치한다. 꾸러미를 PyPI 에서 받으므로 인터넷이 필요하다.

```bash
python3 -m venv ~/minedocscan-venv
. ~/minedocscan-venv/bin/activate
pip install "./mine-docscan[postgres]"
minedocscan --version
```

- `./mine-docscan` 은 받은 소스 폴더다. 통합 DB 에 싣지 않으면 `[postgres]` 없이 `pip install ./mine-docscan`.
- 숫자 인식기를 **학습**할 PC 라면 `[train]` 도 더한다 (torch — 크다). 학습한 모델을 읽는 데는 필요 없다. 윈도우 묶음에는 들어 있지 않다.
- 설정 파일: 소스 폴더의 `config/minedocscan.example.toml` 을 복사해 고치고, 환경 변수 `MINEDOCSCAN_CONFIG` 로 그 파일을 가리킨다.
  없으면 명령을 돌리는 폴더의 `minedocscan.toml` 을 읽는다. 무엇을 적는지는 [3장](3-처음-설정.md#설정-파일)과 같다.
- 화면: `minedocscan serve --reviewer jp --log-dir ~/minedocscan-logs`. 로그온할 때 저절로 켜는 것(시스템의 서비스 관리자 등)은
  그 PC 의 관리자가 정한다. 이 프로그램은 리눅스의 자동 시작을 만들지 않는다.
- 통합 DB 의 비밀번호: 같은 한 줄을 `~/.pgpass` 에 적고 `chmod 600 ~/.pgpass`. 남이 읽을 수 있는 파일은 libpq 가 쓰지 않는다.
- 지우기: 가상 환경 폴더(`~/minedocscan-venv`)를 지운다. 데이터 폴더는 그대로다.
