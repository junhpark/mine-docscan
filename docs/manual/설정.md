# 부록 — 설정 목록

minedocscan 의 설정은 네 곳에서 온다. 같은 설정이 여러 곳에 있으면 **위의 것이 이긴다.**

1. **명령의 선택** — `--site`, `--work-root` … (그 명령을 칠 때 한 번만)
2. **환경 변수** — `MINEDOCSCAN_…`
3. **설정 파일** — `minedocscan.toml`
4. **기본값** — 아래 표의 "기본값"

통합 DB 의 주소(`MINEDOCSCAN_PUBLISH_URL`)만은 **환경 변수로만** 받는다. 설정 파일에 적으면 오류다.

현장에 관한 것(템플릿, 파일 이름의 날짜 규칙, 장비명 대응표 …)은 이 설정이 아니라 사이트 팩의 `site.toml` 에 적는다 —
[아래](#사이트-팩의-sitetoml).

지금 쓰고 있는 값은 `minedocscan info` 가 보여 준다. 통합 DB 는 서버와 DB 이름만 보여 주고 주소 전체와 비밀번호는 찍지 않는다.

```powershell
minedocscan info
```

## 설정 파일

- **자리**: `--config` 를 주면 그 파일, 주지 않으면 환경 변수 `MINEDOCSCAN_CONFIG` 의 파일, 그 변수도 없으면 명령을 친 폴더의
  `minedocscan.toml`. 셋 가운데 처음 정해진 하나만 본다 — 그 파일이 없다고 다음 것을 찾지는 않는다.
  윈도우 설치는 `%APPDATA%\minedocscan\minedocscan.toml` 을 쓰고, 사용자 환경 변수 `MINEDOCSCAN_CONFIG` 가 그 파일을 가리킨다
  ([2. 설치](2-설치.md)). 파일이 없으면 오류 없이 기본값으로 돈다 — 경로를 잘못 적었는지 `minedocscan info` 로 확인한다.
- **보기**: 설치 묶음의 `minedocscan.example.toml` (저장소의 `config/minedocscan.example.toml`). 키마다 설명이 붙어 있다.
- **형식**: TOML, UTF-8. `#` 뒤는 설명이다.
- **윈도우 경로는 작은따옴표로** 싼다: `site = 'D:\minedocscan\site'`. 큰따옴표로 싸면 `\` 를 두 번 적어야 한다
  (`"D:\\minedocscan\\site"`) — 한 번이면 대개 "설정 파일을 읽을 수 없습니다 … Unescaped '\' in a string" 오류다 (`\n`·`\t` 처럼 읽히는
  짝은 오류 없이 다른 글자가 된다). `"D:/minedocscan/site"` 처럼 `/` 로 써도 된다.
- **경로는 절대 경로로** 적는다. 상대 경로는 설정 파일이 있는 폴더가 아니라 명령을 친 폴더에서 센다.
- **값이 틀리면** 명령이 한 줄로 알리고 끝난다. 예: `설정 오류: [pipeline] dup_min_sim 는 0.0 이상 1.0 이하: 1.5`.
  모르는 키(오타)는 알리지 않고 지나간다 — 고친 뒤에는 `minedocscan info` 로 값이 바뀌었는지 본다.
- **고친 뒤에는** `serve` 를 다시 띄운다. 돌고 있는 `serve` 는 켤 때 읽은 설정을 쓴다. 작업 스케줄러가 띄운 `serve` 는 작업을 멈췄다가
  켜면(`Stop-ScheduledTask`·`Start-ScheduledTask -TaskName minedocscan-serve` — [2. 설치](2-설치.md#작업-스케줄러의-serve)) 새 설정으로 뜬다. 다른 명령은 칠 때마다
  설정을 읽는다. 환경 변수를 바꿨을 때는 아래 [환경 변수](#환경-변수)를 본다.

`install.ps1` 이 처음 쓰는 설정 파일에는 `[paths]` 의 `site`·`archive_root`·`work_root`·`inbox` 와 `[export] excel_dir` 만 있다
(`-Inbox`·`-ExcelDir` 를 주었을 때 — 보기는 [3. 처음 설정](3-처음-설정.md#설정-파일)).
나머지 키는 적지 않으면 기본값이다. 아래 표에서 "범위"는 받는 값의 범위다 — 벗어나면 설정 오류다.

### `[paths]` — 폴더

| 키 | 기본값 | 뜻 | 다른 곳 |
|---|---|---|---|
| `site` | 없음 | 사이트 팩 폴더. 없으면 처리·화면이 돌지 않는다 | `MINEDOCSCAN_SITE`, `--site` |
| `archive_root` | 없음 | 보관 폴더 — 원본 스캔. 프로그램은 그 아래 `intake\` 에만 쓰고 나머지는 읽기만 한다. 접수 폴더를 쓰려면 있어야 한다 | `MINEDOCSCAN_ARCHIVE_ROOT`, `--archive-root` |
| `work_root` | `work` (명령을 친 폴더 아래) | 작업 폴더 — 작업 DB, 정합 그림, 리포트. 이 PC 의 디스크에 둔다 (동기화 폴더·네트워크 드라이브 밖). 꼭 적는다 | `MINEDOCSCAN_WORK_ROOT`, `--work-root` |
| `inbox` | 없음 (접수하지 않는다) | 접수 폴더 — 스캐너 프로그램이 저장하는 폴더. `watch`·`serve` 가 지켜본다. 보관 폴더·작업 폴더·사이트 팩과 겹치면(안이거나 그것을 품으면) 시작하지 않는다. 없는 폴더면 만든다 | `MINEDOCSCAN_INBOX` |
| `reviews` | `<사이트 팩>\reviews\reviews.jsonl` | 검수 기록 파일. 결정 기록 `decisions.jsonl` 은 그 옆에 둔다. 사이트 팩 안 그대로 두는 것이 좋다 (같이 백업된다) | `MINEDOCSCAN_REVIEWS` |

### `[database]` — 작업 DB

| 키 | 기본값 | 뜻 | 다른 곳 |
|---|---|---|---|
| `url` | `sqlite:///<work_root>/minedocscan.db` | 작업 DB 의 주소. SQLite 만 받는다. 통합 DB 가 아니다 — 통합 DB 는 [`[publish]`](#publish--통합-db) | `MINEDOCSCAN_DB_URL`, `--db-url` |

### `[pipeline]` — 처리

| 키 | 기본값 | 범위 | 뜻 |
|---|---|---|---|
| `dpi` | `200` | 50–1200 | 템플릿 좌표계의 해상도. 템플릿을 만든 해상도와 같아야 한다 — 바꾸지 않는다 |
| `auto_accept_conf` | `0.90` | 0–1 | 인식기의 신뢰도가 이 이상이면 검수 없이 넣는다. 숫자 인식기 모델에 기준이 있으면 그것을 먼저 쓴다 ([`[recognize.digits]`](#recognize--인식기)) |
| `classify_min_margin` | `1.5` | 0 이상 | 양식 분류에서 1위와 2위 점수의 비율이 이보다 낮은 쪽을 처리 요약과 `pages --low-margin`·`report --by-month` 에 따로 적는다. 적재는 그대로다 |
| `save_aligned` | `true` | true·false | 정합 그림을 작업 폴더의 `aligned` 에 저장한다. 검수 화면은 보통 원본(보관 폴더)에서 칸을 자르고, 원본에 닿지 못하면 이 그림을 쓴다 — `false` 면 그때 칸 그림이 나오지 않는다. `true` 로 둔다 |
| `damaged_pdf` | `"fail"` | `fail`·`warn` | 끝 표시(`%%EOF`)가 마지막 1 KB 에 없는 PDF(전송 중 잘린 파일 등). `fail` 은 그 문서를 실패로, `warn` 은 열리면 처리하고 경고를 남긴다. 멀쩡한 스캔이 늘 "PDF 의 끝 표시(%%EOF)가 없습니다"로 실패하는 스캐너면 `warn`. 열리지 않는 PDF 는 어느 쪽이든 실패다. 환경 변수 `MINEDOCSCAN_DAMAGED_PDF` |
| `blank_max_ink` | `0.02` | 0–1 | 양식을 못 찾은 쪽 가운데 어두운 화소가 이 비율보다 적으면 빈 쪽(양면 스캔의 뒷면)으로 본다 |
| `dup_min_sim` | `0.80` | 0–1 | 같은 날·같은 양식의 먼저 들어온 쪽과 손글씨 자리가 이만큼 비슷하면 "다시 스캔 의심 쪽"으로 붙잡는다 |

`blank_max_ink`·`dup_min_sim` 의 값을 왜 그렇게 정했는지는 [ARCHITECTURE.md](../ARCHITECTURE.md)와 `config.py` 의 주석에 있다.
현장에서 바꾸기 전에 관리자가 그 근거를 본다.

### `[intake]` — 접수 폴더 감시

`watch`·`serve` 가 접수 폴더(`[paths] inbox`)를 볼 때 쓴다.

| 키 | 기본값 | 범위 | 뜻 |
|---|---|---|---|
| `settle_seconds` | `5` | 0 이상 | 수정 시각이 이만큼 지나고 열리는 파일만 가져온다 (스캐너가 다 쓰기를 기다린다). `watch --settle-seconds` |
| `give_up_seconds` | `120` | 0 이상 | 이만큼 지나도 다 쓰이지 않은 파일(열리지 않는다, PDF 의 끝 표시가 없다)은 `damaged_pdf` 대로 등록한다. 읽을 수조차 없으면 접수 폴더의 `_failed` 로 옮긴다. `watch --give-up-seconds` |
| `poll_seconds` | `3` | 0.1 이상 | 접수 폴더를 훑는 간격 (초) |

### `[export]` — 엑셀 폴더

`watch`·`serve` 가 처리를 한 바퀴 마칠 때마다 바뀐 날짜의 일별·월별 엑셀만 다시 쓴다. `excel_dir` 가 없으면 이 자동 내보내기는 꺼져 있다
(홈의 내려받기와 명령 `export excel` 은 된다).

| 키 | 기본값 | 범위 | 뜻 |
|---|---|---|---|
| `excel_dir` | 없음 (자동 내보내기 꺼짐) | 폴더 | 엑셀 폴더. **있는 폴더**여야 한다 (만들지 않는다). 접수 폴더·보관 폴더 안이면 켜지 않는다. 사이트 팩의 `[site] name` 이 있어야 켜진다. 환경 변수 `MINEDOCSCAN_EXCEL_DIR`, 명령 `export excel` 의 폴더 인자 |
| `sweep_minutes` | `30` | 0 이상 | 전체 훑기의 간격 (분). 다른 프로그램이 쓴 검수나 놓친 것을 잡는다. `0` 이면 켤 때만 |
| `retry_seconds` | `60` | 0 이상 | 바꾸지 못한 엑셀 파일(엑셀이 그 파일을 열고 있다)을 다시 써 보는 간격 (초). 그 사이의 바퀴는 그 파일을 건너뛴다 |
| `machine_values` | `false` | true·false | `true` 면 업무 시트에 "기계 값(확정 아님)" 열을 따로 둔다. 기본은 확정된 값만 싣는다 |

### `[publish]` — 통합 DB

통합 DB(현장 서버의 PostgreSQL)로 싣는 설정이다. **주소는 환경 변수 `MINEDOCSCAN_PUBLISH_URL` 로만 준다.** 주소에는 비밀번호를 넣지 않고
(`postgresql://계정@서버/DB`), 비밀번호는 PostgreSQL 의 비밀번호 파일(pgpass)에 둔다 ([2. 설치](2-설치.md#통합-db-의-비밀번호)).
`[publish]` 에 `url`·`dsn`·`password`·`conninfo` 를 적으면 설정 오류다. 주소가 없으면 싣기는 꺼져 있다. 사이트 팩의 `[site] name` 이
없어도 꺼진다.

| 키 | 기본값 | 범위 | 뜻 |
|---|---|---|---|
| `schema` | `"minedocscan"` | 영문 소문자·숫자·밑줄 (63자 안, 숫자로 시작하지 않는다) | 실을 스키마. 환경 변수 `MINEDOCSCAN_PUBLISH_SCHEMA` |
| `enabled` | 적지 않음 = 주소가 있으면 켜짐 | true·false | `false` 면 주소가 있어도 `watch`·`serve` 가 싣지 않는다. 명령 `publish` 는 돈다 |
| `sweep_minutes` | `30` | 0 이상 | 전체 훑기의 간격 (분). `0` 이면 켤 때만 — 그 사이에는 바뀐 문서·날짜만 싣는다 |
| `connect_timeout_s` | `5` | 1–600 | 연결을 기다리는 시간 (초) |
| `lock_timeout_s` | `5` | 1–600 | 연결한 뒤 대상의 잠금을 기다리는 시간 (초). 넘기면 그 바퀴의 싣기만 그만둔다 — 접수·처리는 계속된다 |
| `statement_timeout_s` | `60` | 1–3600 | 대상의 문장 하나를 기다리는 시간 (초). 넘기면 같다 |
| `retry_seconds` | `60` | 0 이상 | 싣기에 실패한 뒤(연결이 안 된다, 판이 다르다 …) 이만큼은 다시 연결하지 않는다 |

### `[recognize]` — 인식기

| 키 | 기본값 | 뜻 |
|---|---|---|
| `backend` | `"null"` | 손글씨를 읽는 인식기. `null` = 읽지 않는다 (글씨가 있는 칸은 모두 검수 대기). `digits` = 숫자 인식기 (모델이 있어야 한다). `oracle` = 시험용 (정답 파일을 그대로 돌려준다 — 현장에서 쓰지 않는다). 명령 `run --recognizer` |

칸 종류마다, 모델마다 고르는 표가 셋 있다. 모델을 학습하고 고르는 순서는 [DATA.md](../DATA.md#숫자-인식기-학습에서-평가까지)에 있다.

| 표 | 키 | 뜻 |
|---|---|---|
| `[recognize.by_kind]` | `handwritten_number`, `handwritten_text` | 칸 종류마다 다른 인식기. 보기: `handwritten_number = "digits"` — 숫자 칸만 숫자 인식기로 읽고 글자 칸은 `backend` 로 |
| `[recognize.digits]` | `model` | 숫자 인식기 모델 — 사이트 팩 `models` 폴더 안의 모델 이름이나 모델 폴더의 경로. `digits` 를 쓰는데 모델이 없으면 처리가 시작할 때 멈춘다. 사이트 팩 `site.toml` 의 같은 키보다 이 설정 파일이 이긴다 |
| `[recognize.digits]` | `auto_accept_conf` | (선택) 모델 카드의 자동 적재 기준 대신 쓸 값 (0–1). 우선순위: 이것 > 모델 카드 > `[pipeline] auto_accept_conf` |
| `[recognize.meta]` | `vehicle_no`, `operator`, `date.month`, `date.day` | 표 밖 필드(차량번호·작성자·손으로 쓴 월·일)를 읽는 모델의 이름 — "메타 키 = 모델 이름". 적지 않은 키는 라벨·검수로만 정한다. 월·일은 쪽의 날짜와 대조만 한다. `site.toml` 의 같은 표보다 이 설정 파일이 이긴다 |

`[recognize.meta]` 에서 `date.month` 처럼 점이 든 키는 큰따옴표로 싸도(`"date.month" = …`) 싸지 않아도 같다. 이 표에는
"메타 키 = 모델 이름" 만 쓴다 — `auto_accept_conf`·`model`·`threshold` 를 쓰면 설정 오류다.

| 키 | 기본값 | 뜻 |
|---|---|---|
| `backend` | `"none"` | 인식한 값의 교정기. 지금은 `none`(교정하지 않는다) 하나뿐이다. 명령 `run --corrector` |

### `[review]` — 검수 화면

| 키 | 기본값 | 범위 | 뜻 |
|---|---|---|---|
| `source_dpi` | `300` | 50–1200 | 검수 화면과 크롭 내보내기에서 원본 PDF 를 다시 그리는 해상도. 스캔한 해상도와 같게 둔다 |

## 설정 파일에 없는 것 — 명령의 선택

몇 가지는 설정 파일이 아니라 명령의 선택으로만 준다. 모든 선택은 [부록 — 명령 목록](명령.md)에 있다.

| 선택 | 명령 | 기본값 | 뜻 |
|---|---|---|---|
| `--reviewer` | `serve`, `review serve`, `doc date` … | 없음 | 검수자 ID (짧은 영문). 검수·결정 기록마다 남는다. `serve` 는 이것이 없으면 뜨지 않는다 |
| `--port` | `serve`, `review serve` | `8765` | 화면의 포트. 바탕 화면의 바로 가기는 8765 를 연다 |
| `--log-dir` | `serve` | 없음 (창에 찍는다) | 출력을 그 폴더의 `serve-YYYYMMDD.log`(UTF-8, 날마다 새 파일, 30일 지난 것은 지운다)에 쓴다 |
| `--no-watch` | `serve` | 꺼짐 | 접수·처리를 하지 않고 화면만 띄운다 |
| `--settle-seconds`, `--give-up-seconds` | `watch` | `[intake]` 의 값 | 위 `[intake]` 의 같은 이름 |
| `--recognizer`, `--corrector` | `run` | `[recognize]`·`[correct]` 의 값 | 위의 `backend` |
| `--config`, `--site`, `--archive-root`, `--work-root`, `--db-url` | 대부분의 명령 | — | 설정 파일·환경 변수의 같은 설정을 그 명령에서만 바꾼다 |

윈도우 설치는 작업 스케줄러의 `minedocscan-serve` 에 `serve --config … --reviewer … --log-dir <설치 폴더>\logs` 를 적어 둔다.
검수자를 바꾸려면 `install.ps1` 을 새 `-Reviewer` 로 다시 돌린다 ([2. 설치](2-설치.md#작업-스케줄러의-serve)).

## 환경 변수

빈 값이면 없는 것으로 본다 (`MINEDOCSCAN_CONFIG` 도 — 빈 값이면 지금 폴더의 `minedocscan.toml` 을 찾는다).

| 환경 변수 | 같은 설정 | 뜻 |
|---|---|---|
| `MINEDOCSCAN_CONFIG` | — | 설정 파일의 자리. 윈도우 설치가 사용자 환경 변수로 넣는다 |
| `MINEDOCSCAN_SITE` | `[paths] site` | 사이트 팩 폴더 |
| `MINEDOCSCAN_ARCHIVE_ROOT` | `[paths] archive_root` | 보관 폴더 |
| `MINEDOCSCAN_WORK_ROOT` | `[paths] work_root` | 작업 폴더 |
| `MINEDOCSCAN_INBOX` | `[paths] inbox` | 접수 폴더 |
| `MINEDOCSCAN_REVIEWS` | `[paths] reviews` | 검수 기록 파일 |
| `MINEDOCSCAN_DB_URL` | `[database] url` | 작업 DB 의 주소 |
| `MINEDOCSCAN_DAMAGED_PDF` | `[pipeline] damaged_pdf` | `fail` 또는 `warn` |
| `MINEDOCSCAN_EXCEL_DIR` | `[export] excel_dir` | 엑셀 폴더 |
| `MINEDOCSCAN_PUBLISH_URL` | **없음 — 환경 변수로만** | 통합 DB 의 주소 `postgresql://계정@서버/DB`. 비밀번호는 넣지 않는다 (pgpass). 로그·화면·`info` 에는 서버와 DB 이름만 나온다 |
| `MINEDOCSCAN_PUBLISH_SCHEMA` | `[publish] schema` | 통합 DB 의 스키마 |

윈도우에서는 **사용자 환경 변수**로 둔다. PowerShell 에서:

<!-- 시험: 돌리지 않음 -->
```powershell
[Environment]::SetEnvironmentVariable('MINEDOCSCAN_PUBLISH_URL', 'postgresql://계정@서버/DB', 'User')
```

`계정`·`서버`·`DB` 는 우리 것으로 바꾼다. 윈도우 설정에서 "환경 변수"를 찾아 사용자 변수에 넣어도 된다. 바꾼 값은 **새로 연 창**부터 보이고,
작업 스케줄러가 띄우는 `serve` 는 로그오프했다가 다시 로그온하면 읽는다. 지우려면 값 자리에 `$null` 을 준다.
리눅스에서는 셸의 시작 파일에 `export MINEDOCSCAN_PUBLISH_URL=…` 를 적는다.

## 사이트 팩의 `site.toml`

사이트 팩 폴더의 `site.toml` 은 현장에 관한 옵션이다 — 어느 PC 에서 돌려도 같아야 하는 것. 설정 파일과 달리 환경 변수로 바꾸지 않는다.
형식과 보기는 [SITE_PACK.md](../SITE_PACK.md#sitetoml)에 있다. 고친 뒤에는 `serve` 를 다시 띄우고 `minedocscan info` 로 본다.

| 표 | 키 | 기본값 | 뜻 |
|---|---|---|---|
| `[site]` | `name` | 없음 — **적는다** | 사이트의 짧은 이름 (보기: `synthetic`). 엑셀 폴더의 기록 파일과 통합 DB 에 "어느 사이트의 사본인지"로 적힌다. 다른 이름의 폴더·대상에는 쓰지도 지우지도 않는다. 없으면 엑셀 자동 내보내기와 통합 DB 싣기가 꺼지고 `export excel`·`publish` 가 거절한다. 처음 적을 때는 [3. 처음 설정](3-처음-설정.md#사이트-이름을-적는다), 바꿀 때는 [5. 관리](5-관리.md#사이트-이름을-바꿀-때)의 순서대로 |
| `[site]` | `title` | 없음 | 사람이 읽는 이름. 프로그램은 쓰지 않는다 |
| `[ingest]` | `date_from_filename` | 없음 | 파일 이름에서 날짜를 뽑는 정규식 (이름 있는 묶음 `yyyy` 또는 `yy`, `mm`, `dd`). 없거나 맞지 않는 이름의 문서는 "날짜를 정할 문서"가 되어 사람이 날짜를 넣을 때까지 기다린다 |
| `[eval]` | `split_salt` | `[site] name` (없으면 폴더 이름) | 평가셋(test 날짜)을 나누는 소금값. 바꾸면 평가셋이 바뀐다. `[site] name` 을 처음 적거나 바꾸기 **전에** 지금 쓰이는 값을 여기에 적는다 — `minedocscan info` 가 그 값을 알려 준다 |
| `[eval]` | `test_share` | `0.2` | test 로 떼어 둘 날짜의 몫 |
| `[equipment.iso_type]` | 현장의 장비 구분 | 없음 | 현장의 장비 구분 → ISO 23725 장비 유형. 확인하지 못한 구분은 적지 않는다 |
| `[equipment.aliases]` | 적힌 장비명 | 없음 | 가동 일보에 손으로 적는 장비명 → 장비 키 (점검표 템플릿의 장비 행). 적힌 이름 그대로만 맞춘다. 마스터에 없는 키를 가리키면 사이트 팩이 열리지 않는다 |
| `[haul]` | `trips_max` | 없음 (보지 않는다) | 운반 횟수의 상한. 이보다 큰 값은 인식기가 확신해도 검수로 보낸다 |
| `[crosscheck.haul]` | `exclude_materials` | `[]` | 교차검증에서 뺄 광종 (한쪽 양식에만 있는 행) |
| `[haul_table]` | `columns`, `slots` | 템플릿의 행 순서, 자리 이름 순 | 월별 엑셀의 운반 표에서 광종·편 열과 자리 블록의 순서. 적지 않은 것은 기본 순서로 뒤에 붙는다. 적는 꼴은 SITE_PACK.md |
| `[redact]` | `meta_keys` | `["operator", "vehicle_no"]` | 가린 쪽 그림에서 가릴 표 밖 필드의 메타 키. 적으면 기본을 바꾼다 (더하는 것이 아니다). 템플릿에 없는 키(오타)면 사이트 팩이 열리지 않는다 |
| `[redact]` | `pad_px` | `48` | 표 밖 필드와 가릴 상자를 사방으로 넓히는 폭 (화소, 0–200) |
| `[recognize.digits]` | `model` | 없음 | 숫자 인식기 모델. 설정 파일의 같은 키가 이긴다 |
| `[recognize.meta]` | 메타 키 | 없음 | 표 밖 필드의 모델. 설정 파일의 같은 표가 이긴다 |

`site.toml` 의 값이 틀리면(문법, 목록이 아니다, 겹치는 항목, `[haul_table]`·`[redact]` 의 모르는 키 …) 사이트 팩을 열 때 설정 오류 한 줄로
알린다. 다른 표의 모르는 키(오타)는 알리지 않고 지나간다. 장비명 대응표의 오류에는 몇 번째 항목인지만 나오고 이름·번호는 찍지 않는다.
