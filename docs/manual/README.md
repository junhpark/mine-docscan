# minedocscan 사용 설명서

minedocscan 1.0.0 의 사용 설명서다. minedocscan 은 광산 현장에서 손으로 쓴 문서를 스캔하면 양식을 알아보고, 칸마다 값을 뽑아
데이터베이스에 넣는 프로그램이다. 확실하지 않은 값은 사람이 화면에서 보고 넣는다.

## 누가 어느 장을 읽는가

- **현장 담당자** — 문서를 스캔하고, 홈에서 날짜와 다시 스캔을 정하고, 검수 대기열에서 값을 넣고, 엑셀을 여는 사람.
  1장으로 전체를 한 번 보고, 4장을 곁에 둔다. 홈에 모르는 것이 보이면 6장을 본다.
- **관리자** — 설치, 설정, 템플릿, 통합 DB 를 맡는 사람. 처음에는 1장 → 2장 → 3장 순서로 설치하고, 현장 담당자와 4장을 한 번 같이 해 본다.
  사이트 팩에 템플릿이 아직 없으면 3장 다음에 7장으로 템플릿부터 만든다. 그다음 5장(백업·다시 처리)과 7장(새 양식). 부록은 찾아볼 때 본다.

설명서는 **순서와 화면**을 적는다. 규칙과 그 이유는 저장소의 문서에 있다 — 양식 정의는 [SITE_PACK.md](../SITE_PACK.md),
데이터의 자리와 지킬 것은 [DATA.md](../DATA.md), 프로그램의 구조는 [ARCHITECTURE.md](../ARCHITECTURE.md).
설치 묶음에는 저장소가 들어 있지 않다. 그 문서들은 저장소의 `docs/` 폴더에서 본다.

## 글의 약속

### 자리표시 `<…>`

꺾쇠로 싼 말은 자기 것으로 바꿔 친다. 꺾쇠는 지운다. 예를 들어 `minedocscan doc date <문서 ID> <날짜> --reviewer <검수자>` 는
`minedocscan doc date 1582ec6d99d57ca4 2030-01-07 --reviewer jp` 처럼 친다.

| 자리표시 | 무엇 | 보기 |
|---|---|---|
| `<사이트 팩>` | 사이트 팩 폴더 (템플릿·현장 옵션·검수 기록) | `D:\minedocscan\site` |
| `<보관 폴더>` | 보관 폴더 (원본 스캔) | `D:\minedocscan\archive` |
| `<작업 폴더>` | 작업 폴더 (작업 DB) | `D:\minedocscan\work` |
| `<접수 폴더>` | 스캐너 프로그램이 저장하는 폴더 | `C:\Scans` |
| `<엑셀 폴더>` | 엑셀 폴더 (일별·월별 파일) | `D:\minedocscan\excel` |
| `<출력 폴더>` | 명령이 결과를 쓸 새 폴더 (없으면 명령이 만든다) — 쓸 때마다 다른 폴더를 준다 | `D:\minedocscan\out\masked-0107` |
| `<문서 ID>` | 문서마다 붙는 16자리 ID (홈과 `doc list` 에 보인다) | `1582ec6d99d57ca4` |
| `<쪽 ID>` | 쪽의 ID — 문서 ID 뒤에 `-p` 와 쪽 번호 | `1582ec6d99d57ca4-p3` |
| `<날짜>` | 작업한 날 (해-달-날) | `2030-01-07` |
| `<달>` | 작업한 달 (해-달) | `2030-01` |
| `<양식>` | 사이트 팩에 있는 템플릿의 이름 | `fuel_log` |
| `<새 양식>` | 새로 만들 템플릿의 이름 (영문 소문자·밑줄) | `fuel_log_draft` |
| `<기준 이미지>` | 빈 양식을 스캔한 그림 (PNG) | `D:\minedocscan\blank-fuel-log.png` |
| `<검수자>` | 검수자 ID (짧은 영문 — 검수·결정 기록에 남는다) | `jp` |
| `<표 둘레>` | 기준 이미지에서 표의 둘레 `x0,y0,x1,y1` (화소) | `90,410,1564,1030` |

### 명령 보기

회색 상자 안의 `minedocscan …` 줄은 PowerShell 창(윈도우)이나 터미널(리눅스)에 한 줄씩 친다.

```powershell
minedocscan doc list --status needs_date      # 날짜를 정할 문서의 목록
```

- 줄 끝의 `#` 뒤는 설명이다. 치지 않아도 된다 (쳐도 PowerShell 과 터미널은 읽지 않는다).
- 윈도우에 설치한 뒤 **새로 연** PowerShell 창이면 어느 폴더에서 쳐도 된다. 설정 파일이 폴더들의 자리를 알려 준다
  (사용자 환경 변수 `MINEDOCSCAN_CONFIG` — [부록 — 설정 목록](설정.md)). 그래서 보기의 명령에는 폴더 경로가 거의 없다.
- 명령의 출력에 보이는 이름·날짜·수는 합성 데모의 것이다. 우리 현장에서는 다르게 나온다.

### 화면 갈무리

설명서의 화면 그림은 모두 **합성 데모**에서 찍었다. 프로그램이 스스로 만든 가짜 현장(사이트 이름 `synthetic`, 검수자 `demo`, 자리 `T01` …)이고
실제 현장의 문서·이름·차량번호는 없다. 우리 현장의 화면은 같은 자리에 실제 값이 보인다.

**우리 현장의 화면 갈무리, 엑셀 파일, 로그 파일을 이슈·메일·문서에 붙이지 않는다** — 작업자 이름, 서명, 차량번호가 들어 있는 현장 데이터다.
물어볼 것이 있으면 수와 화면의 글(예: "날짜를 정할 문서 1")을 옮긴다. 보내도 되는 것과 보내지 않는 것은
[6장의 "물어볼 때"](6-문제-해결.md#물어볼-때)에 있다.

### 한 장짜리 HTML 과 PDF

설치 묶음(zip)을 푼 폴더에 `manual.html` 이 있다. 이 설명서 전체를 그림까지 담은 한 파일이라 인터넷 없이 브라우저로 열린다.
장 사이의 링크도 그 파일 안에서 이어진다. 저장소의 다른 문서(SITE_PACK.md …)를 가리키는 링크는 글로만 남는다.

PDF 가 필요하면 `manual.html` 을 브라우저(Edge·Chrome)로 열고 인쇄(Ctrl+P)에서 프린터를 "PDF로 저장"으로 고른다.
장마다 새 쪽에서 시작한다.

### 설명서를 고치는 사람에게

- 명령 보기는 시험이 실제로 돌린다 (`tests/test_manual.py`, `pytest -m slow`). 합성 데모를 만들어 한 바퀴 처리한 뒤, 코드 블록 안에서
  `minedocscan` 으로 시작하는 줄을 장 파일의 이름 순서대로 돌리고 종료 코드 0 을 본다. 자리표시는 위 표의 것만 쓴다.
- 돌릴 수 없는 블록은 블록 바로 앞 줄에 `<!-- 시험: 돌리지 않음 -->` 을 둔다 (화면에는 보이지 않는다). 오래 도는 `serve`, 통합 DB·실데이터·
  모델이 있어야 하는 것, 사람이 YAML 을 고친 뒤의 명령, 종료 코드가 0 이 아닐 수 있는 것(`publish --check`, `regress`), PowerShell·윈도우
  경로가 든 줄, 그리고 `minedocscan` 으로 시작하는 줄이 든 출력 보기가 그렇다.
- [부록 — 명령 목록](명령.md)은 손으로 고치지 않는다 — `python scripts/cli_reference.py` 가 만든다. [부록 — 설정 목록](설정.md)은 설정 키를 빠짐없이
  적었는지 시험이 본다.
- 화면 그림은 `python scripts/manual_shots.py` 가 합성 데모로 다시 찍는다 (`img/`, 전체 3 MB 안). `manual.html` 은
  `python scripts/manual_html.py --out manual.html` 이 만든다.
