## 0. 이 문서를 쓰는 법

> `CLAUDE.md` 와 `docs/tasks/0008-export.md` 를 읽고 단계 1부터 7까지 이어서 진행해. 다 끝나면 PR 을 하나 열고 결과를 보고해.

- **PR 은 하나다.** 브랜치 `feat/export` 에서 단계 1–7 을 한 번에 한다.
- **단계마다 커밋 하나**(커밋 제목에 단계 번호), 단계마다 `pytest` 와 `ruff check .` 가 통과한 상태로 커밋한다. 문서는 마지막 커밋으로 따로.
- 단계 사이에 멈추지 않는다. 다만 4절을 바꿔야 하거나 수용 기준을 충족할 수 없으면 거기서 멈추고 묻는다.
- **이 작업은 파이프라인의 결과를 바꾸지 않는다.** 분류·정합·판정·핸들러·처리의 단위는 그대로다. DB 에서 **밖으로 나가는 길**을 만든다.
  지금의 합성 묶음의 바이트, `null` 리포트, DB 의 행, 실데이터 회귀(`regress`)의 수치는 하나도 달라지지 않아야 한다. 달라지면 멈추고 묻는다.
  - 다만 처리와 검수 저장이 **무엇을 건드렸는지 알리는 것**(문서 ID·날짜·장비를 돌려주거나 훅으로 넘기는 것)은 더해도 된다 (4.7). DB 의 행은 그대로여야 한다.
- **스키마를 건드리지 않는다** (버전 8, `schema.sql` 의 문 그대로). 내보내기의 기록은 DB 가 아니라 내보낸 곳에 둔다 (4.6, 4.8) —
  "지금의 DB = 처음부터 만든 DB"(0007 의 불변식)를 깨지 않게.
- **실데이터와 통합 DB 서버는 작업 환경에 없다.** 수용 기준은 전부 합성 데이터로 잡았다. 1절의 수치는 실제 3일치(83쪽)로 미리 재 본 것이고
  (값·이름 없이 수만), 현장에서 해 보는 일은 8절에 사람의 일로 적었다.
- **새 의존성은 둘이다.** `openpyxl`(엑셀 쓰기 — 순수 파이썬, 기본 의존성)과 `psycopg`(PostgreSQL — 선택 의존성 `[postgres]`, 그 모듈 안에서만 import).
- PostgreSQL 시험: 작업 환경에 서버가 있으면(우분투의 `/usr/lib/postgresql/16/bin` — `postgres` 사용자로 `initdb` → `pg_ctl start`, 127.0.0.1 의 임시 포트)
  그것으로 돌리고, CI 에는 서비스 컨테이너(`postgres:16`)를 쓰는 작업을 하나 더한다. 서버가 없으면 그 시험은 건너뛴다 (6절).
- 시작하기 전에 `pip install -e ".[dev,postgres]"` 를 이 체크아웃에서 다시 한다 (편집 설치가 다른 체크아웃을 가리키고 있을 수 있다).

## 1. 왜 하는가

스캔한 종이는 이제 사람이 명령을 치지 않아도 업무 테이블까지 간다 (0007). 그런데 **그 결과를 볼 길이 명령줄과 검수 화면뿐이다.**
선행 연구에서 이어받은 요구사항 둘이 남아 있고(PRIOR_WORK.md), 2단계가 읽어 갈 자리가 아직 없다.

**(가) 현장 사용자는 결과를 엑셀로 확인한다.** DB 가 원본이고 엑셀은 내보낸 사본이다 — 그 내보내기가 없다.
- 실제 하루치(30쪽, 필드 3,713개)를 `openpyxl` 로 써 보았다: 양식 모양 시트(쪽마다 표)와 업무 표를 합쳐 시트 12장, 칸 38,513개, **0.3초, 123 KB**.
  사흘 모두 같았다 (0.30–0.38초, 97–123 KB). 느리지 않다 — 처리가 끝날 때마다 써도 된다.
- **같은 내용을 두 번 쓰면 파일의 바이트가 다르다** (xlsx 는 zip 이고 안에 만든 시각이 들어간다). "바뀌었나"는 파일이 아니라 내용의 해시로 본다 (4.6).
- 날짜 하나의 내용(그날의 필드·업무 행)을 읽어 해시만 내는 데 45 ms 다 — 300일이면 14초. 바뀐 날짜만 다시 보고, 전체는 가끔 훑는다 (4.7).
- 현장은 이 종이들(차량별 일보)을 보고 월별 작업일보 엑셀의 입력 시트에 손으로 옮겨 적는다. 그 시트의 모양은
  **행 = 날짜 × 주·야, 열 = 차량마다 한 블록 × 편(광종)** 이다. 업무 테이블(`prod_haul`)에는 같은 축이 다 있다:
  실제 3일치에서 일보의 행 1,500개(날짜 × 자리 30 × 광종·편 25 × 주·야 2), 키(날짜·자리·광종·편·주야)가 겹치는 것 0, 자리 10.
  같은 모양의 표를 내보내면 옮겨 적는 일이 견주는 일이 된다 (4.4). 그 엑셀을 고치는 것은 2단계의 일이다 — 여기서는 표만 낸다.
- 일보의 **자리(`slot`)는 교차검증이 날짜마다 정한다** (행렬의 열과 차량·작성자로). 그날 행렬 쪽이 없거나 차량·작성자를 아직 모르거나 같은 차량의
  일보가 한 장 더 있으면 그 쪽의 자리는 비어 있다. 실제 3일치는 라벨이 다 있어 0 이지만, 표는 "자리를 모르는 일보"를 잃지 않아야 한다 (4.4).
- 그 1,500행 중 값이 있는 칸은 133개이고 지금은 전부 검수 대기다 (숫자 인식기의 실데이터 모델이 아직 없다). 검수 대기인 행에도 기계가 낸 값이
  들어 있을 수 있다 (`prod_haul.trips`, `doc_field.value_final`). **확정되지 않은 값을 엑셀에 확정된 것처럼 실으면 안 된다** — 엑셀은 화면과 달리
  출처도 신뢰도도 보이지 않고, 현장은 그것을 그대로 옮겨 적는다 (4.2).
- 실제 템플릿의 열 이름은 전부 영문 식별자다 (일곱 양식, 열 62개 중 한글 0). 현장이 읽을 표시 이름이 템플릿에 없다 (4.5).
- 가동 기록 40행 가운데 같은 날 같은 장비가 두 장인 경우가 7건(14행)이다 — 표로 낼 때 합치면 안 된다 (ADR 0016).

**(나) 2단계가 읽어 갈 곳이 없다.** 2단계(통합 DB)는 현장 서버의 PostgreSQL 이고 이 저장소의 업무 테이블을 읽어 간다.
ADR 0005 는 "연결과 자리표시자만 바꾸면 되는 PostgreSQL 어댑터"를 남겨 두었다. 재 보니:
- `schema.sql` 은 PostgreSQL 16 에서 **그대로 돈다** (33문 중 실패 0). 실제 83쪽 DB 의 16,293행을 1.6초에 실었고, 같은 행을 다시 upsert 하는 데 0.6초,
  크기는 9.7 MB(3일치) — 1년이면 1 GB 안팎이다.
- **되읽으면 두 열이 다르다**: `doc_page.classify_margin`, `doc_field.ink`. PostgreSQL 의 `REAL` 은 4바이트다 (SQLite 는 8바이트). `INTEGER` 도 32비트다
  (SQLite 는 64비트). 싣는 쪽의 표는 형을 넓혀 만든다 (4.8).
- 조회문은 그대로 돌지 않는다: DB 를 부르는 곳이 154곳·24파일이고 전부 `?` 자리표시자와 sqlite3 의 행 객체에 기댄다. `SUM(비교식)` 4곳
  (PostgreSQL 은 불리언을 더하지 못한다), 트랜잭션·`PRAGMA`·`sqlite_master` 를 직접 만지는 곳 32곳. 그리고 0007 이 만든 것 — 쪽마다 커밋하는 `BEGIN IMMEDIATE`, WAL, DB 옆의 잠금 파일,
  홈이 보는 `PRAGMA data_version`, "`--fresh` 로 지우고 다시 만든다" — 은 전부 로컬 SQLite 파일을 전제로 한다.
- 이어받은 요구사항은 "외부 네트워크 없이 로컬에서 돈다. **DB 도 로컬**"이다. 서버가 꺼져도 스캔과 검수는 돌아야 한다.
- 그래서 **작업 DB 는 SQLite 그대로 두고, 통합 DB 에는 결과를 싣는다** (4.8). 문서 하나(30쪽)의 행을 읽어 지문(해시)을 내는 데 약 50 ms 다
  (문서 3건·15,440행에 0.14초 — 300일이면 14초) — 바뀐 문서만 갈아 끼우고, 전체는 가끔 훑는다.

**(다) 실제 양식의 그림을 밖에 보일 수 없다.** 발표·보고서에 쪽 그림을 쓰려면 이름·서명·차량번호를 가려야 한다 (이어받은 요구사항).
- 템플릿은 그 자리를 안다: 실제 일곱 양식 모두 표 밖 필드가 3–5개(쪽 넓이의 2–7 %), 넷에 `kind: signature`, 다섯에 `meta_key: operator`, 하나에 `vehicle_no`.
- **템플릿이 모르는 자리도 있다**: 행렬 양식의 머리 행에는 운전자·차량번호가 인쇄되어 있고(템플릿의 열에 `header_operator`·`header_vehicle_no` 로 적혀 있다),
  점검표에는 등록번호 열이 인쇄되어 있고, 작업 표의 글자 칸에는 이름을 쓰기도 한다 (CLAUDE.md "작업 표는 자유롭게 쓴다").
  가릴 자리를 템플릿에 더 적을 수 있어야 하고, 글자 칸은 기본으로 가린다 (4.9).

**(라) 0007 에 남긴 것.**
- **다시 스캔의 근거 수치가 낙관적이다.** 지시서 0007 의 "흔들어 다시 정합한 같은 종이 최소 0.91"은 한 번 뽑은 값이고, 서명의 정의도 그 뒤에 바뀌었다
  (표 밖 필드를 지운다). 지금의 서명으로 실제 83쪽(서명이 0 이 아닌 81쪽)에서 다시 쟀다:

  | 실제 3일치, 지금의 서명 | 수 | 유사도 |
  |---|---|---|
  | 같은 날, 같은 계열의 서로 다른 종이 | 286쌍 | 최대 0.593 (99 % 0.524) |
  | 다른 날, 같은 계열의 서로 다른 종이 | 642쌍 | 최대 0.853 |
  | 순하게 흔든 같은 종이 (±1°, ±15 px, 배율 ±1 %, 흐림 0.3–0.8, JPEG 60–90), 세 번씩 | 243쪽 | 최소 0.700, 중앙 0.991 — **0.80 미만 5쪽**, 0.70 미만 0 |
  | 거칠게 흔든 같은 종이 (0007 의 것: ±2.5°, ±25 px, ±3 %, 흐림 0.5–1.3, JPEG 45–80), 세 번씩 | 243쪽 | 최소 0.284, 중앙 0.988 — **0.80 미만 7쪽**, 0.70 미만 2쪽 |
  | 하루치 30쪽 + 그 다시 스캔 30쪽을 파이프라인에 (거친 흔들기, 한 번) | 30쪽 | 28쪽 붙잡힘(최소 0.857), 2쪽은 기준 이미지로 쓴 종이(서명 0) |

  같은 그림에서 서명의 두 정의(인쇄만 지움 / 표 밖 필드도 지움)를 견주면 0.80 미만인 쪽의 수가 같았고(81쪽 중 3), 같은 날 다른 종이의 최대는
  0.632 → 0.593 이다. 즉 **기준 0.80 은 다시 스캔의 2–3 % 를 놓친다.** 0.70 이면 순한 흔들기는 전부 잡고 같은 날 다른 종이 286쌍은 하나도 붙잡지 않는다 —
  그러나 합성(`--meta-fields --mix-pages`)은 같은 날 다른 종이가 0.771 까지 올라간다. 기본값은 0.80 그대로 두고, 근거 수치를 이것으로 고쳐 적는다 (4.10).
  현장의 값은 실제 다시 스캔을 본 뒤 정한다 (0007 8절 4).
- **문서 화면의 그림이 작다.** 날짜를 정하려면 종이의 날짜를 읽어야 하고 다시 스캔 의심 쪽은 두 종이를 견줘야 하는데, 쪽 그림은 폭 290 px 쯤,
  의심 쪽의 짝은 한 장이 135 px 쯤이다 (1300 px 창). 키울 길이 없다. "돌려 보기"로 돌린 그림은 옆 칸을 덮는다 (4.10).

## 2. 끝났을 때 되는 일

```bash
# 엑셀 — 설정: [export] excel_dir = "…/현장이 여는 폴더" (또는 MINEDOCSCAN_EXCEL_DIR)
minedocscan serve --reviewer jp            # 처리·검수·결정 뒤 다음 바퀴에 그 날짜의 엑셀이 따라온다. 홈에 상태와 내려받기
minedocscan export excel [OUT] [--date 2030-01-07 | --from … --to … | --month 2030-01]   # 손으로. 바뀐 파일만 다시 쓴다
#   OUT/daily/2030-01/2030-01-07.xlsx     하루치: 요약, 양식마다 한 장(종이와 같은 행·열), 업무 표
#   OUT/monthly/2030-01.xlsx              한 달: 날짜별 요약, 운반 표(날짜·주야 × 자리 × 광종·편), 배차, 긴 표

# 통합 DB(PostgreSQL)로 싣기 — pip install "minedocscan[postgres]", MINEDOCSCAN_PUBLISH_URL=postgresql://…
minedocscan publish --check                # 쓰지 않고: 다른 문서·날짜의 수
minedocscan publish                        # 바뀐 문서·날짜만 갈아 끼운다 (한 트랜잭션). serve·watch 도 바퀴 끝에 한다
minedocscan publish --rebuild              # 대상 스키마의 표를 다시 만든다 (판이 달라졌을 때)

# 가린 쪽 그림 — 발표·보고서용. 사람이 보고 나서 쓴다
minedocscan export masked-pages OUT --date 2030-01-07 [--page-id …] [--keep-text]
minedocscan template preview <site>/templates/<양식>      # 가릴 자리(redact)도 그린다
minedocscan synth out/x --display-names    # 합성 템플릿에 표시 이름과 가릴 자리를 넣는다
```

- 엑셀의 칸은 **확정된 값만** 보여 준다. 검수 대기인 칸은 값 없이 표시만 있다. 합계는 그 줄이 전부 확정일 때만 적힌다.
- 내보낸 파일과 실은 표는 사본이다. 지워도 되고, 다시 만들면 같다. 엑셀을 고쳐도 DB 로 돌아오지 않는다 — 고치는 곳은 검수 화면이다.
- 싣기가 끝나면 통합 DB 의 표는 작업 DB 의 표와 같다 (다시 처리·버리기·날짜 바꾸기·검수가 어떤 순서로 있었든).
- 서버가 꺼져 있거나 엑셀 파일이 열려 있어도 스캔과 검수는 멈추지 않는다. 다음에 다시 한다.

## 3. 범위

**하는 것**
- 0007 의 뒷정리: 다시 스캔의 근거 수치, 문서 화면의 쪽 그림 크게 보기 (4.10).
- 내보내기 모델(DB → 표, 순수 함수)과 엑셀 쓰기: 일별·월별 파일, 운반 표, 표시 이름(`display`), 내용의 해시와 기록 파일, 자동 내보내기, 홈의 상태와 내려받기.
- 통합 DB 로 싣기: 대상 스키마의 표(형을 넓혀), 문서·날짜 단위 지문, 한 트랜잭션, 실패해도 계속.
- 가린 쪽 그림: 템플릿의 `redact` 상자, 가리는 규칙, 명령.
- 합성: 표시 이름과 가릴 자리를 넣는 선택(`--display-names`). 문서, ADR 둘.

**하지 않는 것**
- 작업 DB 를 PostgreSQL 로 옮기기 (1절 나 — 4.8, ADR 로 남긴다). 조회문의 자리표시자를 바꾸지 않는다.
- 엑셀을 읽어 들이기, 엑셀에서 고친 값을 DB 로 돌리기, 현장의 월별 작업일보 파일을 직접 고치기 (2단계).
- 여러 날을 더한 집계, 차량을 가로지른 합(편별 집계), 환산 톤수, 물질수지 (2단계). 운반 표의 합계는 한 차량의 한 줄 안의 합뿐이다.
- 통합 DB 쪽의 뷰·권한 설계, 2단계의 표와 잇기 (2단계). 여기서는 표를 싣기만 한다.
- 가린 크롭·가린 학습 데이터 묶음 (크롭 내보내기는 지금도 칸 종류로 고른다). 그림에서 이름을 찾아 가리기(글자 인식) — 템플릿이 아는 자리만 가린다.
- 인식·교정 백엔드, 임계값(`dup_min_sim` 포함), 값의 정규화 규칙 바꾸기. 설치 파일·서비스 등록 (M6).

## 4. 이미 정한 것

### 4.1 내보낸 것은 사본이다 — 한 방향, 언제든 다시 만든다

- 원본은 셋뿐이다: 스캔 파일(보관 폴더), 검수 기록, 결정 기록. DB 는 그것으로 다시 만들 수 있고, **내보낸 것(엑셀·통합 DB 의 표·가린 그림)은 DB 로 다시 만들 수 있다.**
- 한 방향이다. 내보낸 것을 읽어 DB 를 고치는 길은 만들지 않는다.
- 내보내기는 **작업 DB 에 아무것도 쓰지 않는다** (읽기만 한다). 무엇을 언제 내보냈는지는 내보낸 곳에 적는다 (엑셀 폴더의 기록 파일, 통합 DB 의 상태 표).
- **읽기는 한 트랜잭션으로** 한다 — 표마다 다른 시점을 보지 않는다 (엑셀의 날짜 하나, 싣기 한 번이 각각 한 시점).
- **엑셀 폴더와 대상에 쓰는 것은 파이프라인이 쉬는 동안에만** 한다: `watch`·`serve` 의 작업 스레드는 바퀴의 끝에서(자기 처리 뒤), 쓰는 명령(`export excel`,
  `publish`, `publish --rebuild`)은 파이프라인 잠금(`pipeline/lock.py`)을 잡고 한다. 잠금을 못 잡으면(`serve`·`watch` 가 돌고 있다) 한 줄로 알리고 끝낸다 —
  설정이 있으면 그 프로세스가 내보내고 있고, 엑셀은 홈에서 내려받을 수 있다 (`--rebuild` 는 `serve` 를 내리고 친다). 그래서 처리 중인 문서의 반쯤 지워진 행을
  폴더·대상에 쓰는 일도, 두 프로세스가 같은 기록 파일을 고치는 일도 없다.
  **읽기만 하는 명령**(`publish --check`, `export masked-pages`)은 잠금을 잡지 않고 읽기 트랜잭션 하나로 한다 (`serve` 가 도는 중에도 된다).
  다시 처리 대기 중인 문서(요청 번호가 남은 것, 원본에 닿지 않은 것)는 옛 행을 그대로 가지고 있으므로 그대로 내보낸다.
- 내보내기가 실패해도(폴더가 없다, 파일이 열려 있다, 서버가 꺼졌다) 접수·처리·검수는 계속된다. 실패는 요약과 홈에 수로 알리고 다음에 다시 한다.
- 내보낸 엑셀과 가린 그림에는 현장의 값(이름·차량번호 포함)이 있다 — **저장소 밖에.** 저장소 안의 경로는 거절한다
  (`review/export.py` 의 `inside_git_tree` 와 같은 규칙. 명령은 `--allow-in-repo` 로 합성만. 설정의 `excel_dir` 가 저장소 안이면 시작할 때 한 줄로 알리고 자동 내보내기를 끈다).
  접수 폴더 안도 거절한다.
- 요약·로그·오류 메시지: `watch`·`serve` 의 로그는 지금처럼 수와 문서 ID 만. 사람이 친 명령(`export`·`publish`)의 요약은 날짜를 내도 된다. 값·이름·파일명은 어디에도 내지 않는다.

### 4.2 칸의 상태 — 확정되지 않은 값은 싣지 않는다

**필드(`doc_field`)의 칸** — 양식 시트에 싣는 것. 위에서부터 먼저 맞는 줄을 쓴다. 정하는 곳은 한 함수다 (시트마다 따로 정하지 않는다).

| `doc_field` 의 모양 | 상태 | 엑셀의 칸 |
|---|---|---|
| `kind = printed` | 인쇄 값 | 템플릿이 확정한 값 그대로 |
| `meta_key` 가 있는 표 밖 필드이고 `doc_page_meta.value` 가 있다 | 쪽 메타 | 그 값 (검수·결정·라벨·파일명, 또는 자동 적재된 기계 값). 값이 없으면 아래 줄들로 내려간다 |
| `pending` 이고 `reviewed_by` 가 있다 | 판독 불가 | `판독 불가` (사람이 보았고 읽지 못했다 — 검수의 illegible. 값은 싣지 않는다) |
| `pending` (그 밖) | 검수 대기 | **값을 적지 않는다.** 표시 `?` 와 바탕색 |
| `auto`·`reviewed`, `has_value = 0` | 빈 칸 | 비운다 |
| `auto`·`reviewed`, `has_value = 1`, `kind = checkmark` | 표시 | `✓` (값이 있든 없든 — 점검표의 ✓ 는 값 `1`, 다른 양식의 ✓ 는 유무만 적는다) |
| `auto`·`reviewed`, `has_value = 1`, `value_final` 이 있다 | 값 | 그 값 (수 형식이면 수로) |
| `auto`·`reviewed`, `has_value = 1`, `value_final` 이 없다 | 글씨 있음 | `●` (서명처럼 유무만 적는 칸) |

- 검수 대기인 칸에는 기계가 낸 값이 들어 있을 수 있다 (`value_final` 이 채워진 채 `pending`, 판독 불가도 같다). **싣지 않는다.**
- **핸들러가 고쳐 말하는 곳** — 위의 표는 `doc_field` 와 템플릿만으로 정해지지만, 양식의 뜻을 아는 것은 핸들러다. `FormHandler` 에 선택적인 메서드 하나를 두어
  (기본은 아무것도 고치지 않는다) 핸들러가 쪽의 칸 상태를 고쳐 말할 수 있게 한다. 지금 필요한 것은 셋이다:
  - 점검표: **점검을 하지 않은 쪽**(체크 열 전체가 판정 불가 — `review/checks.py` 가 유도하는 `column_unused`)은 ✓ 칸을 비우고 쪽의 머리에 "점검 표시 없음" 한 줄.
  - 점검표: **여백 행**(`forms/equipment.is_equipment_row` 가 아닌 행)의 ✓ 칸은 기계가 표시를 보지 못했으면 비운다 (날마다 검수 대기이고 검수할 길이 없는 칸이다).
  - 가동 일보: **작업 표**(`role: activities`)의 글자 칸이 **검수 대기이면** `●` 로 바꾼다 (읽지 않는 표다 — ADR 0016. 그대로 두면 `?` 가 영원히 남는다).
    확정된 값이 있는 칸(사람이 넣었거나 `oracle` 로 돌린 것)은 그 값 그대로다.
- 글자 인식기가 아직 없어 글씨가 있는 글자 칸(점검내역 등)은 전부 검수 대기다 — `?` 로 보인다. 그대로 둔다 (사람이 넣으면 값이 된다).
- **"검수 대기 칸의 수"는 한 가지로 센다**: 모델이 검수 대기(`?`)·판독 불가로 낸 칸의 수 — 요약, 쪽의 머리, 날짜별 요약이 같은 수를 쓴다.
  DB 의 `pending` 필드 수와는 다르다: 값이 있는 메타 필드, 여백 행, 점검하지 않은 쪽의 ✓ 칸, 작업 표의 글자 칸은 `pending` 이어도 세지 않는다.

**업무 행의 값** — 업무 시트·운반 표에 싣는 것. 업무 테이블의 값 열에는 검수 대기인 기계 값이 그대로 들어 있다. **값 열은 그 값이 나온 필드가 확정일 때만 싣는다.**

| 시트 | 값 열 | 확정인가를 보는 곳 |
|---|---|---|
| 운반 (`prod_haul`) | 횟수 | 그 행의 `review_status` (= `source_field_id` 의 필드) |
| 작업량 (`prod_tally`) | 수 | 그 행의 `review_status` |
| 가동 기록 (`eq_usage_daily`) | 계기 시작·종료·총, 시각, 근무 시각 | 값마다 그 필드 (`start_field_id`·`end_field_id`·`total_field_id`, 근무 시각 칸) |
| | 가동 시간(`hours`) | 그 값의 근거(`hours_basis`)가 된 필드가 전부 확정일 때만 |
| 점검 (`insp_daily`) | 이상 유·무 | 그 행의 두 ✓ 칸이 확정일 때만 (NULL 이면 판정 불가. "모름"으로 검수한 행은 값이 남아 있어도 싣지 않는다) |
| | 점검내역 | `source_field_id` 의 필드 (비고 칸) |
| 교차검증 (`xcheck_haul`) | 일보·행렬의 횟수 | 그 날짜·자리·광종·편의 운반 행이 **전부** 확정일 때만 (운반 행에서 다시 본다 — 이 표의 합은 검수 대기 값도 더한 것이다) |
| | 판정(`status`) | 그대로 싣되, 확정되지 않은 운반 행이 끼어 있으면 `(잠정)` 을 붙인다 |
| 계기 검산 (`xcheck_usage`) | 두 값·차이 | 그 검산이 견준 칸 **전부**(`validate/usage.check_cells` — 연속성: 이 쪽의 시작·앞 기록의 종료, 총: 시작·종료·총, 소계: 소계 칸과 더한 칸들)가 확정일 때만. 결과(`result`)는 위와 같이 `(잠정)` |
| 배차 관측 (`eq_assignment_obs`) | 차량번호·작성자 | 그대로 (쪽 메타의 최종 값이다) |

- 확정이 아닌 값 열은 비우고 `상태` 열에 검수 대기(또는 판독 불가)를 적는다. 견준 칸이 없는 검산(연속성의 첫 기록 등 — 필드 ID 가 NULL)은 견준 것이 없는 것이다 (확정을 따지지 않는다).
- 가동 기록의 근무 시각 칸은 행에 필드 ID 가 없다 — 템플릿의 `role: shifts` 표에서 찾는다 (핸들러가 쓰는 것과 같은 규칙으로, 한 곳에서).
- 교차검증에는 자리가 `unresolved:…` 인 행이 있다 (자리를 모르는 일보 쪽 — 4.4). 그 행의 운반 행은 자리가 아니라 그 쪽(들)으로 찾는다. 시트에는 자리를 `자리 미정` 으로 적는다.
- **기계 값은 기본으로 싣지 않는다.** `[export] machine_values = true` 일 때만 업무 시트와 긴 표에 `기계 값(확정 아님)` 열을 따로 둔다 — 최종 값 열과 섞지 않는다.
  정답을 만드는 대기열은 기계 값을 숨기는 것이 결정이다 (ADR 0008) — 엑셀이 그것을 깨지 않게 기본은 끈다.
- **합계는 그 줄의 칸이 전부 확정(값·빈 칸)일 때만 적는다.** 검수 대기·판독 불가가 하나라도 있으면 비우고 표시한다 — 주간만 검수하고 야간은 아직인
  칸의 합은 모르는 것이다 (CLAUDE.md "실데이터에서 배운 것"). 합계는 값으로 적는다 (엑셀 수식을 쓰지 않는다).
- 표시는 색에만 기대지 않는다 (글자 표시 + 바탕색). 범례는 요약 시트에.
- 위의 두 표를 구현한 대응(어느 열이 어느 상태인가)을 `docs/ARCHITECTURE.md` 에 그대로 남긴다. "검수 대기는 값을 싣지 않는다"는 바꾸지 않는다.

### 4.3 일별 파일: 요약, 양식마다 한 장, 업무 표

`OUT/daily/<YYYY-MM>/<YYYY-MM-DD>.xlsx`. 날짜는 쪽의 날짜(`doc_page.work_date`)다. 그 날짜의 쪽이 하나라도 있으면 파일이 있다.
**ISO 날짜(`YYYY-MM-DD`)가 아닌 `work_date`**(쪽 라벨에서 올 수 있다)는 파일로 만들지 않고 수로 알린다 — DB 의 값이 그대로 경로가 되지 않게.

- **요약**: 날짜, 쪽의 수(양식별·상태별 — 적재되지 않은 쪽은 상태마다: 양식 없음·정합 실패·빈 쪽·다시 스캔 의심·버림·오류 …), 검수 대기 칸의 수(양식별),
  교차검증의 상태별 수와 계기 검산의 종류·결과별 수, 처리 중이거나 다시 처리 대기 중인 문서가 걸쳐 있으면(그 문서의 `doc_document.work_date` 가 이 날짜이거나 쪽이 이 날짜에 있다) 그 수("끝난 뒤 다시 보십시오"), 범례,
  "이 파일은 DB 의 사본입니다 — 고치려면 검수 화면에서" 한 줄, 만든 시각과 프로그램 판. 만든 시각은 내용의 해시에 넣지 않는다 (4.6).
  날짜가 없는 문서(날짜를 정할 문서, 실패한 문서)는 엑셀에 없다 — 홈에서 본다 (요약에 그렇게 한 줄).
- **양식 시트** — 그 날짜에 적재된 쪽이 있는 계열(`family`, 없으면 템플릿 이름)마다 한 장. 시트 이름은 그 계열의 표시 이름(4.5 — 없으면 템플릿의 `title`).
  쪽마다 한 블록, 쪽의 순서(`store/order.py`)대로: 쪽의 머리(출처 `파일명#쪽`·쪽 ID·양식의 제목·검수 대기 칸의 수·핸들러가 말한 줄) → 표 밖 필드(이름과 값) →
  표(region)마다 머리글 행과 그 아래 행들. **행과 열의 순서는 종이와 같다** (템플릿의 행·열 순서). 칸은 4.2 의 상태대로.
  `doc_field`·`doc_page_meta` 와 템플릿, 그리고 핸들러가 고쳐 말한 것(4.2)만으로 만든다 — 새 양식 때문에 내보내기 코드를 고치지 않는다 (원칙 1).
- **업무 시트** — 그 날짜에 행이 있는 것만: 운반(일보), 운반(행렬), 교차검증(일보↔행렬), 배차 관측, 가동 기록, 작업량, 계기 검산, 점검.
  한 행 = 업무 테이블의 한 행. 열은 사람이 읽는 것만 고르고(머리글은 한글 — 4.5), 끝에 `상태`·(`machine_values` 면 `기계 값(확정 아님)`)·`출처`(파일명#쪽)·`필드 ID`.
  가동 기록은 쪽 하나에 한 행 그대로 둔다 (같은 날 같은 장비의 둘째 장을 합치지 않는다). 작업량의 소계 행은 표시한다 (`is_subtotal`).
- 시트 이름은 31자 안, 엑셀이 받지 않는 글자(`[]:*?/\`)는 뺀다. 겹치면 번호를 붙인다.
- 날짜와 시각은 글자(ISO)로 적는다 (엑셀이 날짜로 바꿔 읽지 않게). 수는 수로.
- 머리글 행은 틀 고정, 긴 표에는 자동 필터. 그 밖의 꾸밈은 최소로.

### 4.4 월별 파일과 운반 표

`OUT/monthly/<YYYY-MM>.xlsx`. 그 달에 쪽이 있는 날짜를 모은다. `--date`·`--from/--to` 로 범위를 주면 그 범위가 닿는 달의 파일도 (그 달 전체의 내용으로) 쓴다.

- **요약(날짜별)**: 날짜마다 한 줄 — 쪽 수, 적재되지 않은 쪽, 검수 대기 칸, 교차검증의 일치·불일치·한쪽 없음, 계기 검산의 어긋남, 자리 미정인 일보 쪽의 수.
- **운반 표**: 행 = 날짜 × 주·야, 열 = 자리(`slot`)마다 한 블록 × 광종·편(`material`·`level`), 블록 끝에 합계 (4.2 의 규칙). 값은 **일보**(`prod_haul.source_role = 'log'`)의 횟수다.
  주·야의 순서는 주간 → 야간 (`shift` 가 없는 양식은 한 줄).
  - 칸의 상태는 4.2 의 것(값·빈 칸·검수 대기·판독 불가)에 둘을 더한다. **문서 없음** `–`: 그 날짜·자리의 일보 쪽이 없고, 그 날짜에 자리 미정인 일보 쪽도 없다.
    **모름** `–?`: 그 날짜·자리의 일보 쪽이 없는데 자리 미정인 일보 쪽이 있다 (그 쪽이 이 자리의 것일 수 있다). 둘 다 빈 칸과 다르게 보인다.
  - **자리 미정인 일보 쪽**(그 쪽의 운반 행의 `slot` 이 NULL — 자리는 쪽 단위로 정해진다)은 표의 오른쪽에 `자리 미정 1, 2, …` 블록으로 싣는다.
    블록 k = 그 날짜의 자리 미정 쪽 가운데 쪽의 순서(`store/order.py`)로 k 번째. 블록의 수 = 그 달에서 하루에 가장 많았던 수. 블록마다 첫 열이 `출처`(파일명#쪽)이고
    그 뒤가 광종·편의 열과 합계다 (그 날짜에 k 번째 쪽이 없으면 그 블록의 그 줄은 비운다).
    잃지 않는다 — 차량번호·작성자를 검수하면 다음 내보내기에서 자리의 블록으로 옮겨 간다.
  - 교차검증이 불일치(`xcheck_haul.status = 'mismatch'`)인 날짜·자리·광종·편의 칸은 따로 표시한다 (주·야 두 칸 다 — 교차검증에는 주야가 없다).
    **고치지 않는다** — 일보의 값을 그대로 적고 표시만 한다 (ADR 0006).
  - **줄 끝의 합계(차량을 가로지른 합)는 두지 않는다** — 일보가 없는 차량이 있는 날에 합을 말할 수 없다. 집계는 2단계의 일이다.
- 광종·편의 순서와 표시 이름: 기본은 일보 템플릿의 행 순서와 행의 표시 이름(4.5). 사이트 팩의 `site.toml` 이 바꿀 수 있다 —
  `[haul_table] columns = ["ORE|L0", …]`(`광종|편`), `slots = ["T01", …]`. 거기에 없는 것은 뒤에 붙인다 (빠뜨리지 않는다). 현장에 관한 것을 코드에 적지 않는다.
- **배차**: 날짜 × 자리 → 그날의 차량번호·작성자(`eq_assignment_obs`), 인쇄된 머리글과 다르면 표시.
- **긴 표**(그 달 전체): 운반(일보·행렬 — **값이 있거나 검수 대기인 행만**, 빈 칸 행은 싣지 않는다), 교차검증, 가동 기록, 작업량(값이 있거나 검수 대기인 행만),
  계기 검산, 점검. 열은 일별 파일의 업무 시트와 같다.

### 4.5 표시 이름: 템플릿의 `display` 와 한 곳의 머리글

- 템플릿(양식 자체)·표(region)·열·행·표 밖 필드에 **`display`**(선택)를 둘 수 있다 — 엑셀에 보이는 이름. 없으면 지금의 `title`·`name`(행은 `key`)을 쓴다.
  **키 이름은 `label` 이 아니다**: 인쇄된 칸의 값은 행의 메타에서 열 이름으로 찾고(`_printed_value`), 열 이름이 `label` 인 표가 이미 있다 (합성 일보의 곁표) —
  `label` 을 표시 이름으로 쓰면 인쇄된 값이 바뀐다. `template check` 는 열 이름이 `display` 인 표를 오류로 낸다.
- `display` 는 표시에만 쓴다: 분류·정합·핸들러·업무 테이블·`field_id`·인쇄된 값에 닿지 않는다. 동시 판(ADR 0018)은 `display` 도 같아야 한다 ("기하 밖의 전부" — 지금의 비교가 그대로 잡는다).
- 업무 시트의 머리글과 상태·표시의 한글은 한 모듈에 모은다 (시트마다 흩어 적지 않는다).
- 합성 템플릿은 `synth --display-names` 일 때만 `display` 와 `redact`(4.9)를 넣는다 — **지금의 합성 선택들의 출력 바이트는 그대로다**
  (`--display-names` 는 `template.yaml` 만 바꾼다. 스캔·정답·기준 이미지의 바이트는 있어도 없어도 같다).

### 4.6 쓰기: 내용의 해시, 기록 파일, 원자적으로

- **내보내기 모델**은 순수 함수다: `(con, site, 날짜 또는 달) → 시트들`(시트 = 이름 + 칸들: 값·상태·표시). DB 를 읽기만 하고 시각·경로를 품지 않는다.
  순서는 전부 정해져 있다 (쪽의 순서, 필드의 자리, 업무 행의 키) — 같은 DB 면 같은 모델이다. 엑셀 쓰기는 모델을 받아 파일로 옮길 뿐이다.
  시험은 둘로 나눈다: 모델이 맞는가(정답·DB 와), 파일이 모델과 같은가(되읽어서).
- **바뀌었나**는 모델의 해시로 본다 (정규화한 JSON 의 SHA-256). 파일의 바이트를 견주지 않는다 (1절 가).
- **기록 파일** `OUT/.minedocscan-export.json`: 파일마다 내용의 해시와 쓴 시각, 모델의 판. 해시가 같으면 그 파일을 건드리지 않는다 (수정 시각이 그대로다).
  기록 파일도 임시 이름에 쓰고 바꾼다. 모델의 모양을 바꾸면(열을 더했다) 모델의 판을 올린다.
- **쓰는 규칙**: 이름 규칙(`daily/<YYYY-MM>/<날짜>.xlsx`, `monthly/<달>.xlsx`)에 맞는 경로는 이 프로그램의 것이다 — 기록에 없거나 해시·판이 다르면 (다시) 쓴다.
  기록 파일이 없거나 깨졌으면 전부 다시 쓴다.
- **지우는 규칙**: 쪽이 하나도 남지 않은 날짜(문서를 버렸다, 날짜를 옮겼다)의 일별 파일은 지운다 — 남겨 두면 틀린 사본이다. **기록 파일에 있는 파일만 지운다**
  (기록을 잃었으면 지우지 않고 수로 알린다). 사용자가 그 폴더에 둔 다른 파일은 건드리지 않는다. 월별 파일도 그 달에 날짜가 하나도 없으면 같다.
- **원자적으로**: 같은 폴더의 임시 이름(`.xlsx` 가 아닌 것)에 쓰고 `os.replace`. 바꾸지 못하면(윈도우: 엑셀이 그 파일을 열고 있다) 임시 파일을 치우고
  그 파일을 "쓰지 못함"으로 세고 다음에 다시 한다 — 예외로 죽지 않는다. 덜 쓰인 `.xlsx` 가 보이는 일이 없다.
- `OUT`(설정의 `excel_dir`)은 **있어야 한다** — 없으면 만들지 않고 "쓰지 못함"이다 (끊긴 네트워크 폴더의 자리에 로컬 폴더를 만들지 않게). 그 아래의 `daily/…`·`monthly/` 는 만든다.

### 4.7 자동 내보내기와 화면

- 설정 `[export] excel_dir`(또는 `MINEDOCSCAN_EXCEL_DIR`), `sweep_minutes`(기본 30, `0` 이면 시작할 때만), `machine_values`(기본 false). `excel_dir` 가 없으면 자동 내보내기는 꺼져 있다.
- `watch`·`serve` 의 작업 스레드가 **바퀴의 끝에** 폴더에 쓴다 (접수 → 처리 → 내보내기 → 싣기(4.8)). 화면 스레드는 폴더에 쓰지 않는다.
  `run` 은 내보내지 않는다 (명령이다 — 뒤에 `export excel`·`publish` 를 친다. 설정이 있으면 요약에 한 줄로 알린다). `serve --no-watch` 도 폴더에 쓰지 않는다.
- **더러운 날짜**만 다시 본다. 넉넉하게 잡는다 — 좁혀서 놓치지 않는다 (해시가 같으면 쓰지 않으므로 넉넉해도 파일은 그대로다):
  - 처리한(실패한 것 포함) 문서의 쪽이 있던 날짜와 있는 날짜. 그 처리가 다시 계산한 날짜·장비. 처리가 지운 문서의 ID 도 알린다
    (같은 경로의 옛 `failed` 문서 행을 지운다 — 싣기가 대상에서 그 문서를 지우려면 알아야 한다).
  - 검수를 저장한 칸의 쪽의 날짜.
  - **다른 날짜로 번지는 것은 계기의 연속성뿐이다** (`validate/usage.py` — 같은 장비의 어제 종료 = 오늘 시작): 처리나 검수가 가동 기록에 닿으면
    그 장비(검수가 장비명을 고쳤으면 고치기 전·후의 장비 둘 다)의 가동 기록이 있는 **모든 날짜**.
  - 더러운 날짜의 달.
- 필요한 정보(처리 전·후의 날짜와 장비, 실패한 문서, 검수한 칸의 날짜와 장비)는 지금 파이프라인과 검수 저장의 안에만 있다 — 밖으로 알리게 한다 (0절: 알리는 것은 더해도 된다).
  화면 스레드의 저장(검수·결정)은 더러운 날짜·문서 ID 를 작업 스레드에 넘긴다 (스레드 사이에 주고받는 것은 그것뿐). **검수 저장은 작업 스레드를 깨우지 않는다** —
  다음 바퀴(`poll_seconds` 안)에 묶어서 한다 (칸마다 파일을 다시 쓰지 않게). 결정은 지금처럼 깨운다.
- **전체 훑기**: 시작할 때 한 번, 그 뒤 `sweep_minutes` 마다 (다른 프로세스가 쓴 검수 — `review serve` — 와 놓친 것을 잡는다). 전체 훑기도 해시가 같은 파일은 쓰지 않는다.
- `export excel` 명령은 늘 전체(또는 준 범위)를 훑는다 (4.1 — 파이프라인 잠금을 잡고).
- 홈(`/api/home`)에 내보내기의 상태: 켜짐·꺼짐, 마지막으로 쓴 시각과 파일 수, 쓰지 못한 파일의 수. 싣기(4.8)도 같이: 켜짐·꺼짐, 마지막 성공 시각, 밀린 범위의 수, 마지막 실패의 종류.
- **내려받기**: `GET /export/day.xlsx?date=YYYY-MM-DD`, `GET /export/month.xlsx?month=YYYY-MM` — 같은 모델로 그때 만들어 준다 (폴더 설정이 없어도 된다, 디스크에 쓰지 않는다,
  읽기는 한 트랜잭션). 처리 중인 문서가 있으면 요약에 그 수가 적힌다 (4.3). 홈의 최근 문서 옆과 문서 화면에 그 날짜의 내려받기 링크.
  달력에 없는 날짜는 400, 쪽이 없는 날짜는 404. 지금의 Host·Origin 검사와 `no-store` 그대로.

### 4.8 통합 DB 로 싣기: 작업 DB 는 SQLite 그대로, PostgreSQL 은 싣는 곳

- **작업 DB 를 PostgreSQL 로 옮기지 않는다** (ADR 0005 의 보완 — 새 ADR). 이유는 1절 (나): DB 도 로컬이어야 하고, 0007 의 처리 단위·잠금·`--fresh` 는 로컬
  SQLite 파일을 전제로 하며, 지우고 다시 만드는 DB 를 다른 프로그램이 읽게 둘 수 없다. 통합 DB 에는 **결과의 사본**을 싣는다.
- **대상**: 환경변수 `MINEDOCSCAN_PUBLISH_URL`(`postgresql://사용자:비밀번호@호스트/DB`) — **환경변수로만** 받는다 (비밀값을 설정 파일에 적지 않는다).
  `[publish] schema`(기본 `minedocscan`, 환경변수 `MINEDOCSCAN_PUBLISH_SCHEMA`), `enabled`(기본: URL 이 있으면 켜짐), `sweep_minutes`(기본 30), `connect_timeout_s`(기본 5),
  `retry_seconds`(기본 60 — **연결에 실패한 뒤** 이만큼은 다시 연결하지 않는다: 꺼진 서버에 바퀴마다 매달리지 않게). `psycopg` 가 없으면 `publish` 는 한 줄로 알리고
  종료 코드 2, `watch`·`serve` 는 시작할 때 한 번 알리고 싣기를 끈다. 연결은 한 함수를 거친다 (시험이 바꿔 끼울 수 있게 — 6절).
- **싣는 표**: `doc_document`, `doc_page`, `doc_field`, `doc_page_meta`, `eq_equipment`, `eq_assignment_obs`, `insp_daily`, `prod_haul`, `prod_tally`,
  `eq_usage_daily`, `xcheck_haul`, `xcheck_usage`. 싣지 않는 표: `doc_page_sig`(안에서만 쓴다), `doc_review`·`doc_decision`(원본은 파일이다), `meta_schema`.
- **싣는 열**: 작업 DB 의 열 전부에서 **0007 의 불변식이 빼는 열**을 뺀 것 — `created_at`·`received_at`·`work_requested`·`work_done`·`source_path`
  (시각·요청 번호·로컬 경로: 내용이 같아도 `--fresh` 마다 달라진다). 표와 열의 목록은 `store/db.py` 의 `PRIMARY_KEYS` 옆 한 곳에 두고 불변식 시험과 같이 쓴다.
- **표의 정의는 `schema.sql` 한 곳에서 나온다** (싣는 쪽의 DDL 을 따로 적지 않는다). 그 파일의 글자를 파싱하지 말고, 메모리의 SQLite 에 `schema.sql` 을 올려
  `PRAGMA table_info` 와 인덱스 목록에서 만든다 (한 줄에 열이 여럿이고 표 단위 제약이 섞여 있다). 만들 때 **형을 넓힌다**:
  `REAL` → `DOUBLE PRECISION`, `INTEGER` → `BIGINT` (1절 나). `schema.sql` 의 문은 고치지 않는다. **대상의 표에는 외래 키를 걸지 않는다** —
  문서 단위로 갈아 끼우고, 맞는지는 작업 DB 가 원본이다. 기본 키와 인덱스는 건다.
- **불변식**: 싣기가 끝나면, 싣는 표마다 **대상의 행 = 작업 DB 의 행** (싣는 열 전부, 행의 순서와 무관). 그 전에 무엇이 있었든(다시 처리, 버리기, 날짜 바꾸기,
  검수, `--fresh`, 지난 싣기가 끊겼든). 실수(float)도 되읽어 정확히 같다.
- **방법 — 지문으로 갈아 끼운다**:
  - 범위는 셋이다. **문서**: `doc_document` 의 그 행 + 그 문서의 쪽을 가리키는 행 전부 (`doc_page`·`doc_field`·`doc_page_meta`·`prod_haul`·`prod_tally`·`eq_usage_daily`·
    `insp_daily`·`xcheck_usage` — 쪽 ID 로 문서에 붙인다). **날짜**: 날짜가 키인 표(`xcheck_haul`, `eq_assignment_obs`). **통째**: `eq_equipment`.
    싣는 표의 모든 행이 이 셋 중 하나에 들어야 한다 — 어디에도 들지 않는 행이 있으면(쪽 ID 가 없는 행) 싣기를 멈추고 수로 알린다 (조용히 빠뜨리지 않는다).
  - 범위마다 지문 = 그 행들을 정해진 순서와 표현으로 이은 것의 SHA-256. 대상의 상태 표(`pub_state`: 범위의 종류·키 → 지문, 실은 시각; 스키마 버전과 **싣기의 판**)에 적어 둔다.
    싣기의 판 = 범위·표현·표와 열의 목록의 판 — 바꾸면 올린다.
  - 지문이 다른 범위만 갈아 끼운다: 대상에서 그 범위의 행을 지우고(자식부터) 지금의 행을 넣는다. 작업 DB 에 없는 범위(대상에만 남은 문서·날짜)는 지운다.
    **지울 것을 먼저 다 지우고 넣는다** — 같은 키의 행이 문서 사이를 옮겨 다닌다 (`insp_daily` 의 이기는 쪽이 바뀐다, 일보의 자리가 바뀐다).
  - **한 번의 싣기는 한 트랜잭션이다.** 끊기면 대상은 싣기 전 그대로다. 읽는 쪽(2단계)은 반쯤 바뀐 문서를 보지 않는다.
  - **실을 수 없는 값**(대상의 형이 받지 않는 값 — 예: NUL 문자가 든 글자. SQLite 는 저장한다)이 있는 범위는 싣지 않고 수로 알린다. 그 범위 하나가 싣기 전체를 막지 않는다.
    그 범위의 옛 행은 대상에서 **지운다** (남기면 그 행이 쥔 키가 다른 범위와 부딪친다). 불변식은 "건너뛴 범위를 뺀 나머지"에 선다. 다음에도 "다르다"고 나온다.
  - 대상의 스키마 버전이나 싣기의 판이 다르면 싣지 않고 `publish --rebuild` 를 알린다. `--rebuild` 는 이 프로그램이 만든 표만 지우고 다시 만든다 (`CASCADE` 하지 않는다 —
    2단계의 뷰가 걸려 있어 지우지 못하면 그렇다고 알리고 멈춘다).
- **언제**: `publish` 명령(늘 전체를 훑는다 — 4.1 의 잠금), 그리고 `watch`·`serve` 의 바퀴 끝.
  - 바퀴 끝에는 **더러운 범위**만 지문을 다시 낸다: 4.7 의 더러운 날짜(날짜 범위), 그리고 더러운 문서 = 처리·실패한·지워진 문서 + **더러운 날짜에 쪽이 있는 문서 전부(작업 DB 와 대상 양쪽에서 —
    대상에도 `doc_page.work_date` 가 있다)** + 검수한 칸의 문서. 같은 날짜의 다른 문서의 행도 바뀌기 때문이다 (자리, 점검의 이기는 쪽, 뒤 문서의 다시 처리). `eq_equipment` 는 늘 본다 (작다).
  - 더러운 범위만 실은 것이 실패하면(빠뜨린 문서가 키를 쥐고 있었다) **같은 바퀴에 전체 훑기로** 다시 한다.
  - 전체 훑기는 시작할 때와 `sweep_minutes` 마다.
  - 실패하면(서버가 꺼졌다, 권한이 없다) 그 바퀴의 싣기만 건너뛰고 홈과 요약에 알린다. 접수·처리·엑셀은 계속된다.
- **비밀값과 값**: 로그·요약·오류 메시지·`info` 에 URL 을 그대로 찍지 않는다 — 호스트·DB 이름·스키마만. 드라이버의 오류 글에 비밀번호가 섞여 나오지 않는지 시험한다.
  실패한 행의 값을 찍지 않는다 (표 이름과 수만).
- **이름·차량번호가 대상으로 간다** (`doc_field`, `doc_page_meta`, `prod_haul`, `eq_assignment_obs` …). 현장의 서버라는 전제다 — `DATA.md` 에 적는다.
  대상의 계정은 그 스키마에만 쓰는 전용 계정으로 (관리자 계정을 쓰지 않는다 — 안내만 한다).
- `publish --check` 는 쓰지 않고(상태 표도) 다른 범위의 수만 낸다 (잠금을 잡지 않는다 — 4.1). 종료 코드: 같으면 0, 다르면 1, 닿지 못하면 2.
- CLAUDE.md 의 "DB 쓰기는 `store.db.upsert()` 만"은 작업 DB 의 규칙이다 — 대상에 쓰는 것은 싣는 모듈 한 곳뿐이라고 문서에 적는다.

### 4.9 가린 쪽 그림

- **무엇을 가리나** — 정합 그림(템플릿 좌표) 위에서:
  1. 표 밖 필드 중 `kind: signature` 인 것과 `meta_key` 가 가릴 목록에 든 것. 목록의 기본은 `operator`·`vehicle_no`, 사이트 팩의 `site.toml` `[redact] meta_keys` 가 바꾼다.
  2. 템플릿의 **`redact`** 상자(새로, 선택): `redact: [{name: approval, bbox: [x0, y0, x1, y1]}, …]` — 템플릿이 아는데 필드가 아닌 자리
     (결재란, 행렬 양식 머리의 인쇄된 이름, 점검표의 인쇄된 등록번호 열). `template check` 가 쪽 안인지·넓이가 있는지 보고, `template preview` 가 그린다.
     **`redact` 는 기하다** — 동시 판(ADR 0018)은 판마다 따로 적는다 (판 B 는 표가 내려가 있다). `template variant` 는 기존 판의 `redact` 를 그대로 베끼므로
     끝에 "가릴 자리를 다시 확인하라"고 알린다.
  3. **글자 칸 전부** (표의 `handwritten_text` 열과 표 밖의 글자 필드) — 기본. 자유롭게 쓰는 칸에는 이름이 들어간다. `--keep-text` 면 남긴다 —
     그때는 `meta_key` 가 없는 이름 필드도 남는다는 것을 명령의 요약과 문서가 말한다.
  수 칸·✓ 칸·인쇄는 남는다.
- **어떻게**: 상자를 한 색으로 채운다 (흐리게 하지 않는다 — 되돌릴 수 없게). 표의 칸은 괘선까지 (템플릿의 칸을 안쪽 여백 없이 — `cells(inset=0)`. `doc_field` 의 상자는 4 px 안쪽이다).
  표 밖 필드와 `redact` 상자는 조금 넓힌다 (글씨가 상자를 넘는다) — 넓히는 폭은 `site.toml` `[redact] pad_px`, 기본값은 합성에서 잰 근거와 함께 상수로.
  출력은 PNG.
- **템플릿이 아는 자리만 가린다.** 표 위에 걸쳐 쓴 메모, 수 칸에 적은 이름, 템플릿에 적지 않은 인쇄는 남는다. 그래서:
  내보낸 그림은 **사람이 보고 나서 쓴다** (명령의 요약과 문서에 그렇게 적는다), 내보낸 폴더도 현장 데이터다 — 저장소 밖에, 명령은 저장소 안을 거절한다.
- 명령 `export masked-pages OUT --date D | --page-id ID…`: 적재된 쪽만. 파일 이름은 쪽 ID (원래 파일명을 쓰지 않는다). 정합 그림이 없으면(`save_aligned = false`)
  호모그래피로 원본에서 다시 편다 (`tools/printlayer.py` 가 하는 것과 같은 길). 요약: 쪽 수, 종류별로 가린 상자의 수, 내지 않은 쪽의 수 (이름·값 없이).
- 화면(홈·문서 화면)의 그림은 가리지 않는다 — 127.0.0.1 에서 검수하는 사람이 본다.

### 4.10 0007 의 뒷정리

### 단계 2 — 내보내기 모델과 일별 엑셀

할 일
- `export/` 패키지: 모델(4.2·4.3 — 순수 함수), 핸들러가 칸의 상태를 고쳐 말하는 메서드(점검표·가동 일보), 엑셀 쓰기, 한글 머리글 한 곳(4.5), 기록 파일과 원자적 쓰기(4.6).
- 템플릿의 `display` (로더·`template check`·`SITE_PACK.md`). `synth --display-names`.
- `minedocscan export excel [OUT] [--date | --from --to | --month] [--allow-in-repo]` — 이 단계에서는 일별 파일만. `OUT` 이 없으면 `[export] excel_dir`. 파이프라인 잠금.
- `openpyxl` 의존성.

수용 기준
- **모델이 DB 와 같다** — 합성 묶음(기본, 가동 일보 + 인쇄 층)을 `oracle` 로 돌린 DB 에서: 양식 시트의 칸이 4.2 의 표대로다 (쪽·표·행·열로 맞춰 — 확정인 칸은 `doc_field` 의 최종 값,
  메타 필드는 `doc_page_meta` 의 값), 행·열의 순서가 템플릿과 같고, 업무 시트의 행 수가 업무 테이블의 그 날짜 행 수와 같고 값 열이 4.2 의 둘째 표대로다.
- **요약의 수** — 그 날짜로 좁혀 직접 센 것과 같다: 쪽의 상태별 수, `xcheck_haul` 의 상태별 수, `xcheck_usage` 의 종류·결과별 수. (문서 수는 견주지 않는다. 검수 대기 칸의 수는 아래.)
- **확정되지 않은 값은 없다** — 같은 묶음을 `null` 로 돌리면 값이 있는 수 칸은 전부 검수 대기로 표시되고 **양식 시트·업무 시트의 어느 칸에도 기계 값이 없다.**
  신뢰도가 기준 아래인 값을 내는 가짜 인식기로 하루치를 돌려도 같다 (`machine_values = true` 일 때만 긴 표의 따로 둔 열에 있다 — 기본은 그 열도 없다).
  교차검증 시트의 횟수는 그 칸의 운반 행이 전부 확정일 때만 있고, 아니면 판정에 `(잠정)` 이 붙는다. 검수를 저장하면 그 칸이 값으로 바뀐다. 읽을 수 없음으로 저장하면 `판독 불가` 다.
- **핸들러가 말한 것** — 점검을 하지 않은 쪽(합성에 있다)은 ✓ 칸이 비고 쪽의 머리에 그 줄이 있다. 평일 쪽의 여백 행 ✓ 칸이 비어 있다 (`?` 가 아니다).
  가동 일보의 작업 표에서 검수 대기인 글자 칸은 `●` 이고, `oracle` 로 돌린 묶음에서는 그 칸에 값이 있다.
- **검수 대기 칸의 수** — 요약의 수 = 그 날짜의 양식 시트에서 `?`·`판독 불가` 인 칸의 수 (쪽의 머리의 수를 더한 것과도 같다).
  DB 와의 관계: 그 날짜의 적재된 쪽의 `pending` 필드 수 = 그 수 + 값이 있는 메타 필드 + 여백 행의 ✓ 칸 + 점검하지 않은 쪽의 ✓ 칸 + 작업 표의 글자 칸 (시험이 넷을 따로 세어 확인한다).
- **파일이 모델과 같다** — 쓴 파일을 `openpyxl` 로 되읽으면 모델의 모든 칸이 그 자리에 그 값·표시로 있다. 수는 수, 날짜는 글자다. 시트 이름이 31자 안이다.
- **바뀐 것만 쓴다** — 같은 DB 로 두 번 내보내면 둘째는 아무 파일도 쓰지 않는다 (수정 시각 그대로, 요약에 0). 운반 횟수 칸 하나를 검수하면 그 날짜의 파일만 바뀐다.
  기록 파일을 지우면 전부 다시 쓴다 (지우지는 않는다). 쪽이 없어진 날짜의 파일은 지워지고, 그 폴더에 따로 둔 파일은 남는다.
- **쓰지 못해도 죽지 않는다** — `os.replace` 가 `PermissionError` 를 내게 하면 그 파일은 "쓰지 못함"으로 세고 임시 파일이 남지 않으며, 다음 실행에 써진다. `OUT` 이 없으면 만들지 않고 알린다.
- `display` 가 있는 템플릿(`synth --display-names`)에서는 머리글과 시트 이름이 `display` 이고, 없는 템플릿에서는 `name`·`title` 이다. `display` 를 넣어도 `doc_field`(인쇄된 값 포함)·
  업무 테이블·`null` 리포트가 그대로다. 열 이름이 `display` 인 표는 `template check` 가 오류로 낸다.
- 저장소 안의 `OUT` 은 거절한다. 접수 폴더 안도. ISO 가 아닌 `work_date` 의 쪽은 파일이 되지 않고 수로 나온다. 파이프라인 잠금을 다른 프로세스가 잡고 있으면 `export excel` 은 한 줄로 알리고 끝난다.
- 점검표의 "모름"으로 검수한 행은 점검 시트에 이상 유·무가 없다. 점검표가 아닌 양식의 ✓ 칸(값 없이 유무만)이 `✓` 로 보인다 (시험이 `generic` 핸들러의 작은 템플릿으로).
- 지금의 합성 선택들의 출력 바이트가 그대로다 (`--display-names` 없이). 가동 기록의 둘째 장이 따로 한 행이다.

### 단계 3 — 월별 엑셀과 운반 표

할 일
- 월별 모델과 파일 (4.4): 날짜별 요약, 운반 표, 배차, 긴 표. `site.toml` 의 `[haul_table]`. `export excel --month`, 범위를 주지 않으면 일별과 월별 모두.

수용 기준
- **운반 표가 정답과 같다** — `oracle` 로 돌린 합성 묶음에서 (날짜·주야·자리·광종·편)의 값이 `truth.json` 의 일보 횟수와 같다. 일보를 내지 않은 차량(합성에 있다)의
  블록은 그 날짜에 **문서 없음**이고 빈 칸과 다르게 표시된다. 교차검증 불일치(합성이 일부러 넣는다)인 칸이 표시되고 값은 일보의 것 그대로다.
- **자리 미정** — 같은 차량의 일보가 한 장 더 있는 날(불변식 시험의 묶음에 있다 — 둘째 장의 자리는 비어 있다): 둘째 장이 `자리 미정` 블록에 있고 그 자리의 블록은 첫 장의 값이다.
  행렬 쪽이 없는 날(일보만 넣은 묶음): 일보가 전부 `자리 미정` 블록에 있고(쪽의 순서대로, 블록마다 출처) 자리의 블록은 **모름**이다. 그 쪽들의 값이 표 어디에도 없는 일은 없다
  (그 달의 일보 운반 행 가운데 값이 있거나 검수 대기인 것의 수 = 운반 표에서 값·검수 대기·판독 불가인 칸의 수).
  교차검증 시트에서 그 쪽들의 행은 자리가 `자리 미정` 이고, 횟수는 그 쪽의 운반 행이 확정일 때만 있다.
- **합계의 규칙** — 블록의 한 줄이 전부 확정이면 합계가 있고 값들의 합과 같다. `null` 로 돌린 묶음에서는 값이 있는 칸이 있는 줄의 합계가 비어 있고 표시된다.
  그 줄의 칸을 전부 검수하면 합계가 생긴다. 문서 없음·모름인 블록에는 합계가 없다. 줄 끝의 합계는 없다.
- 광종·편의 열 순서가 일보 템플릿의 행 순서와 같다. `[haul_table] columns`·`slots` 를 주면 그 순서가 되고, 거기에 없는 것도 뒤에 있다 (빠지지 않는다).
- 긴 표에 빈 칸 행이 없다 (값이 있거나 검수 대기인 행만). 가동 기록·교차검증·계기 검산·점검은 전부 있다.
- 날짜별 요약의 수가 날짜마다 직접 센 것과 같다 (단계 2 의 키). 달이 바뀌는 묶음(`generate(start=…)` 로 월말에 시작 — CLI 선택은 더하지 않아도 된다)은 달마다 파일이 하나씩이다.

### 단계 4 — 자동 내보내기와 화면

할 일
- 처리와 검수 저장이 건드린 것을 알리기 (4.7). 작업 스레드의 바퀴 끝에 내보내기, 더러운 날짜, 전체 훑기. `[export]` 설정과 환경변수, `info`.
- 홈의 내보내기 상태, 내려받기 (`/export/day.xlsx`, `/export/month.xlsx`), 홈과 문서 화면의 링크.

수용 기준
- 합성 접수 묶음(`synth --intake`)을 `excel_dir` 를 준 `watch --once` 로 끝까지 처리하면 날짜마다 일별 파일과 달의 파일이 있고 내용이 DB 와 같다 (되읽어 모델과).
  날짜를 기다리는 문서의 날짜를 정하고 다시 돌리면 그 날짜의 파일이 생긴다. 쪽을 버리면 그 날짜의 파일이 바뀐다.
- 한 번 더 `watch --once`: 아무 파일도 쓰지 않는다.
- **넉넉한 더러운 날짜** (전체 훑기를 끄고 — `sweep_minutes = 0`, 시작할 때의 훑기가 끝난 뒤에):
  - 가동 일보의 계기 값을 검수해 다음 날의 연속성 검산이 바뀌면 **다음 날의 파일도** 바뀐다.
  - 가동 일보의 장비명을 검수로 고치면 고치기 전 장비의 다른 날짜 파일도 따라온다.
  - 운반 횟수 칸 하나를 검수하면 그 날짜의 일별 파일과 그 달의 파일만 바뀐다.
  - 문서의 날짜를 다른 날로 옮기면 옛 날짜의 파일이 그 문서 없이 다시 쓰이고(쪽이 안 남으면 지워지고) 새 날짜의 파일에 들어 있다.
  - 문서가 다시 처리하다 실패해도 그 문서가 있던 날짜의 파일이 따라온다.
  - 위의 어느 경우에도, 끝난 뒤 전체를 훑으면 쓸 파일이 0 이다 (놓친 날짜가 없다).
- `serve`: 화면 스레드에서 검수를 저장하면 작업 스레드의 다음 바퀴에 그 날짜의 파일이 바뀐다 (신호로 순서를 맞춘다 — 시간을 재지 않는다). 검수 저장은 작업 스레드를 깨우지 않는다.
  다른 프로세스가 저장한 검수는 전체 훑기에서 잡힌다 (시계를 주입한다).
- 쓰지 못한 파일이 있어도 바퀴가 끝나고 다음 바퀴에 다시 한다. 엑셀 폴더가 없어져도 처리는 계속되고 그 자리에 폴더를 만들지 않는다. 홈의 수가 맞다.
- 내려받기: 받은 파일을 되읽으면 그 날짜의 모델과 같다. 달력에 없는 날짜 400, 쪽이 없는 날짜 404, 다른 출처의 요청은 지금처럼 막힌다. 서버 로그에 질의(날짜)가 없다.
- 설정이 없으면 아무것도 쓰지 않고 지금과 같다 (`watch`·`serve`·`run` 의 지금 시험이 그대로 통과). 알리는 것을 더한 뒤에도 DB 의 행과 `null` 리포트가 그대로다.
  설정의 `excel_dir` 가 저장소 안이면 한 줄로 알리고 쓰지 않는다. `run` 은 쓰지 않고 요약에 한 줄.

### 단계 5 — 통합 DB 로 싣기

할 일
- 싣는 표와 열의 목록(불변식 시험과 같이 쓴다). `publish/`: `schema.sql` 에서 대상의 표 만들기(형을 넓혀, 외래 키 없이), 범위와 지문, 갈아 끼우기(한 트랜잭션), 상태 표, `--check`, `--rebuild`.
  `psycopg` 는 여기서만.
- `minedocscan publish`, 작업 스레드의 바퀴 끝(4.8 — 더러운 범위, 실패하면 전체 훑기, 다시 연결하는 간격), 홈의 상태, `info`. CI 에 PostgreSQL 작업.

수용 기준 — 기본 `pytest` (PostgreSQL 없이)
- `psycopg` 가 없는 환경(CI 의 기본 작업은 `.[dev]` 만 설치한다)에서 `publish` 는 한 줄 안내와 종료 코드 2, `watch` 는 한 번 알리고 싣지 않는다. 다른 명령과 기본 `pytest` 는 전부 그대로다.
  `schema.sql` 의 문이 그대로다 (주석만 다르다).
- 대상의 DDL 을 만드는 함수가 `schema.sql` 에서: 싣는 표만, 싣는 열만, `REAL`·`INTEGER` 가 넓혀져 있고, 외래 키가 없고 기본 키가 있다 (글자열로 확인 — 서버 없이).
- 범위와 지문(순수 함수): 싣는 표의 모든 행이 세 범위 중 하나에 든다 (합성 묶음의 DB 에서). 같은 DB 면 같은 지문, 행 하나가 바뀌면 그 범위의 지문만 바뀐다.
  `--fresh` 로 다시 만든 DB 의 문서·날짜 범위의 지문이 같다.
- **연결 함수를 바꿔 끼운 시험** (`psycopg` 없이 — 비밀번호 표시 글자열이 든 예외를 던지는 가짜 연결): `watch --once` 는 접수·처리·엑셀을 끝내고 종료 코드 0, 요약에 "싣지 못함" 한 줄.
  `connect_timeout_s` 가 연결 함수에 넘어간다. 그 뒤 `retry_seconds` 안의 바퀴는 연결 함수를 다시 부르지 않고, 지나면 부른다 (시계 주입 — 벽시계를 재지 않는다).
  `publish` 명령은 종료 코드 2 와 한 줄. 그 출력과 홈의 상태에 비밀번호가 없다. `info` 에 호스트·DB·스키마만.

수용 기준 — PostgreSQL 이 있는 환경에서 (`pytest -m postgres`)
- **불변식** — 합성 묶음(기본 + 가동 일보)을 돌리고 `publish` 하면 싣는 표마다 대상의 행이 작업 DB 의 행과 같다 (싣는 열 전부, 실수까지 정확히).
  싣지 않는 표와 열은 대상에 없다.
- **바뀐 것만** — 바로 다시 `publish` 하면 갈아 끼운 범위가 0 이다. 운반 횟수 칸 하나를 검수하고 싣으면 그 문서와 그 날짜만 갈아 끼워지고 불변식이 선다.
- **결정과 다시 처리** — 문서 버리기·되살리기, 쪽 버리기, 날짜 바꾸기(다른 문서가 있는 날짜로도), 다시 스캔 의심 쪽의 세 선택을 하나씩 넣고 그때마다 처리 → 싣기 → 불변식.
  같은 날 점검표 두 쪽이 같은 장비를 적어 이기는 쪽이 바뀌는 경우, 일보의 자리가 다른 문서로 옮겨 가는 경우를 넣는다 (지울 것을 먼저 지운다).
  0007 의 불변식 흔들기에 싣기를 끼운 판 하나(`-m "slow and postgres"`): 걸음마다 **더러운 범위만** 싣고 견준다 (전체 훑기 없이 — 훑기로 넘어간 횟수를 센다).
  실패한 뒤 성공해 옛 `failed` 문서 행이 지워지는 걸음을 넣는다 (대상에서도 지워진다).
- **`--fresh` 뒤** — 작업 DB 를 지우고 다시 만든 뒤 싣으면 갈아 끼운 문서·날짜 범위가 0 이다 (내용이 같으면 지문이 같다). 작업 DB 에서 빠진 파일의 문서는 대상에서 지워진다.
- **한 트랜잭션** — 싣는 가운데에서 예외를 내면(주입) 대상은 싣기 전과 같다. 다음 싣기에서 불변식이 선다.
- **실을 수 없는 값** — 작업 DB 의 글자 열에 NUL 문자가 든 값을 직접 넣은 문서는 싣지 않고 수로 알리며(그 문서의 옛 행은 대상에서 지워진다), 나머지 범위는 실리고 그것들의 불변식이 선다.
- 실제 드라이버로 닫힌 포트(127.0.0.1)에 붙으면 `connect_timeout_s` 가 지켜지고 예외 글에 비밀번호가 없다.
- 스키마 버전이나 싣기의 판이 다른 대상은 거절하고 `--rebuild` 를 알린다. `--rebuild` 뒤 불변식. 대상의 표에 뷰를 걸어 두면 `--rebuild` 가 지우지 않고 그렇다고 알린다.
- `--check` 는 아무것도 쓰지 않는다 (상태 표도). 종료 코드가 같음 0 / 다름 1. 다른 프로세스가 파이프라인 잠금을 잡고 있어도 돈다. `publish` 와 `--rebuild` 는 그때 한 줄로 알리고 끝난다.
- 걸린 시간을 보고한다: 합성 30일치(`synth --days 30`)의 첫 싣기, 바뀐 것이 없을 때의 전체 훑기, 문서 하나가 바뀌었을 때.

### 단계 6 — 가린 쪽 그림

할 일
- 템플릿의 `redact` (로더·`template check`·`template preview`·`template variant` 의 안내·`SITE_PACK.md`), `site.toml` 의 `[redact]`. `synth --display-names` 가 합성 템플릿에 `redact` 상자 하나씩.
- `export masked-pages` (4.9).

수용 기준
- 합성 쪽(`synth --display-names --usage-logs`)에서: 가린 상자 **안**은 전부 한 색이고, 상자 **밖**의 화소는 정합 그림과 같다.
  서명·작성자·차량번호 필드, `redact` 상자, 글자 칸이 가려지고 수 칸·✓ 칸이 남는다. `--keep-text` 면 글자 칸이 남고 나머지는 가려진다.
  `--keep-text` 에서 `[redact] meta_keys` 에 장비명을 더하면 그 필드도 가려진다 (더하지 않으면 남는다).
- 필드의 상자를 넘어가게 쓴 글씨(시험이 정합 그림에 직접 그린다 — 상자 밖 `pad_px` 안)가 가린 그림에 남지 않는다. 기본 `pad_px` 의 근거를 주석으로 (합성 필드에서 글씨가 상자를 넘는 폭을 잰 수).
- 정합 그림을 저장하지 않은 DB(`save_aligned = false`)에서도 같은 그림이 나온다 (화소 차이는 보간만큼 — 평균 2 이하).
- 동시 판(`--usage-variants`): 판 B 의 쪽은 판 B 의 `redact` 상자로 가려진다. `template variant` 의 출력에 확인하라는 줄이 있다.
- 파일 이름에 원래 파일명이 없다. 요약에 이름·값이 없다. 저장소 안의 `OUT` 은 거절한다. 적재되지 않은 쪽은 내지 않고 수로 알린다. 다른 프로세스가 파이프라인 잠금을 잡고 있어도 돈다.
- `template check` 가 쪽 밖의 `redact` 상자와 넓이 없는 상자를 오류로 낸다. `template preview` 에 그 상자가 보인다. `redact` 를 넣어도 파이프라인의 결과가 그대로다.

### 단계 7 — 끝에서 끝까지, 문서

할 일
- 10절의 문서, ADR 둘. 깨끗한 환경에서 `pip install .` → `pytest`, 그리고 합성 접수 묶음으로 처음부터 끝까지:
  `synth --intake --usage-logs --print-layers --display-names` → `MINEDOCSCAN_EXCEL_DIR`·`MINEDOCSCAN_PUBLISH_URL` 을 준 `watch --once` → `doc date` → `watch --once` →
  `doc discard` → `watch --once` → 엑셀을 되읽어 확인, `publish --check` 가 0, `export masked-pages`.

수용 기준
- 위의 끝에서 끝까지가 한 시험으로 있다 (`-m "slow and postgres"`; PostgreSQL 이 없으면 싣기를 뺀 판이 `-m slow` 로).
  끝난 뒤: 일별·월별 파일이 DB 와 같고, 대상의 표가 작업 DB 와 같다.
- 그 엑셀이 견줄 묶음(`baseline`)을 `run` 한 DB 로 내보낸 엑셀과 **내용이 같다** — 견주는 것: 양식 시트의 칸, 업무 시트의 행, 운반 표.
  빼는 것: 요약 시트(접수 묶음에는 빈 쪽·버린 쪽·실패한 문서가 더 있다), 문서를 가리키는 칸(출처, 쪽 ID, 필드 ID, 쪽의 머리)과 쪽 번호에 기댄 순서 (0007 단계 6 과 같은 비교).
- 지금의 합성 묶음의 바이트, `null` 리포트가 그대로다. 기본 `pytest` 의 시간이 지금의 1.15배 안이다 (넘으면 무거운 것을 `slow` 로 — 무엇을 옮겼는지 보고한다).

## 6. 시험

- 전부 합성 데이터. 실제 문서의 이미지·이름·장비 번호·파일명을 시험에 넣지 않는다. 엑셀 폴더·가린 그림·기록 파일은 전부 `tmp_path` 로.
- 기본 `pytest`(torch·PostgreSQL 없음)는 OpenCV 5.0 과 하한 판에서 통과한다. `openpyxl` 은 하한 판 작업에도 설치된다 (하한 `3.1.0`).
- **PostgreSQL 시험은 표시 `postgres`** 로 떼고, 환경변수 `MINEDOCSCAN_TEST_PG_URL` 이 없으면 건너뛴다. 시험마다 새 스키마를 만들고 끝나면 지운다 (서로 섞이지 않게).
  CI 에 `postgres:16` 서비스 컨테이너를 쓰는 작업 하나 (`pytest -m postgres`, `slow` 인 것도 같이). 로컬에서 돌렸으면 서버의 판을 보고한다.
  서버 없이 되는 것(DDL 만들기, 범위와 지문, 닿지 않는 URL)은 기본 `pytest` 에 둔다.
- 엑셀의 시험은 파일의 바이트를 견주지 않는다 (1절 가) — 모델을 견주고, 파일은 되읽어 견준다.
- 시험에서 잠들지 않는다 (전체 훑기·다시 연결의 시계는 주입한다). 스레드를 쓰는 시험은 단계 4 의 하나뿐이고 신호로 순서를 맞춘다.
- **묶음을 되도록 새로 돌리지 않는다**: 지금의 세션 픽스처(기본 묶음의 `null`·`oracle`, 가동 일보 묶음의 `oracle`, 불변식 시험의 묶음)를 같이 쓴다.
  새로 돌려도 되는 것: 하루치(가짜 인식기, 가동 일보의 `null`), `--display-names` 의 한 번(결과가 그대로인지), 월말에 시작하는 이틀치. 접수 묶음을 끝까지 도는 것(단계 4 의 첫 기준, 단계 7)과
  싣기를 끼운 흔들기는 `slow` 다.
- 윈도우에서 다른 것: 열려 있는 파일은 바꿀 수 없다(4.6), 경로에 한글이 있다 — 한글 이름의 엑셀 폴더를 시험에 넣는다.

## 7. 지켜야 할 것

- **내보내기는 작업 DB 에 쓰지 않는다.** 스키마를 바꾸지 않는다. 파이프라인의 결과를 바꾸지 않는다.
- **확정되지 않은 값을 확정된 것처럼 싣지 않는다** (4.2). 합계는 확정된 줄만. 교차검증의 불일치를 맞춰 넣지 않는다 — 보여 준다 (ADR 0006).
- 엑셀·가린 그림은 현장 데이터다 — 저장소 밖에. 시험의 산출물을 저장소에 넣지 않는다. 화면과 엑셀의 갈무리를 PR 에 붙이지 않는다.
- 비밀값(통합 DB 의 URL)은 환경변수로만 받고, 어디에도 찍지 않는다. `watch`·`serve` 의 로그는 지금처럼 수와 문서 ID 만.
- 가린 그림은 "템플릿이 아는 자리만"이다 — 명령과 문서가 그렇게 말한다. 가렸다는 이유로 저장소·이슈에 넣어도 된다고 적지 않는다.
- 현장에 관한 것(편의 순서, 자리의 순서, 가릴 메타 키, 표시 이름)은 사이트 팩으로. 코드에 적지 않는다.
- 사용자가 엑셀 폴더에 둔 파일을 지우거나 덮지 않는다 (이름 규칙에 맞는 것만 쓰고, 기록 파일에 있는 것만 지운다).
- `CLAUDE.md` 의 작업 규칙을 따른다.

## 8. 사람이 할 일 (실데이터와 통합 DB 서버가 있는 곳에서)

PR 이 합쳐진 뒤, 순서대로.

1. 템플릿에 `display` 를 적는다 — 실제 양식에 인쇄된 머리글대로 (양식·열·행·표 밖 필드). `template check`.
2. 엑셀 폴더를 정해 `[export] excel_dir` 에 넣고 `serve` 를 띄운다. 하루치를 처리해 **일별 파일을 종이와 나란히** 본다 (가능하면 현장 담당자와):
   종이와 견주기 쉬운가, 빠진 것·필요 없는 것, 표시(`?`·`●`·`✓`·`–`·`–?`·`판독 불가`·`(잠정)`)가 읽히는가.
3. 월별 파일의 **운반 표를 현장의 월별 작업일보 입력 시트와** 견준다: 편의 순서와 이름, 차량 블록의 순서를 `site.toml` 의 `[haul_table]` 로 맞춘다.
   그 시트에 붙여 넣을 수 있는 모양인가, 무엇이 다른가 (2단계에서 쓸 것이다). 자리 미정 블록이 얼마나 생기는가.
4. 통합 DB 서버에 전용 계정과 스키마를 만든다 (관리자 계정을 쓰지 않는다). `MINEDOCSCAN_PUBLISH_URL` → `publish --check` → `publish`.
   가진 전체 묶음으로 첫 싣기에 걸린 시간과 행 수를 본다. 서버를 끈 채로 스캔해 보고, 켠 뒤 따라오는지 본다.
5. 양식마다 `redact` 상자를 적는다 (결재란, 행렬 양식 머리의 인쇄된 이름, 점검표의 인쇄된 등록번호 열 — 판이 둘이면 판마다). 양식마다 한 쪽씩 `export masked-pages` 로 내어
   **눈으로 본다** — 가려지지 않은 이름·번호가 있는가, 글씨가 가린 상자를 넘는가 (`[redact] pad_px`).
6. 엑셀 폴더와 통합 DB 가 무엇을 받는지 현장에 알린다 (이름·차량번호가 들어 있다). 정답을 만드는 사람은 엑셀을 보지 않고 대기열에서 넣는다.

**돌려줄 수치와 의견** (이름·번호·파일명 없이): 일별 파일을 종이와 견준 쪽 수와 다르게 보인 칸의 수(있으면 종류), 현장 담당자가 고쳐 달라는 것,
운반 표와 현장 시트의 모양 차이, 자리 미정 블록의 수, 첫 싣기의 시간·행 수와 바퀴마다의 싣기 시간, 서버가 꺼졌을 때의 동작, 가린 그림에서 가려지지 않은 자리의 종류(메모·수 칸의 이름·인쇄)와
맞는 `pad_px`, 엑셀이 열려 있어 쓰지 못한 횟수.

## 9. 열린 질문과 기본값

| 질문 | 기본값 |
|---|---|
| 작업 DB 를 PostgreSQL 로 옮길까 | 옮기지 않는다. SQLite 그대로, 통합 DB 에는 싣는다 (4.8). 2단계의 설계가 정해진 뒤 다시 볼 수 있다 |
| 2단계가 직접 입력한 값을 어디에 두나 | 여기서 정하지 않는다. 실은 표는 이 프로그램이 갈아 끼우므로 2단계는 읽기만 하고, 자기 표에 적어 뷰로 합친다 — `ROADMAP.md` 의 "2단계와의 접점"을 그렇게 고친다 |
| 검수 대기 칸의 기계 값을 엑셀에 보일까 | 싣지 않는다. `machine_values = true` 일 때만 긴 표의 따로 둔 열에 |
| 합계 | 한 차량의 한 줄이 전부 확정일 때만. 값으로 (수식 아님). 차량을 가로지른 합은 두지 않는다 |
| 운반 표의 값 | 일보(차량별)의 횟수. 행렬과 다르면 표시만 한다 |
| 자리를 모르는 일보 | `자리 미정` 블록에 싣는다 (잃지 않는다). 그 날짜의 빈 자리는 `모름` |
| 엑셀의 파일 단위 | 하루 한 파일(양식마다 시트) + 한 달 한 파일. 문서 유형마다 파일을 나누지 않는다 (`PRIOR_WORK.md` 의 요구사항 표에 그렇게 고쳐 적는다) |
| 날짜의 표현 | 글자(ISO). 엑셀의 날짜 형식을 쓰지 않는다 |
| 날짜가 없는 문서(날짜를 정할 문서·실패한 문서) | 엑셀에 없다. 홈에서 본다 |
| 쪽이 없어진 날짜의 파일 | 지운다 (기록 파일에 있는 것만) |
| 엑셀이 열려 있어 못 쓰면 | 그 파일만 건너뛰고 다음에 다시. 다른 이름으로 쓰지 않는다 |
| 엑셀을 보호(잠금)할까 | 하지 않는다 (필터·정렬을 막는다). 요약에 사본이라고 적는다 |
| `serve` 가 도는 중의 명령 | 쓰는 것(`export excel`·`publish`·`--rebuild`)은 거절한다 (잠금) — 설정이 있으면 `serve` 가 하고 있고 엑셀은 홈에서 내려받는다. 읽기만 하는 것(`publish --check`·`export masked-pages`)은 된다 |
| `run` 뒤의 내보내기 | 하지 않는다. 명령을 따로 친다 |
| 싣는 단위 | 한 번의 싣기가 한 트랜잭션. 문서·날짜 단위 지문으로 바뀐 것만 |
| 실을 수 없는 값이 있는 범위 | 싣지 않고 대상에서 지운다. 수로 알린다 |
| 검수 대기 칸의 수 | 모델이 `?`·`판독 불가` 로 낸 칸의 수 (DB 의 `pending` 수가 아니다) |
| 대상의 외래 키 | 걸지 않는다 |
| 싣는 열 | 작업 DB 의 열에서 시각·요청 번호·로컬 경로를 뺀 것 (0007 의 불변식이 빼는 열) |
| 전체 훑기의 간격 | 30분 (엑셀·싣기 따로 설정) |
| 가린 그림의 글자 칸 | 기본으로 가린다 (`--keep-text` 로 남긴다) |
| 가리는 방법 | 한 색으로 채운다. 흐리게 하지 않는다 |
| 화면의 그림 | 가리지 않는다 (`PRIOR_WORK.md` 의 "화면으로 내보낼 때"는 밖에 보일 그림을 말한다고 고쳐 적는다) |
| 같은 초의 같은 결정 | 그대로 둔다 (4.10) |
| `dup_min_sim` | 0.80 그대로. 근거 수치만 고친다 |
| 설치 파일·사용 설명서·시험 성적(M6), 가상의 다른 양식(V2) | 다음 지시서 |

## 11. 끝나고 보고할 것

- 단계별로 무엇을 만들었고 무엇을 만들지 않았는지. 수용 기준 중 충족하지 못한 것이 있으면 그것부터.
- 테스트 수와 시간(기본 / 하한 판 / `slow` / `postgres`). PostgreSQL 시험을 어디서 돌렸는지(로컬·CI, 서버의 판).
- 지금의 합성 묶음의 바이트, `null` 리포트, DB 의 행이 그대로인지 (알리는 것을 더한 뒤에도).
- 칸의 상태 두 표를 어떻게 구현했는지 (4.2 와 다르게 정한 줄이 있으면 그것부터), 엑셀의 시트와 열의 목록.
- 합성 하루치의 일별 파일을 만드는 시간과 크기, 30일치의 전체 훑기 시간(엑셀·싣기), 바뀐 것이 없을 때와 하나 바뀌었을 때. 더러운 범위만 싣다가 전체 훑기로 넘어간 횟수(흔들기에서).
- 가린 그림: 넓히는 폭과 그 근거.
- 4절에서 벗어난 것이 있으면 무엇을 왜.
- 브라우저에서 직접 확인한 것과 확인하지 못한 것 (단계 1 의 크게 보기, 단계 4 의 내려받기). 엑셀 프로그램으로 직접 열어 보지 못했으면 그렇다고.
