## 0. 이 문서를 쓰는 법

> `CLAUDE.md` 와 `docs/tasks/0012-site-pack-on-real-data.md` 를 읽고 단계 1부터 5까지 이어서 진행해. 다 끝나면 PR 을 하나 열고 결과를 보고해.

- **이 작업의 주된 산출물은 저장소 밖에 있다** — 실제 사이트 팩(템플릿·기준 이미지·인쇄 층·기준 수치). 저장소의 PR 에는 문서(수만), 그리고 실데이터에서
  막혀 고친 도구의 코드와 그 합성 시험만 들어간다. 사이트 팩은 zip 으로 사용자에게 돌려준다 (`SendUserFile` — 4.7).
- main(판 1.1.0)에서 시작한다. 브랜치 `feat/site-pack-real`, PR 하나, 단계마다 커밋 하나 (커밋 제목에 단계 번호, 단계마다 `pytest`·`ruff check .` 통과 —
  코드를 고치지 않은 단계는 문서 커밋만).
- 단계 사이에 멈추지 않는다. 다만 실데이터를 받지 못했거나, 4절을 바꿔야 하거나, 파이프라인의 규칙(정합·판정·인식의 임계값)을 고쳐야 하면 거기서 멈추고 묻는다.
- 이 작업은 **실데이터가 있는 세션에서만** 한다. 실데이터는 이 세션 안(저장소 밖 경로)에만 두고, 화면으로 본 것(미리보기·쪽 그림·잘라 본 칸)은 어디에도
  옮기지 않는다 (7절).
- **사람의 판단이 들어가는 입력은 하지 않는다**: 검수(`reviews.jsonl`), 결정(`decisions.jsonl`), 라벨(`labels/pages.json`), 장비명 대응표
  (`[equipment.aliases]`), `[site] name`. 정답은 사람이 만든다 — 기계가 만든 정답으로 평가하면 평가가 아니다 (ADR 0007).

## 1. 왜 하는가

**(가) 실데이터로 아직 한 번도 전체를 돌리지 않았다.** 지금 사이트 팩(템플릿 6종)과 기준 수치는 문서 30건·110쪽(2024-07 의 일일 점검표 27일치 +
하루치 묶음 3일치)뿐이다. 공유 드라이브의 `mine-docscan/DB_scans` 에는 하루치 묶음 PDF 가 약 170개 있다 (2024-10 – 2025-03, 약 1.3 GB — 보통 날은
6–10 MB 로 30쪽 안팎, 주말·휴일은 1–3쪽). 전체 묶음 운용(`run … --skip-existing`, `report --by-month`, `pages --status unknown_form --thumbs`)은
[0002](0002-full-archive-and-evalset.md) 에서 만들었지만 돌리는 것은 사람의 일로 남았다. 그래서 모르는 것:
- 양식마다 몇 쪽인가, 달마다 양식이 바뀌었나(개정판 — ADR 0010), 정합이 실패하는 쪽은 몇인가.
- **양식을 못 찾은 쪽(`unknown_form`)이 무엇인가** — ROADMAP M1 은 관리 계열 양식(선광 작업일지, 경비 근무일지, 전기 안전일지 …)이 묶음에 있다고
  적었지만 지금의 110쪽에는 없었다 (110쪽 모두 6종으로 분류). 공유 드라이브의 `스캐닝용 작업일지.pdf`(8쪽)는 그런 양식들을 **사진으로 찍은 견본**이다 —
  원근이 있어 기준 이미지로는 쓰지 않는다.

**(나) 가동 일보 세 양식이 아직 분류 전용이다.** 중기운행일보·점보 작업일보·로우더 작업일보(갱외)는 `regions: []` 라 쪽만 고르고 값은 하나도 적재하지
않는다. 그 템플릿을 만드는 코드(핸들러 `usage`, 값의 형식, 인쇄 층, 동시 판, 표 더하기, 소수·시각 모델)는 0005·0006·0011 에서 다 들어갔고, 남은 것은
**사이트 팩의 템플릿** — 0006 8절 1–4 의 순서다. 0006 을 검증할 때 만든 초안 템플릿은 남아 있지 않다. 그때 잰 것 (실제 3일치, 가동 일보 40쪽):
- 중기운행일보 30쪽 중 5쪽이 **판 B**(표가 8–12 px 아래, 줄 간격도 다름 — 같은 날 섞여 쓰인다). 판 A 하나로는 4쪽 정합 실패, 1쪽은 칸이 어긋난 채 통과했다.
- 칸 안의 인쇄(작업량의 "하단: _ 대", 근무 시각의 "~", 계기의 "시작:")는 인쇄 층 없이는 빈 칸도 늘 검수 대기였다 (작업량 48/48, 근무 시각 9/9).

**(다) 엑셀과 가린 그림이 실제 양식에서 쓸 만하지 않다.** 실제 템플릿의 열 이름은 전부 영문 식별자다 — 엑셀의 시트·표·열 이름이 그대로 나온다
(`display` 가 없다). 가릴 상자(`redact`)도 없다 — 가린 그림은 표 밖 필드만 가린다 (0008·0009 8절).

## 2. 끝났을 때 되는 일

- 공유 드라이브의 묶음 전부가 사이트 팩으로 돈다: 양식 × 달의 쪽 수, 적재·분류 전용·정합 실패·양식 없음, 남은 `unknown_form` 쪽이 무엇인지 (목록과 까닭).
- 가동 일보 세 양식이 **적재된다** — 표마다 `role`(meter·shifts·tally·activities), 칸마다 `format`, 표 밖 필드(장비명·작성자·서명 …), 인쇄 층,
  중기운행일보의 판 B(다른 양식에도 섞인 판이 있으면 그것도). `eq_usage_daily`·`prod_tally` 에 행이 생기고 `readings`·`usage-check` 대기열이 돈다.
- 묶음에서 찾은 관리 양식(10쪽 이상인 것)이 `generic` 핸들러로 적재된다 — `doc_field`, 엑셀의 양식 시트, 통합 DB 의 `doc_field` 까지 (V2 가 합성으로
  보인 길 — 코드 변경 없이).
- 모든 템플릿에 한글 표시 이름(`display` — 종이에 인쇄된 머리글대로)과 가릴 상자(`redact`). 엑셀의 시트·표·열이 한글로 나온다.
- 회귀 기준이 새 템플릿을 담는다 (리눅스 — 4.6). 사용자는 새 사이트 팩 zip 을 받는다.

## 3. 범위

하는 것
- 실데이터 받기와 전체 묶음 목록(4.1), 가동 일보 세 양식의 템플릿(4.2), 관리 양식의 템플릿(4.3), 표시 이름·가릴 상자(4.4), 다시 돌리기와 기준(4.6),
  사이트 팩 돌려주기(4.7). 실데이터에서 막힌 **도구**(템플릿 도구·목록·미리보기 …)의 작은 고침과 그 합성 시험(4.5).

하지 않는 것
- 검수·결정·라벨·장비명 대응표·`[site] name` 의 입력 (0절 — 8절의 사람의 일).
- 인식기 학습과 자동 적재 기준 (정답이 없다). `[recognize.*]` 설정을 바꾸지 않는다 — 기본 `null` 그대로.
- 관리 양식의 **업무 테이블**(새 핸들러). 어느 값이 업무 행이 될 만한지는 목록으로만 남긴다 (11절) — 다음 지시서.
- 파이프라인의 판정 규칙(정합 품질, 값 유무, ✓ 판정, 다시 스캔 서명의 임계값)을 바꾸는 것. 바꿔야 하면 멈추고 묻는다 (0절).
- 운반·점검표 양식의 인쇄 층 (M1 — 숫자 정답이 생긴 뒤).
- 2단계(대시보드 — [0013](0013-stage2-dashboard.md)).
- 윈도우 현장 PC 의 회귀 기준 (8절).

## 4. 설계

### 4.1 실데이터와 전체 묶음 목록

받을 것 (세션의 저장소 밖 경로에 — 예 `~/real/`):

| 무엇 | 어디서 | 비고 |
|---|---|---|
| 지금의 사이트 팩 | 사용자가 준다 — 사이트 팩 zip (템플릿 6종·`labels/pages.json`·`expected/regression.json`, 16개 파일, 약 3.5 MB. 이 지시서를 쓴 세션이 2026-10-22 에 사용자에게 보냈다) | 공유 드라이브에는 아직 없다. 받지 못하면 멈추고 묻는다 |
| 회귀 기준의 입력 | 같이 보낸 점검표 zip(2024-07 의 27개 PDF와 정답 CSV, 약 14 MB) + `DB_scans` 의 그 3일치 | `site.toml` 과 README 가 상대 경로를 적어 둔다 |
| 하루치 묶음 전부 | 공유 드라이브 `mine-docscan/DB_scans` — Google Drive 커넥터의 내려받기 | 내려받기 한 번에 10 MB 까지다. 넘는 파일(몇 개)은 건너뛰고 이름을 적어 사용자에게 받는다. 커넥터가 없으면 멈추고 묻는다 |

- 내려받은 결과는 큰 도구 결과로 파일에 저장된다 (base64 의 JSON) — 디코딩해서 PDF 로 쓴다. **파일 내용을 대화에 올리지 않는다.**
- 디스크: PDF 약 1.3 GB, 정합 그림이 쪽당 약 0.5 MB 다 — 모자라면 달 단위로 돌리고 끝난 달의 `aligned/` 는 인쇄 층·미리보기에 쓸 양식만 남긴다.
  시간: 쪽당 약 1초 (CPU) — 전체 한 번이 한 시간 남짓이다. 템플릿을 다듬는 동안은 몇 날짜만 돌리고 전체는 단계 끝에서.
- 목록: 지금의 사이트 팩 그대로 `run <묶음 폴더> --skip-existing` → `report --by-month`, `pages --status unknown_form --thumbs`,
  `pages --status align_failed --thumbs`. 양식 없는 쪽은 미리보기를 보고 **양식별로 묶는다** (빈 쪽·사진·한 번만 나온 종이는 따로). 묶는 데 도구가
  필요하면 세션 안의 일회용 스크립트로 한다 — 저장소에 넣는 것은 다른 현장에도 쓸 도구일 때만 (4.5).

### 4.2 가동 일보 세 양식

[SITE_PACK.md](../SITE_PACK.md) "가동 일보 템플릿을 만드는 절차"와 0006 8절 1–3 을 그대로 따른다. 요약:
1. 분류 전용 그대로 전체를 돌린 뒤 `template print-layer` (판이 섞였을 수 있는 양식의 첫 층은 `--percentile 50` — 괘선을 잡는 데만, 쪽 수는 홀수로).
   요약의 "인쇄에 덮인 칸"과 `template preview --print` 로 잔상을 본다.
2. `template add-region --role …` 으로 표를 더하고 열·행·필드를 채운다. 인쇄가 든 칸은 떼어 내지 않고 그대로 둔다 (CLAUDE.md "실데이터에서 배운 것").
   표 밖 필드: 장비명 `meta_key: equipment`, 작성자 `meta_key: operator`, 서명 `kind: signature`, 그 밖의 글자는 `doc_field` 에만.
   칸마다 `format` (계기 `reading`, 근무 시각 `time_range`, 작업량 `integer` …) — 종이에 적힌 값을 보고 정한다.
3. 판이 섞였으면 `pages --status align_failed` 와 괘선 오차의 분포로 찾고 깨끗한 쪽으로 `template variant` → 같은 `family` + `concurrent: true`.
   판마다 그 판으로 적재된 쪽만으로 **백분위 75** 의 인쇄 층을 다시 만들어 `print_image` 에 적는다 (첫 50 층은 버린다).
4. `template check` 오류 0 → 그 양식이 든 날짜 몇 개로 `run --fresh` → 미리보기(`--scan`)로 칸이 글씨에 맞는지 본다 → 전체.

판정 규칙·임계값은 그대로다. 템플릿으로 풀리지 않는 것이 나오면(새 종류의 인쇄, 표가 한 쪽에 셋 이상 붙은 판 …) 멈추고 묻는다.

### 4.3 관리 양식

- 4.1 의 묶음에서 **10쪽 이상**인 양식마다 템플릿 하나 — [SITE_PACK.md](../SITE_PACK.md) "새 양식을 추가하는 절차" (`template init` → `add-region` → 열·행 →
  `check`·`preview`). 핸들러는 `generic` — 값은 `doc_field` 에만 간다 (업무 테이블은 3절에서 뺐다).
- 기준 이미지는 묶음의 스캔 중 글씨가 적고 반듯한 쪽 (견본 PDF 는 사진이라 쓰지 않는다). 돌아서 들어온 B5 가로 양식이면 `--rotate`.
- 칸의 종류: 숫자로 적는 칸은 `handwritten_number` + `format`(정수·소수·시각 — 종이를 보고), ✓ 를 적는 칸은 `checkmark`, 나머지는 `handwritten_text`,
  서명·결재는 `signature`. 날짜 줄이 있으면 월·일 필드(`meta_key: date.month`·`date.day` — 대조에만 쓰인다).
- 달마다 모양이 바뀌었으면(`report --by-month` 의 정합 실패·괘선 오차) 개정판 — `family` + `valid_from`/`valid_to` (ADR 0010). 같은 날 섞이면 4.2 의 3.
- 10쪽 미만인 양식, 빈 쪽, 사진, 다른 종이는 템플릿 없이 목록으로 (11절).

### 4.4 표시 이름과 가릴 상자 (모든 템플릿 — 지금의 셋 포함)

- `display`: 양식·표·행·표 밖 필드에 **종이에 인쇄된 머리글대로** ([SITE_PACK.md](../SITE_PACK.md) "표시 이름" — 열 이름 `display` 는 쓰지 않는다,
  동시 판끼리 같아야 한다). `export excel --date …` 로 그 날짜의 일별 파일을 만들어 시트·표·열 이름이 한글로 나오는지 본다 (파일은 저장소 밖).
- `redact`: 필드가 아닌 가릴 자리 — 결재란, 행렬 양식 머리의 인쇄된 이름, 점검표의 인쇄된 등록번호 열 … ([SITE_PACK.md](../SITE_PACK.md) "가릴 자리",
  판마다). `export masked-pages OUT --date …` (기본 넓힘 48 px)로 양식마다 하루치를 내어 **모든 쪽을 눈으로** 본다 — 이름·차량번호·등록번호가 남은
  쪽의 수를 센다 (남으면 상자를 넓히거나 더한다, 끝까지 남는 것은 11절에 까닭과 함께).

### 4.5 도구를 고칠 때

- 실데이터에서 막힌 것이 **도구**(템플릿 도구, `pages`·`report`, 미리보기, 내려받은 파일 다루기가 아닌 것)면 고친다. 같은 경우를 합성으로 다시 만든
  시험과 함께 (`tools/synth*.py` 의 선택이나 시험 안의 작은 합성 — 기존 합성의 바이트는 그대로). 실제 문서를 `tests/fixtures/` 에 넣지 않는다.
- 파이프라인의 결과를 바꾸는 고침(정합·분류·값 유무·핸들러)은 하지 않는다 — 멈추고 묻는다 (0절). 템플릿의 내용으로 풀 수 있는 것은 템플릿으로.
- 고친 것이 실데이터의 수치를 바꾸면(예: `report` 의 새 키) 기준을 다시 잡고 무엇이 왜 바뀌었는지 커밋 메시지에 (CLAUDE.md "변경은 수치로 판단한다").

### 4.6 다시 돌리기와 기준

- 끝에 전체를 `run --fresh` (스키마 8) — 4.1 의 목록을 새 사이트 팩으로 다시 낸다.
- 회귀 기준: 입력(점검표 27일치 + 묶음 3일치)은 그대로 두고 `regress` → 달라진 항목이 **새 템플릿 때문인 것만**인지 본다 (가동 일보·관리 양식의 쪽이
  분류 전용 → 적재, 새 업무 행, 지금의 셋은 그대로) → `--update`. 지금의 기준은 PyMuPDF 때의 것이라(0009 8절 1) PDFium 의 차이도 같이 들어온다 —
  ADR 0023 의 예상(값 유무가 바뀐 필드 19/10,274 안팎)과 견주어 보고한다.
- **이 기준은 리눅스의 것이다.** 윈도우의 OpenCV 는 같은 그림을 조금 다르게 정합한다 — 현장 PC 에서 다시 잡는다 (8절). 사이트 팩 README 에 그렇게 적는다.

### 4.7 사이트 팩 돌려주기

- 사이트 팩 전체(템플릿·기준 이미지·`print.png`·판의 `reference.png`·`site.toml`·`expected/`·README)를 zip 하나로 — 이름에 날짜 (`site-pack-<YYYYMMDD>.zip`,
  현장 이름은 사람이 붙인다). `labels/` 는 받은 그대로 넣는다. `reviews/`·`models/` 는 받은 것이 없으므로 없다.
- README 에: 양식 목록(이름·핸들러·표 수·판·인쇄 층의 쪽 수), 기준 수치의 입력과 OS(리눅스), 사람이 할 일(8절의 2–6) — 수와 이름(양식 이름)만.
- `SendUserFile` 로 보낸다 (`display: attach`). 공유 드라이브에 올리는 것은 사람이 한다 (8절).

## 5. 단계

### 단계 1 — 실데이터와 전체 묶음 목록

할 일: 4.1.

수용 기준
- 공유 드라이브 `DB_scans` 의 모든 파일이 셈에 든다: 내려받음 / 10 MB 를 넘어 건너뜀(이름 목록 — 사용자에게) / 열리지 않음 (`failed`, 까닭의 종류).
- 지금의 사이트 팩으로 받은 전부를 돌린 표: 달마다 양식별 쪽 수와 상태(적재·분류 전용·정합 실패·양식 없음·빈 쪽·실패), 양식마다 괘선 오차의 중앙·95 %.
- `unknown_form` 쪽을 양식별로 묶은 표: 묶음마다 쪽 수, 처음·마지막 달, 종이에 인쇄된 양식 제목(일반 명사 — "선광 작업일지" 같은), 10쪽 이상인가.
  빈 쪽·사진·다른 종이는 따로 센다.
- 지금의 셋(점검표·덤프트럭 일보·상차 행렬)의 정합 실패 쪽은 까닭별로 (판이 다른가, 스캔이 나쁜가) — 개정판이면 4.3 의 개정판 규칙으로 단계 3 에서.

### 단계 2 — 가동 일보 세 양식

할 일: 4.2.

수용 기준
- 세 양식(과 찾은 판)의 `template check` 오류 0.
- 전체 묶음에서 양식마다: 그 양식으로 분류된 쪽 중 적재 98 % 이상 (나머지는 까닭과 함께 — 스캔 상태, 사진 …), 괘선 오차 중앙 1.5 px 이하.
  판마다 고른 쪽 수, 두 판의 오차 차이가 1 px 미만인 쪽 수(`pages --variants`).
- 칸이 글씨에 맞는지: 양식·판마다 날짜를 고르게 10쪽씩 미리보기(`--scan`)로 보고 어긋난 칸의 수를 센다 — 0 이 될 때까지 템플릿을 고친다.
- 인쇄 층: 판마다 만든 쪽 수(20쪽 이상 — 그만큼 없으면 있는 만큼, 5쪽 미만이면 인쇄 층 없이), 백분위 75. 회귀 기준의 3일치에서 **인쇄 층을 켜기 전과
  뒤의 검수 대기 칸 수**(계기·근무 시각·작업량) — 0006 1절 가의 표와 같은 꼴로.
- 전체에서 `eq_usage_daily` 의 행 수와 `reading_kind`·`hours_basis` 의 분포, `readings` 대기열에 오르는 쪽 수, `usage-check` 의 항목 수,
  리포트의 `usage_dotted_suspect`. 대응표가 없으므로 `equipment_id` 는 비어 있다 — 그대로 (8절).

### 단계 3 — 관리 양식과 남은 양식 없는 쪽

할 일: 4.3 (그리고 단계 1 에서 찾은 개정판).

수용 기준
- 10쪽 이상인 양식마다 `template check` 오류 0, 적재 95 % 이상, 괘선 오차 중앙 1.5 px 이하, 미리보기 10쪽에서 어긋난 칸 0.
- 전체 묶음의 `unknown_form` 이 11절의 목록(10쪽 미만인 양식·빈 쪽이 아닌 것으로 갈리지 않은 쪽·사진·다른 종이 — 쪽 수와 까닭)뿐이다.
- 일별 엑셀 하루치에 새 양식의 양식 시트가 나온다 (V2 와 같은 길 — 저장소 밖에서 열어 본다).

### 단계 4 — 표시 이름과 가릴 상자

할 일: 4.4.

수용 기준
- 모든 템플릿에 양식·표·행·필드의 `display` (동시 판끼리 같다), `template check` 오류 0. 일별 엑셀의 시트·표 이름에 영문 식별자가 남지 않는다
  (`display` 를 둘 수 없는 것은 11절에).
- 양식(판)마다 하루치 가린 그림을 모두 보고: 이름·차량번호·등록번호가 남은 쪽 0 — 남으면 그 쪽의 수와 까닭(템플릿이 모르는 자리, 칸 위로 크게 쓴 글씨 …)을

### 단계 5 — 다시 돌리기·기준·문서·돌려주기

할 일: 4.6, 4.7, 10절.
