## 0. 이 문서를 쓰는 법

> `CLAUDE.md` 와 `docs/tasks/0009-release.md` 를 읽고 단계 1부터 7까지 이어서 진행해. 다 끝나면 PR 을 하나 열고 결과를 보고해.

- **PR 은 하나다.** 브랜치 `feat/release` 에서 단계 1–7 을 한 번에 한다.
- **단계마다 커밋 하나**(커밋 제목에 단계 번호), 단계마다 `pytest` 와 `ruff check .` 가 통과한 상태로 커밋한다. 문서는 마지막 커밋으로 따로 — 다만
  문서가 코드와 다른 곳을 고치는 것(4.1 아)과 그 단계의 코드가 바꾼 규칙의 설명은 그 단계에서.
- 단계 사이에 멈추지 않는다. 다만 4절을 바꿔야 하거나 수용 기준을 충족할 수 없으면 거기서 멈추고 묻는다.
- **파이프라인의 결과가 바뀌어도 되는 단계는 없다.** PDF 는 지금처럼 `pymupdf` 로 읽는다 (사람이 정했다 — 1절 나, 4.3). 어느 단계에서든 합성 묶음의 바이트,
  `null` 리포트, 작업 DB 의 행이 그대로여야 한다 (내보내기·싣기 쪽의 모양 — 4.1 가의 표시, 4.1 다의 `pub_meta` — 은 바뀌어도 된다). 달라지면 멈추고 묻는다.
- **스키마를 건드리지 않는다** (버전 8). 통합 DB 쪽의 판(`PUBLISH_VERSION`)은 올린다 (4.1 다).
- **윈도우 PC 는 작업 환경에 없다.** 윈도우에서 해야 하는 것은 CI 의 윈도우 작업(GitHub Actions `windows-latest`)으로 돌리고 그 기록을 본다 (4.4·4.5).
  푸시하고 CI 를 기다리는 일이 여러 번 생긴다 — 윈도우 작업만 따로 돌 수 있게(`workflow_dispatch` 등) 만든다.
- **실데이터와 통합 DB 서버도 없다.** 수용 기준은 전부 합성 데이터로 잡았다. 1절의 수치는 실제 3일치(83쪽)와 그것을 날짜·ID 를 바꿔 252일로 복제한 DB 로
  미리 재 본 것이고(값·이름 없이 수만), 현장에서 해 보는 일은 8절에 사람의 일로 적었다.
- **두 종류의 도구.** 프로그램이 쓰는 도구(`synth`, 템플릿 도구 …)는 지금처럼 `src/minedocscan/tools/`. **만들고 재는 도구**(묶음, 라이선스 목록, 명령 목록, 설명서의 HTML·갈무리,
  성적서, 규모 복제)는 저장소 루트의 `scripts/` — 설치되는 패키지에 들어가지 않는다 (묶음을 만드는 도구가 오프라인 제품에 들어가지 않게).
- **의존성.** `pymupdf` 는 그대로 — 이 프로그램을 AGPL-3.0 으로 낸다 (4.3). `psycopg` 의 하한을 3.2 로 (4.1 라). 개발용으로만 `markdown`·`playwright`(선택 의존성 `[docs]`).
- PostgreSQL 시험은 0008 과 같다 (작업 환경의 `/usr/lib/postgresql/16/bin` 또는 CI 의 `postgres:16`).
- 시작하기 전에 `pip install -e ".[dev,postgres]"` 를 이 체크아웃에서 다시 한다.

## 1. 왜 하는가

1단계 소프트웨어는 **독립 소프트웨어로 등록한다** (`CLAUDE.md`). 등록하려면 혼자서 설치·실행·시험이 되어야 하고, 설명서와 시험 결과가 있어야 한다.
지금은 개발자의 리눅스에서 `pip install -e` 로만 돈다. 그리고 PR #15 의 검토에서 남은 것이 있다.

**(가) 현장 PC 는 윈도우이고 외부망이 없다** (ADR 0003, `DATA.md` 의 여러 곳). 윈도우에서 돌려 본 적이 없다 — CI 는 우분투만이다.
- 설치 파일이 없다. 외부망이 없으니 `pip install` 이 PyPI 에 닿지 못한다 — 파이썬과 바퀴(wheel)를 다 담은 **오프라인 묶음**이 있어야 한다.
- `serve` 를 켤 때마다 사람이 명령을 쳐야 한다. 로그온하면 떠 있어야 한다.
- **출력의 글자**: 프로그램이 찍는 글에 한국어 윈도우의 코드 페이지(cp949)로 쓸 수 없는 글자가 여섯 가지 있다 — `—`(줄표, 거의 모든 안내 글),
  `–`, `−`, `≈`, `✓`, `〜`. 파이썬은 출력이 파일·파이프로 갈 때 코드 페이지로 쓴다 — 리눅스에서 `PYTHONIOENCODING=cp949` 로 흉내 내면 `—` 에서
  `UnicodeEncodeError` 로 죽는다. GitHub 의 윈도우 러너는 cp1252 라 한글부터 쓰지 못한다 (그래서 CI 로 잡힌다).

**(나) PDF 를 읽는 라이브러리와 이 프로그램의 라이선스 — 정했다: `pymupdf` 를 두고 이 프로그램을 AGPL-3.0 으로 낸다** (사람이 정했다, 2026-10-09 —
상용 라이선스를 사지 않고 공개하며 쓴다). `pymupdf` 1.28 은 **AGPL-3.0 또는 Artifex 의 상용 라이선스**다. 지금 이 프로그램은 `Proprietary` 로 적혀 있고(pyproject)
저장소는 공개이며 라이선스 파일이 없다 — `pymupdf` 와 묶어서 배포하는 순간 어긋난다. AGPL 로 내면 배포할 때 따르는 것: 프로그램 전체가 AGPL, 받는 사람에게 **대응 소스**
(설치·빌드 스크립트까지)를 같이 준다, 고지를 유지하고 받는 사람의 권리에 제한을 더하지 않는다, 고친 판을 네트워크로 쓰게 하면 그 사용자에게도 소스를 알린다
(13조 — `serve` 는 127.0.0.1 에서만 열리지만 화면에 자리를 둔다). 법률 판단과 남은 결정(저작권자, `-only`·`-or-later`, 외부 기여, 기술이전)은 기관의 일이다 (8절 1). 조사한 것:
- 다른 직접 의존성은 MIT·BSD·Apache-2.0, `psycopg` 는 LGPL-3.0 — 모두 AGPL-3.0 과 같이 배포할 수 있다. 바퀴 안에 같이 든 것 중 소스의 조건이 붙은 것도 있다:
  numpy 의 libquadmath(`LGPL-2.1-or-later` — numpy 바퀴의 라이선스 파일에 적혀 있다), GCC 런타임(`GPL-3.0-or-later WITH GCC-exception-3.1` — 예외가 소스의 의무를 푼다).
- **`pymupdf` 바퀴의 라이선스 파일은 한 줄**(`Dual Licensed - GNU AFFERO GPL 3.0 or Artifex Commercial License`, 64 바이트)이다 — AGPL 의 본문도, MuPDF 안에 든 것의 고지도 없다.
  PyMuPDF 의 sdist(88 MB — 대부분 시험용 PDF)에도 MuPDF 의 소스는 없다. 빌드할 때 그 판의 MuPDF 소스 묶음(`mupdf-<판>-source.tar.gz`, mupdf.com)을 받는다 (`setup.py`).
  그래서 묶음에 든 `pymupdf`(윈도우 바퀴 19.8 MB)의 대응 소스는 sdist 와 그 MuPDF 소스 묶음 둘이다 (4.3 다).
- **AGPL 의 본문**: gnu.org 는 이 작업 환경에서 닿지 않았다. GitHub 의 저장소들에 두 가지가 있다 — 주소가 `https` 인 지금의 FSF 판(34,523 바이트, sha256 `0d96a4ff…079abcb0`,
  서로 다른 두 저장소에서 같다)과 `http` 인 옛 판(34,520 바이트 — PyMuPDF·MuPDF 의 `COPYING` 과 다른 두 저장소에서 같다). 차이는 주소 세 줄뿐이다. 지금 판을 쓴다 (4.3 가).
- **잘린 PDF**(전송 중 끊긴 파일): 실제 묶음 하나를 50 %·90 %·99.9 % 로 자르면 `pymupdf` 는 셋 다 "복구해서" 0쪽으로 연다(`is_repaired`). 지금의 손상 방침
  (`[pipeline] damaged_pdf` — 0쪽이면 오류, 복구했으면 `fail`)과 접수의 "복구 없이 열린다"가 그것을 막는다. 바꿀 것이 없다. 실제 PDF 30개는 모두 복구 없이 열린다.
- 대안 **`pypdfium2`**(Apache-2.0 또는 BSD-3, PDFium)를 실제 3일치로 재 보았다 — 바꾸지 않기로 했으니 기록만 남긴다 (ADR 0023): 83쪽 모두 적재되지만 필드 10,274개 중
  **값 유무 19개**(수 칸 5, 글자 칸 12, 서명 2)·상태 16개·운반 8행·교차검증 8행이 바뀌고(화소의 평균 차 2.0 — 그림을 늘리는 방식이 다르다), 크기의 규칙이 올림이라
  합성 A4 쪽이 1654 → 1655 px, 잘린 PDF 는 열지 않고(`Data format error`), `save` 가 매번 다른 `/ID` 를 쓴다. 언젠가 바꾸면 회귀 기준을 다시 잡고 합성 PDF 를 직접 써야 한다.

**(다) PR #15 의 검토에서 남은 것** (고친 것은 연결 뒤의 시간 제한 하나다). 실제 3일치를 252일로 복제한 DB(6,972쪽, 135만 행 — 한 해 규모)로 쟀다:

| | 처음 | 바뀐 것 없는 전체 훑기 (기본 30분마다, 작업 스레드에서) |
|---|---|---|
| 싣기 (`publish`) | 34초, 최대 메모리 1.6 GB | 16초, 1.5 GB |
| 엑셀 (`export excel`) | 96초, 0.4 GB | 42초, 0.4 GB |

- 싣기의 메모리는 `CHUNK = 500` 이 **문서** 수라서다 — 한 해(252 문서)가 한 묶음으로 올라온다. 처음 싣기는 바뀐 범위의 행을 전부 쥐고 있다(`todo`).
- **가동 일보의 칸 하나를 검수하면 그 장비의 모든 날짜가 "더러워진다"**: 위 DB 에서 84/252일 → 엑셀 바퀴 30초, 싣기는 그 날짜들의 문서 전부. 운반 칸 하나는 1일, 0.1초다.
  0008 4.7 이 넉넉하게 잡았다 (지시서의 잘못). 연속성은 같은 장비의 이웃한 기록만 잇는다.
- **엑셀 파일 하나를 바꾸지 못하면**(윈도우에서 엑셀이 열고 있다 — 이 폴더를 쓰는 보통의 방식) 바퀴마다(3초) 그 날짜·달의 모델을 다시 만들고 임시 파일을 쓰고
  실패하고 한 줄을 찍는다 — 20초에 8줄.
- **운반 표**: 한 쪽에 (광종·편, 주야)가 같은 일보 행이 둘이면 뒤의 것이 앞의 것을 덮는다. 합성 DB 에서 그렇게 만들면 값 칸 71 → 70, 합 309 → 305 이고 그 줄의
  합계는 확정으로 나온다 (교차검증은 더한다). 실제 3일치에는 겹침이 0 이지만 `template check` 에 규칙이 없다.
- **기록 파일**(`OUT/.minedocscan-export.json`)을 UTF-16 으로 다시 저장하면 `UnicodeDecodeError` — `export excel` 은 트레이스백, `watch` 는 사람이 지울 때까지
  바퀴마다 "내보내지 못함". 0008 4.6 의 "깨졌으면 전부 다시 쓴다"가 되지 않는다.
- **사본의 주인을 모른다**: 실제 DB 를 실어 둔 스키마에 합성 묶음의 작업 폴더로 `publish` 하면 문서 3·날짜 3 범위를 지우고 합성 행으로 바꿨다 (한 트랜잭션,
  묻지 않는다). URL 이 환경변수에 있는 PC 에서 설명서의 합성 예제를 돌리면 일어난다. 엑셀 폴더도 같다 — 빈 작업 DB 로 훑으면 기록된 파일을 다 지운다.
- **가린 그림**: 실제 일보 30쪽(검증용으로 그린 초안 템플릿)에서 기본 넓히는 폭 16 px 로는 약 25쪽에서 작성자 이름의 첫 획이 상자 밖에 남았다. 48 px 로는
  이름이 30쪽 모두 가려졌다 (끝 획의 꼬리 2쪽). 번호를 칸 위에 크게 쓴 1쪽은 48 px 로도 일부가 남는다 — 상자 자체를 넓혀야 하는 경우다.
  동시 판 사이에 `redact` 가 같은지 보지 않는다 (판 B 에 상자가 없어도 사이트 팩이 읽힌다).
- **멈춰 버린 서버**: 연결은 살아 있는데 서버의 프로세스가 돌지 않으면(가상 머신의 일시 정지, 저장 장치의 멈춤 — 실험에서는 그 백엔드에 `SIGSTOP`) 서버가 거는
  시간 제한도, TCP keepalive 도 작동하지 않는다 (서버의 커널이 답한다). 풀릴 때까지 기다렸다 (153초까지 보고 풀었다). 망이 끊긴 경우는 91초에 `connection_lost` 로 끝난다 (고쳤다).
- 그 밖의 작은 것과 문서·시험의 빈틈 — 4.1.

**(라) 확장성을 보인 적이 없다** (ROADMAP V2). "양식은 데이터다"(원칙 1)지만 지금 적재되는 것은 실제 양식 세 계열(점검·운반·가동)과 그 합성판뿐이다.
새 양식이 **템플릿만으로** 들어가 엑셀·통합 DB 까지 나간다는 것을, 그리고 더 거친 글씨에서 분류·정합이 버티는지를 합성으로 보인다.
여기서 나오는 수치는 확장성의 증거이지 인식 정확도가 아니다 (`CLAUDE.md` "하지 말 것"). 그리고 인식기에 보내는 칸은 지금 형식이 없거나 `integer` 인 칸뿐이다
(`handlers/base.readable` — 소수·시각·계기 칸은 잉크가 있으면 검수 대기). 정답 인식기(`oracle`)도 그 칸만 받는다 — 수용 기준을 그것에 맞춘다 (4.6, 4.7).

**(마) 시험 결과가 흩어져 있다** — 여섯 CI 작업의 `pytest`, `regress`, `eval`, PR 마다의 검증. 등록 서류의 시험 성적서는 한 문서여야 한다.
합성으로 되는 것은 기계가 만들고, 실데이터 수치는 사람이 채울 칸을 명령과 함께 둔다.

## 2. 끝났을 때 되는 일

- 윈도우 PC 에서 (외부망 없이): 묶음 zip 하나를 풀고 `install.ps1` → `minedocscan selftest` 통과 → 로그온하면 `serve` 가 떠 있고 바탕 화면의 바로 가기로 홈이 열린다.
  `uninstall.ps1` 은 프로그램만 지우고 사이트 팩·보관 폴더·작업 폴더·엑셀 폴더·설정은 건드리지 않는다. 새 판의 묶음으로 다시 설치하면 올라간다.
- CI 에 윈도우 작업: 기본 시험 + 묶음 만들기 → 설치 → `serve` → 자가 시험 → 지우기. 묶음과 자가 시험의 결과가 CI 산출물로 남는다.
- 이 프로그램은 **`AGPL-3.0-or-later`** 다 (`LICENSE`·`NOTICE`·pyproject, `--version` 과 화면의 바닥). 설치 묶음 옆에 **소스 묶음**(이 프로그램과 묶음에 든 것 중
  소스의 조건이 붙은 것의 소스)이 같이 나온다. 제3자 라이선스 목록이 묶음에 들어가고, AGPL 과 같이 배포할 수 없는 라이선스가 묶음에 들어오면 CI 가 실패한다.
- `minedocscan selftest`: 합성 데이터로 설치가 제대로인지 3분 안에 확인하고 결과를 파일로 남긴다 (시험 성적서의 한 부분).

## 4. 이미 정한 것

### 4.1 0008 의 뒷정리 — 맞게, 그리고 안전하게

**가. 운반 표의 겹침.** `template check` 가 운반 일보(`haul`, role log)의 표에서 (광종, 편)이 같은 행이 둘 이상이거나 횟수 열의 `shift` 가 겹치면 오류로 낸다.
그래도 DB 에 겹친 행이 있으면(검사 전에 만든 템플릿) 월별 운반 표는 **더하지 않고** 그 칸에 `겹침` 을 적고 그 줄의 합계를 비운다. 교차검증 시트는 그대로.
범례의 `겹침` 줄은 **겹침이 있는 파일에만** 넣는다 (그래야 겹침이 없는 파일의 모델이 그대로다).
수의 보존: "값이 있거나 검수 대기인 일보 행의 수 = 표의 값·`?`·`판독 불가` 칸의 수 + `겹침` 칸이 덮는 행의 수".

**나. 기록 파일의 글자.** 바이트로 읽어 UTF-8 로 디코딩하지 못하면 "깨졌다"(전부 다시 쓴다)로 간다. 쓰는 것은 지금처럼 UTF-8.

**다. 사본의 주인 — 사이트 표식.** 표식 = 사이트 팩의 `site.toml` 의 **`[site] name`**.
- 자동 내보내기·자동 싣기·`publish`·`export excel` 은 `[site] name` 이 **적혀 있어야** 한다 (폴더 이름으로 대신하지 않는다 — 폴더를 옮기면 바뀌고, 두 사이트 팩의
  폴더가 다 `site` 일 수 있다). 없으면 자동 일은 시작할 때 한 줄로 알리고 끄고, 명령은 한 줄로 거절한다. `info` 가 보여 준다.
- 통합 DB: `pub_meta` 에 `site` 를 둔다 (`PUBLISH_VERSION` 2 — 판이 다른 대상은 지금처럼 `--rebuild` 를 알린다). 다르면 싣지 않는다: `PublishError`(종류 `other_site`,
  종료 코드 2). 글에 두 이름을 찍지 않는다 ("대상은 다른 사이트 팩의 사본입니다 — 맞는 대상인지 확인하고, 이 사이트로 바꾸려면 `publish --rebuild`").
  `--check` 도 같다. 자동 싣기는 그 바퀴의 실패로 (홈: "다른 사이트의 대상").
- 엑셀 폴더: 기록 파일에 `site` 를 둔다. 다르면 아무것도 쓰거나 지우지 않는다 (요약·홈: "다른 사이트의 폴더"). 기록 파일에 `site` 가 없으면(옛 기록) 받아들이고 적는다.
- **빈 작업 DB 는 지우지 않는다**: 작업 DB 에 쪽이 하나도 없으면 엑셀 폴더의 파일을 지우지 않는다 ("남겨 둔 파일"로 센다).
- 사이트 이름을 바꾸면: 엑셀은 기록 파일을 지우고(전부 다시 쓴다), 통합 DB 는 `publish --rebuild`. **평가셋의 분할 소금값이 이름을 기본으로 쓴다**
  (`SitePack.split_salt` — `[eval] split_salt` 가 없으면 이름) — 이름을 바꾸기 전에 `[eval] split_salt` 에 지금 이름을 적는다 (그러지 않으면 test 날짜가 바뀐다).
  `DATA.md` 에 적고, `info` 가 `split_salt` 가 이름을 따르고 있으면 그렇다고 적는다.
- `--rebuild` 는 대상 스키마에 `pub_meta` 가 있을 때만 이 프로그램의 표를 지운다. `pub_meta` 가 없는데 이름이 같은 표가 있으면 지우지 않고 알린다
  (이 프로그램이 만든 표가 아니다). `pub_meta` 도 표도 없으면 그냥 만든다.

**라. 멈춰 버린 서버 — 우리 쪽의 기다림의 상한.** 대상에 보내는 문장 하나(`execute`·COPY)마다 감시 타이머: `statement_timeout_s + 30초` 안에 돌아오지 않으면
`cancel_safe(timeout=5)`(psycopg 3.2 — 취소도 새 연결이라 멈춘 서버에서는 기다린다, 그래서 시간 제한을 준다)를 보내고, 그래도 돌아오지 않으면 그 연결의 소켓에
`shutdown()` 을 건다 (다른 스레드에서 `close()`·PQfinish 를 부르지 않는다 — libpq 가 쓰는 중이다) → 드라이버가 예외를 낸다 → 종류 `connection_lost`, 지금의 실패 경로.
- 시험은 서버를 멈출 수 없으니 **멈추는 TCP 중계**로 한다 — 시험 안에서 psycopg 와 PostgreSQL 사이에 두고, 신호를 주면 소켓을 연 채 아무것도 넘기지 않는다
  (서버의 커널은 살아 있는데 프로세스가 돌지 않는 것과 같다). **답을 기다리는 동안에** 멈춘다(느린 트리거로 문장 하나를 붙잡아 둔 뒤) — COPY 를 보내는 동안 멈추면
  리눅스의 `tcp_user_timeout` 이 먼저 끊어 감시 타이머를 시험하지 못한다.
- 중계를 풀면 클라이언트 쪽이 닫힌 것을 서버 쪽으로 넘긴다 (그래야 서버의 옛 트랜잭션이 끝나 잠금을 놓는다 — 다음 바퀴가 `lock_timeout` 에 걸리지 않는다).

**마. 가린 그림.**
- 넓히는 폭의 기본값을 **48 px** 로 (근거: 1절 다 — 실제 30쪽, 초안 템플릿. 가리는 쪽으로 틀리는 편이 낫다). 48 px 이면 이웃한 수 칸을 덮을 수 있다 —
  `export/masked.py` 의 "수 칸은 남는다"는 설명을 "넓힌 상자에 걸친 만큼은 가려진다"로. `SITE_PACK.md` 에 그 수치와 "상자 자체를 넓혀야 하는 경우"를 적는다.
- 같은 계열의 동시 판(`concurrent: true`)은 `redact` 의 이름 목록이 같아야 한다 — 다르면 사이트 팩을 읽을 때 오류 (`variant_key_diff` 와 같은 곳에서, 좌표는 판마다 다르다).
- `export masked-pages` 는 내보낼 쪽이 있을 때만 `OUT` 을 만든다.
- 저장소·접수 폴더·보관 폴더 안을 거절하는 것을 같게: `review export-crops`, `recognizer eval --errors` 도 `export excel`·`masked-pages` 와 같은 검사(`check_out_dir`)를 거친다
  (지금은 저장소 안만 본다 — `DATA.md:17` 이 적은 것이 맞게 된다).

**바. 더러운 범위의 구멍.**
- 쪽이 없는 문서(버린 문서)의 **문서 날짜**를 처리의 앞·뒤로 건드린 것에 남긴다 (`waiting_documents` 가 문서 날짜로 센다).
- `eq_equipment` 의 행을 바꾸는 처리(점검표 템플릿의 장비 행이 바뀌었다 — 모든 날짜의 점검 시트에 나온다)는 "전부"로 남긴다.
- 더러운 범위만 싣는 바퀴에서 대상의 표가 없어 새로 만들었으면(`res.created`) 더러운 범위만 실은 것으로 끝내지 않는다: 단계 1 에서는 그 자리에서 전체로 싣고,
  단계 2 뒤에는 새 조각 바퀴를 시작한다 (4.2 가).
- 키 충돌로 전체 싣기로 넘어가 성공했으면 그것을 전체 훑기를 마친 것으로 센다 (`last_sweep`, 단계 2 뒤에는 조각 바퀴도 처음부터).

**사. 작은 것들** (PR #15 의 검토 2절 7 과 그 뒤에 찾은 것).
- `describe_url`: URL 꼴인데 사용자 정보(`@`)가 없고 호스트 자리에 숫자가 아닌 포트나 경로 한 조각만 있으면(`postgresql://이름:비밀/db` — `@호스트`를 빠뜨렸다)
  읽을 수 없는 URL 로. 키워드 꼴의 `host`·`dbname` 에 `:` 이 있으면 `?`. 공백뿐인 `MINEDOCSCAN_PUBLISH_URL` 은 없는 것으로.
- `MINEDOCSCAN_DB_URL`(작업 DB): `sqlite:///…` 는 지금처럼 경로를 보이고, 그 밖의 URL(비밀번호가 든 PostgreSQL URL 을 잘못 넣었다)은 `describe_url` 로 —
  `info` 와 `store/db.py` 의 오류 글 둘 다 (0008 이전부터 그대로 찍혔다).
- `[publish]` 의 비밀값 검사를 대소문자 없이, `conninfo` 도. `[export] excel_dir` 이 글자가 아니면 `ConfigError`. 숫자 설정의 `nan`·`inf` 를 거절.
- **하위 명령 앞에 준 공통 옵션이 버려진다** — `export --work-root W excel OUT`, `review …`, `doc …`, `template …`, `recognizer …` 다섯 명령. 하위 파서가 기본값으로 덮는다.
  앞에 줘도 뒤에 줘도 같게 (하위의 공통 옵션은 기본값을 `argparse.SUPPRESS` 로). 시험은 다섯 명령 모두.
- `publish --check` 의 종료 코드: 같으면 0, 다르면 1, 닿지 못하거나 **설정이 틀리면 2** (지금은 URL·DB 가 없을 때 1).
- `--rebuild` 가 잠금으로 그만두었을 때의 글: 명령이면 "다시 실행하십시오"(지금은 "다음에 다시 합니다").
- `[haul_table]`: `columns` 의 각 항목을 `|` 의 양쪽에서 다듬은 뒤에 겹침을 본다. `[redact] meta_keys = []` 는 받되 `info` 가 "메타 필드를 가리지 않는다"고 적는다.
- 월별 운반 표의 주야 순서: `day`·`night` 가 아닌 이름은 이름 순으로 (지금은 프로세스마다 달라 파일을 다시 쓴다).
- `export excel --month` 에 `date` 가 다룰 수 있는 마지막 해의 12월(`OverflowError`), `--date` 의 `YYYYMMDD` 꼴: 다른 명령처럼 `YYYY-MM-DD` 만.
- 홈의 엑셀 내려받기 연결: 그 날짜에 쪽이 있는 문서에만 (지금은 쪽이 다 다른 날짜로 간 문서에도 있어 누르면 404 의 JSON 이 뜬다).
- 크게 보기: `Esc` 로 닫을 때 날짜 칸으로 초점을 옮기며 맨 위로 스크롤하지 않는다(`preventScroll`). `Ctrl`·`Cmd` 와 같이 누른 `R` 은 가로채지 않는다.

**아. 문서가 코드와 다른 곳** (PR #15 의 검토 3절): `DATA.md:17`(마의 마지막 줄로 코드가 맞게 된다), `ARCHITECTURE.md` 12.4 의 "결정 저장 | 남기지 않는다",

**자. 시험의 빈틈.**
- `--month`·`--date`·`--from/--to` 를 기록 파일이 있는 폴더에서 시험한다 (지금의 시험은 첫 호출이라 전체 훑기 — 선택을 무시해도 통과한다).
- **엑셀의 더러운 범위만 내보내는 흔들기** (`slow`): 검수(수·계기·근무 시각·메타·글자)·결정(날짜·버리기·되살리기)을 섞어 넣고 바퀴마다 "엑셀 폴더 = 그 DB 를 전부 내보낸 것"
  (기록 파일의 해시로 견준다). 싣기의 흔들기와 같은 묶음으로 같이 돌려도 된다.
- 가린 그림의 설정 검사(`[redact]` 를 읽는 것, 동시 판의 `redact` 이름)를 기본 `pytest` 로 (지금은 모듈 전체가 `slow`).
- `/export/day.xlsx`·`/export/month.xlsx` 를 HTTP 로 (머리글, Host 검사, 400·404). `on_touched` 를 `/api/check`·`/api/reviews` 로도.
- `test_template_drift_in_meter_checks_is_not_confirmed`: 행이 있다는 것부터 단언한다.

### 4.2 0008 의 뒷정리 — 규모

**가. 훑기를 달 단위로 나눈다.** 자동 내보내기·자동 싣기의 전체 훑기를 한 번에 하지 않고 **바퀴마다 한 조각**을 한다.
- 조각 = 달 하나(그 달의 날짜와 달 파일, 그 달에 쪽이 있는 문서와 그 달의 날짜 범위) — 달의 목록은 **작업 DB 의 달과, 기록 파일·대상에만 있는 달**을 합친 것 —
  그리고 마지막에 "날짜 없는 조각"(쪽에 날짜가 없는 문서, 통째 범위, 대상에만 있는 문서 키, 기록에만 있는 파일).
- 조각들을 한 바퀴 다 돌면 지금의 전체 훑기와 같다 (불변식 시험 — 흔들기에서 훑기를 조각으로).
- `sweep_minutes` 마다 한 바퀴를 시작하고, 그 바퀴는 작업 바퀴마다 한 조각씩 끝까지 간다 (`poll_seconds` 3초면 13조각에 40초쯤). 시작할 때도 조각으로 돈다
  (홈: "처음 훑는 중 3/13", 다 돌면 마지막 전체 훑기의 시각).
- 더러운 범위의 일은 지금처럼 그 바퀴에 같이 한다 (조각과 겹치면 한 번만).
- 대상의 표를 새로 만든 더러운 바퀴(`res.created`)는 새 조각 바퀴를 시작한다. 키 충돌로 넘어간 전체 싣기(한 트랜잭션)가 성공하면 그 조각 바퀴를 마친 것으로 센다 (4.1 바).
- 명령(`export excel`, `publish`)은 지금처럼 한 번에 전부다 — 메모리만 나에서 줄인다.
- 자동 싣기의 처음 싣기도 조각으로 간다 — 다 돌 때까지 대상은 일부만 있다. `DATA.md`·ADR 0021 에 적는다.

**나. 싣기의 메모리.** 지문을 범위 하나씩 낸다 — 바뀐 범위의 목록에는 (종류, 키, 지문)만 두고, 넣을 때 그 범위의 행을 다시 읽는다. 한 번에 메모리에 있는 행은
문서 하나와 날짜 범위 몇 개 몫이다. 한 트랜잭션이라는 것은 그대로. (처음 싣기는 행을 두 번 읽는다 — 시간 기준을 그만큼 넉넉하게.)

**다. 가동 일보의 더러운 범위를 좁힌다.** 연속성을 다시 계산하는 곳(`validate/usage.recompute_continuity` — 부르는 곳은 `UsageHandler.finalize` 와 `on_review`)이
그 장비들의 연속성 행을 **다시 계산하기 전과 뒤로 견주어 바뀐 행의 쪽**(행이 걸린 쪽과 가리키는 쪽 — `page_id`·`other_page_id`)을 돌려준다.
- 돌려주는 길: `on_review` 가 그 쪽들을 돌려주고 `review/store.save` 가 `touched` 에 그 쪽의 날짜·문서를 더한다. `finalize` 는 지금 돌려주는 요약에 그 쪽들을 더하고
  `Pipeline.finalize` 가 `touched` 에 더한다 (요약을 찍는 곳에는 수만).
- 장비(`refs`·`finalize(equipment=…)`)는 **어느 사슬을 다시 계산할지 고르는 데**에는 그대로 쓴다. 엑셀·싣기의 더러운 범위를 장비로 넓히는 것(`Touched.all_dates` 의 장비 부분)만 없앤다.
- 장비 이름을 고쳐 장비가 바뀐 경우(옛 장비의 사슬에서 빠지고 새 장비의 사슬에 든다)도 같은 견주기가 둘 다 잡는다.

**라. 엑셀의 다시 쓰기 간격.** 바꾸지 못한 파일은 `[export] retry_seconds`(기본 60초)가 지난 뒤에 다시 한다 — 그 사이의 바퀴는 그 파일의 모델을 만들지 않는다.
바퀴의 요약 줄은 "쓰지 못한 파일의 수"가 바뀔 때만 찍는다. 홈의 수는 그대로 보인다.

**마. 규모를 재는 도구와 기준.** `scripts/bigdb.py`: 합성 작업 DB(와 그 사이트 팩)를 복제해 한 해 규모로 만든다.
- **하루의 행 수를 실제(하루 약 5,400행)에 맞춘다** — 합성 하루는 약 600행이라(0008 12절: 30일 18,487행) 날짜만 늘리면 실제의 9분의 1 이다. 같은 날짜에 문서를 복제해
  밀도를 맞추고 날짜·ID 를 바꿔 252일로. **복제한 뒤 마무리(`finalize`)를 전부 다시** 한다 (옛 연속성·교차검증 행을 베끼면 다시 계산이 모든 사슬을 바꿔 수치가 틀린다).
- 재는 것 (같은 기계에서 고치기 전과 뒤): 바퀴 하나의 가장 긴 일(조각 하나 + 더러운 범위 — 엑셀·싣기 각각), 명령 `publish`(처음·바뀐 것 없을 때)·자동 싣기의 조각의 최대 메모리
  (하위 프로세스의 최대 RSS − import 만 한 기준선), 가동 일보의 칸 하나를 검수한 바퀴의 더러운 날짜 수.
- 기준: **바뀐 것 없는 조각 하나가 5초 안**(엑셀·싣기 각각 — 처음 훑기의 조각은 보고만), **최대 메모리 300 MB 안**(기준선을 뺀 것 — 지금 1.5–1.6 GB),
  **가동 일보의 칸 하나 → 더러운 날짜 3일 안**(지금 84), 명령 `publish` 의 시간은 고치기 전의 1.5배 안.
- 잰 수치는 `docs/test-report/scale-<날짜>.json` 으로 커밋한다 (성적서가 읽는다 — 4.9).
- 시험: `slow` 에 60일치 복제 — 벽시계가 아니라 **읽은 행 수와 `tracemalloc`** 으로, 조각 하나가 읽는 행 수가 날짜 수에 비례하지 않는다(30일·60일에서 같다).

### 4.4 윈도우에서 돈다

- CI 에 `windows` 작업: `windows-latest`, 파이썬 3.12, `pip install -e ".[dev,postgres]"`, 기본 `pytest`. 30분을 넘으면 무거운 것을 그 작업에서만 빼고(목록을 보고) 그래도 단계 5 의
  설치 시험은 같은 작업에서.
- **출력의 글자**: `cli.main` 의 처음에, 표준 출력·오류가 있고(`pythonw` 에서는 `None` 이다) UTF-8 이 아니면 UTF-8 로 다시 연다 (`reconfigure`, `errors="replace"` — 콘솔은 파이썬이
  이미 유니코드로 쓴다). 작업 스케줄러로 돌 때는 `serve --log-dir` 이 UTF-8 로 쓴다 (4.5 나 — 무엇을 찍기 전에 연다).
  시험: 윈도우 작업에서 명령을 **표준 출력을 파일 핸들에 묶어**(파이썬의 `subprocess` 또는 `cmd /c` — PowerShell 의 `>` 는 다시 인코딩해 시험이 되지 않는다) 러너의 기본
  코드 페이지로 돌려 종료 코드 0, 파일이 UTF-8. 리눅스에서는 `PYTHONIOENCODING=cp949`·`ascii` 로 같은 명령.
- **경로**: 접수 폴더의 겹침은 이미 `normcase(resolve())` 로 본다 (`intake/inbox.py`). 남은 것 — git 작업 트리의 검사(`inside_git_tree`)와 `check_out_dir` 를 대소문자·
  구분자에 상관없이, UNC 경로·연결한 드라이브 문자에서도.
- **긴 경로**: 보관 경로(`intake/<해-달>/<받은 시각>-<문서 ID>/<원래 이름>`)가 259자를 넘으면 **접수하지 않고** 접수 폴더에 둔 채 홈·요약에 알린다 ("경로가 너무 길다 —
  이름을 줄이거나 보관 폴더를 짧은 경로로"). 원래 이름을 줄이지 않는다 — 보관한 이름이 `source_name` 이 되고 `run --fresh` 와 날짜 규칙(`date_from_filename`)이 그것을 다시 읽는다.
  윈도우 작업에서 긴 한글 이름으로 시험.
- 윈도우에서 실패한 시험은 고치거나, 윈도우에서만 뜻이 없는 시험이면(예: 열린 파일을 지운다) 이유를 적고 그 작업에서만 건너뛴다. 무엇을 고쳤고 무엇을 건너뛰었는지 보고한다.
- 지금 알고 있는 윈도우의 차이(열린 파일은 바꾸거나 지울 수 없다, 다른 프로세스가 연 DB 는 지울 수 없다)는 그대로 — 문서에 있다.

| `INSTALL.txt` | 다섯 줄 — 무엇을 어떤 순서로 (zip 의 차단 풀기, `powershell -ExecutionPolicy Bypass -File install.ps1 …`). 그리고 한 줄 — 이 묶음을 남에게 줄 때는 소스 묶음을 같이 준다 |
| `SHA256SUMS.txt`, `VERSION` | 묶음 안 파일의 해시, 판 |

**나. `install.ps1`** — 관리자 권한 없이, 지금 사용자로. 매개변수: `-InstallDir`(기본 `%LOCALAPPDATA%\minedocscan`), 설정을 새로 쓸 때의 `-Site -Archive -Work -Inbox -ExcelDir`
(절대 경로로 적는다) 또는 기존 설정 파일 `-Config`, `-Reviewer`(검수자 ID — `serve --reviewer`, `-NoTask` 가 아니면 필수), `-NoTask`, `-Quiet`.
1. `SHA256SUMS.txt` 로 묶음을 확인한다. 인터넷에서 받은 zip 의 차단 표시(Mark of the Web)를 풀었는지 본다 (`Unblock-File`).
2. **앱 전용 파이썬**: embeddable 패키지를 `InstallDir\python` 에 푼다 — 레지스트리·시작 메뉴를 건드리지 않고, PC 에 다른 파이썬이 있어도 상관없다.
   `python312._pth` 에서 `import site` 를 켜고, 묶음의 pip 바퀴로 그 안에 pip 을 놓는다 (`python pip-….whl/pip install --no-index …`). embeddable 로 되지 않는 것이 있으면
   python.org 의 설치 파일(지금 사용자, 런처 없이)로 바꾸고 그 이유를 보고한다.
3. `InstallDir\python` 에 `pip install --no-index --find-links wheels "minedocscan[postgres]"` — **망에 닿지 않는다**.
4. **런타임 확인**: `python -c "import cv2, numpy, pymupdf, psycopg, openpyxl"`. 실패하면 이유를 한 줄로 — embeddable 에는 `msvcp140.dll` 이 없다. 바퀴들이 그것을 담고 있는지
   CI 에서 확인하고, 담지 않으면 "Visual C++ 재배포 패키지가 필요하다"(그리고 N·KN 판 윈도우의 미디어 기능 팩)를 안내한다. 러너에는 둘 다 있어 CI 로는 잡히지 않는다 (8절 2).
5. 설정: `%APPDATA%\minedocscan\minedocscan.toml` 이 없으면 매개변수로 쓴다 (있으면 건드리지 않는다). **사용자 환경 변수** `MINEDOCSCAN_CONFIG` 를 그 파일로,
   **사용자 PATH** 에 `InstallDir\python\Scripts` 를 더한다 (관리자 권한 없이 — 설명서의 명령이 새 창에서 그대로 돈다. 설정은 `MINEDOCSCAN_CONFIG` 나 `./minedocscan.toml` 에서만 찾는다).
6. `minedocscan info` 를 돌려 보여 준다.
7. 작업 스케줄러에 `minedocscan-serve`: 지금 사용자, 로그온할 때, 실패하면 1분 뒤 다시(세 번), 시간 제한 없음, **배터리에서도 시작하고 멈추지 않는다**
   (`-AllowStartIfOnBatteries -DontStopIfGoingOnBatteries`), 작업 폴더 `InstallDir`. 돌리는 것은
   `InstallDir\python\pythonw.exe -m minedocscan.cli serve --config … --reviewer … --log-dir InstallDir\logs` — `pythonw` 라 **창이 뜨지 않는다**.
   새 선택 `serve --log-dir DIR`: 표준 출력·오류를 그 폴더의 `serve-YYYYMMDD.log`(UTF-8, 날이 바뀌면 새 파일)에 쓰고 30일 지난 것을 지운다 (리눅스에서도 쓸 수 있다).
8. 바탕 화면에 바로 가기 "광산 문서 스캔" → `http://127.0.0.1:8765/`.
9. 끝에 요약: 어디에 무엇을 두었나, 다음에 할 일(`minedocscan selftest`, 템플릿 — 설명서의 장).

**다. 비밀번호.** 설치는 통합 DB 의 URL 을 받지 않는다. 설명서: URL 에는 비밀번호를 넣지 않고(사용자 환경 변수 `MINEDOCSCAN_PUBLISH_URL=postgresql://계정@서버/DB`),
비밀번호는 libpq 의 `%APPDATA%\postgresql\pgpass.conf` 에 둔다 (그 파일의 권한). 프로그램은 바꾸지 않아도 된다 — libpq 가 읽는다. 시험: `-m postgres` 에서 pgpass 로 연결.

**라. `uninstall.ps1`** — 작업을 멈추고 지우고, 바로 가기·`InstallDir`(앱 전용 파이썬·로그)·사용자 PATH 의 그 항목·`MINEDOCSCAN_CONFIG` 를 지운다. 설정 파일(`%APPDATA%\minedocscan`)과
사이트 팩·보관 폴더·작업 폴더·엑셀 폴더는 **건드리지 않고** 어디에 있는지 찍는다 (`-RemoveConfig` 일 때만 설정도).

**마. 올리기** — 새 판의 묶음으로 `install.ps1` 을 다시 돌린다: 작업을 멈추고, `InstallDir\python` 을 새로 만들어(옆에 만들어 바꿔 끼운다 — 실패하면 옛것이 남는다),
설정·로그는 그대로, 작업을 다시 켠다. 작업 DB 의 스키마 버전이 바뀌는 판이면 그렇다고 알리고 `minedocscan run --fresh …` 를 안내한다 (스스로 돌리지 않는다).

**바. CI** — 윈도우 작업에서 (`shell: powershell` — 현장과 같은 Windows PowerShell 5.1): 묶음 만들기 → `install.ps1 -Quiet`(임시 `InstallDir`, 합성 사이트 팩) —
**설치하는 동안 망을 막는다**(`PIP_NO_INDEX=1`, 닿지 않는 프록시) → 설치한 `minedocscan selftest` → 작업 스케줄러의 작업을 켜고 `http://127.0.0.1:8765/api/home` 이 200 → 끄기 →
`uninstall.ps1` → 작업·폴더가 없고 설정·데이터 폴더는 있다. 러너에서 작업을 켤 수 없으면(대화형 로그온이 없다) 등록한 작업의 정의(동작·트리거·다시 시도·배터리)를 확인하고,
같은 명령줄을 직접 띄워 `/api/home` 을 보는 것으로 대신한다 — 그렇다고 보고한다. 묶음 zip·소스 묶음과 자가 시험 결과를 CI 산출물로 (보존 14일). 두 묶음의 크기를 보고한다.

### 4.6 자가 시험 — `minedocscan selftest`

`minedocscan selftest [--out DIR] [--keep] [--publish-schema NAME]` — 설치한 프로그램만으로 (pytest 없이), **합성 데이터만으로**, 임시 폴더에서. `synth` 와 `oracle` 은 패키지 안에 있다.
- 합성 묶음 이틀치(점검·운반·가동 일보, 접수 폴더의 시나리오 일부)를 만들고 `oracle` 로 처리 → 쪽이 다 적재되고, **기계가 읽는 칸**(형식 없음·`integer`)의 CER 0.
  읽지 않는 형식(소수·시각·계기)의 칸은 "잉크 있음 + 검수 대기"가 기대값이다 (1절 라).
- 검수 몇 건(읽지 않는 칸에 정답을 넣는 것 포함)·결정 몇 건(날짜·버리기) → 다시 처리 → **지금의 DB = 처음부터 만든 DB**(0007 의 불변식).
- 엑셀: 일별·월별을 써서 되읽고, 운반 표 = 합성 정답, 정답을 검수로 넣은 칸은 그 값. 가린 그림: 상자 밖 = 정합 그림, 안 = 한 색.
- 화면: 그 안에서 `serve` 를 빈 포트로 띄워 `/api/home`·`/export/day.xlsx` 가 200.
- `--publish-schema NAME`(그리고 `MINEDOCSCAN_PUBLISH_URL`)이면 `minedocscan_selftest_` 로 시작하는 그 스키마에 싣고 `--check` 가 0 이면 그 스키마를 지운다
  (`--keep` 이면 남긴다). 다른 이름은 받지 않는다. DB 의 `CREATE` 권한이 있어야 한다 — 없으면 그렇다고 알리고 그 검사만 건너뛴다.
- 결과: `selftest.json`·`selftest.md` — 검사마다 통과·실패와 시간, 환경(OS, 파이썬, 의존성의 판, CPU 수, 메모리). 사용자의 경로·이름은 넣지 않는다. 종료 코드 0/1.
- 기준: CI 러너에서 3분 안. 실패하면 어느 검사가 왜 — 한 줄씩.

### 4.7 가상 양식 (V2)과 거친 손글씨

**가. 양식 두 종** — `synth --v2-forms` 가 템플릿과 쪽을 더한다 (핸들러 `generic`, 날마다 한 장씩). **기계가 읽는 칸이 대부분**이고 읽지 않는 형식은 몇 칸만 둔다
(읽지 않는 길의 증거 — 1절 라). 양식 이름과 필드 이름은 이 둘에만 있는 접두(`fuel_`·`env_`)를 쓴다.
- **유류일지**(`fuel_log`): 장비 행 × (주유량 `integer`(리터), 유종 글자, 주유자 글자, 주유 시각 `time` — 읽지 않는 칸), 주유자 서명 열. 표 밖: 날짜 줄, 작성자(`meta_key operator`).
- **환경일지**(`env_log`): 측정 지점 행 × (탁도 `integer`, 유량 `integer`, 비고 글자, pH `decimal` — 읽지 않는 칸), 확인자 서명. 표 하나는 두 줄 머리글.
- 인쇄된 값(장비명·지점명)은 템플릿에서 확정한다 (원칙 2). 합성 정답(`truth.json`·`answers.json`)에 들어간다.

**나. 거친 손글씨** — `synth --rough`: 획의 굵기 변화, 기울기, 떨림, 연한 잉크, 번짐 몇 점, 쪽 전체의 기울어짐(±1.5°)과 스캔 잡음·JPEG 압축. 모든 양식에 걸린다.
난수는 따로 — 두 선택 없이는 지금의 바이트 그대로.

**다. 보일 것** (수용 기준은 단계 6):
- **파이프라인 코드의 변경이 없다** — `handlers/`·`export/`·`publish/`·`forms/`·`pipeline/`·`recognize/`·`imaging/`·`review/`·`store/`·`validate/`·`intake/` 의 diff 가 0줄이다
  (`cli.py` 의 `synth` 선택과 `tools/` 는 된다). 그리고 V2 의 고유 이름(양식 이름, `fuel_`·`env_` 로 시작하는 필드 이름)이 `src/minedocscan/` 에서 `tools/` 밖에 없다 —
  메타 키(`operator`)·형식 이름은 이미 쓰이는 말이라 검사에서 뺀다.
- 적재와 출처, 엑셀의 양식 시트, 통합 DB 의 `doc_field` 까지.
- **템플릿 도구로 만든 템플릿으로도 된다**: 유류일지의 빈 기준 이미지에서 `template init` → `add-region` → 열·행을 적어(시험이 YAML 을 적는다) 만든 템플릿으로
  처리해도 칸이 생성기의 템플릿과 같은 자리(4 px 안)이고 `oracle` 의 결과가 같다 — `SITE_PACK.md` 의 절차가 새 양식에서 통한다는 증거. 설명서의 "새 양식 더하기"가 이 순서를 그대로 따른다.
- 수치(시험 성적서의 확장성 표): 양식마다 쪽 수, 분류, 정합 통과, 괘선 오차의 중앙, 칸 수, 인식기에 보낸 칸의 `oracle` CER, 값 유무의 정밀도·재현율(`null` — 정답의 잉크 유무와) —
  보통 글씨와 거친 글씨. 거친 글씨의 연한 잉크는 잉크 문턱(`text_ink_min`) 아래로 떨어져 인식기에 가지 않을 수 있다 — 그것은 CER 이 아니라 값 유무의 재현율에 나온다.

### 4.8 사용 설명서

- `docs/manual/` (한국어, Markdown). 읽는 사람: 현장 담당자(스캔·홈·검수·엑셀)와 관리자(설치·설정·템플릿·통합 DB).
  1. 개요 — 무엇을 하고 하지 않는가, 데이터가 어디에 있는가(그림 하나), 라이선스(`NOTICE` 를 가리킨다 — 묶음을 남에게 줄 때 소스 묶음을 같이)
  2. 설치 — 묶음, `install.ps1` 의 매개변수, 차단 풀기·실행 정책, 비밀번호(pgpass), 지우기, 올리기, 리눅스(`pip`)
  3. 처음 설정 — 사이트 팩(`[site] name` 을 적는다), 폴더, 설정 파일, `info`, `selftest` (템플릿 만들기는 7장으로)
  4. 날마다 쓰기 — 스캔 → 홈 → 날짜를 정할 문서 → 다시 스캔 의심 → 검수 대기열 → 엑셀 → 통합 DB 의 상태
  5. 관리 — 백업할 것(사이트 팩: 검수·결정 기록, 보관 폴더. 작업 DB 는 다시 만들 수 있다), 로그, 다시 처리, 회귀 검사, 사이트 이름을 바꿀 때
  6. 문제 해결 — 표: 홈에 보이는 것 → 뜻 → 할 일 (날짜를 기다린다, 다시 스캔 의심, 쓰지 못함, 싣지 못함의 종류, 다른 사이트의 폴더·대상, 경로가 너무 길다,
     런타임 DLL …)
  7. 새 양식 더하기 — V2 의 유류일지로 처음부터 끝까지 (4.7 다)
  부록: 명령 목록 — **argparse 의 동작(actions)에서** 만든다(`format_help` 는 터미널 폭과 파이썬 판에 따라 달라진다 — `scripts/cli_reference.py` → `docs/manual/명령.md`,
  시험이 지금의 것인지 본다), 설정 키 목록.
- **갈무리는 합성 데모로만** (`scripts/manual_shots.py` — Playwright, `[docs]`). `docs/manual/img/` 에 넣어도 된다 (합성 데이터 — 저장소에 넣는 그림 전체 3 MB 안).
  실데이터 화면의 갈무리는 어디에도 넣지 않는다 (`CLAUDE.md`).
- `scripts/manual_html.py` → 그림을 담은 한 장짜리 `manual.html` (CI 산출물, 설치 묶음에 들어간다). PDF 는 브라우저의 인쇄로 (설명서에 적는다).

  빌드: PEP 639 를 읽는 `hatchling` 판 (4.3 가).
- 새 설정: `[export] retry_seconds`(60), `serve --log-dir`. `config/minedocscan.example.toml` 에.

## 5. 단계

### 단계 1 — 0008 의 뒷정리: 맞게, 안전하게

할 일
- 4.1 가–자. `psycopg` 의 하한.

수용 기준
- **운반 표의 겹침**: 겹친 행을 가진 템플릿은 `template check` 가 오류로 낸다. DB 에 겹친 행이 있으면(시험이 만든다) 그 칸이 `겹침` 이고 합계가 비며, 범례에 그 줄이 있고,
  수의 보존(4.1 가)이 선다. 겹침이 없는 묶음의 엑셀은 모델의 해시까지 그대로다.
- **기록 파일**: UTF-16·쓰레기 바이트·빈 파일 → 전부 다시 쓴다. 잠긴(읽을 수 없는) 기록 파일 → 지금처럼 아무것도 쓰지 않는다.
- **사이트 표식**: 다른 사이트 팩의 작업 폴더로 같은 스키마에 `publish` → 종료 코드 2, 대상은 그대로 (행 수·지문). `--check` 도 2. 자동 싣기는 그 바퀴의 실패 `other_site`.
  `--rebuild` 로는 바꿔 실을 수 있다. 엑셀 폴더도: 다른 사이트의 기록이면 쓰지도 지우지도 않는다. 빈 작업 DB 로 훑어도 기록된 파일이 남는다. 옛 기록(사이트 없음)은 받아들인다.
  `[site] name` 이 없는 사이트 팩이면 자동 일은 꺼지고(한 줄) 명령은 거절한다. `pub_meta` 없이 이름만 같은 표가 있는 스키마에서 `--rebuild` 는 지우지 않는다.
  판이 1 인 대상은 `--rebuild` 를 알린다.
- **멈춘 서버**(`-m postgres`): 멈추는 중계를 사이에 두고 답을 기다리는 동안 멈추면 그 바퀴가 `statement_timeout_s + 35초` 안에 `connection_lost` 로 끝나고(시험은 시간 제한을
  줄여서 — 1초·2초), 같은 작업의 다음 바퀴는 처리를 하고, 중계를 풀면 따라잡아 대상 = 작업 DB (서버의 옛 트랜잭션이 남아 `lock_timeout` 에 걸리지 않는다).
  감시 타이머를 빼면 이 시험이 실패한다 (멈추지 않고 — 스레드에서 기다리다 시간을 넘기면 실패).
- **가린 그림**: 기본 넓히는 폭이 48 이고 그 근거가 코드의 주석에. 동시 판 사이에 `redact` 이름이 다르면 사이트 팩을 읽을 때 오류. 쪽이 없는 날짜로 `masked-pages` → `OUT` 을 만들지 않는다.
  `export-crops`·`recognizer eval --errors` 가 접수 폴더·보관 폴더 안을 거절한다.
- **더러운 범위의 구멍**: 각각 시험 하나 — 쪽이 없는 문서가 날짜를 바꿀 때 옛 문서 날짜의 파일이 다시 써진다, 장비 행이 바뀌면 모든 날짜의 점검 시트가 다시 써진다,
  대상의 표가 없어진 뒤의 더러운 바퀴가 전부를 싣는다 (`sweep_minutes = 0` 에서).
- **작은 것들**: 4.1 사의 줄마다 시험 하나 (하위 명령 앞의 옵션은 다섯 명령 모두).
- **문서**: 4.1 아의 다섯 곳.
- **시험의 빈틈**: 4.1 자. 엑셀의 흔들기는 `slow` 에서 두 씨앗, 매번 같음.
- 합성 묶음의 바이트, `null` 리포트, 작업 DB 의 행이 그대로다.

### 단계 2 — 0008 의 뒷정리: 규모

할 일
- 4.2 가–마.

수용 기준

- **가동 일보의 더러운 범위**: 계기 칸 하나의 검수 → 더러운 날짜 3일 안 (복제 DB, 고치기 전의 수치와 같이 보고). 장비 이름을 고친 검수도 흔들기에 넣어 폴더·대상이 같다.

- **엑셀의 다시 쓰기 간격**: 시계를 주입한 시험에서 바꾸지 못하는 파일 하나가 10바퀴 동안 열려 있으면 그 파일의 모델은 `retry_seconds` 마다만 만들고, 요약 줄은 수가 바뀔 때만.
- `slow` 의 60일 복제 시험 (4.2 마).
- 합성 묶음의 바이트, `null` 리포트, 작업 DB 의 행이 그대로다.

## 6. 시험

- 전부 합성 데이터. 실제 문서의 이미지·이름·장비 번호·파일명을 시험·설명서·성적서에 넣지 않는다.
- 기본 `pytest`(torch·PostgreSQL 없음)는 우분투(OpenCV 5.0·하한 판)와 **윈도우**에서 통과한다.
- 시험에서 잠들지 않는다 (시계는 주입한다). 멈추는 중계를 쓰는 시험(`postgres`)은 스레드에서 기다리고 시간을 넘기면 실패로 끝난다 — 멈추지 않는다.
- 규모의 수치(252일 복제)는 시험이 아니라 재는 것이다 — 성적서와 보고에. 시험은 `slow` 의 60일 판 (행 수·`tracemalloc` — CI 의 벽시계는 흔들린다).
- 설치 시험은 윈도우 CI 에서만 돈다 (`install.ps1` 을 리눅스에서 흉내 내지 않는다). `serve --log-dir` 은 어디서나 시험한다.
- 묶음을 되도록 새로 돌리지 않는다: 지금의 세션 픽스처를 같이 쓴다. V2 묶음은 세션 픽스처 하나(`oracle`)와 거친 글씨의 하나(`slow`).

## 7. 지켜야 할 것

- 파이프라인의 결과를 바꾸지 않는다. 스키마를 바꾸지 않는다.
- **AGPL-3.0 과 같이 배포할 수 없는 라이선스의 의존성을 넣지 않는다** (`scripts/licenses.py --check`). 묶음·설명서·설치 스크립트에 받는 사람의 권리를 막는 조건
  (재배포 금지, 사용처 제한 …)을 넣지 않는다. 설치 묶음은 늘 소스 묶음과 같이 나온다.
- **확정되지 않은 값을 확정된 것처럼 싣지 않는다** (ADR 0022). 교차검증의 불일치를 맞춰 넣지 않는다 (ADR 0006).
- 설치는 **망에 닿지 않는다**. 외부 API 를 부르는 것을 넣지 않는다 (ADR 0003). 자가 시험도 망 없이 돈다. 묶음을 만드는 도구(`scripts/`)는 설치되는 패키지에 넣지 않는다.
- 비밀값은 환경변수·pgpass 로만. 설치 스크립트·로그·자가 시험의 결과·성적서에 URL·비밀번호를 찍지 않는다.
- 설명서의 갈무리·성적서·묶음에 현장 데이터가 들어가지 않는다 — 합성뿐. 실데이터 수치는 수만, 사람이 넣는다.
- `uninstall.ps1` 은 데이터·설정을 지우지 않는다 (`-RemoveConfig` 의 설정만). 원본을 지우지 않는다 (`CLAUDE.md`).
- 현장에 관한 것(사이트 이름, 양식, 장비)은 사이트 팩으로. V2 의 양식은 `tools/` 와 시험에만.
- `CLAUDE.md` 의 작업 규칙을 따른다.

## 8. 사람이 할 일

PR 이 합쳐진 뒤, 순서대로.

1. **라이선스의 남은 결정** — 기관이: 저작권자 문구(`NOTICE` 의 첫 줄), `AGPL-3.0-or-later` 와 `-only` 중 어느 것, 연구 성과물을 공개 라이선스로 내는 기관의 규정과
   과제 협약(성과물의 귀속), **등록 뒤 유상 기술이전을 계획하는지**(AGPL 로 공개하면 받은 사람이 다시 나눠 주는 것을 막지 못한다), 외부 기여를 받을지와 그 조건(기여한 부분의
   저작권은 기여자에게 있다 — 나중에 라이선스를 바꾸려면 그들의 동의가 필요하다), 바퀴 안에 같이 든 것(libquadmath …)의 소스를 소스 묶음에 넣을지 (4.3 다).
   정해지면 `NOTICE`·`pyproject.toml` 을 고친다. 실데이터로 `minedocscan regress` — 이 지시서는 파이프라인의 결과를 바꾸지 않으므로 기준과 같아야 한다.
2. **현장 PC 에 묶음으로 설치** (외부망 없이): `install.ps1` → 런타임 확인(Visual C++ 재배포 패키지·미디어 기능 팩이 필요하다고 나오는지) → `minedocscan selftest` →
   로그온해서 홈이 열리는지 → 스캐너의 저장 폴더를 접수 폴더로 → 하루치. 걸린 시간, 막힌 곳, 로그의 크기.
3. **사이트 팩**: `site.toml` 에 `[site] name` 이 없으면 적는다 — 그 전에 `[eval] split_salt` 에 지금 쓰이는 값(`info` 가 보여 준다)을 적어 test 날짜를 지킨다.
4. **통합 DB**: 대상이 판 1 이면 `publish --rebuild` (사이트 표식). 비밀번호는 pgpass 로 옮기고 URL 에서 뺀다.
5. **가린 그림**: 실제 템플릿의 `redact` 상자와 기본 48 px 로 양식마다 한 쪽씩 내어 눈으로 본다 (0008 8절 5 의 계속). 판이 둘이면 판마다.
6. **시험 성적서의 실데이터 칸**: 정답이 있는 만큼 채운다 (`regress`, `eval`, `eval --meta`, `eval --checks`, 처리 시간) — 수만.
7. **사용 설명서**를 현장 담당자와 한 번 읽어 본다 — 모르는 말, 빠진 화면, 순서.
8. 선행 등록물과의 관계, 등록 서류 — 기관이 정한다 (`PRIOR_WORK.md` "권리 관계"). 등록 서류의 라이선스 칸은 1 의 결정대로.
9. 정해지면 `v1.0.0` 태그와 GitHub Release(설치 묶음·소스 묶음·성적서 첨부 — 설치 묶음만 올리지 않는다).

**돌려줄 수치와 의견** (이름·번호·파일명 없이): 회귀가 기준과 같은지, 설치 시간·막힌 곳, 자가 시험의 시간, 현장 PC 의 사양(CPU·메모리·윈도우 판), 가린 그림에 맞는 넓히는 폭,
설명서에서 고칠 것.

## 11. 끝나고 보고할 것

- 단계별로 무엇을 만들었고 무엇을 만들지 않았는지. 수용 기준 중 충족하지 못한 것이 있으면 그것부터.
- 테스트 수와 시간(기본 / 하한 판 / `slow` / `postgres` / **윈도우**). 윈도우에서 실패했던 것과 고친 것, 그 작업에서만 건너뛴 시험.
- 라이선스: `LICENSE` 의 해시, 바퀴의 메타데이터, `--version`·화면의 줄. 소스 묶음의 크기와 안에 든 것, `SOURCES.txt` 의 항목(넣은 것과 받을 곳만 적은 것).
- 규모의 표(4.2 마 — 고치기 전과 뒤, 같은 기계, 복제 DB 의 행 수), 조각 하나의 가장 긴 시간, 가동 일보 검수의 더러운 날짜 수.
- 묶음의 크기·설치 시간·자가 시험 시간(우분투·윈도우), 설치 시험의 단계마다 결과, `msvcp140.dll`.
- 확장성 표(4.7 다), 템플릿 도구로 만든 템플릿의 칸 차이.
- 라이선스 목록의 요약(라이선스마다 배포판 수), 대응표에 넣은 것, 바퀴 안에 같이 든 것의 목록 — 소스를 같이 줘야 하는 것은 따로.
- 4절에서 벗어난 것이 있으면 무엇을 왜.
- 윈도우 PC 에서 직접 해 보지 못한 것 (CI 의 러너로만 한 것) — 그렇다고.
