## 1. 왜 하는가

0005 를 실제 3일치(가동 일보 40쪽)에 돌려 보니 양식 쪽에서 세 가지가 막혔다. 셋 다 템플릿을 아무리 다듬어도 풀리지 않는다.

**(가) 칸 안에 인쇄된 글자.** 로우더 작업일보의 작업량 칸에는 "하단: _ 대 / 저광장: _ 대", 근무 시각 칸에는 "~", 계기 칸에는 "시작:" 이 인쇄되어 있다.
잉크 판정은 인쇄와 손글씨를 가리지 못한다.
- 0005 의 마지막 수정으로 값이 사라지지는 않게 되었지만, 그 대가로 인쇄가 있는 칸은 비어 있어도 늘 검수 대기다:
  작업량의 인쇄 칸 48개 중 48개, 근무 시각의 빈 칸 9개 중 9개 (6쪽). 근무 시각 칸이 검수 대기면 그 쪽의 가동 분 합이 NULL 이다.
- 인쇄를 나눔 선으로 떼어 내는 것으로는 안 된다 (두 자리 숫자를 48칸 중 0칸에서 잡았다 — 0005 12절).
- 해결의 실마리: **인쇄는 모든 쪽에서 같은 자리에 있고 손글씨는 쪽마다 다르다.** 같은 양식의 정합 이미지 여러 장에서 화소마다 밝기의 높은 백분위를
  잡으면 손글씨가 빠진 빈 양식(인쇄 층)이 나온다. 실제로 26장·6장·4장으로 만들어 보았고, 그것을 뺀 뒤에 지금의 규칙 그대로 값 유무를 쟀다:

  | 칸 (실제 3일치) | 쓴 칸을 "있음"으로 | 빈 칸을 "있음"으로: 지금 → 인쇄 층을 뺀 뒤 |
  |---|---|---|
  | 로우더 작업량의 인쇄 칸 (48) | 숫자를 그려 넣으면 48/48 (한 자리·두 자리 모두) | 48/48 → 1/48 |
  | 로우더 근무 시각 칸 (18) | 9/9 → 9/9 | 9/9 → 0/9 |
  | 중기운행일보·점보 작업일보의 계기 칸 (90) | 30/30 → 30/30 | 5/60 → 2/60 |
  | 로우더 작업량의 그 밖의 칸 (132) | — | 34 → 34 (전부 표 위에 쓴 메모 — 실제 잉크다) |

  백분위 50·75, 인쇄를 넓히는 폭 1–3 px 에서 결과가 같았다. 만드는 쪽 수를 2–26장으로 바꿔도 계기 칸의 결과가 같았다.

**(나) 같은 날 섞여 쓰이는 인쇄 판.** 중기운행일보 30쪽 중 5쪽은 표가 8–12 px 아래에 있고 줄 간격도 조금 다른 다른 인쇄 판이다(판 B).
머리 상자와 제목의 자리는 같다. 묵은 양식을 같이 쓰는 것이라 **같은 날 묶음에 두 판이 섞여 있다** — 날짜로 가릴 수 없다 (ADR 0010 의 전제가 깨진다).
- 지금(판 A 의 템플릿 하나): 4쪽이 `align_failed`, **1쪽은 괘선 오차 5.5 px 로 통과해 칸이 8–12 px 어긋난 채 적재되었다.**
- 모양(인라이어)으로는 못 가린다: 두 판의 1위/2위 비율이 중앙값 1.57, 최소 1.01.
- **괘선 오차로는 갈린다**: 두 판에 각각 정합해 오차가 작은 쪽을 고르면 A 25쪽, B 5쪽, 실패 0쪽. B 로 간 5쪽의 오차는 A 에서 5.5–10.5 px, B 에서 0.0–1.5 px.

**(다) 가동 시간 칸의 입력.** `readings` 대기열은 계기 칸만 싣는다. 로우더 작업일보는 계기가 비어 있고(6쪽 전부) 가동 시간이 근무 시각 칸에만 있다
(오전 6/6, 오후 3/6, 연근 0/6). 그 칸은 지금 `pending` 대기열에서 칸 하나씩 봐야 한다.
그리고 시각을 적은 3쪽 중 2쪽이 점으로 썼다(08.00): 적힌 대로 입력하면 계기 값 8.00 이 되고, 첫날에는 검산에도 걸리지 않는다.

그래서 이번에 하는 것은 **인쇄 층**(가), **동시에 쓰이는 판**(나), **가동 시간 칸을 한 번에 입력하기**(다)다.
0005 의 문서가 예고한 "소수·시각을 기계가 읽기"는 **미룬다**: 계기 값은 하루 10칸 안팎이라 손으로 넣는 데 1분이 안 걸리고,
첫 인식기(운반 횟수)의 실데이터 수치가 아직 없다. 읽는 모델을 하나 더 만들기 전에 양식이 제대로 적재되어야 한다.

## 2. 끝났을 때 되는 일

```bash
minedocscan template print-layer <site>/templates/<양식>      # 적재된 쪽들에서 인쇄 층을 만든다 → <양식>/print.png + 요약
minedocscan template preview <site>/templates/<양식> --print   # 인쇄 층 위에 칸을 그려서 확인 (값 자리가 인쇄에 덮이지 않았나)
minedocscan template variant <site>/templates/<양식> --scan F --page N --name <양식>_b   # 다른 인쇄 판의 템플릿 (괘선만 다시 잡는다)
minedocscan template add-region <site>/templates/<양식> --roi x0,y0,x1,y1 --name meter --role meter   # 표 하나를 더한다

minedocscan run DB_scans --fresh        # 인쇄만 있는 칸은 빈 칸으로 자동 적재, 섞인 판은 괘선 오차로 고른다
minedocscan report                      # 양식별: 인쇄 층을 쓴 쪽, 판을 고른 쪽과 두 판의 오차
minedocscan review serve --queue readings --reviewer jp   # 쪽마다 계기 칸 + 근무 시각 칸을 한 번에. 08.00 을 넣으면 "시각이면 콜론으로" 를 묻는다
```

## 3. 범위

**이번에 한다**
- 0005 에서 남은 손질 (단계 1)
- 인쇄 층: 만들기, 템플릿에서 켜기, 확인 도구 (단계 2)
- 인쇄 층을 뺀 그림으로 값 유무를 정한다 — 가동 일보의 표 칸과 필드 (단계 3)
- 같은 날 섞여 쓰이는 판: 계열 안의 동시 판, 괘선 오차로 고르기, 판 템플릿을 만드는 명령 (단계 4)
- `readings` 에 근무 시각 칸, 점으로 쓴 시각의 확인 (단계 5)
- 템플릿에 표를 더하는 명령, 합성 양식의 확장 (단계 6)

**이번에 하지 않는다**
- 소수·시각을 기계가 읽는 것 (1절). 텍스트 인식도
- 인식기에 넘기는 크롭·검수 화면의 크롭에서 인쇄를 지우는 것. 크롭은 지금처럼 원래 그림이다 (4.3)
- 인쇄 층을 정합·분류의 기준 이미지로 쓰는 것 (4.5 — 재 보니 나빠졌다)
- 표 밖 필드(서명·체크·메타 필드 포함)와 작업 표(`activities`)에 인쇄 층을 쓰는 것 (4.3 — 늘 같은 자리에 같은 글씨로 쓰는 칸은 인쇄 층에 들어가 지워진다)
- 표마다 괘선을 다시 맞추는 2차 정합(괘선 스냅). 판 B 는 줄 간격까지 달라 평행 이동으로 풀리지 않고, 넣으면 모든 양식의 수치가 바뀐다 → 판을 템플릿으로 둔다 (4.6)
- 운반·점검표 양식에 인쇄 층을 켜는 것. 켤 수는 있게 만들지만 기본은 꺼져 있고, 합성 운반·점검표 템플릿에는 넣지 않는다 (4.4)
- 관리 계열 양식, 여백 행 규칙, 엑셀 내보내기, 폴더 감시
- 판정 규칙(정합·체크·잉크·덩어리)의 임계값 변경. 인쇄 층이 없는 템플릿의 `null` 회귀 수치는 바뀌면 안 된다

## 4. 이미 정한 것

### 4.1 인쇄 층은 사이트 팩의 데이터다

- 양식 하나의 인쇄 층 = `<템플릿 폴더>/print.png` — 기준 이미지와 같은 크기·같은 좌표(템플릿 좌표계)의 회색조 그림. 그 양식에 **인쇄된 것만** 있다.
- 템플릿에 `print_image: print.png` 가 있으면 쓴다. 없으면 모든 것이 지금과 같다 (원칙 1: 양식은 데이터다. 코드가 양식 이름을 알지 않는다).
- 인쇄 층은 판마다 따로다 (4.6 의 판 B 는 자기 것을 가진다).
- 저장소에 넣지 않는다. 늘 같은 자리에 같은 글씨로 쓰는 칸(작성자 이름, 늘 "ok" 인 점검란, 서명)은 쪽이 많아도 손글씨의 잔상이 남는다
  — 현장 글씨다 (CLAUDE.md 의 개인정보 규칙에 더한다).
  예외는 합성 양식으로 만든 것뿐이다.

### 4.2 인쇄 층은 여러 쪽에서 추정한다

- 방법: 그 템플릿으로 분류된 쪽들을 템플릿 좌표로 편 그림 N장 → 쪽마다 잉크를 1 px 넓힌 뒤(회색조 erode 3×3 — 정합의 1 px 흔들림)
  → **화소마다 밝기의 75 백분위**. 인쇄는 거의 모든 쪽에서 어둡고 손글씨는 일부 쪽에서만 어둡다. 빈 양식을 스캔해 올 필요가 없다
  (현장에 요청하지 않는다). 40장을 실수로 쌓으면 세로 양식에서 메모리가 약 0.5 GB 더 든다 — 행 묶음으로 나누거나 uint8 로 계산한다.
- 쪽은 날짜별로 고르게 뽑는다 (기본 최대 40장). **5장 미만이면 경고**하고 만들기는 한다, 2장 미만이면 거절한다.
  정합한 그림이 WORK_ROOT 에 없으면 `doc_page.homography`·`render_dpi` 로 다시 편다: `io.load_page(원본, 쪽, render_dpi)` →
  `warpPerspective`(INTER_LINEAR, borderValue 255) — `imaging/align.py` 와 같은 그림이라 저장된 정합 그림과 바이트까지 같다.
  (`imaging/hires.py` 의 경로는 300 dpi·CUBIC 이라 화소의 3/4 이 달라 쓰지 않는다.)
- **판이 섞였을 수 있는 양식의 첫 인쇄 층은 `--percentile 50` 으로 만든다.** 판을 나누기 전(템플릿이 하나뿐일 때)에는 두 판의 쪽이 한 층에
  들어간다. 75 백분위는 쪽의 75 % 넘게 어두운 화소만 남기므로, 소수 판의 몫이 25 % 를 넘으면 다수 판의 표 괘선이 층에서 빠지고
  `add-region` 이 괘선을 못 잡는다. 실제 중기운행일보의 쪽으로 재 보면, 판 A 의 가로 괘선이 층에 남은 비율이 A 의 몫 0.83(실제)에서는
  50·75 백분위 모두 1.00, 0.64 에서는 1.00·0.55, 0.50 에서는 1.00·0.44 였다. 기본값(75)은 그대로 두고, 요약에 쓴 백분위를 적는다.
- 명령은 요약을 낸다 (값·이름 없이): 쓴 쪽 수와 날짜 수, 인쇄 화소의 비율, **손으로 쓰는 칸마다 인쇄에 덮인 비율**(큰 순서로 몇 개 — 칸 이름만:
  `template check` 와 같은 표기 `<표>/<열>/행 N`, `fields/<이름>`. 행 키는 장비 번호일 수 있어 찍지 않는다).
  덮인 비율이 큰 칸은 인쇄가 든 칸이거나 잔상이다 — 사람이 `template preview --print` 로 본다.
- 템플릿의 칸 정의가 없어도 만든다 — 인쇄 층을 먼저 만들고 그 위에서 괘선을 잡는다 (단계 6). 칸 정의가 없는 템플릿의 쪽은 `loaded` 가
  아니라 `classified_only` 이고 정합하지 않는다 (`pipeline/runner.py` — 호모그래피도 정합 그림도 없다). 그래서 print-layer 가 그 쪽들을
  원본에서 직접 정합한다: `io.load_page(render_dpi)` → `align_to_template` 의 호모그래피. 표가 없어 괘선 오차가 없으므로 품질은
  인라이어(`min_inliers`)만으로 보고, 못 미치는 쪽은 뺀다. DB 에는 쓰지 않는다 — runner·report·regress 의 수치는 그대로다.
- 같은 쪽·같은 설정이면 같은 그림이다 (바이트까지). 요약에 그림의 해시 = `print_sha` = sha256(높이·너비 + 화소 바이트)의 앞 16자
  (PNG 파일의 바이트가 아니다 — 다른 도구로 다시 저장해도 같다).
- print-layer 는 `print.png` 만 쓴다. `template.yaml` 에 `print_image: print.png` 를 적는 것은 사람이고, 명령이 안내한다 — 파일보다 키가
  먼저 있으면 템플릿 오류로 사이트 팩 전체가 읽히지 않는다. 명령은 템플릿을 검증 없이(`validate=False`) 읽는다.

### 4.3 인쇄 층은 "값이 있는가"에만 쓴다

- 쪽마다 **잉크를 재는 이진 그림**을 한 번 만든다: 정합한 그림을 지금처럼 이진화(`imaging/grid.binarize`)한 뒤, 인쇄 마스크의 화소를
  0(잉크 아님)으로 한 것. 인쇄 마스크 = 인쇄 층을 같은 `grid.binarize` 로 이진화해 2 px 넓힌 것. 새 임계값은 없다.
  회색 그림에서 인쇄를 흰색(255)으로 칠한 뒤 이진화하면 안 된다 — 적응 이진화가 칠한 자리의 가장자리를 잉크로 잡아 인쇄만 있는 칸이
  남는다 (합성 10일치: 인쇄만 있는 작업량 칸 89칸 중 13칸이 여전히 "있음". 이진화한 뒤 지우면 넓히는 폭 0–3 px 모두 0칸. 값이 적힌 칸은
  어느 쪽이든 잃지 않았다).
- 그것을 쓰는 곳: **role 이 `meter`·`shifts`·`tally` 인 표의 형식 있는 칸**의 잉크 비율(`imaging/cells.observe_cells` 의 `ink`)과
  덩어리 배정(`imaging/blobs.assign_blobs`). 규칙과 임계값은 그대로다. 1절이 다루는 칸도 이것뿐이다.
- 쓰지 않는 곳: 표 밖 필드(서명·체크·메타 필드 포함)와 작업 표(`activities`), ✓ 판정(`imaging/marks.py`), 정합·분류,
  **크롭 전부**(인식기·내보내기·검수 화면 — ADR 0011 의 "크롭 구현 하나"는 그대로). 사람은 인쇄가 있는 원래 그림을 본다.
- 필드에 쓰지 않는 이유: 날마다 같은 자리에 같은 글씨로 쓰는 칸은 쪽이 많아도 인쇄 층에 들어간다. 합성에서도 로우더의 점검란(늘 "ok")이
  켜면 6쪽 중 6쪽에서 빈 칸으로 자동 적재되었다. 서명은 검수 경로가 없어 `signed` 가 조용히 0 이 되고, 메타 필드는 잉크가 0 이면 모델을
  건너뛴다 (`pipeline/runner.py`).
- 0005 의 "덩어리 배정 또는 잉크 비율 중 하나라도 있음" 규칙은 그대로 둔다. 인쇄 층은 그 규칙이 잘못 "있음"이라 하는 칸을 줄일 뿐이다.
  인쇄 층이 틀려도(잔상, 어긋난 정합) 결과는 "검수 한 번 더"이지 값이 사라지는 쪽이 아니어야 한다. 구조로 보장되는 것은 아니다 — 두 판정이
  같은 지운 그림을 쓰므로 마스크가 손글씨를 덮으면 둘 다 "없음"이 된다. role 표의 칸에서는 맞는 층·다른 양식의 층·±5 px 밀린 층·2–5장으로
  만든 층 어느 것에서도 값이 적힌 칸을 잃지 않았고(합성, 최소 여유는 기준의 1.55배), 이것을 시험으로 고정한다 (단계 3).
  층과 쪽이 맞는지 보는 안전장치는 새 수치가 필요해 넣지 않는다.
- 인쇄와 겹친 획은 지워진다 (괘선을 넘는 숫자에 틈이 생긴다). 값 유무에는 지장이 없었다 (1절의 "쓴 칸" 열). 그래서 크롭에는 쓰지 않는다.
- 어느 인쇄 층으로 쟀는지 쪽에 남긴다 (`doc_page.print_sha` — 원칙 3).

### 4.4 켜는 것은 템플릿이고, 운반·점검표는 이번에 켜지 않는다

- 실제 운반 양식에 켜 보면 숫자 칸 4,620개 중 16칸의 값 유무가 달라진다 (없음→있음 15, 있음→없음 1). 좋아진 것인지는 정답이 있어야 안다.
  → 가동 일보 양식에만 켠다 (8절). 운반 양식에 켜는 것은 숫자 정답이 생긴 뒤에 `regress` 와 `eval` 로 판단한다.
- 합성 데이터: 가동 일보 두 종의 템플릿에만 인쇄 층을 넣는 선택 기능. 기본 합성 데이터와 운반·점검표의 결과는 바이트까지 그대로.

### 4.5 인쇄 층은 기준 이미지가 아니다

- 기준 이미지를 인쇄 층으로 바꿔 정합해 보니 인라이어의 중앙값이 1,315 → 777 로 줄었다 (여러 쪽을 겹친 그림이라 획이 무르다).
  정합·분류의 기준은 지금처럼 스캔 한 장(`reference.png`)이다.
- 다만 **괘선을 잡는 데는 인쇄 층이 낫다** — 채워진 스캔에서 괘선을 잡으면 손글씨의 세로획이 괘선으로 섞여 나온다. `template add-region` 은
  인쇄 층이 있으면 그것에서 잡는다 (단계 6).

### 4.6 같은 날 섞여 쓰이는 판은 괘선 오차로 고른다

- 판은 지금처럼 **별도 템플릿**이다 (이름이 다르고 자기 `template.yaml`·`reference.png`·`print.png` 를 가진다). 같은 `family` 를 적는다.
  `concurrent` 는 `family` 가 있을 때만 쓸 수 있다 (없으면 템플릿 오류). 실제 세 양식은 개정판이 아니라 `family` 가 없을 것이다 — 없이 두면
  두 판이 묶이지 않고, 분류가 모양으로 판 하나를 골라(합성에서 1위/2위 1.01–1.08) 그 판에만 정합하므로 틀린 판으로 조용히 통과할 수 있다.
- 동시 판끼리 키가 같아야 한다: 표 이름·`role`·열(idx·name·kind·format)·행(row·key)·필드(name·kind·meta_key·format). 괘선 좌표·bbox·
  기준 그림·인쇄 층만 다를 수 있다. 다르면 사이트 팩을 읽을 때 오류. `field_id` 에 템플릿 이름이 없어 키가 같으면 판이 바뀐 쪽에도 검수가
  붙지만, 다르면 조용히 떨어진다. 정답을 템플릿 이름으로 찾는 곳(`eval`, `review export-answers`, oracle)은 동시 판을 계열로 묶어 찾는다.
- 같은 계열에서 유효 기간이 겹치면 지금은 오류다 (ADR 0010). 이제 **겹치는 쪽 전부에 `concurrent: true` 가 있으면 허용**한다 —
  "같은 날 섞여 쓰이는 판"이라고 사람이 적은 것이다. 하나라도 빠지면 지금처럼 오류.
- 분류: 그날 후보 중 같은 계열의 동시 판들은 **한 후보로 묶는다** (점수는 그중 최댓값). 1위/2위 여유는 계열 사이에서 잰다 — 판끼리의 비율(≈ 1)이
  낮은 여유 표시(`low_margin`)를 늘 켜고, 분류가 고른 판 하나에만 정합하게 되지 않게. (지금 여유는 `unknown_form` 을 만들지 않는다 — 1위의
  인라이어가 `min_inliers` 이상이면 그 양식이고, 여유는 표시에만 쓴다.) 묶음이 없는 템플릿의 분류 점수·여유는 지금과 같다.
- 고르기: 묶인 계열로 분류되면 **동시 판마다 정합**하고, 통과한 판 중 괘선 오차가 가장 작은 것을 고른다. 오차의 차이가 0.5 px 이내면
  그 판에 정합한 인라이어(`n_inliers`)가 많은 쪽, 그래도 같으면 이름 순서. (괘선 오차는 0.5 px 단위다 — 같거나 한 단위 차이는 가르지 않는다.
  실제 판 B 의 쪽은 두 판의 차이가 4 px 이상이었다.) 통과한 판이 없으면 오차가 가장 작은 판의 수치로 `align_failed`.
- 쪽에 남긴다: `doc_page.template_name` = 고른 판, `doc_page.variant_errs` = 판마다의 괘선 오차
  (JSON `{판 이름: 오차 | null}` — 괘선을 못 찾아 유한하지 않으면 null). 업무 테이블의 `source_form` 은 판의 이름이다.
- 판이 하나뿐인 양식(지금의 전부)은 정합을 한 번만 한다 — 속도와 결과가 그대로다.
- 판을 만드는 일을 쉽게 한다 (`template variant`, 단계 4): 기존 판의 열·행·필드 정의를 그대로 두고 **표마다 괘선만 새 스캔에서 다시 잡는다.**
  - 새 기준 그림: 그 쪽을 기존 판에 맞춰 편다. 호모그래피는 **표 영역(괘선 범위 + 60 px) 밖의 특징점**(머리·제목)만으로 구한다.
    쪽 전체로 구하면 RANSAC 이 표 쪽으로 타협해 표를 기존 판 자리로 끌어오고 머리를 옮긴다 — 다시 잡은 괘선이 판 B 의 실제 자리와
    2–16 px 다르고, 표 밖 필드의 bbox 도 맞지 않는다.
  - 괘선: 기존 괘선마다 ±min(40 px, 이웃 표까지 간격의 절반) 안에서 가장 가까운 괘선과 짝짓는다 (창이 이웃 표의 괘선을 품지 않게 —
    합성 양식은 두 표 사이가 50 px 다). 짝이 없는 괘선이 있는 표는 기존 괘선을 두고 사람이 고치도록 알린다. 인쇄되지 않은 나눔 선
    (`split_ys`·`split_xs`)이 있는 표도 알린다 (다시 잡을 수 없다).
  - 표 밖 필드의 bbox 는 그대로 둔다 (판 B 는 머리 상자가 같은 자리였다) — `template preview` 로 확인한다.
  - `family` 는 기존 판의 것, 없으면 기존 판의 이름. 두 판에 적을 `family`·`concurrent: true` 를 안내한다 (기존 판의 파일은 고치지 않는다).
    `print_image` 는 복사하지 않는다 — 판 B 의 인쇄 층은 B 로 적재된 쪽으로 따로 만든다.

### 4.7 `readings` 는 "가동 시간을 정하는 칸"의 대기열이다

- 항목 = 쪽 하나: 계기 칸(시작·종료·총) + **근무 시각 칸**(`shifts` 표의 `time_range` 칸). 그중 하나라도 잉크가 있으면 올라온다. 빈 칸은 Enter.
- 기계 값·다른 쪽의 값을 싣지 않는 것은 그대로다 (ADR 0008, 0005 4.7).
- 작업량 칸의 검수 대기는 지금처럼 `pending` 대기열이다 (`--template`, `--kind` 로 좁힌다 — 계기·근무 시각 칸도
  같은 `handwritten_number` 라 같이 나온다. 그 칸은 `readings` 에서 넣는 것이 빠르다). 대기열을 새로 만들지 않는다.

### 4.8 점으로 쓴 시각은 화면이 묻는다. 코드는 여전히 콜론만 본다

- 계기 표의 시작·종료 칸(`reading` 형식)에 **소수 두 자리이고 24.00 이하이며 소수부가 00–59 인 값**(08.00, 17.30)을 넣으면 화면이
  저장 전에 묻는다: "시각이면 콜론으로 (08:00). 계기 값이면 그대로 저장." — 고르면 그대로 저장한다. 서버의 규칙(ADR 0015)은 바꾸지 않는다.
  총 칸은 묻지 않는다 (가동 시간 — 길이다). 입력이 미리 채운 값(`usage-check` 의 저장된 값)과 같으면 묻지 않는다 — 이미 정한 칸이다.
- 리포트에 수 하나: `eq_usage_daily` 에서 `reading_kind = 'meter' AND meter_start <= 24 AND meter_end <= 24` 인 쪽의 수 (시각을 숫자로
  넣었을 수 있는 쪽), 옆에 `reading_kind = 'mixed'` 인 쪽의 수 (한 칸만 콜론으로 넣은 쪽). 값을 고치지 않는다.

### 4.9 스키마 버전 7

- `doc_page.print_sha`(쓴 인쇄 층의 해시, 없으면 NULL), `doc_page.variant_errs`(동시 판마다의 괘선 오차 JSON — 4.6, 판이 하나면 NULL). 마이그레이션은 만들지 않는다 (ADR 0005).

## 5. 단계

### 단계 1 — 손질

할 일
- `template preview` 가 저장소 안이라 거절할 때 "오류를 전부 보려면 template check …" 가 같이 나온다 — 그 안내는 템플릿 오류일 때만.
- `template check`: 행·열이 괘선 범위를 벗어나 칸을 만들 수 없으면 기하 검사를 건너뛰었다고 한 줄로 알린다 (지금은 조용히 건너뛴다).
- `[equipment.aliases]` 를 고친 뒤에는 다시 돌려야 장비 ID 가 붙는다 — `minedocscan info` 가 대응표의 해시를 낸다. `report` 는 사이트 팩이 있으면
  `eq_usage_daily`·`prod_tally` 에서 `equipment_id` 가 지금 대응표로 정한 값(`SitePack.equipment_id_of(equipment)`)과 다른 행의 수를 한 줄로
  알린다 (값·이름 없이). 사이트 팩이 없거나 읽을 수 없으면 이 검사만 건너뛴다. (해시를 DB 에 남겨 비교하지 않는다 — 장비 ID 는 쪽을
  적재할 때만 정해지므로 `--skip-existing`·일부 실행 뒤에는 해시가 맞아도 ID 가 낡았을 수 있다.)
- 남은 "소수·시각 읽기는 0006" 참조를 "미룸 (tasks/0006 1절)"로: `handlers/base.py`(`unread_row` 근처), `handlers/usage.py` 모듈 설명,
  `store/schema.sql` 의 `eq_usage_daily` 주석, ADR 0015·0016 (본문은 두고 각주). `docs/ROADMAP.md` M1 첫 항목과 "다음 작업" 줄이
  템플릿 만들기를 tasks/0005 8절로 안내하는 것을 tasks/0006 8절로. (`docs/tasks/README.md` 의 0006 행과 ROADMAP 의 "(0006)" 은
  이 지시서의 PR 에서 이미 고쳤다. 상태는 문서 커밋에서 "완료 (PR #N)".)

수용 기준
- 저장소 안으로 `--out` 을 주면 거절 메시지 한 줄만 나온다.
- 대응표를 바꾼 뒤 `report` 가 한 줄로 알리고, 그 쪽들을 다시 돌리면(`--fresh` 또는 그 문서) 사라진다.

### 단계 2 — 인쇄 층 만들기

할 일
- `minedocscan template print-layer <템플릿 폴더> [--max-pages 40] [--percentile 75] [--out FILE]` (4.2). 기본 출력은 `<템플릿 폴더>/print.png`.
  출력 파일(기본 `<템플릿 폴더>/print.png`, 또는 `--out`)이 git 작업 트리 안이면 거절한다 (`template preview` 와 같은 검사).
  시험의 합성 사이트 팩은 `tmp_path` 라 걸리지 않는다. README 처럼 `out/` 에 만든 합성 팩은 저장소 안이라 거절되므로, SITE_PACK 의 예와
  6절의 끝까지 확인은 저장소 밖 경로에서 한다 (필요하면 `--allow-in-repo`).
  템플릿은 검증 없이 읽고 `print.png` 만 쓴다. `print_image` 키는 사람이 적도록 안내한다 (4.2).
- `forms/template.py`: `print_image` (선택). 파일이 없거나 크기가 기준 이미지와 다르면 템플릿 오류. `Template.print_mask` (4.3 의 마스크: `grid.binarize(print.png)` 를 2 px 넓힌 것, 한 번만 계산).
- `template check`: `print_image` 의 크기, 손으로 쓰는 칸 중 인쇄에 덮인 비율이 절반을 넘는 칸(값 자리가 없다)을 알린다.
- `template preview --print`: 인쇄 층 위에 칸을 그린다 (그림에 인쇄 화소를 색으로).
- `minedocscan info`: 템플릿마다 인쇄 층이 있는지.

수용 기준 (합성 가동 일보)
- 합성 쪽들로 만든 인쇄 층을 넓히지 않고 `grid.binarize` 한 것이 빈 양식(생성기의 빈 그림을 `grid.binarize` 한 것)의 인쇄 화소를 99 % 이상
  덮고, role 표(meter·shifts·tally)의 손으로 쓰는 칸 전체에서 인쇄 아닌 화소 중 인쇄로 잡힌 것이 1 % 미만이다 (칸마다의 값은 요약에만).
  2 px 넓힌 마스크로 재지 않는다 — 손글씨가 없어도 괘선 둘레가 칸의 4 px 안쪽으로 들어와 5–7 % 다. 필드에는 잔상이 남는다 (4.3).
- 쪽이 1장이면 거절, 3장이면 경고와 함께 만든다. 같은 쪽·같은 설정이면 같은 해시.
- 요약과 오류 메시지에 값·이름이 없다 (칸 이름과 수만).

### 단계 3 — 인쇄 층을 뺀 그림으로 값 유무를

할 일
- 파이프라인: 템플릿에 인쇄 층이 있으면 쪽마다 잉크를 재는 이진 그림을 한 번 만들고(4.3), role 표의 형식 있는 칸에서 `observe_cells` 의
  잉크 비율과 핸들러의 `assign_blobs` 가 그것을 쓴다. 필드·작업 표는 지금 그대로.
  `CellObs.crop` 과 `PageContext` 의 크롭 경로는 원래 그림 그대로. `doc_page.print_sha`.
- 합성 가동 일보: 로우더 양식의 근무 시각 칸에 인쇄된 "~" 를 넣는다 (작업량의 칸 안 인쇄는 0005 에서 넣었다). `synth --usage-logs` 에 인쇄 층을
  같이 만들어 넣는 선택 기능 (`--print-layers`). 기본 합성 데이터는 바이트까지 그대로.
  "~" 는 `--usage-logs` 합성에 늘 넣는다 — 인쇄 층을 끈 0005 시험의 기대가 바뀐다 (아무것도 안 쓴 SHOVEL 쪽의 근무 시각 칸이 "있음"이 되어
  그 쪽이 pending). 그 시험은 고친다. `--print-layers` 가 무엇을 넣는지(생성기의 빈 그림 / 합성 쪽에서 4.2 로 추정한 것)는 구현에서 정하고
  12절에 적는다 — 단계 2·3 의 수용 기준은 추정한 층으로 잰다.
  합성 계기 칸에는 칸 안 인쇄("시작:")가 없다 — 1절의 계기 칸 효과는 합성으로 시험하지 않는다 (8절의 실데이터 수치로 본다).
- `report`: 양식별로 인쇄 층을 쓴 쪽 수.

수용 기준 (합성 가동 일보, 인쇄 층을 켠 것과 끈 것을 같은 쪽으로 비교)
- 인쇄만 있는 칸(작업량의 인쇄 칸, 근무 시각의 "~" 뿐인 칸): 끄면 검수 대기, **켜면 빈 칸으로 자동 적재**.
- 값이 적힌 칸은 켜든 끄든 하나도 빈 칸으로 자동 적재되지 않는다 (계기·근무 시각·작업량, 인쇄 사이의 두 자리 숫자 포함). 대상은 role 표의
  형식 있는 칸이다 — 글자 필드에는 인쇄 층과 무관한 `text_ink_min` 경계의 기존 한계가 있다 (합성에서도 끈 상태로 2칸).
- 모든 쪽의 같은 자리에 같은 글씨를 쓴 필드(합성 로우더의 점검란 "ok")는 켜도 끈 때와 결과가 같다 (필드는 인쇄 층을 쓰지 않는다).
- 일부러 틀린 인쇄 층(다른 양식의 것을 같은 크기로, 5 px 밀린 것)을 넣어도 role 표의 값이 적힌 칸이 빈 칸으로 자동 적재되지 않는다 —
  검수 대기가 늘 뿐이다 (시험한 층에 대해서다 — 4.3).
- 켠 뒤 정답대로 검수하면 `eq_usage_daily`·`prod_tally`·`xcheck_usage` 가 합성 정답과 같다. 불변식(저장 직후의 DB = 새로 돌린 DB)이 성립한다.
- 크롭 PNG(`export-crops`, 검수 화면의 `/crop`)는 켜든 끄든 바이트까지 같다. `labels.jsonl` 의 `inked` 는 인쇄만 있는 칸에서 False 로
  바뀐다 (인식기에 가지 않으므로 의도한 것).
- 인쇄 층이 없는 템플릿의 결과와 `null` 의 회귀 수치가 그대로다.

### 단계 4 — 같은 날 섞여 쓰이는 판

할 일
- `forms/template.py`·`forms/sitepack.py`: `concurrent` (4.6). 계열의 겹침 검사, `templates_for(date)` 가 동시 판을 묶음으로 알려 준다.
- `forms/classify.py`: 묶음의 점수와 계열 사이의 여유. `pipeline/runner.py`: 묶음이면 판마다 정합해 고른다. `doc_page.variant_errs`.
- `minedocscan template variant <기존 템플릿 폴더> --scan FILE --page N --name NAME`: 새 판의 폴더를 만든다 —
  4.6 의 방법대로 — 표 영역 밖의 특징점으로 기존 판에 맞춰 편 그림이 새 기준 이미지, 표마다 기존 괘선을 ±min(40 px, 이웃 표까지의 절반)
  안의 가장 가까운 괘선과 짝짓는다, 열·행·필드는 그대로, `family`(없으면 기존 판의 이름)와 두 판 모두에 적을 `concurrent: true` 를
  안내한다 (기존 판의 파일은 고치지 않는다). 짝이 없는 괘선이나 나눔 선이 있는 표는 기존 괘선을 두고 알린다. `print_image` 는 복사하지 않는다.
  출력 폴더가 git 작업 트리 안이면 거절한다 (기준 이미지는 현장 스캔이다).
- 합성: 가동 일보(`synth_usage_log`)의 판 B — **작업 표와 계기 표 두 개만** 10 px 아래, 줄 간격 +1 %. 머리 상자·제목과 표 아래의 비고 상자·
  꼬리 문구는 판 A 와 같은 자리 (표 아래까지 같이 내리면 판 A 만으로도 작은 오차로 통과하고 칸도 맞아, 막으려는 실패가 합성에 없다).
  날마다 두 판이 섞인다 (`--usage-variants`). 정답의 `template` 은 그 쪽의 판 이름이다.
- `report`: 계열별로 판마다 고른 쪽 수, 두 판의 오차 차이가 1 px 미만인 쪽 수 (가르기 어려웠던 쪽 —
  두 오차가 모두 유한할 때만 센다). `pages --variants` 로 그 쪽들.

수용 기준 (합성)
- 판 A 의 템플릿만 있으면 판 B 의 쪽이 `align_failed` 이거나, `loaded` 인 쪽에서 판 B 정답 칸의 중심(템플릿 좌표로 옮긴 것)이 판 A 의 칸과
  4 px 이상 어긋난 칸이 있다 (묶음 전체에서 하나 이상) — 이 시험이 막는 실패가 합성에 있다는 것을 먼저 보인다.
- 두 판을 두면 모든 쪽이 `loaded` 이고 고른 판이 합성 정답과 같다. 판 B 의 쪽을 정답대로 검수한 결과가 합성 정답과 같다.
- `concurrent` 가 한쪽에만 있거나, `family` 없이 있거나, 동시 판끼리 키(4.6)가 다르면 사이트 팩을 읽을 때 오류다. 날짜로 가리는
  개정판(0002)은 그대로 돈다. 묶음이 없는 템플릿의 분류 점수·여유는 지금과 같다.
- 판 B 의 깨끗한 합성 쪽으로 `template variant` 를 돌려 만든 괘선(`grid.ys`·`xs`)이 생성기의 판 B 괘선과 2 px 안에서 같다 (머리에 맞춰 편
  그림이므로 생성기의 판 B 와 같은 좌표계다). 표 밖 필드의 bbox 도 그대로 맞는다.
- 판이 하나뿐인 양식은 정합 횟수가 그대로다 (시험으로 센다). 기본 `pytest` 의 시간이 1.25배를 넘지 않는다.

### 단계 5 — 가동 시간 칸의 입력

할 일
- `readings`: 항목에 근무 시각 칸을 더한다 (4.7). 끝난 쪽 = 그 칸들이 전부 검수된 쪽. `--audit N` 은 그대로.
- 화면: 점으로 쓴 시각의 확인 (4.8 — 계기 표의 시작·종료 칸만, 미리 채운 값과 같으면 묻지 않는다). `time_range` 칸의 안내("8-17, 08:00~17:00")는 0005 의 것을 그대로.
- `report`: 4.8 의 수.

수용 기준
- 계기가 비고 근무 시각만 적힌 합성 쪽이 `readings` 에 올라오고, 한 번의 저장으로 그 쪽의 가동 시간이 `shifts` 근거로 정해진다.
- 응답에 기계 값과 다른 쪽의 값이 없다 (0005 의 시험을 근무 시각 칸까지).
- `08.00` 은 화면에서 묻고, 그대로를 고르면 계기 값으로, 콜론을 고르면 `08:00` 으로 저장된다. `1234.5`, `8.5`, `25.30`, `08.75` 는 묻지 않는다.
  총 칸의 `08.00` 과 `usage-check` 에서 고치지 않고 확인하는 저장된 값도 묻지 않는다.
  (브라우저에서 확인하고 PR 본문에 적는다.)

### 단계 6 — 템플릿에 표 더하기, 문서

할 일
- `minedocscan template add-region <템플릿 폴더> --roi x0,y0,x1,y1 --name NAME [--role ROLE] [--header-rows N]`: 그 영역의 괘선을 잡아
  표 하나의 뼈대(괘선, 열·행의 자리)를 `template.yaml` 에 더한다. 인쇄 층이 있으면(`print_image` 키) 그것에서, 없으면 기준 이미지에서 잡는다.
  같은 이름의 표가 있으면 거절. 템플릿은 검증 없이 읽는다 (열을 채우기 전의 뼈대는 아직 템플릿 오류일 수 있다).
  파일의 다른 부분과 주석은 건드리지 않는다: `regions` 블록의 끝(다음 최상위 키 바로 앞)에 글자로 끼워 넣는다 — `fields` 가 `regions` 뒤에
  있어 파일 끝에 붙이면 필드가 된다. `regions: []` 이면 그 줄을 블록으로 바꾼다. 의존성은 PyYAML 뿐이다 (주석을 보존하는 YAML 라이브러리를
  더하지 않는다). 쓴 뒤 다시 읽어 표가 하나 늘었는지 확인한다.
  `--role` 을 주면 그 역할이 요구하는 열 이름·형식의 자리표시로 뼈대를 만든다 (meter: `start`·`end`·`total` 에 `reading`, shifts: `time_range`
  열 하나, tally: `integer`). handler 가 `usage` 가 아니면 알린다. 인쇄되지 않은 나눔 선(`split_ys`)은 사람이 넣는다.
- `docs/SITE_PACK.md`: 가동 일보 템플릿을 만드는 순서를 다시 쓴다 — 분류 전용으로 돌린다 → `print-layer` → `add-region` → 열·행·필드 →
  `check`·`preview --print` → 다른 판이 있으면 `variant`. 합성 템플릿을 예로 (저장소 밖 경로에서).
  열·행을 채우고 `template check` 가 통과할 때까지 그 사이트 팩으로 `run` 하지 않는다 (사이트 팩은 템플릿 오류 하나로 전부 멈춘다).

수용 기준
- 합성 양식의 빈 템플릿(분류 전용)에서 시작해 `print-layer`(4.2 의 "분류 전용 쪽을 직접 정합") → `add-region` 세 번으로 만든 괘선
  (`grid.ys`·`xs`)이 생성기의 괘선과 2 px 안에서 같다.
- 채워진 쪽(손글씨가 괘선 가까이 있는 합성 쪽)에서 잡으면 틀리는 괘선이 인쇄 층에서는 맞는다 — 인쇄 층에서 잡는 이유를 시험으로.

여기까지 끝나면 PR 을 연다.

## 6. 시험

- 전부 합성 데이터. 실제 문서의 이미지·이름·장비 번호를 테스트에 넣지 않는다. 합성으로 만든 인쇄 층은 시험 중에 만든다 (저장소에 넣지 않는다).
- 기본 `pytest`(torch 없음)는 OpenCV 5.0 과 하한 판에서 통과하고, 시간은 지금의 1.25배를 넘지 않는다. 새 파이프라인 실행은 세션에서 한 번 만든 것을 같이 쓴다.
  합성 가동 일보 파이프라인 한 번이 8–9 s 라 비교마다 전체를 돌리면 예산을 넘는다 — 켬/끔·틀린 층 비교는 같은 정합 그림에서 잉크를 재는
  그림과 값 유무만 다시 계산한다. 전체 실행은 인쇄 층을 켠 픽스처 하나와 판 묶음 픽스처 하나. 시험 픽스처는 `save_aligned=False` 라 인쇄 층은
  4.2 의 다시 펴는 경로로 만든다 — "정합 그림이 있을 때와 없을 때 print.png 가 바이트까지 같다"를 시험으로.
- 인쇄 층은 OpenCV 판에 따라 화소가 조금 다를 수 있다 — 바이트 비교는 같은 환경 안에서만 하고, 판 사이에서는 값 유무의 결과가 같은지로 본다.
- 0001 의 불변식 시험에 인쇄 층을 켠 가동 일보와 판 B 의 쪽을 더한다.
- 마지막에 깨끗한 환경에서 한 번: `pip install .` → `pytest`, 그리고 합성 묶음으로 2절의 명령을 처음부터 끝까지.

## 7. 지켜야 할 것

- 인쇄 층·미리보기·판의 기준 이미지는 저장소 밖에만. 요약·로그·오류 메시지에 이름·장비 번호·차량번호를 찍지 않는다.
- 인쇄 층이 값을 지우는 쪽으로 틀리면 안 된다 (4.3). 의심스러우면 검수 대기다. 인쇄 층은 role 표의 형식 있는 칸에만 쓴다.
- 판정 규칙의 임계값을 건드리지 않는다. 인쇄 층이 없는 템플릿, 판이 하나뿐인 양식의 결과는 그대로다.
- `CLAUDE.md` 의 작업 규칙을 따른다.

## 8. 사람이 할 일 (실데이터가 있는 컴퓨터에서)

PR 이 합쳐진 뒤, 순서대로. 0005 8절의 1번(세 양식의 템플릿)을 이 순서로 바꿔서 한다.

1. 세 양식(중기운행일보, 점보 작업일보, 로우더 작업일보)을 분류 전용 그대로 전체 묶음에 돌린 뒤 `template print-layer` 로 인쇄 층을 만든다
   (분류 전용 쪽은 명령이 직접 정합한다 — 4.2. 묵은 양식이 섞여 쓰이는 양식이면 `--percentile 50`). 요약의 "인쇄에 덮인 칸"과 `template preview --print` 로 표 칸에 잔상이 없는지 본다
   (필드의 잔상은 쓰지 않으므로 상관없다). 그 뒤 `template.yaml` 에 `print_image: print.png` 를 적는다.
2. `template add-region` 으로 표를 더하고 열·행·필드를 채운다 → `template check`. 인쇄가 든 칸은 **떼어 내지 않고 그대로** 둔다.
3. 중기운행일보의 판 B: `pages --status align_failed --thumbs` 로 실패한 쪽을 보고, 그중 깨끗한 쪽으로 `template variant`.
   두 판에 같은 `family` 와 `concurrent: true` (명령이 안내한다). 판 B 의 인쇄 층은 B 로 적재한 뒤에 만들고, **판 A 의 인쇄 층도 A 로 적재된 쪽만으로 다시 만든다** (첫 층에는 B 의 쪽이 섞여 있었다). 다른 양식에도 섞인 판이 있는지는 `report` 의 괘선 오차 분포로 본다.
4. `run DB_scans --fresh` (스키마 7) → `regress --update` (가동 일보 양식의 항목만 달라져야 한다).
5. 0005 8절의 나머지: `[equipment.aliases]`, `page-fields`, `readings`(이제 근무 시각 칸도), `usage-check`.

**돌려줄 수치** (이름·번호 없이 수치만): 양식별로 인쇄 층을 만든 쪽 수, 인쇄 층을 켜기 전과 뒤의 검수 대기 칸 수(계기·근무 시각·작업량),
`readings` 에 값 없이 올라온 쪽 수, 판마다 고른 쪽 수와 `align_failed` 의 수, 두 판의 오차 차이가 1 px 미만인 쪽 수,
섞인 판이 더 발견된 양식, 점으로 쓴 시각을 물은 횟수.

| 인쇄 층을 쓰는 칸 | role 이 meter·shifts·tally 인 표의 형식 있는 칸만. 필드·서명·작업 표는 원래 그림 (4.3) |
| 인쇄 층을 만드는 쪽 수 | 최대 40, 5 미만이면 경고, 2 미만이면 거절 |
| 두 판의 오차가 비슷할 때 | 차이 0.5 px 이내면 그 판에 정합한 인라이어가 많은 쪽. 리포트에 차이 1 px 미만인 쪽의 수 |
| 판이 셋 이상인 계열 | 같은 규칙 (판마다 정합). 속도는 판의 수만큼 든다 |
| 운반·점검표 양식에 인쇄 층 | 켜지 않는다. 숫자 정답이 생긴 뒤에 `regress`·`eval` 로 판단 |
| 인식기의 크롭에서 인쇄 지우기 | 하지 않는다. 숫자 모델의 실데이터 수치를 본 뒤 |
| 소수·시각을 기계가 읽는 것 | 미룬다 (1절). 숫자 모델과 메타 모델의 실데이터 수치가 나온 뒤에 다시 정한다 |

## 12. 지시서와 달라진 점 (구현 뒤)

4절(이미 정한 것)을 바꾼 것은 없다. 4.3 의 한 문장은 합성에서 맞지 않았다 — 바로 아래 열린 질문으로 둔다.
그 밖에는 4·5절이 정하지 않은 자리를 다음처럼 채웠다.

**열린 질문 (사람이 정할 것): 적은 쪽으로 만든 인쇄 층**
- 4.3 은 맞는 층·틀린 층과 함께 "2–5장으로 만든 층 어느 것에서도 값이 적힌 칸을 잃지 않았"다고 적었다. 합성 3일치에서 명령의
  차례(`pick_order`)로 앞 k장만 써서 만든 층은 **로우더의 값이 적힌 작업량 칸을 2장이면 1칸, 3장이면 4칸 잃는다** (인쇄 사이의 두 자리 값).
  그 칸은 빈 칸으로 자동 적재된다 — 7절이 막으려는 것이다. 4·5장은 0칸이다. 단계 3 에서(판을 나누기 전) 운행일보는 2–5장 모두 0칸이었고,
  임의의 두 장 짝으로는 로우더 15짝 중 9짝, 운행일보 36짝 중 2짝이 한 칸 이상 잃었다.
- 까닭: 쪽이 적으면 대부분의 쪽에서 같은 자리에 쓴 손글씨가 75 백분위에 남고, 마스크가 그 자리에 쓴 값을 지운다.
- 지금은 4.2·9절대로 두었다: 2장 미만 거절, 5장 미만 경고 (`tools/printlayer.MIN_PAGES = 2`, `WARN_PAGES = 5`). 경고 문구가 그 위험(같은
  자리에 쓴 값이 지워져 빈 칸으로 자동 적재될 수 있다)을 말한다. 시험은 4·5장 통과, 2·3장은 strict xfail
  (`tests/test_print_presence.py::test_layers_from_few_pages_do_not_lose_written_values` — 정하면 이 표시를 바꾼다).
- 고를 것: (가) 거절 기준을 4–5장으로 올린다 — 4.2·9절과 단계 2 의 수용 기준("3장이면 경고와 함께 만든다")이 바뀐다.
  (나) 4.3 을 "4장부터 (합성)"로 고치고, 8절에서 5장 이상으로만 만들라고 적는다. 1절의 실제 층 하나는 4장으로 만들었고,
  8절 3번의 판 B 층은 처음에 쪽이 적다.

**단계 1 — 손질**
- `template check`: 칸을 만들 수 없는 표는 **그 표만** 기하 검사(겹침·쪽 밖·좁은 칸)에서 빼고, 나머지 표와 필드는 검사한다 (지시서는 "조용히
  건너뛰지 않는다"만 적었다). 알림 줄은 원인을 하나로 단정하지 않는다 — 행·열이 괘선 범위 밖이거나 표 정의가 빠졌을 수 있고, 실제 원인은
  위의 오류 줄에 있다. 표 이름과 수만 찍는다.
- `report` 의 낡은 장비 ID: 행 수와 함께 쪽·문서 수를 낸다. JSON 에서는 `report` 밖의 최상위 키 `stale_equipment_ids` 다 — `regress` 가
  비교하지 않는다. 키는 `eq_usage_daily`·`prod_tally` 에 행이 있을 때만(0 이어도) 생긴다 — 운반·점검표뿐인 사이트의 `report --json` 은
  사이트 팩이 있어도 예전과 같다. 사이트 팩을 읽을 수 없으면 예외 종류의 이름만 한 줄로 알리고, JSON 에는 넣지 않는다. `run` 은 알리지 않는다.
- 대응표의 해시(`SitePack.equipment_aliases_sha`): 정렬한 (이름, 장비 키) 쌍의 sha256 앞 16자. 순서나 주석을 바꿔도 같다.
- `template preview`: 기준 이미지를 읽을 수 없으면 템플릿 오류로 본다 (check 안내가 붙는다). 저장소 안 거절과 없는 쪽은 한 줄이다.

**단계 2 — 인쇄 층 만들기**
- 쪽 고르기: 날짜마다 돌아가며 한 장씩. 날짜 안에서는 (문서, 쪽) 순서, 날짜 없는 쪽은 맨 뒤의 한 묶음이다. 쓸 수 없는 쪽은 다음 쪽으로 채운다.
  저장된 정합 그림은 기준 이미지와 크기가 같을 때만 쓴다. `render_dpi` 가 없으면 설정의 dpi 로 렌더링한다.
- 분류 전용 쪽의 정합 품질은 정합과 같은 `MIN_INLIERS`(60, `imaging/align.py`)로 본다. 새 수치는 없다. DB 는 읽기 전용으로 연다
  (`store.db.open_db_readonly`). DB 파일이 없으면 거절한다.
- 새 규칙: `print_image` 는 PNG 만, `--out` 도 `.png` 만. 손실 압축이면 파일의 화소가 요약의 `print_sha` 와 달라진다.
  깨진 PNG 는 사이트 팩을 읽을 때(머리만 읽는다) 오류가 아니고, `template check` 가 한 줄로 알린다.
- `template check` 가 인쇄 층이 절반 넘게 덮은 칸을 셀 때는 **표의 칸만** 센다. 필드의 잔상은 쓰지 않으므로(4.3, 8절 1번) 세면 실제 템플릿이 check 를
  통과하지 못한다. 필드는 print-layer 요약의 `covered` 와 `preview --print` 에 그대로 보인다.
- `preview --print` 는 `--scan` 과 같이 쓸 수 없다. 출력 파일은 `<이름>__print.png` 다.
- 수용 기준 1(빈 양식의 인쇄를 99 % 이상 덮고, 잘못 잡은 인쇄는 1 % 미만)은 **양식마다, 합성 10일치**로 잰다. 3일치(운행일보 9쪽)는 모든
  쪽이 같은 자리에 계기 값을 써서 운행일보만 약 1.9 % 다 — 방법이 아니라 쪽 수의 문제다. 10일치(단계 3 의 "~" 뒤): 운행일보 0.46 %·로우더
  0.56 % (OpenCV 5.0), 0.48 %·0.58 % (4.9). 덮음은 모두 1.0.

**단계 3 — 인쇄 층을 뺀 그림으로 값 유무**
- 인쇄 층을 쓰는 칸은 `Template.role_value_cell` 한 곳에서 정한다. `observe_cells` 와 `handlers/usage.presence`(덩어리 배정 또는 잉크 비율)가
  그것을 본다.
- `doc_page.print_sha` 는 그런 칸이 있는 양식(`Template.uses_print_layer`)에서만 남는다. 역할이 없는 표뿐인 양식(운반·점검표)에
  `print_image` 를 적어도 아무것도 바뀌지 않는다. `template check`(참고 줄)와 `info` 가 "쓰지 않음"을 알린다. 3절의 "켤 수는 있게"(4.4)는
  이 PR 에서는 코드를 고쳐야 쓸 수 있다는 뜻이 되었다.
- `synth --print-layers` 는 **추정한 층**을 넣는다 (생성기의 빈 그림이 아니다). 스캔한 쪽(PDF 와 같은 JPEG)을 알려진 아핀의 역으로 템플릿
  좌표에 되돌린 뒤, 4.2 와 같은 방법으로 만든다 (75 백분위, 날짜별로 고르게 최대 40장). 난수를 더 쓰지 않아 스캔과 `answers.json` 은 켜든
  끄든 바이트까지 같다. 달라지는 것은 두 템플릿(`print.png`, `print_image`)과 `truth.json` 의 `print_layers` = {양식: print_sha} 뿐이다.
  생성기는 고를 쪽만 들고 있다 (메모리).
- 합성 근무 시각 칸의 "~" 는 Hershey 글꼴이 아니라 선으로 그린다. Hershey "~" 의 잉크가 OpenCV 5.0 에서 102 px, 4.9 에서 276 px 였고,
  이 표시 하나가 값 유무를 정한다.
- `report` 의 인쇄 층 수는 **적재된 쪽**만 센다 (오류 난 쪽은 `print_sha` 가 남아도 세지 않는다). 그런 쪽이 없으면 키가 없다 — 예전 리포트와 같다.
- 합성 로우더의 점검란 "ok": 6쪽 중 1쪽은 잉크 0.0072 로 `text_ink_min`(0.008) 아래라 켜든 끄든 빈 칸이다 (기존 한계). 시험은 "켜고 끈
  행이 같다"와 "잉크가 기준 이상인 쪽은 ok" 로 잰다.
- 시험: 세션의 가동 일보 픽스처가 인쇄 층을 **켠** 것이 되었다 — 0005 의 검수·불변식 시험이 켠 쪽을 덮는다. 끈 결과, 틀린 층, 적은 쪽의 층은
  같은 쪽을 다시 펴서 `observe_cells` 와 핸들러만 다시 돌린다 (새 파이프라인 실행 없음). 다시 돌린 결과가 세션의 DB 와 같은지도 본다.
  ±5 px 밀린 층은 시간 때문에 로우더 쪽에서만 잰다 (세 표의 값이 적힌 칸이 다 있다). 다른 양식의 층은 모든 쪽에서 잰다.

**단계 4 — 같은 날 섞여 쓰이는 판**
- 합성: 날마다 운행일보의 쪽이 판 A·B 를 번갈아 쓴다. 그날 시작하는 판은 따로 둔 난수로 정해서, 쪽의 내용은 판이 없을 때와 같다. 세션의
  3일치는 A 5쪽·B 4쪽이고, 날마다 두 판이 다 있다. 두 판의 `family` 는 판 A 의 이름(`synth_usage_log`)이다.
- 동시 판의 키 비교: 4.6 의 "괘선 좌표·bbox·기준 그림·인쇄 층만 다를 수 있다"를 그대로 — 열·행은 사전 통째로(메타까지), 표의
  `header_rows`·`role`·그 밖의 항목, 필드는 bbox 밖 전부, 템플릿의 `handler`·`handler_options` 를 비교한다. 이름·제목·유효 기간도 다를 수
  있다. 형식은 실제로 쓰는 형식(`format` 이 없으면 종류의 기본값)으로 본다. 표·열·행·필드는 순서와 무관하게 비교한다. 오류는 두 템플릿
  이름과 처음 다른 항목의 종류(handler, handler_options, 표 이름, 표 X 의 role·header_rows·열·행·그 밖의 항목, 필드)만 찍는다. 행 키·값은
  찍지 않는다.
- 계열에 `concurrent` 판이 하나뿐이면 사이트 팩 오류다 (`template variant` 바로 뒤, 기존 판에 두 줄을 적기 전의 상태 — 수용 기준의 "한쪽에만").
  오류는 그 판과 계열, 두 줄을 적을 판(계열과 이름이 같은 템플릿이 있으면 그것)을 말한다. 두 동시 판의 유효 기간이 겹치지 않으면 읽힌다.
  이름이 같은 템플릿이 둘이어도 사이트 팩 오류다 (예전에는 뒤의 것이 말없이 덮었다). `template variant` 는 옆 템플릿이 쓰는 `--name` 을
  거절하고, 읽을 수 없는 기존 판(YAML·이름·기준 이미지)도 한 줄로 거절한다.
- 통과한 판이 없으면 같은 규칙(0.5 px → 인라이어 → 이름)을 판 전부에 적용하고, 고른 판의 수치로 `align_failed` 다. 이때 `print_sha` 는 NULL,
  `variant_errs` 는 그대로 남긴다. 판이 셋 이상이면 "가르기 어려웠던 쪽"은 오차가 가장 작은 두 판으로 잰다. 리포트의 수(`near_tie`)는 판을
  고른 쪽만 센다 — 두 판 모두 정합에 실패한 쪽은 `align_failed` 로만 (빠진 판을 가리키는 쪽이다). `pages --variants` 는 그런 쪽도 상태와 함께 낸다.
- 리포트의 묶음 이름은 계열이다. `run`·`report`·`regress` 가 사이트 팩에서 계열을 받는다 (`SitePack.variant_families()`). 사이트 팩 없이
  `build_report` 만 부르면 DB 에 계열이 없어 판 이름들("A / B")로 묶는다. `variants` 키는 그런 쪽이 있을 때만 생긴다 — 판이 없는 사이트의
  리포트와 회귀 기준은 그대로다.
- `template variant`: 나눔 선이 있는 표는 표 전체의 기존 괘선과 나눔 선을 그대로 두고 알린다. 이웃 표는 다른 축으로 범위가 겹치는 표다.
  반지름은 기존 판의 괘선으로 잰다 (다시 잡은 괘선이 아니다 — 표의 순서와 무관하게). 새 템플릿에 `title`·`valid_from`·`valid_to` 를
  복사하고 `print_image` 는 뺀다.
- `run --template X` 는 묶음을 건너뛰고 그 판에 한 번만 정합한다.
- 4.6 이 꼽은 "정답을 템플릿 이름으로 찾는 곳" 셋 중 고친 것은 둘이다: `eval`(`evaluate_fields(site=…)`)과 oracle
  (`OracleRecognizer(site=…)`)이 사이트 팩이 있으면 `SitePack.answer_key` 로 동시 판을 계열에 맞춘다. `review export-answers` 는 그대로다 —
  검수 기록에 적힌 쪽의 판 이름으로 정답을 쓰고, 그것을 읽는 두 곳이 계열로 맞춘다.
- 4.2 의 현상을 합성에서도 보았다. 두 판이 섞인 하루치로 75 백분위 층을 만들면 판 A 의 작업 표 괘선이 4–54 % 만 남는다. 그래서 분류 전용
  경로의 시험은 판 A 만 있는 하루치(10일치 합성의 첫날)로 한다.
- 판 A 의 템플릿만 두면 합성 판 B 의 쪽은 하나만이 아니라 **전부** `align_failed` 이거나 칸이 4 px 이상 어긋난다. 시험은 전부를 요구한다
  (수용 기준은 "하나 이상").
- 깨끗한 판 B 의 수용 기준은 두 씨앗으로 잰다. "표 밖의 특징점만"은 `findHomography` 에 들어가는 점을 보고 잰다. OpenCV 4.9 에서는
  깨끗한 쪽이면 쪽 전체의 호모그래피도 맞게 나와 결과로는 가를 수 없다.
- 시험 쪽의 줄임: 불변식 시험과 대응표 시험은 세션 실행의 분류 결과를 쪽 화소의 해시로 다시 쓴다. 분류는 검수·대응표와
  무관하고 결정적이다. 정합, 판 고르기, 칸, 핸들러, 검수 적용은 다시 계산한다. 대응표 시험은 낡은 두 문서 중 하나만 다시 돌린다 — 다시 돈
  문서의 행은 사라지고 다른 문서의 행은 남는다. 정합 횟수는 세션 실행 안에서 `align_to_template` 를 세어 잰다. `usage_run` 의 정답 인식기는
  일부러 사이트 팩 없이 둔다 — 판을 잘못 고르면 값이 빠져 드러난다.

**단계 5 — 가동 시간 칸의 입력**
- 항목의 칸 순서: 계기(시작·종료·총) 다음에 `shifts` 표의 `time_range` 칸 (행 순서, 같은 행이면 x 순서). 라벨은 "근무 시각 " 과 행의 인쇄된
  근무 구분(없으면 행 키)이고, `time_range` 열이 둘 이상이면 열 이름을 붙인다. 라벨은 템플릿의 값이지 손글씨가 아니다. 제목 끝에 "· 계기",
  "· 근무 시각", "· 계기·근무 시각".
- 끝난 쪽은 항목의 칸이 전부 검수된 쪽이다. 계기 칸만 검수된 쪽(0005 의 `readings`, `pending`)은 근무 시각 칸 때문에 다시 올라온다.
- 묻는 표시(`QueueCell.ask_dotted`)는 대기열이 아니라 칸의 속성이다. `usage` 양식의 role meter 표에서 시작·종료 자리이고, 형식이 `reading` 인
  손글씨 칸이다. `readings`·`usage-check`·`pending` 이 다 단다 (4.7: 같은 칸이 `pending` 에도 나온다). 사이트 팩이 없으면 달지 않는다.
  `decimal`·`time` 형식의 계기 칸은 묻지 않는다 — 소수는 시각을 담을 수 없고, `time` 은 점도 시각으로 받는다.
- 규칙의 자리: `forms/formats.DOTTED_CLOCK`·`CLOCK_MAX_MINUTE`·`CLOCK_MAX_DAY_MINUTES` 와 `dotted_clock()`. 서버가 정규식과 두 상한을 대기열
  JSON 의 `dotted_clock`(`dotted_clock_rule()`)으로 보내 화면과 Python 이 한 규칙을 쓴다 — 화면의 스크립트에는 수가 없다. 시험이 화면의
  `dottedClock` 에 수가 없는지 보고, node 가 있으면 그 함수를 같은 벡터로 돌려 Python 과 견준다 (CI 에 node 가 없으면 건너뛴다). "24.00 이하"는
  24:00 까지다: 24.00 은 묻고 24:00 이 되며, 24.30 은 묻지 않는다.
- 화면: `confirm()` 이 아니라 입력 아래의 판이다. 1 = 시각(HH:MM 으로 저장), 2 = 그대로, Esc = 저장하지 않고 입력으로. 판이 열린 동안 다른 키는
  먹는다 (Enter 를 거듭 눌러 답이 되지 않게). 시작·종료가 둘 다 점으로 쓴 시각이면 칸마다 차례로 묻는다.
- "미리 채운 값과 같으면 묻지 않는다"의 미리 채운 값은 **사람이 정한 값**이다 (앞선 검수, `usage-check` 의 저장된 값). `pending` 이 미리
  채우는 기계 값은 정한 값이 아니라서 같아도 묻는다.
- 4.8 의 수는 리포트의 최상위 키 `usage_dotted_suspect` (`report.dotted_suspect`)이고 가동 기록이 있을 때만 생긴다. `usage` 묶음 안에 두면
  가동 일보가 없는 사이트까지 0005 뒤의 모든 회귀 기준과 달라진다. `mixed` 의 수는 따로 세지 않고 `usage.reading.mixed` 를 같은 줄에 낸다.
  가동 기록이 있는 사이트에서는 회귀에 새 항목으로 나온다 (실패가 아니다 — 8절 4번의 `regress --update`).
- **8절의 "점으로 쓴 시각을 물은 횟수"는 어디에도 남지 않는다.** 질문은 `reviews.jsonl` 에 흔적이 없다 — 고른 결과(08:00 또는 8.00)만
  남는다. 검수하는 사람이 손으로 세거나 "재지 않음"으로 돌려준다. 값 없는 표시를 남길지는 나중에 정한다.
- 시험: `conftest.review_usage` 에 `skip=` 를 더했다. `reviewed` 픽스처는 근무 시각 칸을 `readings` 로 검수하고 칸마다의 검수에서는
  건너뛴다. 끝 상태는 같고, 두 번 검수하는 칸은 없다.

**단계 6 — 템플릿에 표 더하기**
- 자리: `tools/mktemplate.add_region`. `template init` 과 뼈대 함수(`region_skeleton`)를 같이 쓴다. 행 키는 init 처럼 `row_<i>` 다.
- 역할의 자리표시 (지시서가 열의 자리를 정하지 않았다):
  - meter: **마지막** 데이터 열들. 셋 이상이면 start·end·total(`reading`)이고 앞 열은 `printed`(인쇄된 라벨 열 — 합성 두 양식과 같다).
    둘이면 start·end, 한 열 한 행이면 start. 한 열에 행이 둘 이상이면 세로 계기다: 행 키 start·end·total 과 `reading` 열 하나.
  - shifts: 마지막 열이 `range`(`time_range`). 열이 둘 이상이면 첫 열이 `printed` 인 `shift`.
  - tally: 모든 열이 `integer` 다 (인쇄된 구분·장소 열 포함 — 사람이 `printed` 로 바꾸고 행·열 메타를 더한다). activities: 글자 칸.
  - 요약에 열 번호마다 자리표시를 적는다. `template check` 는 자리표시가 맞는 열에 갔는지 보지 않는다고 같이 적는다.
- 요약의 알림 (지시서에 없던 것):
  - usage 가 아닌 핸들러에 역할을 주면 표는 쓰고 알린다 (check 가 오류로 잡는다).
  - 동시 판이면 같은 계열의 다른 판에도 같은 표가 있어야 사이트 팩이 읽힌다고 알린다. check 는 한 판만 본다.
  - 인쇄 층에서 잡았으면: 적은 쪽으로 만든 층은 잔상이 괘선으로 잡힌다 — 줄 수를 인쇄된 표와 대 보라.
  - 기준 이미지에서 잡았으면: 채워진 스캔은 손글씨 획이 괘선이 된다 — 먼저 `print-layer`.
- template.yaml 쓰기:
  - 다음 최상위 키 바로 위의 빈 줄과 0열 주석은 그 키의 것으로 보고 그 위에 넣는다. 기존 항목의 들여쓰기를 따른다.
  - `regions: []`·null·빈 값은 블록으로 바꾸고 그 줄의 주석은 남긴다. `regions` 가 없으면 파일 끝에 더한다. CRLF 를 지킨다.
  - 같은 폴더의 임시 파일에 쓴 뒤 `os.replace`. 다시 읽어 regions 밖의 키가 같고, regions = 예전 + 새 표이고, `Template(validate=False)` 로
    읽히는지 본다. 아니면 원래 바이트로 되돌린다.
- 거절 (한 줄): 흐름 표기 `regions: [...]`(블록으로 바꾸라고 안내), 리스트가 아닌 `regions`, `print_problems()` 에 걸리는 `print_image`
  (기준 이미지로 내려가지 않는다), 쪽 밖의 ROI(자르지 않는다), 이름 `fields`, 모르는 역할, 음수 `--header-rows`, 괘선이 너무 적은 영역.
  저장소 검사는 무엇을 읽기 전에 한다.
- 잰 것: 로우더에서는 채워진 쪽에서 잡으면 계기 값의 획이 세로선으로 하나 더 잡히고, 인쇄 층에서는 맞다 (수용 기준 2).
  **운행일보에서는 첫날(4쪽)로 만든 층이 아직 깨끗하지 않다**: 계기 표의 시작 칸 안에 세로선이 하나 더 잡힌다 (같은 자리에 쓴 값의 잔상).
  10일치 층과 빈 양식은 맞다. ROI 의 여유를 4쪽 층에서 5–25 px, 빈 양식에서 5–40 px 로 바꿔도 같고, 60 px 에서는 빈 양식에서도 이웃 표의
  괘선이 들어온다. 고칠 것은 ROI 가 아니라 층의 쪽 수다. 시험이 이것을 고정한다
  (`tests/test_add_region.py::test_usage_log_meter_placeholders_and_few_page_layer_residue`).

**시험 시간**
- 세션의 합성 가동 일보 묶음(`usage_synth`·`usage_run`)이 인쇄 층을 켜고(단계 3) 두 판을 섞은(단계 4) 것이 되었다. 0005 의 검수·불변식 시험이
  켠 쪽과 판 B 의 쪽을 같이 덮는다. 켬/끔·틀린 층·적은 쪽의 층은 같은 정합 그림에서 잉크를 재는 그림과 값 유무만 다시 계산한다.
- 단계 2 의 10일치 분류·정합 픽스처(24.6 s)는 단계 4 에서 합성의 추정 층(`--print-layers`, 10일치, 파이프라인 없이)으로 바꿨다. 분류 전용
  경로는 하루치다.
- 기본 `pytest` 의 시간 (이 컴퓨터는 작업 중에 부하가 달라 같은 코드가 200–280 s 로 흔들렸다 — 배율은 main 과 이 브랜치를 같은 때에
  이어서 잰 것으로만 말한다): 마지막 코드(전체 검토 반영 뒤)에서 main(a777831) 216.1 s, 이 브랜치 270.0 s — **1.249배** (기준 1.25배).
  단계 5 뒤에는 220 s 대 257 s (1.17배)였다. 늘어난 것의 대부분은 세션 픽스처다: 수용 기준 1 의 10일치 합성(약 11 s), 인쇄 층과 두 판이
  들어간 세션 가동 일보 묶음(main 의 약 8 s → 약 11.5 s — 층 추정과 판마다의 정합). 10일치를 8일치로 줄이면 약 2 s 가 줄지만 운행일보의
  잔상이 0.62 % 로 1 % 기준에 가까워져 그대로 두었다 (7일치 0.95 %).
- 하한 판(OpenCV 4.9, numpy 1.26)에서 전체가 통과한다. 깨끗한 환경(새 clone → `pip install .` → `pytest`)도 통과했고, 2절의 명령(합성
  `--usage-only --print-layers --usage-variants` → run → report → print-layer → preview --print → variant → add-region)을 끝까지 돌렸다.
