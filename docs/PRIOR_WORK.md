# 선행 연구와의 관계

이 저장소는 처음부터 새로 쓴 코드다. 그러나 출발점은 같은 문제를 먼저 다룬 위탁연구 두 건(2024년, 2025년)이고,
그 산출물(소프트웨어, 사용 매뉴얼, 최종보고서·요약서)과 특허 세 건을 읽고 설계했다.
무엇을 이어받고 무엇을 바꿨는지, 그 근거가 무엇인지 여기에 남긴다.

## 선행 연구가 만든 것

- **2024년**: 표 기반 셀 인식과 데이터셋 자동 구축.
- **2025년**: 컴퓨터비전 + 그래프 신경망으로 레이아웃을 인식하고, 광산 용어로 미세조정한 소형 언어모델로 OCR 오류를 교정하는
  멀티모달 손글씨 인식. 대상은 일일 장비 점검현황.

선행 파이프라인의 흐름:

```
스캔 → 민감정보 마스킹(규칙) → 상용 OCR → 표 셀 검출, 글자 상자를 가장 가까운 셀에 배정
     → 셀 간 관계를 그래프로 표현 → 소형 언어모델(미세조정)로 교정 → 엑셀
```

## 그대로 이어받는 요구사항

선행 매뉴얼과 보고서가 정한 운용 조건은 이 소프트웨어에도 그대로 적용된다.

| 요구사항 | 이 저장소에서 |
|---|---|
| 스캐너에서 스캔 버튼만 누르면 끝까지 자동으로 돈다. 사용자는 명령을 치지 않는다 | 접수 폴더 감시(`serve`·`watch` — [tasks/0007](tasks/0007-intake.md))가 업무 테이블까지 처리하고, 바퀴 끝에 (설정이 있으면 — `[export] excel_dir`, `MINEDOCSCAN_PUBLISH_URL`) 엑셀·통합 DB 까지 ([tasks/0008](tasks/0008-export.md)). 사람은 화면에서 결정(날짜·버리기 …)과 검수만 한다. 합성 접수 묶음으로는 선다 — 스캐너로는 아직 (ROADMAP M5). `serve` 를 띄우는 것(설치·서비스 등록)은 M6 |
| 갱내 통신 불가와 보안 때문에 **외부 네트워크 없이** 로컬에서 돈다. DB 도 로컬 | 인식·교정 백엔드는 로컬 모델만. 외부 API 백엔드를 만들지 않는다. 작업 DB 는 로컬 SQLite 그대로 — 통합 DB(현장 서버의 PostgreSQL)에는 결과의 사본을 싣고(`publish`), 서버가 꺼져도 접수·처리·검수는 돈다 ([ADR 0021](decisions/0021-publish-to-the-shared-db.md)) |
| 현장 사용자는 결과를 **엑셀**로 확인한다 (날짜·문서 유형별 파일) | 엑셀은 DB 에서 만든 사본이다 (원본은 스캔·검수 기록·결정 기록) — 한 방향, 확정된 값만 싣는다 (검수 대기 `?`, `판독 불가`; 기계 값은 `[export] machine_values` 일 때만 업무 시트·긴 표의 따로 둔 열에) ([ADR 0022](decisions/0022-exports-are-copies.md)). 하루 한 파일(`daily/<달>/<날짜>.xlsx` — 요약, 양식마다 시트(종이와 같은 행·열), 업무 표) + 한 달 한 파일(`monthly/<달>.xlsx` — 날짜별 요약, 운반 표, 배차, 긴 표). **문서 유형마다 파일을 나누지 않는다** — 유형은 일별 파일 안의 시트로 나뉘고(양식마다 한 장), 교차검증·운반 표는 양식을 가로지르므로 한 파일에 있어야 견줄 수 있다 (tasks/0008 9절). `serve`·`watch` 가 바퀴 끝에 쓰고(`[export] excel_dir`), 손으로는 `export excel`, 홈에서 내려받는다 ([tasks/0008](tasks/0008-export.md)) |
| 이름·결재·차량번호 등 민감정보를 가린다 | 템플릿이 그 위치를 안다: 서명 필드, 작성자·차량번호 필드(`site.toml` `[redact] meta_keys`), 템플릿의 `redact` 상자(결재란, 행렬 머리의 인쇄된 이름·차량번호, 점검표의 인쇄된 등록번호 열 — 판마다), 글자 칸(기본). **밖에 보일 그림**(발표·보고서 — 예전에 "화면으로 내보낼 때"라고 적은 것)은 `export masked-pages` 가 정합 그림 위의 그 자리를 한 색으로 채운다. 템플릿이 아는 자리만 가리므로 사람이 보고 나서 쓴다 ([ADR 0022](decisions/0022-exports-are-copies.md)). 가린 그림도 현장 데이터다 — 저장소 밖에 (명령이 git 작업 트리 안을 거절한다). 가리지 않는 것: 운영·검수 화면(127.0.0.1)의 그림 — 현장에서 검수하는 사람이 본다. 엑셀과 통합 DB 의 표에는 이름·차량번호가 그대로 들어간다 (현장 안의 사본 — 엑셀 폴더와 서버를 볼 사람은 현장이 정한다, [ADR 0021](decisions/0021-publish-to-the-shared-db.md), [DATA.md](DATA.md)). 학습용 크롭은 가리지 않는다 — 가린 크롭·학습 데이터 묶음은 만들지 않았다 (tasks/0008 3절). 메타 크롭(`export-crops --meta`)은 이름·차량번호 그 자체다 — 저장소 밖에만 (git 작업 트리 안이면 도구가 거절한다, [DATA.md](DATA.md)) |
| 사용자가 고친 값은 모델 개선에 쓴다 | 검수 결과(`reviewed`)가 그대로 정답이 된다 |
| GPU 가 없으면 CPU 로 돈다 | 인식기를 뺀 전 단계가 CPU 에서 쪽당 약 1초 |

## 자산 — 가진 것과 없는 것 (코드가 아니라 데이터로)

2026-10 현재 선행 연구팀에 추가 자료를 요청하기 어렵다. 계획은 **가진 것만으로** 세운다.
전부 저장소 밖(아카이브·사이트 팩)에 둔다.

| 자산 | 상태 | 쓰임 |
|---|---|---|
| 일일 장비 점검현황 스캔 | 2024년 7월 27일치를 가지고 있다 (보고서상 전체는 376건, 2024.5 – 2025.7) | 텍스트 인식·교정의 평가셋 |
| 전문가가 판독·검증한 정답 | 같은 27일치를 가지고 있다 | `eval --inspection-csv` 의 정답 |
| 상용 OCR 결과를 표의 셀에 배정한 엑셀 | 같은 27일치를 가지고 있다 (서비스의 원 응답은 아니다) | 새로 호출하지 않고 기준선을 계산한다. 이 기준선은 "상용 OCR + 선행 셀 배정"의 성적이다 |
| 지시 데이터셋 | 2024년 7월 교정용 일부를 가지고 있다 | 문구 후보, 교정 모델의 학습·평가 자료 |
| 미세조정 어댑터 (소형 언어모델) | 설정 파일만 있고 **가중치가 없다** | 지금은 평가할 수 없다 |
| 장비별 점검내역 사전, 광산 용어 751개 | 없다 | 문구 사전은 정답 27일치와 검수값에서 직접 만든다 |
| 작업일보·운행일보 3,923건 | 지금 가진 하루치 묶음 PDF(2024.10 – 2025.3)와 같은 자료로 보인다. 정답은 없다 | 숫자 정답은 검수 도구로 만든다 (ADR 0007) |

## 바꾼 것과 이유

| | 선행 | 여기 | 이유 |
|---|---|---|---|
| 셀 찾기 | 페이지마다 표를 검출하고 글자 상자를 가장 가까운 셀에 배정 | 양식별 템플릿에 정합. 셀 좌표는 미리 정해져 있다 | 양식은 몇 종뿐이고 날마다 같다. 보고서도 셀 경계가 흐리거나 글씨가 서식을 넘는 문서에서 보정이 더 필요하다고 적었다 (ADR 0001) |
| 셀 간 관계 | 그래프 신경망으로 추론 | 템플릿이 확정 (행 키, 열 이름) → `CellContext` | 어느 장비의 어느 열인지는 추론할 것이 아니라 양식에 적혀 있다 |
| 글씨 → 셀 | 무게중심 최근접 | 괘선 제거 + RLSA 덩어리, 여러 칸에 걸친 메모는 따로 구분 | 칸을 넘는 글씨가 흔하다 (`imaging/blobs.py`) |
| 인식 | 상용 OCR 서비스 | 교체 가능한 로컬 백엔드 | 외부 API 는 "외부 네트워크 없이"라는 요구와 맞지 않고, 손글씨에 맞게 학습시킬 수 없다 (ADR 0003) |
| 교정 | 언어모델이 문장을 다시 쓴다 | 후보 중에서 고른다. 숫자와 고유값은 건드리지 않는다 | 아래 "교정에 대해" |
| 평가 | 지시 데이터에서의 손실·퍼플렉서티, 예시 문장 비교 | 같은 평가셋에서 CER·필드 정확도·자동 적재율, 과교정 건수 | 퍼플렉서티는 교정 결과가 맞는지를 말해 주지 않는다. 보고서에는 교정 후 CER 수치가 없다 |
| 출력 | 엑셀 | DB + 값마다 출처(페이지·좌표·원문·신뢰도) | 검수와 교차검증에는 "이 값이 어디서 왔는가"가 필요하다. 엑셀은 DB 에서 내보낸다 |
| 여러 문서 | 문서 한 종(점검현황) | 양식 간 교차검증 | 물질수지 관점에서는 문서들이 서로 맞는지가 핵심이다 (ADR 0006) |

### 교정에 대해

선행 보고서의 비교표가 자유 생성 교정의 위험을 그대로 보여 준다.

- 미세조정하지 않은 언어모델들은 오류 문장을 고치는 대신 설명문을 지어냈다 (CER 137 – 185 %).
- 미세조정한 모델은 짧은 셀(단어 하나, 항목 두세 개)은 정확히 고쳤다.
- 그러나 항목이 여섯 개인 긴 셀에서는 **항목의 순서가 바뀌고, 일부가 빠지고, 원문에 없는 수량과 항목이 생겼다.**
  보고서도 "긴 문장의 경우 일부 정보 재배치 현상"이 있다고 적었다.

점검 기록에서 "2통"이 "1통"이 되는 것은 오타가 아니라 다른 사실이다. 그래서 이 저장소의 교정은

1. 후보(같은 장비·같은 열에서 반복된 문구, 용어 사전)를 내고 그중에서 고르거나 편집거리 제한 안에서만 고친다.
2. 숫자·단위·등록번호는 교정기가 바꾸지 못한다. 교정 전후로 숫자열이 같은지 검사하고, 다르면 교정을 버린다.
3. 교정이 맞는 값을 틀리게 만든 건수(과교정)를 따로 센다.

선행 연구의 미세조정 모델은 가중치를 받게 되면 이 틀 안에서 후보 백엔드로 평가할 수 있다. 다만 기반 모델(EXAONE 3.5)의 사용 허락이
비상업 조건(EXAONE AI Model License Agreement 1.1 - NC)이므로, 현장에 배포하는 소프트웨어에 넣기 전에 범위를 확인해야 한다.

## 권리 관계

나중에 다시 본다 (2026-10). 그때 확인할 것만 적어 둔다.

- 선행 연구팀은 별도의 특허 출원과 소프트웨어 등록을 예정하고 있었다 (2025년 최종보고서 기준).
- 이 저장소의 코드는 선행 소프트웨어의 코드를 포함하지 않는다. 방식도 다르다 (표 검출·그래프 추론이 아니라 템플릿 정합).
- 선행 산출물(어댑터, 사전, 데이터셋)을 이 소프트웨어와 함께 배포하게 되면 그 권리 관계는 용역 계약서에서 확인한다.
